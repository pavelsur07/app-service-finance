# Интеграция с 1С:Бухгалтерией предприятия 3.0

Внешняя обработка ВФ_Обмен в базе клиента сама отправляет данные к нам по HTTPS: рукопожатие (параметры базы и справочник организаций) и части пакетов. Мы к 1С не подключаемся. Обработка «тонкая», разбор — на сервере. Контракт — [api-contract.md](api-contract.md), требования к обработке для разработчика 1С — [processor-spec.md](processor-spec.md).

Сейчас сервер принимает и хранит пакеты `kind=invoices` (счета на оплату покупателям и от поставщиков). Разбор счетов, привязка организаций к компаниям в кабинете и перепроведение — следующие этапы.

## Подключить базу

1. Пользователь с правом записи `finance` в активной компании открывает «Компания → Подключения 1С» (`/onec/connections`) и нажимает «Подключить 1С».
2. Вводит название базы. На экране — адрес рукопожатия и токен. Токен показан один раз, хранится только его SHA-256. Оба значения вставляются в настройки ВФ_Обмен; адрес пакетов — тот же с `/packages` вместо `/handshake`.
3. Обработка выполняет рукопожатие: закрепляет `base_id` за подключением и присылает полный справочник организаций. `support.level` в ответе — совместимость; при `unsupported` пакеты отклоняются (422), пока не будет рукопожатия поддерживаемой версией. 409 — токен принадлежит другой базе.
4. Обработка отправляет пакеты. Карточка подключения показывает организации, выгрузки «частей N из parts_total», предупреждения обработки и даёт скачать каждую часть такой, как она пришла.

**Перевыпуск токена** в карточке сразу делает прежний токен недействительным (401) и показывает новый один раз. Отключённое подключение перевыпуском включается снова (статус «Ждёт рукопожатия»). **Отключение** отзывает токен: обработка получает 401. Оба действия, как и создание, пишутся в журнал аудита активной компании с ID пользователя.

Пороги версий — параметры `onec.minimum_config_version` и `onec.minimum_processor_version` в `site/config/services.yaml`. Пустое значение — порога нет. Семейство и редакция проверяются всегда.

## Как хранятся пакеты

- Каждая часть сохраняется байт-в-байт, сжатая gzip, через общий `Shared\Service\Storage\ObjectStorageInterface`. Путь — `onec/{connection_id}/{kind}/{yyyy}/{mm}/{package_id}/{part}-{sha256}.json.gz`, месяц — из `snapshot_at` в UTC; части, принятые до 27.11.2026, лежат по старому пути `onec/{connection_id}/{package_id}/…` и не переносятся.
- Пакет принимается только по организациям с галочкой «Загружать» (`export_allowed`): её ставит в карточке подключения пользователь с правом записи `finance`. На проде драйвер `s3` (timeweb, регион `ru-1`), локально и в тестах — `local`. Хранение бессрочное.
- Метаданные — `onec_package`: подключение, `package_id`, `part`, `parts_total`, `kind`, период, версии конфигурации на момент загрузки, версия обработки, `warnings`, число документов, путь, SHA-256 исходных байтов, размер, статус (`stored`), время приёма.
- Ключ повтора — unique `(connection_id, package_id, part)`. Повтор с теми же байтами получает прежний ответ с `duplicate: true`, с другими — 409. Сначала пишется объект (вне транзакции, путь детерминирован), затем строка через `INSERT … ON CONFLICT DO NOTHING`, поэтому одновременные повторы не дают 500.
- Тело пакета и токен не логируются: `/api/onec/v1/*` вычищается из событий GlitchTip, хранилище логирует только путь.
- Скачать часть может пользователь компании подключения с правом чтения `finance` (`/onec/packages/{id}/raw`) и администратор (`/admin/onec/packages/{id}/raw`).

Код — `site/src/OneC`: `ReceivePackageAction`, `PackageEnvelope`, `HandshakeAction`, `OneCConnectionRepository`. Таблицы — `onec_connection`, `onec_organization`, `onec_package`.

## Владение подключением и привязка организаций

Подключение принадлежит **компании**: `onec_connection.company_id`. `created_by_user_id` — кто создал, только для аудита; удаление пользователя подключение не удаляет.

- Создаёт подключение и управляет им (перевыпуск, отключение) пользователь с правом записи в модуле «Деньги и отчёты» (`finance`) активной компании: владелец, «Полный доступ», «Финансист». Видят список, карточку и сырьё — с правом чтения `finance`.
- Всё ищется по паре (подключение, активная компания): из другой компании того же владельца подключение не видно (404).
- Организации подключения относятся к его компании; привязка — флаг `enabled`. Привязать организацию к другой компании нельзя. Если в одной базе 1С ведутся юрлица разных компаний, каждой компании нужно своё подключение: `base_id` уникален внутри компании.
- Рукопожатие называет только компанию подключения.
- Удаление компании каскадно удаляет её подключения, организации и метаданные пакетов; объекты в хранилище остаются.

## Проверка после выпуска

Тестовое подключение → рукопожатие → часть пакета curl'ом по контракту → в бакете под `onec/{connection_id}/` лежит объект, в карточке «частей 1 из N», скачанная часть совпадает с отправленной.

# Контракт обмена v1

Два эндпоинта: рукопожатие и приём частей пакета. Адрес пакетов — адрес рукопожатия с заменой `/handshake` на `/packages`.

## Рукопожатие

Обработка ВФ_Обмен отправляет HTTPS POST на `/api/onec/v1/handshake` с заголовками `Authorization: Bearer <token>` и `Content-Type: application/json`. Кодировка UTF-8. Лимиты — 10 МиБ, до 65 536 открывающих скобок и запятых вне строк в сумме, 60 рукопожатий за минуту на действующее подключение. Владелец получает токен в кабинете.

Пример полного снимка справочника организаций:

```json
{
  "base_id": "26c4bc0e-58e8-4411-84f8-e434b7387894",
  "config_name": "БухгалтерияПредприятия",
  "config_synonym": "Бухгалтерия предприятия",
  "config_version": "3.0.100.1",
  "platform_version": "8.3.24.1",
  "processor_version": "1.0",
  "organizations": [
    {"guid":"23c15967-e31e-49bb-afa7-8441c7784b63","name":"Тестовая организация","inn":null,"kpp":null}
  ]
}
```

`base_id` — постоянный UUID базы. При первом валидном рукопожатии он закрепляется за подключением. Имя конфигурации — идентификатор метаданных. Версии — строки из чисел, разделённых точками. В MVP поддерживается только «БухгалтерияПредприятия» редакции 3.0. Номера выше приведены для примера. `config_synonym` необязателен. Лимит строки названия или версии — 255 символов. Неизвестные поля игнорируются.

`organizations` — обязательный массив. В каждой записи обязательны уникальный в пределах базы UUID и название. ИНН и КПП передаются строками либо null. Пустая строка принимается как отсутствие значения. ИНН физического лица в справочнике не сохраняется. Отсутствие GUID в полном снимке помечает организацию исчезнувшей. При пустом массиве исчезнувшими становятся все организации базы. Если обработка не смогла прочитать полный справочник, ей следует повторить запрос после успешного чтения.

Ответ 200:

```json
{
  "connection_id": "01949708-b318-75a3-a4f6-aa776cba619a",
  "status": "connected",
  "server_time": "2026-11-25T12:00:00+00:00",
  "support": {"level":"supported","message":"Поддерживаемая редакция БП 3.0."},
  "organizations": [{"guid":"23c15967-e31e-49bb-afa7-8441c7784b63","mapped":false,"company_name":null}],
  "messages": []
}
```

Ответ содержит организации текущего снимка. Привязки к компаниям владельца и флаг загрузки сохраняются при обновлении. Новая организация появляется без привязки. `mapped` отражает наличие доступной компании, независимо от флага загрузки. При `support.level=warning` подключение получает статус `connected`, при `unsupported` — `error` и пояснение в ответе 200. Это действительное рукопожатие и оно также закрепляет базу.

Ошибка имеет форму `{"error":"base_conflict","message":"Подключение уже привязано к другой базе."}`.

| HTTP | Код | Что сделать обработке |
|---|---|---|
| 401 | invalid_token | Проверить токен подключения |
| 403 | disabled | Обратиться к владельцу подключения. Отключение в кабинете отзывает токен, поэтому сейчас обработка получает 401 |
| 409 | base_conflict | Проверить базу и подключение. Повтор с теми же параметрами конфликт не разрешит |
| 413 | payload_too_large | Проверить размер отправляемого снимка |
| 422 | invalid_handshake | Исправить JSON или реквизиты и отправить полный снимок |
| 429 | rate_limited | Повторить через интервал из заголовка Retry-After в секундах |

При потере ответа повторить рукопожатие с тем же UUID базы. Ограничение уникальности базы действует внутри владельца. Два разных владельца могут независимо подключить базы с одинаковым UUID. Изменения v1 добавляющие.

## Приём части пакета

`POST /api/onec/v1/packages`, те же заголовки, UTF-8 JSON. Лимиты — 10 МиБ на часть, до 500 документов, до 200 000 открывающих скобок и запятых вне строк, до 10 000 частей в выгрузке, 120 частей в минуту на подключение. Тело читается после проверки токена и лимита запросов. Перед первой частью нужно успешное рукопожатие этой же базы.

```json
{
  "package_id": "01949708-b318-75a3-a4f6-aa776cba619b",
  "base_id": "26c4bc0e-58e8-4411-84f8-e434b7387894",
  "kind": "invoices",
  "processor_version": "1.0",
  "period_from": "2026-11-01",
  "period_to": "2026-11-30",
  "include_open_outside_period": true,
  "part": 1,
  "parts_total": 2,
  "warnings": ["Документ не найден в конфигурации"],
  "documents": [ … ]
}
```

- `kind` — пока только `invoices`: счета на оплату покупателям и от поставщиков. Другое значение — 422.
- `package_id` — UUID одной выгрузки. Во всех частях одинаковы `base_id`, `kind`, `period_from`, `period_to`, `include_open_outside_period`, `parts_total`. Часть с той же выгрузкой и другой оболочкой — 409.
- `part` — целое от 1 до `parts_total`. Даты — `ГГГГ-ММ-ДД`, начало не позже конца.
- `warnings` — массив без символа U+0000, сохраняется как есть; владельцу показываются первые 20 по 500 символов. `documents` — массив; на этапе приёма документы не разбираются, поля документа описаны в [ТЗ обработки](processor-spec.md). Неизвестные поля игнорируются.

Сервер сохраняет тело части без изменений и отвечает 200:

```json
{"accepted": true, "package_id": "01949708-b318-75a3-a4f6-aa776cba619b", "part": 1, "status": "stored", "duplicate": false}
```

`status: "stored"` — часть сохранена, разбор счетов выполняется отдельно. Счётчики `created`, `updated`, `cancelled` и ошибки документов появятся в ответе с этапом разбора — это добавляющее изменение v1.

**Повтор.** Ключ части — подключение, `package_id`, `part`. После тайм-аута или потери ответа обработка повторяет часть **байт-в-байт тем же телом**: сервер сравнивает SHA-256 исходных байтов. Совпадение — тот же ответ с `duplicate: true`, повторно ничего не сохраняется; одновременные повторы тоже получают этот ответ. Другое тело под тем же ключом — 409 `package_conflict`, принятая часть не меняется. Исправленная выгрузка получает новый `package_id`.

| HTTP | Код | Что сделать обработке |
|---|---|---|
| 401 | invalid_token | Токен неверен, перевыпущен или подключение отключено. Остановить отправку |
| 409 | base_conflict | Выполнить рукопожатие этой базой; токен принадлежит другой базе или рукопожатия не было |
| 409 | package_conflict | Не повторять. Новая выгрузка — новый `package_id` |
| 413 | payload_too_large | Часть больше 10 МиБ или слишком сложная: разбить мельче |
| 422 | invalid_package | Исправить оболочку; повтор без изменений не поможет |
| 422 | unsupported | Последнее рукопожатие вернуло `support.level=unsupported`: обновить обработку или конфигурацию и повторить рукопожатие |
| 429 | rate_limited | Повторить через `Retry-After` секунд |

При сетевых сбоях и 5xx — ограниченные повторы той же части с возрастающей паузой.

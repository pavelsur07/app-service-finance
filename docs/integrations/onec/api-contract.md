# Контракт обмена v1

Два эндпоинта: рукопожатие и приём частей пакета. Адрес пакетов — адрес рукопожатия с заменой `/handshake` на `/packages`.

Машинная форма контракта — JSON Schema [`site/src/OneC/Contract/v1/schema.json`](../../../site/src/OneC/Contract/v1/schema.json) (draft 2020-12, определения в `$defs`: `handshake_request`, `handshake_response`, `package_part`, `coverage`, `invoice`, `invoice_item`, `package_response`, `error`) и примеры в [`examples/`](../../../site/src/OneC/Contract/v1/examples/). Обработка может проверять по ней тело перед отправкой. Тест `ContractV1Test` держит схему, примеры и разбор сервера в согласии. Где текст и схема расходятся, правят оба в одном PR.

## Рукопожатие

Обработка ВФ_Обмен отправляет HTTPS POST на `/api/onec/v1/handshake` с заголовками `Authorization: Bearer <token>` и `Content-Type: application/json`. Кодировка UTF-8. Лимиты — 10 МиБ, до 65 536 открывающих скобок и запятых вне строк в сумме, 60 рукопожатий за минуту на действующее подключение. Владелец получает токен в кабинете.

Пример полного снимка справочника организаций:

```json
{
  "base_id": "26c4bc0e-58e8-4411-84f8-e434b7387894",
  "config_name": "БухгалтерияПредприятия",
  "config_synonym": "Бухгалтерия предприятия",
  "config_version": "3.0.100.1",
  "platform_version": "8.3.24.1",
  "processor_version": "1.0",
  "organizations": [
    {"guid":"23c15967-e31e-49bb-afa7-8441c7784b63","name":"Тестовая организация","inn":null,"kpp":null}
  ]
}
```

`base_id` — постоянный UUID базы. При первом валидном рукопожатии он закрепляется за подключением. Имя конфигурации — идентификатор метаданных. Версии — строки из чисел, разделённых точками. В MVP поддерживается только «БухгалтерияПредприятия» редакции 3.0. Номера выше приведены для примера. `config_synonym` необязателен. Лимит строки названия или версии — 255 символов. Неизвестные поля игнорируются.

`organizations` — обязательный массив. В каждой записи обязательны уникальный в пределах базы UUID и название. ИНН и КПП передаются строками либо null. Пустая строка принимается как отсутствие значения. ИНН физического лица в справочнике не сохраняется. Отсутствие GUID в полном снимке помечает организацию исчезнувшей. При пустом массиве исчезнувшими становятся все организации базы. Если обработка не смогла прочитать полный справочник, ей следует повторить запрос после успешного чтения.

Ответ 200:

```json
{
  "connection_id": "01949708-b318-75a3-a4f6-aa776cba619a",
  "status": "connected",
  "server_time": "2026-11-25T12:00:00+00:00",
  "support": {"level":"supported","message":"Поддерживаемая редакция БП 3.0."},
  "organizations": [{"guid":"23c15967-e31e-49bb-afa7-8441c7784b63","mapped":false,"company_name":null}],
  "messages": [],
  "settings": {"open_outside_period_months": 12}
}
```

`settings.open_outside_period_months` — глубина выгрузки открытых счетов вне периода, см. [ниже](#открытые-счета-вне-периода). Обработка берёт значение из последнего рукопожатия; если ключа нет — 12.

Ответ содержит организации текущего снимка. Организация может относиться только к компании подключения; привязка сохраняется при обновлении. Новая организация появляется без привязки. `mapped=true` — организация привязана к обмену и компания подключения действует; `company_name` — имя компании подключения, у непривязанной `null`. Имена других компаний ответ не раскрывает. При `support.level=warning` подключение получает статус `connected`, при `unsupported` — `error` и пояснение в ответе 200. Это действительное рукопожатие и оно также закрепляет базу.

Ошибка имеет форму `{"error":"base_conflict","message":"Подключение уже привязано к другой базе."}`.

| HTTP | Код | Что сделать обработке |
|---|---|---|
| 401 | invalid_token | Проверить токен подключения |
| 403 | disabled | Обратиться к владельцу подключения. Отключение в кабинете отзывает токен, поэтому сейчас обработка получает 401 |
| 409 | base_conflict | Проверить базу и подключение. Повтор с теми же параметрами конфликт не разрешит |
| 413 | payload_too_large | Проверить размер отправляемого снимка |
| 422 | invalid_handshake | Исправить JSON или реквизиты и отправить полный снимок |
| 429 | rate_limited | Повторить через интервал из заголовка Retry-After в секундах |

При потере ответа повторить рукопожатие с тем же UUID базы. Ограничение уникальности базы действует внутри компании. Разные компании могут независимо подключить базу с одинаковым UUID. Изменения v1 добавляющие.

## Приём части пакета

`POST /api/onec/v1/packages`, те же заголовки, UTF-8 JSON. Лимиты — 10 МиБ на часть, до 500 документов, до 200 000 открывающих скобок и запятых вне строк, до 10 000 частей в выгрузке, 120 частей в минуту на подключение. Тело читается после проверки токена и лимита запросов. Перед первой частью нужно успешное рукопожатие этой же базы.

```json
{
  "package_id": "01949708-b318-75a3-a4f6-aa776cba619b",
  "base_id": "26c4bc0e-58e8-4411-84f8-e434b7387894",
  "kind": "invoices",
  "processor_version": "1.0",
  "period_from": "2026-11-01",
  "period_to": "2026-11-30",
  "include_open_outside_period": true,
  "open_outside_period_months": 12,
  "snapshot_at": "2026-11-26T10:15:00+03:00",
  "part": 1,
  "parts_total": 2,
  "warnings": ["Документ не найден в конфигурации"],
  "coverage": [
    {"organization_guid": "23c15967-e31e-49bb-afa7-8441c7784b63", "type": "customer_invoice", "state": "complete", "outside_period_state": "complete"},
    {"organization_guid": "23c15967-e31e-49bb-afa7-8441c7784b63", "type": "supplier_invoice", "state": "partial", "outside_period_state": "partial"}
  ],
  "documents": [ … ]
}
```

- `kind` — пока только `invoices`: счета на оплату покупателям и от поставщиков. Другое значение — 422.
- `package_id` — UUID одной выгрузки. Во всех частях одинаковы `base_id`, `kind`, `period_from`, `period_to`, `include_open_outside_period`, `snapshot_at`, `parts_total`. Часть с той же выгрузкой и другой оболочкой — 409.
- `snapshot_at` — обязательно: время начала чтения в 1С, RFC 3339 со смещением, до секунды (`2026-11-26T10:15:00+03:00` или `…Z`). Одно на все части выгрузки и не меняется при повторе. Позже времени сервера больше чем на сутки — 422. Определяет старшинство выгрузок, см. [правила разбора](#правила-разбора).
- `open_outside_period_months` — глубина, с которой обработка отобрала открытые счета вне периода (значение из рукопожатия на момент чтения). Нужно при `include_open_outside_period=true`; без него сервер не закрывает счета вне периода по отсутствию.
- `part` — целое от 1 до `parts_total`. Даты — `ГГГГ-ММ-ДД`, начало не позже конца.
- `warnings` — массив без символа U+0000, сохраняется как есть; владельцу показываются первые 20 по 500 символов.
- `coverage` — полнота выборки по каждой паре «организация + вид счёта» в периоде и среди открытых вне периода, см. [ниже](#полнота-выборки). Необязательно, но без него сервер не отменяет счета, пропавшие из выгрузки.
- `documents` — массив счетов по [схеме документа](#документ-invoices). Неизвестные поля игнорируются.

Сервер сохраняет тело части без изменений и отвечает 200:

```json
{"accepted": true, "package_id": "01949708-b318-75a3-a4f6-aa776cba619b", "part": 1, "status": "stored", "duplicate": false}
```

`status: "stored"` — часть сохранена, разбор счетов выполняется отдельно. Счётчики `created`, `updated`, `cancelled` и ошибки документов появятся в ответе с этапом разбора — это добавляющее изменение v1.

**Повтор.** Ключ части — подключение, `package_id`, `part`. После тайм-аута или потери ответа обработка повторяет часть **байт-в-байт тем же телом**: сервер сравнивает SHA-256 исходных байтов. Совпадение — тот же ответ с `duplicate: true`, повторно ничего не сохраняется; одновременные повторы тоже получают этот ответ. Другое тело под тем же ключом — 409 `package_conflict`, принятая часть не меняется. Исправленная выгрузка получает новый `package_id`.

| HTTP | Код | Что сделать обработке |
|---|---|---|
| 401 | invalid_token | Токен неверен, перевыпущен или подключение отключено. Остановить отправку |
| 409 | base_conflict | Выполнить рукопожатие этой базой; токен принадлежит другой базе или рукопожатия не было |
| 409 | package_conflict | Не повторять. Новая выгрузка — новый `package_id` |
| 413 | payload_too_large | Часть больше 10 МиБ или слишком сложная: разбить мельче |
| 422 | invalid_package | Исправить оболочку; повтор без изменений не поможет |
| 422 | unsupported | Последнее рукопожатие вернуло `support.level=unsupported`: обновить обработку или конфигурацию и повторить рукопожатие |
| 429 | rate_limited | Повторить через `Retry-After` секунд |

При сетевых сбоях и 5xx — ограниченные повторы той же части с возрастающей паузой.

## Документ `invoices`

Один элемент `documents` — счёт на оплату покупателю или от поставщика вместе со строками. Обработка раскладывает реквизиты 1С по этим полям без интерпретации; исходные значения, которые сервер переводит в свои коды, передаются рядом (`status_raw`).

**Представление значений.** Суммы, цены, количество — строки с десятичной точкой и исходной точностью (`"1000.00"`, `"0.125"`), без пробелов и разделителей разрядов. Даты — `ГГГГ-ММ-ДД`. Неизвестное или недоступное значение — `null`, не ноль и не пустая строка. ИНН и КПП — строками; ИНН физического лица (12 цифр) не передаётся, вместо него `null`.

```json
{
  "guid": "29b49210-1111-4000-8000-000000000001",
  "type": "customer_invoice",
  "number": "00БП-000017",
  "date": "2026-11-12",
  "organization_guid": "23c15967-e31e-49bb-afa7-8441c7784b63",
  "counterparty": {"guid": "29b49210-1111-4000-8000-000000000002", "name": "ООО «Покупатель»", "inn": "7701234567", "kpp": "770101001"},
  "contract": {"guid": "29b49210-1111-4000-8000-000000000003", "name": "Договор поставки № 15 от 01.02.2026"},
  "bank_account_guid": "29b49210-1111-4000-8000-000000000004",
  "amount": "120000.00",
  "vat_amount": "20000.00",
  "amounts_include_vat": true,
  "currency": "RUB",
  "due_date": "2026-11-26",
  "status": "partially_paid",
  "status_raw": "Оплачен частично",
  "paid_amount": "50000.00",
  "comment": "Отгрузка партии 3",
  "posted": true,
  "deletion_mark": false,
  "items": [
    {
      "line_no": 1,
      "nomenclature": {"guid": "7c0e1f3a-3333-4000-8000-000000000021", "name": "Кофе зерновой 1 кг", "article": "CF-1000", "kind": "goods"},
      "content": null,
      "unit": {"name": "шт", "code": "796"},
      "quantity": "40",
      "price": "2400.00",
      "amount": "96000.00",
      "vat_rate": "20%",
      "vat_amount": "16000.00",

    },
    {
      "line_no": 2,
      "nomenclature": {"guid": "7c0e1f3a-3333-4000-8000-000000000022", "name": "Доставка", "article": null, "kind": "service"},

      "unit": {"name": "усл", "code": null},

      "amount": "24000.00",

    }

```

| Поле | Обяз. | Значение |
|---|---|---|
| `guid` | да | UUID ссылки на документ, ключ счёта в пределах подключения |
| `type` | да | `customer_invoice` — счёт покупателю, `supplier_invoice` — счёт от поставщика |
| `number` | | Номер как в 1С, строкой, с префиксом и ведущими нулями |
| `date` | да | Дата документа |
| `organization_guid` | да | GUID организации из справочника рукопожатия |
| `counterparty` | | `{guid, name, inn, kpp}` либо `null` |
| `contract` | | `{guid, name}` либо `null` |
| `bank_account_guid` | | GUID банковского счёта организации либо `null` |
| `amount` | да | Сумма документа в его валюте |
| `vat_amount` | | Сумма НДС документа |
| `amounts_include_vat` | | Флаг «сумма включает НДС» документа: включают ли НДС `amount`, `price` и `amount` строк. `null` — неизвестно |
| `currency` | | Код валюты как в 1С (`RUB`, `USD`). Не подставлять `RUB` по умолчанию |
| `due_date` | | Срок оплаты |
| `status` | | `not_paid`, `partially_paid`, `paid`, `cancelled` либо `null`, если исходное значение не сопоставлено |
| `status_raw` | | Исходное значение статуса из БП, передаётся всегда, когда есть |
| `paid_amount` | | Оплачено по этому счёту, если достоверно известно; иначе `null` |
| `comment` | | Комментарий документа |
| `posted` | | Проведён ли документ |
| `deletion_mark` | | Помечен ли на удаление |
| `items` | | Строки табличной части, см. ниже. `[]` — строк нет, `null` — строки прочитать не удалось (с предупреждением в `warnings`) |

Строка `items[]`:

| Поле | Значение |
|---|---|
| `line_no` | Номер строки в документе, целое |
| `nomenclature` | `{guid, name, article, kind}`: GUID и наименование номенклатуры из справочника, артикул, `goods` или `service`. `null`, если в строке номенклатуры нет |
| `content` | «Содержание» строки — свой текст, заданный в документе (часто у услуг), иначе `null` |
| `unit` | `{name, code}` — единица измерения и код ОКЕИ, если есть |
| `quantity`, `price`, `amount` | Количество, цена и сумма строки. Включают ли цена и сумма НДС — по `amounts_include_vat` документа |
| `vat_rate` | Ставка как в 1С: `"20%"`, `"10%"`, `"0%"`, `"Без НДС"` |
| `vat_amount` | Сумма НДС строки |
| `comment` | Примечание к строке, если есть |

Обязательный минимум документа — `guid`, `type`, `date`, `organization_guid`, `amount`; без них документ попадёт в ошибки разбора, остальная часть загрузится. Недоступное необязательное поле — `null` и предупреждение, документ не пропускается. Сервер сверяет сумму строк с `amount` и при расхождении загружает счёт с предупреждением.

Строки утяжеляют часть: делить выгрузку нужно по всем трём лимитам — 500 документов, 10 МиБ, 200 000 элементов JSON.

## Полнота выборки

`coverage` — по одной записи на каждую пару «организация + вид счёта», которую обработка пыталась прочитать. Во всех частях выгрузки одинаково. Два поля состояния:

- `state` — счета пары с датой в `period_from..period_to`;
- `outside_period_state` — открытые счета пары вне периода по [критерию](#открытые-счета-вне-периода). При `include_open_outside_period=false` — `not_selected`.

| Значение | Смысл |
|---|---|
| `complete` | Прочитаны все счета пары по своему критерию, в том числе ноль документов |
| `partial` | Чтение прервано, не хватило прав или пропущен документ из-за ошибки |
| `not_selected` | Пара или выборка не выбрана пользователем |

Пара без записи и отсутствующее поле считаются `partial`. Сервер сохраняет `coverage` вместе с частью; применяется оно с этапом разбора.

## Открытые счета вне периода

При `include_open_outside_period=true` в выгрузку дополнительно входят счета выбранных пар с датой вне периода, если выполнено одно из условий:

1. Счёт открыт: `status` — `not_paid` или `partially_paid`, нет пометки удаления, дата не раньше чем `open_outside_period_months` месяцев до даты `snapshot_at` (12 по умолчанию, значение из рукопожатия).
2. По счёту есть оплата с датой в периоде, независимо от статуса и давности.

Каждый GUID попадает в выгрузку один раз. `outside_period_state=complete` означает, что список полон по обоим условиям.

## Правила разбора

Исполняются сервером на этапе нормализации; приём их не применяет.

- **Полный пакет** — получены все части `1..parts_total` одного `package_id`.
- **Старшинство.** Сервер хранит для документа (`guid`) `last_applied_snapshot` — `snapshot_at` пакета, чьё решение о документе применено последним: документ пришёл, отменён или закрыт по отсутствию. Пакет меняет документ, только если его `snapshot_at` позже `last_applied_snapshot`; опоздавший старый пакет документ не трогает. Любое применённое решение обновляет `last_applied_snapshot`.
- **Отмена по отсутствию** — только по полному пакету, только в парах с `state=complete` и только для документов, у которых дата в периоде пакета и `last_applied_snapshot` раньше `snapshot_at` этого пакета. Такой счёт помечается отменённым, не удаляется.
- **Открытые вне периода.** Наш открытый счёт с датой вне периода получает статус «закрыт в 1С, причина неизвестна», если одновременно: пакет полный, у пары `outside_period_state=complete`, в пакете есть `open_outside_period_months` и дата счёта не раньше чем столько месяцев до даты `snapshot_at`, документа в пакете нет, `last_applied_snapshot` раньше `snapshot_at`. Счёт старше окна давности по отсутствию не закрывается. Счёт не удаляется; следующая выгрузка с этим документом возвращает ему фактический статус.
- **Очерёдность.** Пакеты одного подключения разбираются последовательно под блокировкой подключения, в порядке `snapshot_at`.

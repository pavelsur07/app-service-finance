# Реклама по тегам в предпросмотре ОПиУ — план

Дата: 2026-10-17 · поручение Владельца: разобрать расходы на рекламу по тегам, «вариант 2 —
считать точно, это супер важно». Продолжение `docs/plan/marketplace-pl-preview-by-tags.md`.

## Проблема

В учёте (`marketplace_costs`) реклама почти всегда без товара: WB удерживает её суммой на
кабинет, у Ozon оплата за клик и продвижение приходят начислениями без SKU. Поэтому в
предпросмотре вся реклама лежит в колонке «Общие / без тега».

Точные суммы по товарам уже есть в модуле «Реклама» (`marketplace_ad_documents` / `_lines`):
Ozon — статистика Performance по кампании и SKU, WB — сумма кампании (`/adv/v1/upd`), разнесённая по
товарам по доле расходов `fullstats`. С учётом эти данные сейчас никак не связаны и не сверяются.

## Решение (вариант 2)

- **Колонки тегов** — реклама товаров тега берётся **из рекламной статистики**: ровно та сумма,
  которую кампании потратили на эти товары за период.
- **«Итого»** — по-прежнему учётная сумма: предпросмотр остаётся предпросмотром будущего ОПиУ,
  который проводит учёт.
- **«Общие / без тега»** — реклама товаров без тегов из статистики + строка
  **«Реклама: расхождение учёта и статистики»** = учёт − статистика. Колонки сходятся в «Итого»,
  расхождение видно числом, а не размазано по тегам.
- На какую статью ОПиУ кладётся реклама из статистики — на ту же, куда маппинг затрат относит
  заменяемую учётную категорию (никакого второго маппинга).

## Что надо проверить до кода (этап 0, только чтение прода)

1. Сходятся ли суммы: реклама в учёте против суммы рекламной статистики по каждому маркетплейсу
   за последние 3 месяца, по месяцам. Если расхождение большое и систематическое — сначала
   разобраться, почему (это вопрос данных, а не отчёта).
2. Какая доля статистики не привязана к товару (WB `__unallocated__`, кампании без найденного
   листинга, Ozon SKU без листинга — сейчас такие строки Ozon молча пропускаются).
3. Совпадают ли даты: удержания WB датированы не днём показа — проверить сдвиг на границе месяца.

Итог этапа 0 — короткий отчёт Владельцу с цифрами; от него зависит, нужны ли этапы 1–2 в
задуманном виде.

## Этапы

**Этап 1. Какие учётные категории — реклама из статистики.** Флаг у правила маппинга затрат
«рекламу брать из рекламной статистики» (поле в `marketplace_cost_pl_mappings` + переключатель
на экране «Маппинг затрат»), по умолчанию выключен. Кандидаты: Ozon `ozon_cpc`, WB
`wb_okazanie_uslug_wb_prodvizhenie`; подписки («Джем», Premium, «Аналитика»), баллы за отзывы и
акции не покрываются статистикой и остаются в «Общих». Миграция — отдельный dispatch на проде.

**Этап 2. Данные статистики через Facade.** Новый метод `MarketplaceAdsFacade` — расход по
листингам за период и маркетплейс + сумма, не привязанная к листингам. Только чтение, компания —
параметром. Ozon-строки без найденного листинга перестают теряться: попадают в непривязанную сумму
(сейчас `ProcessAdRawDocumentAction` их пропускает — это отдельная правка с тестом).

**Этап 3. Предпросмотр.** В `BuildMarketplacePlPreviewAction`: для статей с флагом — колонки тегов
и «Общие» из статистики, «Итого» из учёта, строка расхождения в «Общих». Блок «Сверка рекламы»:
учёт / статистика / не привязано к товарам / расхождение по каждому маркетплейсу. Экран и xlsx.

**Этап 4. Unit-экономика (отдельно, по результату этапа 0).** Там реклама по строке уже из
статистики, а рекламные учётные категории дополнительно попадают в «прочие» — проверить на данных
прода, нет ли двойного счёта, и чинить отдельной задачей.

## Чек-лист готовности

- [ ] Этап 0: цифры сходимости учёта и статистики по маркетплейсам и месяцам — у Владельца.
- [ ] Сумма рекламы на теге = сумма статистики по его листингам за период (тест на фикстуре).
- [ ] Колонки тегов (без пересечения) + «Общие» = «Итого»; «Итого» = проведение (как сейчас).
- [ ] Расхождение учёт − статистика — отдельной строкой и в блоке сверки, не размазано.
- [ ] Категории без флага ведут себя как сейчас.
- [ ] Компания везде параметром; Marketplace ходит в MarketplaceAds только через Facade.
- [ ] Экран и xlsx показывают одно и то же.

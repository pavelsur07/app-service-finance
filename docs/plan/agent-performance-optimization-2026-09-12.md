## Проблема

Система деградирует: простые задачи выполняются 2–3 часа, задачи средней
сложности — 8–9 часов.

## Диагноз: почему всё тормозит

### 1. Перегруженный контекст в каждой сессии (~6000+ строк правил до начала работы)

- `AGENTS.md` (397 строк) требует «read fully at start», плюс автозагрузка
  `CLAUDE.md` (263), и по инструкции читаются `PATTERNS.md` (1513 строк),
  `ARCHITECTURE.md` (3366 строк), `docs/workflow/*` (~560 строк). Модель тонет
  в правилах, деградирует на длинном контексте и тратит время на ритуалы
  вместо задачи.

### 2. Церемония workflow несоразмерна задачам

- Даже «Small» задача: baseline → реализация → внутреннее ревью полного диффа →
  внешнее ревью другим CLI (10 мин на раунд, до 3 раундов) → PR → handoff.
  «Large»: Phase 0 + Stages + checkpoint после каждого work item + Stage Report +
  внешнее ревью на каждый HIGH-LOCAL Stage. Это и есть 2–3 часа на простое.
- Полные гейты (`make site-stan`, `cs-check`, тесты) гоняются на каждый Stage,
  а не один раз в конце.

### 3. Конфиги агентов добавляют тормоза

- `~/.codex/config.toml`: `model_reasoning_effort = "high"`, план-режим
  `"xhigh"` — Codex думает максимально долго над каждым шагом, включая
  тривиальные.
- `~/.claude/settings.json`: включены 3 плагина (ponytail, superpowers,
  php-modernization) — сотни skills, все описания грузятся в каждую сессию.
  Плюс блок `autoMode.environment` описывает **другой проект**
  (app-service-analytics, `conwix-prod`) — мусор в контексте и риск путаницы.
- `.codex/config.toml` проекта: `sandbox_mode = "danger-full-access"` +
  `network_access = false` конфликтует с пользовательским конфигом
  (`workspace-write`, сеть включена) — непредсказуемое поведение и ретраи
  сетевых команд.
- Сессии живут часами без компакта: `~/.claude/projects` — 125 MB, 108
  каталогов `session-env`.

## План по приоритету

### Этап 1 — Быстрые победы (30–60 мин, эффект сразу)

1. **Codex: снизить reasoning effort.** В `~/.codex/config.toml`:
   `model_reasoning_effort = "medium"`, `plan_mode_reasoning_effort = "high"`.
   Для рутины «xhigh» — чистая потеря времени. Ожидаемый эффект: −30–50%
   времени на шаг.
2. **Claude: убрать лишние плагины.** В `~/.claude/settings.json` отключить
   `ponytail` и `php-modernization` (superpowers оставить только если реально
   используется). Это сотни skills-описаний из каждого контекста.
3. **Claude: удалить чужой `autoMode.environment`** про app-service-analytics
   из `~/.claude/settings.json` — он про другой репозиторий и другой прод-хост.
4. **Codex: устранить конфликт сети.** В `.codex/config.toml` убрать
   `network_access = false` (либо синхронизировать с user-конфигом) — сейчас
   composer/npm/внешние вызовы под проектной песочницей падают и ретраятся.
5. **Правило работы: одна задача = одна свежая сессия.** Не тянуть сессию
   часами; при компактах контекст деградирует. Длинные исследования выносить в
   субагентов.

### Этап 2 — Упрощение workflow (главный резерв времени)

6. **Убрать обязательное внешнее ревью для Small-задач** (`AGENTS.md` §7.2):
   оставить внутреннее ревью, внешнее — только по явному запросу или при
   HIGH-риске (миграции, финлогика, auth). Минус 10–30 мин на каждой простой
   задаче.
7. **Внешнее ревью на Large: только на handoff, 1 раунд, `--effort medium`.**
   Убрать обязательный раунд на каждый HIGH-LOCAL Stage — внутреннее ревью +
   гейты достаточны.
8. **Гейты — один раз в конце.** На Work item — только узкий тест + lint
   изменённых файлов; полный `make site-stan && site-cs-check &&
   site-test-unit` — только на handoff (сейчас — на каждый Stage).
9. **Сократить автозагружаемый контекст.** Ужать `AGENTS.md` до ~120–150 строк
   (подробности — в workflow-доки по ссылке); убрать «read fully at start» для
   `PATTERNS.md`/`ARCHITECTURE.md` — читать только нужный раздел по задаче (в
   `CLAUDE.md` это уже написано, усилить приоритет этой строки).

### Этап 3 — Структурные изменения

10. **Ввести класс задачи «XS»** (багфикс < 30 строк, один файл): implement →
    узкий тест → commit → PR, без checkpoint/ревью-ритуалов. Именно этот класс
    сейчас съедает «2–3 часа на простое».
11. **Замерить baseline до/после:** на 3 типовых задачах фиксировать wall-time
    и число вызовов инструментов. Цель: XS < 30 мин, Small < 1 ч, средняя
    Large < 3 ч.
12. **Гигиена сессий:** почистить `~/.claude/session-env` (108 каталогов) и
    старые сессии; добавить в рутину периодическую очистку.

### Что НЕ трогать

- `deny`/`ask`-списки в `.claude/settings.local.json` — они осмысленные,
  безопасность прода важнее скорости.
- Доменные минимумы `CLAUDE.md` (companyId-изоляция, финформулы) — это не
  ритуал, а защита.

## Целевые метрики

| Класс задачи | Сейчас | Цель |
|---|---|---|
| XS (багфикс < 30 строк) | 2–3 ч | < 30 мин |
| Small | 2–3 ч | < 1 ч |
| Средняя Large | 8–9 ч | < 3 ч |

## Протокол замера (п. 11)

На ближайших 3 типовых задачах (по одной класса XS, Small, Large) фиксировать
в описании PR или `handoff.md`:

- wall-time от старта сессии до handoff;
- класс задачи и число раундов внешнего ревью (0 — ожидаемая норма для XS и
  обычной Small);
- сколько раз гонялись полные гейты (норма — один раз, на handoff).

Сверка с целевыми метриками — через 2 недели, по этим трём записям. Если Small
снова занимает больше часа — смотреть, какой ритуал вернулся, и резать его.

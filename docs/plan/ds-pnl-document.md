## 1. Аудит (Stage 0)
Подробно — `stages/stage-0.md`. Главное:
- Страница — `DocumentController` (`document_new` / `_copy` / `_edit`), общий
  `document/_page.html.twig` + `_page_scripts.html.twig`; формы `DocumentType` /
  `DocumentOperationType`.
- Статья операции — `EntityType` по `findTreeByCompany()` (один запрос),
  `required: false`, группы выбираемы; уровни 1–5. Типа операции в модели нет —
  «Доход/Расход» по `flow` статьи, у `NONE` — по знаку суммы.
- Проект/ЦФО есть и у документа, и у операции; сервер подставляет шапку только в
  пустые поля операций и системную пару «Общий × Общий» в пустую пару.
- Описание операции — существующее поле `comment` (varchar 255).
- Soft-delete и восстановление, копия, JSON — есть; истории — нет.
- Из операции ДДС документ создаётся сразу (POST → правка); форма «Новый» — ручное
  создание без основания и копия.

## 2. Решения SPEC §8

| § | Решение | Основание |
|---|---|---|
| 8.1 Проект/ЦФО шапки | хранятся в документе (поля уже есть) | эвристика «самое частое значение» не нужна; схема не меняется |
| 8.2 Описание операции | поле `comment`, подпись «Описание» | миграции нет; `maxlength` 255 по колонке, а не 200 из SPEC — иначе не ввести/не сохранить уже длинные описания (**вопрос**) |
| 8.3 Удаление | модалка «Удалить документ?» → «Удалённые»; восстановление там же | правка удалённого запрещена контроллером — баннера на форме нет |
| 8.4 Создание без основания | форма «Новый» — ручная (как сейчас); создание из ДДС — сразу в правку, без формы | поток не менялся (**вопрос**: нужна ли форма предзаполнения из ДДС) |
| 8.5 Иерархия статей | `parent`, 4 группы + лист; лист — статья без детей; `flow` листа: INCOME → доход, EXPENSE → расход, NONE → обе стороны | регистр берёт знак из статьи операции |
| 8.6 Дублировать / JSON / История | «Дублировать документ» (= копия), «Выгрузить JSON»; истории нет | нерабочих пунктов не показываем |

## 3. Сделано
**PR 1 — виджет.** `PLCategoryTreeBuilder` (дерево из уже загруженных статей, без
чтения `children`), `PLCategoryTreeType` (EntityType + дерево, тема формы). Виджет
«Статьи ДДС» расширен без копии: одно дерево на страницу
(`<script type="application/json" id="document-category-tree">`, `data-tree-source`),
один открытый popover, MutationObserver подключает виджет к строкам из
`data-prototype` и отключает у удалённых, путь под полем, теги «Доход»/«Расход»,
сохранённое значение вне листьев показывается текстом. Имя поля, value и select без
JS — прежние.

**PR 2 — страница правки.** Шапка в две колонки с Проектом, ЦФО (виджет плоским
списком), плашкой о наследовании и счётчиком описания; строка операции по SPEC §5.1
(Тип · Категория · Проект · ЦФО · Сумма · Дублировать/Удалить), «Описание» второй
строкой, контрагент операции — третьей. Наследование на клиенте (SPEC §4.1):
смена шапки меняет только строки, равные прежнему значению; уведомление «… подставлен
в N из M операций. В K задан вручную»; «Изменён» + «Как в шапке»; новая строка — шапка,
дубль — исходная. Единственную операцию не удалить; «Сохранить» в правке неактивна без
изменений; суммы «70 000,00» (на сервер — с точкой). «Ещё» — только работающее.
Раскладка: таблица >1340, по два поля 761–1340, карточки ≤760.

## 4. Отклонения от эталона

| Эталон / SPEC | Решение | Почему |
|---|---|---|
| Select «Тип» в строке, фильтр дерева по типу, сброс несовместимой категории (скрин 05) | тип — подпись по `flow` категории; дерево показывает все листья с тегами | поля «Тип» нет в модели (решение #2699); фильтр без поля стал бы состоянием, которое не сохраняется |
| «Категория ОПиУ *», «Проект *» обязательны | звёздочка только у суммы | сервер категорию не требует, пустой проект заменяет на «Общий» (**вопрос**) |
| Запрет группы на сервере | в UI группа не выбирается; select принимает группу, как раньше | `disabled` у групп сломал бы сохранение документов, где группа уже стоит |
| «Период в отчёте» | нет | нет поля в модели (как в #2699) |
| Колонки без контрагента | контрагент операции — третьей строкой | поле есть и используется; редизайн не прячет логику |
| Описание операции maxlength 200 | 255 | колонка varchar(255), `Length(max: 255)` |
| «История изменений» | нет | нет бэкенда |
| Тип документа в шапке | есть | поле модели |

## 8. Открытые вопросы владельцу (SPEC §8)
1. Категория операции обязательна на сервере? Сейчас нет: операции без статьи
   (создание из ДДС без маппинга) сохраняются и не входят в итог.
2. Запретить группу статей на сервере (существующие операции с группой перестанут
   сохраняться без правки)?
3. Длина описания операции — 255 (колонка) или 200 (SPEC, нужна проверка данных)?
4. Нужна ли форма «Новый документ» с предзаполнением из операции ДДС (сейчас
   документ из ДДС создаётся сразу)?
5. Поле «Тип» в операции (и тогда фильтр дерева по типу) — нужно ли отдельно от
   `flow` статьи?
6. Проект в шапке — обязателен (сейчас пустой → «Общий»)?

# Отображаемое название контрагента в едином виде — план

Дата: 2026-10-13 · поручение Владельца в чате: привести названия к единому стандарту, но
**путь загрузки (импорт 1С, файлов) не трогать** — нормализовать отдельным шагом позже.

## Принцип: «храним сырое, производное считаем отдельно»

- `name` — как загрузили (выписка, форма), навсегда; импорт не меняется.
- `display_name` — производное, пишет только шаг нормализации; рядом `display_name_source`
  (`auto` / `manual`) и `display_rules_version`.
- Показ, поиск, экспорт: `display_name ?? name` — пока строка не обработана, видно сырое.
- Ручная правка (`manual`) главнее правил: нормализатор её не перезаписывает.
- «Не уверен — не трогай»: нераспознанное остаётся `null` и попадает в отчёт.
- Тот же паттерн уже есть: `BackfillCounterpartyNamesAction` пересчитывает `name_core` /
  `legal_form_hint`, не трогая `name`.

## Этапы (каждый — отдельный PR)

1. **Правила** — `Company\Domain\Service\CounterpartyDisplayNameFormatter` + unit-тесты. Чистый
   сервис, без БД. ← этот PR.
2. Поля `display_name`, `display_name_source`, `display_rules_version` (миграция — отдельный
   dispatch на проде) и команда пересчёта с `--dry-run`.
3. Сухой прогон на проде (read-only), отчёт «было → станет / не распознано» Владельцу.
4. Запись на проде и расписание в планировщике — отдельное согласие (изменение данных).
5. Интерфейс: список, формы, пилюля, поиск — `display_name`; правка в форме → `manual`.

## Этап 1. Правила

| Вход | Выход |
|---|---|
| `БАНК ГПБ (АО)//40701810992000010090 ИНН7705042179 СПАО "Ингосстрах"` | `СПАО «Ингосстрах»` |
| `ИНДИВИДУАЛЬНЫЙ ПРЕДПРИНИМАТЕЛЬ ЛИЗУНОВА ОЛЬГА НИКОЛАЕВНА` | `ИП Лизунова Ольга Николаевна` |
| `ИП Абрамов Кирилл Викторович` | без изменений |
| `ОБЩЕСТВО С ОГРАНИЧЕННОЙ ОТВЕТСТВЕННОСТЬЮ "РВБ"` | `ООО «РВБ»` |
| `ООО "ИНТЕРНЕТ МАРКЕТИНГ"` | `ООО «ИНТЕРНЕТ МАРКЕТИНГ»` |

1. **Банковская строка (383-П, есть `//`)**: «банк//счёт ИНН клиент», «ФИО//адрес//»,
   «банк//ФИО//адрес//». Сегменты-адреса (`г.`, `ул.`, `д. 1`, индекс из 6 цифр, `р/с`) и
   сегменты без букв отбрасываются; первый сегмент со словом «БАНК» отбрасывается, если есть
   другие. Остался один — он; несколько — тот, в котором ровно одна ОПФ; иначе `null`.
2. **Реквизиты** — `ИНН…`, `КПП…`, `ОГРН(ИП)…`, 20-значный счёт и оставшиеся пустые скобки
   убираются, хвостовая пунктуация срезается.
3. **ОПФ** → сокращённая: ООО, АО, ПАО, НАО, ЗАО, ОАО, СПАО, САО, АНО, ИП.
   - Префиксом — после ОПФ пробел или кавычка («ООО-Ромашка», «ООО. Ромашка» → `null`).
   - Суффиксом в скобках — «Банк ВТБ (ПАО)».
   - Голым суффиксом — **только после названия в кавычках** («"Ромашка" ООО»): без кавычек это
     округ («Префектура ЗАО», «Администрация Ненецкого АО»).
   - Сокращение — только целиком заглавными или строчными («Сао Пауло», «Ип Ман» — не ОПФ);
     полная форма — в любом регистре. ИП — только префиксом (суффиксное «И.П.» — инициалы).
   - Больше одной ОПФ в строке → `null`.
4. **Организация**: `ОПФ «Название»`; внешние кавычки любого вида → «ёлочки»; **регистр не
   меняется**. Название без хвостов: начинается с буквы или цифры; без вложенных кавычек, скобок,
   запятых, `/`, реквизитов, чисел из 5+ цифр или групп по 4 (счёт, карта), адреса — иначе `null`.
5. **ИП**: `ИП Фамилия Имя Отчество`; 2–4 слова, каждое — кириллица (двойная фамилия через
   дефис) или инициалы «И.» / «И.И.». Целиком заглавными или строчными → каждая буквенная группа с
   заглавной, частицы «оглы / кызы» строчными; смешанный регистр — как ввели.
6. **`null` (не трогать)**: нет ОПФ (Ozon, ФНС России); госучреждения и органы власти (ФГБУ, ГКУ,
   МКУ, МУП, УФК, ИФНС, ОМВД, префектура, управа, администрация, департамент, министерство,
   управление), филиалы и отделения (ОПФ головной организации), «Глава КФХ». Исключение —
   сторона банковской строки без ОПФ (человек): возвращается текстом, если в нём только буквы,
   пробелы, точки и дефисы. Невидимые символы (U+200B–U+200D, U+FEFF) убираются.
7. **Идемпотентность**: `format(format(x))` — тот же результат для ОПФ и ИП; для стороны
   банковской строки без ОПФ — `null` («оставить как есть»: `//` уже нет). На этапе 2 правила
   применяются только к сырому `name`.
8. Скорость ~100 мкс на вызов — достаточно для пересчёта десятков тысяч строк; при росте —
   одна скомпилированная альтернация вместо цикла по вариантам (FOLLOW-UP).

Словарь ОПФ — собственный, не `CounterpartyNameNormalizer`: тот строит ключ сравнения
(верхний регистр, без кавычек), и добавление в него СПАО/НАО/АНО и скобочной формы сменило бы
`name_core` уже сохранённых записей (backfill, переоценка дублей) — вне этого этапа.

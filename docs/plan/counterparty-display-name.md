# Отображаемое название контрагента в едином виде — план

Дата: 2026-10-13 · поручение Владельца в чате: привести названия к единому стандарту, но
**путь загрузки (импорт 1С, файлов) не трогать** — нормализовать отдельным шагом позже.

## Принцип: «храним сырое, производное считаем отдельно»

- `name` — как загрузили (выписка, форма), навсегда; импорт не меняется.
- `display_name` — производное, пишет только шаг нормализации; рядом `display_name_source`
  (`auto` / `manual`) и `display_rules_version`.
- Показ, поиск, экспорт: `display_name ?? name` — пока строка не обработана, видно сырое.
- Ручная правка (`manual`) главнее правил: нормализатор её не перезаписывает.
- «Не уверен — не трогай»: нераспознанное остаётся `null` и попадает в отчёт.
- Тот же паттерн уже есть: `BackfillCounterpartyNamesAction` пересчитывает `name_core` /
  `legal_form_hint`, не трогая `name`.

## Этапы (каждый — отдельный PR)

1. **Правила** — `Company\Domain\Service\CounterpartyDisplayNameFormatter` + unit-тесты. Чистый
   сервис, без БД. ← этот PR.
2. Поля `display_name`, `display_name_source`, `display_rules_version` (миграция — отдельный
   dispatch на проде) и команда пересчёта с `--dry-run`.
3. Сухой прогон на проде (read-only), отчёт «было → станет / не распознано» Владельцу.
4. Запись на проде и расписание в планировщике — отдельное согласие (изменение данных).
5. Интерфейс: список, формы, пилюля, поиск — `display_name`; правка в форме → `manual`.

## Этап 1. Правила

| Вход | Выход |
|---|---|
| `БАНК ГПБ (АО)//40701810992000010090 ИНН7705042179 СПАО "Ингосстрах"` | `СПАО «Ингосстрах»` |
| `ИНДИВИДУАЛЬНЫЙ ПРЕДПРИНИМАТЕЛЬ ЛИЗУНОВА ОЛЬГА НИКОЛАЕВНА` | `ИП Лизунова Ольга Николаевна` |
| `ИП Абрамов Кирилл Викторович` | без изменений |
| `ОБЩЕСТВО С ОГРАНИЧЕННОЙ ОТВЕТСТВЕННОСТЬЮ "РВБ"` | `ООО «РВБ»` |
| `ООО "ИНТЕРНЕТ МАРКЕТИНГ"` | `ООО «ИНТЕРНЕТ МАРКЕТИНГ»` |

1. **Банковская строка (383-П, есть `//`)**: «банк//счёт ИНН клиент», «ФИО//адрес//»,
   «банк//ФИО//адрес//». Сегменты-адреса (`г.`, `ул.`, `д. 1`, индекс из 6 цифр, `р/с`) и
   сегменты без букв отбрасываются; первый сегмент со словом «БАНК» отбрасывается, если есть
   другие. Должен остаться **ровно один** кандидат, иначе `null` («ФИО//ПАО СБЕРБАНК//» — это
   человек и его банк, кто сторона — не угадываем). Адресные сокращения здесь — только
   строчными: заглавное «Г.» — инициал («ИВАНОВ Г.П.»).
2. **Реквизиты** — `ИНН…`, `КПП…`, `ОГРН(ИП)…` и оставшиеся пустые скобки убираются, хвостовая
   пунктуация срезается; удвоенные кавычки CSV (`""`) схлопываются. 20-значный счёт вырезается
   только в банковской строке: в обычной рядом остаётся подпись («сч», «р.с.») — такое название
   отклоняется по длинному числу.
3. **ОПФ** → сокращённая: ООО, АО, ПАО, НАО, ЗАО, ОАО, СПАО, САО, АНО, ИП.
   - Префиксом — после ОПФ пробел или кавычка («ООО-Ромашка», «ООО. Ромашка» → `null`).
   - Суффиксом в скобках — «Банк ВТБ (ПАО)».
   - Голым суффиксом — **только после названия в кавычках** («"Ромашка" ООО»): без кавычек это
     округ («Префектура ЗАО», «Администрация Ненецкого АО»).
   - Сокращение — только целиком заглавными или строчными («Сао Пауло», «Ип Ман» — не ОПФ);
     полная форма — в любом регистре. ИП — только префиксом (суффиксное «И.П.» — инициалы).
   - Больше одной ОПФ в строке → `null`.
4. **Организация**: `ОПФ «Название»`; внешние кавычки любого вида → «ёлочки»; **регистр не
   меняется**. Название без хвостов: начинается с буквы или цифры; без вложенных кавычек, скобок,
   запятых, `/`, реквизитов, чисел из 5+ цифр или групп по 4 (счёт, карта), адреса в любом
   регистре («Г. МОСКВА», «ул Ленина», «с. Ивановка», «мкр. 5») и служебного текста (НДС, «в
   лице», тел, ОКПО, БИК) — иначе `null`.
5. **ИП**: `ИП Фамилия Имя Отчество`; 2–3 слова (четвёртое — только «оглы / кызы»), каждое — кириллица (двойная фамилия через
   дефис) или инициалы «И.» / «И.И.». Целиком заглавными или строчными → каждая буквенная группа с
   заглавной, частицы «оглы / кызы» строчными; смешанный регистр — как ввели.
6. **`null` (не трогать)**: нет ОПФ (Ozon, ФНС России); госучреждения и органы власти (ФГБУ, ГКУ,
   МКУ, МУП, УФК, ИФНС, ОМВД, префектура, управа, администрация, департамент, министерство,
   управление), филиалы, отделения и обособленные подразделения (фил., ОП, ОСП — ОПФ головной
   организации), «Глава КФХ». Исключение — сторона банковской строки без ОПФ: только
   узнаваемое ФИО — с отчеством на -вич / -вна / -ична (или частицей) либо «Фамилия И.И.»;
   приводится к регистру как у ИП. «ВНУТРЕННИЙ ПЕРЕВОД», «МОСКВА», «Иванов Иван» — `null`.
   Невидимые символы (U+200B–U+200D, U+FEFF) убираются.
7. **Идемпотентность**: `format(format(x))` — тот же результат для ОПФ и ИП; для стороны
   банковской строки без ОПФ — `null` («оставить как есть»: `//` уже нет). На этапе 2 правила
   применяются только к сырому `name`.
8. Скорость ~100 мкс на вызов — достаточно для пересчёта десятков тысяч строк; при росте —
   одна скомпилированная альтернация вместо цикла по вариантам (FOLLOW-UP).

Словарь ОПФ — собственный, не `CounterpartyNameNormalizer`: тот строит ключ сравнения
(верхний регистр, без кавычек), и добавление в него СПАО/НАО/АНО и скобочной формы сменило бы
`name_core` уже сохранённых записей (backfill, переоценка дублей) — вне этого этапа.

## Этап 2. Поля и команда пересчёта

- Миграция `Version20261014100000`: `counterparty.display_name VARCHAR(255)`,
  `display_name_source VARCHAR(16)` (`auto` / `manual`), `display_rules_version SMALLINT` —
  nullable, без DEFAULT (мгновенный ALTER), данные не меняются; `down()` удаляет колонки.
- `Counterparty`: поля, геттеры, `setManualDisplayName()` (на этап 5; пробелы схлопываются,
  `touch`); `rename()` сбрасывает авто-название, только если сырое `name` действительно сменилось
  (форма вызывает `rename()` при каждом сохранении), ручное сохраняет. `SaveCounterpartyAction`
  после переименования дополнительно сбрасывает авто-название в БД
  (`CounterpartyDisplayNameWriter::resetAuto()`): если пересчёт записал его уже после загрузки
  карточки, в снимке Doctrine поля пустые, и flush их бы не тронул (находка внешнего ревью).
- `CounterpartyDisplayNameFormatter::RULES_VERSION = 1` — поднимать при любом изменении
  результата правил: следующий прогон пересчитает все авто-названия.
- `RefreshCounterpartyDisplayNamesAction` + `app:counterparty:refresh-display-names
  [--dry-run] [--samples=50]`:
  - чтение — `CounterpartyDisplayNameBacklogQuery`: скалярные порции по 200, keyset по id, все
    компании, только строки без авто-названия текущей версии; ручные — никогда;
  - запись — `CounterpartyDisplayNameWriter::writeAutoIfUnchanged()`: условный UPDATE
    `WHERE name = <прочитанное> AND source IS NULL OR 'auto'`. Пользователь переименовал или
    задал ручное название во время прогона — строка пропускается (`skippedConcurrent`) и
    берётся в следующий раз, его правка не перезаписывается;
  - нераспознанное записывается как обработанное (`null` + версия) и повторно не берётся;
  - отчёт: обработано / изменено (из них стало нераспознанным) / без изменений / не распознано
    / пропущено из-за параллельной правки; примеры «сырое → отображаемое» и нераспознанные —
    **только с `--dry-run`** (в них ФИО ИП, а плановый прогон пишет stdout в логи планировщика);
    в логах — только счётчики.
- Не сделано на этом этапе: запуск на проде (этапы 3–4) и показ в интерфейсе (этап 5) —
  до этапа 5 поле никто не читает. Для этапа 3 команду нужно добавить в `codex-console`
  (только `--dry-run` и `--samples`) — расширение wrapper'а, отдельное согласие Владельца.

FOLLOW-UP этапа 2 (ревью): забытый `RULES_VERSION` при смене правил ничем не ловится — можно
снапшот-тест хэша `format()` по набору этапа 1; очередь без индекса — при росте справочника
частичный индекс по `display_rules_version`.

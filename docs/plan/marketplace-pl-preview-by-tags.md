# Предпросмотр ОПиУ маркетплейсов по тегам — план

Дата: 2026-10-17 · поручение Владельца в чате: отчёт по дереву категорий ОПиУ на основании
нормализованных данных модуля Marketplace и текущего маппинга, **без создания операций ОПиУ**,
с аналитикой по тегам товара.

## Суть

Отчёт показывает, каким будет ОПиУ, если прямо сейчас провести нормализованные данные
маркетплейсов через текущие правила маппинга. Только чтение: документы ОПиУ, операции и
`pl_daily_totals` не создаются и не меняются. Исправили правило маппинга — перестроили
предпросмотр и увидели эффект.

Отличие от существующего:

- «Предварительное ОПиУ» (`month-preliminary-rebuild`) создаёт реальные документы, предпросмотр —
  нет.
- Обычный ОПиУ строится из `pl_daily_totals`, где нет измерения «тег товара»; здесь оно есть.

## Решения Владельца (2026-10-17)

| Вопрос | Решение |
|---|---|
| Листинг с несколькими тегами | Полная сумма в **каждый** тег. Колонки тегов пересекаются, в «Итого» сумма учитывается один раз |
| Затраты без листинга (хранение, подписка, общие удержания) | Колонка «Общие / без тега», по тегам не распределяются |
| Какие данные брать | **Все** данные за период, независимо от того, проведены они в ОПиУ или нет |
| Где показывать | Новый экран в разделе Marketplace, Twig |
| Выгрузка | xlsx |
| Затраты, исключённые из ОПиУ (`include_in_pl = false`) | Справочный блок под таблицей |

## Разрезы аналитики

**Строки** — дерево ОПиУ компании целиком: статьи ввода, подытоги, формулы, KPI. Значения
считает тот же `PlReportCalculator`, что и обычный ОПиУ.

**Колонки:**

| Колонка | Что входит |
|---|---|
| Тег 1 … Тег N | Суммы листингов с этим тегом; листинг с несколькими тегами — полной суммой в каждый |
| Общие / без тега | Листинги без тегов; затраты и строки «Реализации» Ozon без листинга |
| Итого | Каждая сумма один раз; совпадает с будущим ОПиУ по этим данным |

В шапке пометка: колонки тегов пересекаются, их сумма может не равняться «Итого».

**Фильтры:**

- период — месяц, квартал или произвольные даты;
- маркетплейс — все / WB / Ozon;
- теги — какие колонки показать (по умолчанию все).

**Блоки под таблицей:**

1. **Не размечено в ОПиУ** — суммы без правила маппинга: маркетплейс × категория затрат или
   источник суммы. Это то, что потеряется при закрытии месяца.
2. **Исключено из ОПиУ** (справочно) — затраты с `include_in_pl = false`.
3. **Сверка** — нормализованные данные периода = размечено + не размечено + исключено;
   расхождение красным.

**Отнесение к периоду:** продажи — `sale_date`, возвраты — `return_date`, затраты —
`cost_date`, «Реализация» Ozon — период документа. Направление (проект) из правил продаж в
предпросмотре не используется.

## Этапы

Каждый этап самостоятельный: свой код, свои тесты, зелёные гейты, обновлённый
`ARCHITECTURE.md`, отдельный локальный коммит. Push и PR — одним шагом на handoff.

### Этап 1. Общие формулы сумм

Формулы `CASE amount_source` сейчас дублируются в `UnprocessedSalesQuery`,
`UnprocessedReturnsQuery`, `UnprocessedRealizationQuery`, `UnprocessedRealizationReturnQuery`.
Вынести в один класс Marketplace, запросы переключить на него. Поведение не меняется.

- Тесты: регрессия сумм каждого запроса на фикстурах до и после рефакторинга.
- Готово: проведение ОПиУ даёт те же суммы, формулы в одном месте.

### Этап 2. Расчёт дерева ОПиУ по колонкам (Finance)

Новый метод `FinanceFacade::calculatePlForColumns(companyId, columns)`: на входе — значения
статей ввода по колонкам (`columnKey → plCategoryId → сумма`), на выходе — DTO строк ОПиУ по
колонкам. Внутри — `PlReportCalculator` с провайдером фактов из памяти; дерево загружается один
раз на все колонки.

- Тесты: подытоги, веса, формулы и KPI, статья без кода, чужая категория игнорируется;
  обычный ОПиУ не меняется.
- Готово: метод в `ARCHITECTURE.md`, вызов из Marketplace только через Facade.

### Этап 3. Факты размеченных данных по листингам

`PlPreviewFactsQuery` (Marketplace): агрегат SQL «статья ОПиУ × листинг → сумма со знаком»
по продажам, возвратам, затратам и «Реализации» Ozon за период, по формулам этапа 1. Листинг
`null` — для затрат и реализации без листинга. Возвращает `list<DTO>`.

- Тесты: каждый источник, знак возвратов и затрат, неактивное правило не берётся, только своя
  компания, фильтр маркетплейса, границы периода.
- Готово: «Итого» по статьям совпадает с проведением тех же фикстур.

### Этап 4. Не размечено, исключено, сверка

Два запроса: суммы без правила маппинга (маркетплейс × категория затрат / источник суммы) и
затраты с `include_in_pl = false`. Плюс контрольная сумма всех нормализованных данных периода.

- Тесты: затрата без правила, правило без статьи, исключённая затрата, сверка сходится.
- Готово: размечено + не размечено + исключено = всё за период.

### Этап 5. Сборка отчёта по тегам

`BuildMarketplacePlPreviewAction`: берёт факты этапа 3, раскладывает листинги по тегам через
`ListingTagAssignmentRepository`, формирует колонки «Тег…», «Общие / без тега», «Итого»,
считает дерево через Facade этапа 2, добавляет блоки этапа 4. Только чтение, без `flush()`.

- Тесты: листинг с двумя тегами попадает в оба и один раз в «Итого»; затрата без листинга — в
  «Общие»; фильтр тегов; пустой период (негативный).
- Готово: результат — один DTO отчёта, который используют и экран, и выгрузка.

### Этап 6. Экран

Контроллер `/marketplace/pl-preview` (Twig), фильтры, таблица с деревом, блоки под таблицей,
пункт меню раздела Marketplace. Дизайн-система «Ваш Финдир», суммы — `vf_money`. Активная
компания проверяется до запросов.

- Тесты: functional — страница открывается, фильтры применяются, чужие теги не видны.
- Готово: визуальная проверка локально, скриншот.

### Этап 7. Выгрузка xlsx

Кнопка «Скачать xlsx» с теми же фильтрами: лист отчёта (дерево с отступами, колонки тегов,
«Итого»), лист «Не размечено», лист «Исключено». Строит файл из DTO этапа 5, отдаёт потоком.

- Тесты: functional — ответ xlsx, заголовки колонок, суммы совпадают с экраном.
- Готово: файл открывается, отступы дерева и числовой формат сумм сохраняются.

## Чек-лист готовности

- [ ] Отчёт ничего не пишет: нет `persist` / `flush`, документы и `pl_daily_totals` не меняются.
- [ ] «Итого» по статьям = результат проведения тех же данных (тест на одном наборе фикстур).
- [ ] Сверка: нормализованные данные = размечено + не размечено + исключено.
- [ ] Листинг с несколькими тегами — в каждом теге, в «Итого» один раз.
- [ ] Все запросы ограничены `companyId`; чужие теги и листинги не попадают.
- [ ] Нет N+1: один агрегат SQL на источник, дерево загружается один раз.
- [ ] Marketplace обращается к Finance только через Facade.
- [ ] Экран и xlsx показывают одинаковые суммы.
- [ ] Гейты зелёные, baseline не вырос, `ARCHITECTURE.md` обновлён.

## Вне рамок

- Переход из ячейки к листингам.
- Разрез «маркетплейс» колонками вместо тегов.
- Распределение общих затрат по тегам пропорционально выручке.

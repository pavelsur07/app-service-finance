## 1. Список «Документы ОПиУ» (PR 1)

- **Название** — title, H1, крошки «Доходы и расходы / Документы ОПиУ», `_tabs`, «Удалённые документы ОПиУ», flash.
  Меню — группа «Доходы и расходы» → «Документы ОПиУ» (как «Деньги», «Баланс»), активна на всех `document_*`. Адреса прежние.
- **Фильтры** (паттерн «Операций ДДС»): поиск `q` — описание, номер, контрагент документа, статья операции; пресеты —
  общий `partials/_period_presets` ссылками; «Выбрать период»; сегмент Все / Доходы / Расходы (`direction`); пилюли Тип,
  Проект, ЦФО; «Ещё фильтры» — offcanvas: тип, статус, номер, контрагент. Чипсы «Применено», «Сбросить всё». Ссылки
  строятся из нормализованного DTO: мусор из адреса в них не переносится.
- **Бэкенд:** `DocumentListDTO` + `q`, `projectDirectionId`, `responsibilityCenterId` (uuid, нижний регистр), `direction`;
  `findByCompany` — условия по операциям через `EXISTS`, а не `WHERE` по fetch-join (иначе документ гидрировался бы с
  неполным набором операций и суммы строки врали бы); проект и ЦФО — у документа **или** у любой его операции; «Доходы» —
  документы, где есть хотя бы одна доходная операция. `summarizeByCompany(companyId, dto)` — итог по всей выборке
  (два агрегатных запроса) **по правилам регистра ОПиУ** (`PLRegisterUpdater`): операция без статьи не входит; природа —
  `flow` статьи, у статьи `NONE` — знак суммы; обычный документ — модуль каждой операции; `marketplace_pl` (списание «−»,
  сторно «+») — модуль суммы статьи по документу. **Валюты не смешиваются**: документ из операции ДДС несёт её сумму без
  пересчёта (`CashTransactionToDocumentService`), ручной — рубли; полоса итога — рубли и «в валюте USD: …» (DS-Money).
  Строки списка считает `DocumentPlContribution` по тем же правилам, в валюте документа.
  `FinancialResponsibilityCenterFacade::getNamesByIds()` — названия ЦФО страницы одним запросом (включая архивные).
- **Таблица:** Дата · Документ (тип, №, «Из ДДС», «Черновик»/«Неактивен», «Без маппинга», описание в строку, «N операций») ·
  Статья ОПиУ · Проект / ЦФО · Контрагент · Доход · Расход · Итог · «⋯». Несколько статей/проектов/контрагентов —

| Счётчики на вкладках | нет | зависят от фильтра; «Найдено N» — в полосе итога |
| Чекбоксы строк | нет | нет массового действия (SPEC) |
| «Добавить операцию» в меню строки | нет | нет роута; добавление — на странице документа |
| «Период в отчёте», выбор «Тип» в операции | нет / тип только показывается | нет поля в модели; тип задаёт `flow` статьи |

| «История изменений» | нет | SPEC: не делать |

## 7. Вкладка «Операции» (PR 3)

План и чек-лист — `docs/tasks/ds-pnl-operations/plan.md`. Эталон — `screens/pnl-refs/03–04`.

**Сделано.** `/documents/operations` (`document_operation_index`): одна строка — одна операция неудалённого документа
компании. Колонки: Дата · Документ (тип, №, описание, «В документе N операций», комментарий операции) · Статья ОПиУ ·
Проект / ЦФО · Контрагент · Доход · Расход · меню («Открыть документ», «Просмотр документа», «Открыть операцию ДДС» при
основании). ≤1340 px статья, проект, ЦФО и контрагент уходят в подстроку. Полоса итога «Найдено M операций · N документов»,
другие валюты — отдельно. Проект, ЦФО и контрагент строки и фильтров — операции, иначе документа; «Доходы/Расходы» — природа
операции. Операция без статьи видна («Нужно указать статью», сумма «не в итоге»).

Шапка, вкладки, фильтры, чипсы, пагинация и «Ещё фильтры» вынесены в `document/_list_layout.html.twig` — у вкладок одна
разметка. Новые пилюли «Статья ОПиУ» и «Сумма» (от/до по модулю) — на обеих вкладках; на вкладке документов направление,
статья и сумма — условия на одну операцию (`EXISTS`). Счётчик у активной вкладки = «Найдено». Ссылка вкладки переносит
фильтры. Итог обеих вкладок без фильтров совпадает (стенд: доходы 1 451 579,35, расходы 751 900,00).

**Деньги.** `DocumentPlContribution::forOperation()`: обычный документ — модуль операции; `marketplace_pl` — со знаком
полной суммы той же статьи и природы в документе, без фильтров списка (списание −100 → 100, сторно +20 → −20). Фильтр,
оставивший одно сторно, показывает его как −200, то есть он уменьшает расход, а не добавляет к нему (находка ревью, тест).
Итог `DocumentOperationRepository::summarizeForList()` строится по тому же правилу, поэтому сумма строк равна итогу (тест).
Направление «Доходы/Расходы» на обеих вкладках определяется природой операции: у статьи без потока — по знаку суммы.
Перепутанные границы суммы меняются местами.

**Запросы страницы** — константа (тест 3 → 30 операций): пользователь, компания, страница операций (fetch-join документа,
статьи, проекта, контрагента и основания; без `d.operations`), count, суммы `marketplace_pl` страницы, число операций в
документах страницы, итог (2), названия ЦФО (батч), проекты, ЦФО, дерево статей.

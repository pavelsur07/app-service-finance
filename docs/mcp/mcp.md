# MCP-сервер ДДС

Локальный MCP-сервер поверх `site-php-cli`. Даёт модели доступ к транзакциям ДДС,
статьям ДДС и автоправилам **одной компании**, а также глобальный поиск ID компании
по точному названию. Внешних доступов нет: ни портов, ни HTTP, ни авторизации —
только stdio процесса, который запускает сам клиент.

## Запуск вручную

```bash
docker compose run --rm -T site-php-cli \
    php bin/console app:mcp:serve --company-id=<uuid> [--allow-write]
```

| Опция | Значение |
|---|---|
| `--company-id` | UUID компании, обязательна. Все финансовые инструменты работают только с её данными. |
| `--allow-write` | Разрешает инструменты, изменяющие данные. Без неё сервер только на чтение. |

`companyId` задаётся аргументом процесса, а не параметром инструмента: у модели нет
поля, куда подставить чужую компанию. Единственное исключение —
`company_find_by_name`: он глобально ищет компанию, но возвращает только её ID.

## Подключение к Claude Code

`.mcp.json` в корне репозитория:

```json
{
  "mcpServers": {
    "vashfindir-cash": {
      "command": "docker",
      "args": [
        "compose", "run", "--rm", "-T", "site-php-cli",
        "php", "bin/console", "app:mcp:serve",
        "--company-id=00000000-0000-0000-0000-000000000000"
      ]
    }
  }
}
```

Подставьте свой `--company-id`. Добавьте `"--allow-write"` последним элементом
`args`, когда нужна запись — начинать стоит без него.

Проверить, что сервер отвечает, можно без клиента:

```bash
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
  | docker compose run --rm -T site-php-cli php bin/console app:mcp:serve \
      --company-id=<uuid> 2>/dev/null
```

## Инструменты

| Инструмент | Пишет | Что делает |
|---|---|---|
| `company_find_by_name` | — | Глобально возвращает ID по полному названию без учёта регистра; отсутствие и дубли считаются ошибкой. |
| `cash_transactions_list` | — | Транзакции с фильтрами по датам, счёту, статье, контрагенту, сумме, направлению и подстроке в назначении. Постранично, `limit` ≤ 200, по умолчанию 50. |
| `cash_categories_tree` | — | Плоское дерево статей ДДС с уровнем и родителем. |
| `cash_autorules_list` | — | Автоправила вместе с условиями и целевой статьёй. |
| `cash_category_upsert` | ✍ | Создать статью (без `id`) или изменить (с `id`). |
| `cash_autorule_upsert` | ✍ | Создать автоправило (без `id`) или изменить (с `id`). |

### Правила работы с записью

- **Передаются только указанные поля.** Отсутствующее поле не меняется. Поэтому
  очистить описание или вынести статью в корень через MCP нельзя — это делается в UI.
- **`conditions` заменяют набор условий целиком.** Чтобы добавить условие, передайте
  прежние вместе с новым: возьмите их из `cash_autorules_list`.
- **Проект и ЦФО автоправила через MCP не задаются.** Это единственное место с
  проверкой допустимости пары, оно осталось за UI. При редактировании существующие
  значения сохраняются.
- **Отключение автоправила необратимо.** `isActive: false` отключает правило
  насовсем — включить обратно через приложение нельзя, это инвариант сущности.
- Вложенность статей — не глубже 5 уровней. Системные статьи защищены от изменений.

## Что сервер не делает

- Не применяет автоправила к транзакциям: массовая перекатегоризация проводок
  необратима, поэтому такого инструмента нет намеренно.
- Не удаляет статьи и автоправила.
- Не создаёт и не редактирует транзакции.
- Не отдаёт `rawData` транзакций — только идентификаторы, суммы и названия.

## Диагностика

- STDOUT занят протоколом. Любой `echo`, `dump()` или `var_dump()` в коде инструмента
  ломает сессию — сообщение перестаёт быть валидным JSON.
- Диагностика и логи идут в STDERR. При `SHELL_VERBOSITY=-1` в окружении консольный
  вывод подавляется, включая сообщение о неверном `--company-id`; на протокол это
  не влияет, но об ошибке тогда сигналит только код возврата `2`.
- Ожидаемый отказ инструмента приходит как `isError: true` с текстом причины —
  например, недопустимое значение enum с перечислением допустимых. Это не сбой
  протокола, модель может исправить аргументы и повторить вызов.
- Каждый вызов инструмента пишется в лог на уровне INFO с именем, `companyId` и
  длительностью.

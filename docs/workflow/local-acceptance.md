# Локальная приёмка

Во время разработки запускать тесты изменяемого модуля и точечные линтеры.
После исправлений ревью запустить один полный последовательный прогон:

```bash
docker compose up -d --wait site-postgres site-redis
make site-composer-install
make site-accept
```

Нужны Docker/Compose, Python 3 (уже используется workflow-тестами), dev-образ
site-php-cli и зависимости с require-dev. Runner проверяет Docker, БД,
наличие инструментов и запись в cache/log/test до длинных проверок. Он один
раз готовит тестовую БД миграциями и прогревает test-контейнер Symfony,
после чего последовательно запускает cs, strict types, локальный PHPStan
(level 8, существующий baseline и paths, один основной процесс без дочерних workers, 2 ГБ), Unit,
Integration и Functional. Каждый PHPUnit — отдельный процесс в одном
временном CLI-контейнере; контейнер удаляется при завершении и прерывании.
Другая приёмка или тесты не должны одновременно менять ту же test-БД/кеш.

`DOCKER_COMPOSE` позволяет выбрать локальный проект/override. Существующие
Make-цели сохранены. Xdebug выключен, timeout Composer снят. Нет повторных
попыток: первая ошибка завершает прогон ненулевым кодом.

Артефакты находятся в игнорируемом `site/var/accept/<timestamp>-<id>/`:
журналы шагов, `commands.jsonl` (команды, длительности, exit codes, память),
`resource-snapshot.log` (память внутри Docker), `summary.json` с отпечатками
исходников и итоговым кодом. Логи могут содержать диагностику приложения;
они закрыты правами и не предназначены для публикации без очистки.

Память хоста измеряется по `/proc/meminfo` с учётом доступных лимитов текущей
и родительских cgroup v1/v2. `null` явно означает недоступное измерение.
При удалённом Docker данные runner относятся к локальному хосту; отдельный
снимок контейнера показывает доступные Docker-измерения. Это наблюдения
до/после шагов, а не непрерывный мониторинг пиков каждого дочернего процесса.

Отпечаток включает содержимое/режим всех отслеживаемых и неигнорируемых новых
файлов, удаления и symlink. Изменение исходников во время прогона делает
результат недействительным, даже когда проверки зелёные. Во время приёмки
не редактировать код или task-документацию; артефакты в `site/var/` исключены.
Кратковременное изменение с возвратом к прежним байтам между снимками
отпечаток не обнаруживает.

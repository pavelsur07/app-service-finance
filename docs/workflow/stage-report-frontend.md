# Self-review checklist фронтового Stage

Правила фронта — `CLAUDE.frontend.md`; порядок закрытия Stage и шаблон отчёта —
`AGENTS.md` §5 и `docs/workflow/templates.md`. Ниже проверки, специфичные для
фронта. Красный пункт означает, что Stage не закрыт: чинить и повторять.

## Проверки

Прогнать в контейнере, где есть node:

```bash
npm run lint && npm run build
```

Плюс `npm run api:types:check`, если задача трогала контракт API. Скриптов
`typecheck` и `test` в проекте нет и тест-раннер не установлен — не заявлять их
прогон. Вместо автотестов обязателен ручной smoke затронутой страницы с
описанием, что именно проверено.

## Структура и границы

- [ ] Изменения строго в рамках цели Stage
- [ ] Naming по таблице `CLAUDE.frontend.md`
- [ ] Нет импорта фичи одного модуля из другого, общее через `shared/`
- [ ] Нет импорта из `_legacy/` в `modules/`, `shared/` или `ui-kit/`
- [ ] В entry-файле только монтирование, без бизнес-логики
- [ ] Smart/Dumb split соблюдён для нетривиальной фичи

## TypeScript

- [ ] Нет `any`, `@ts-ignore`, non-null `!`
- [ ] Пропсы через `interface` над компонентом, не инлайном
- [ ] Возвращаемый тип хука указан явно
- [ ] Хук возвращает безопасные дефолты, View не падает на `undefined`
- [ ] `npm run build` зелёный (единственная проверка типов в проекте)

## Дизайн-система

- [ ] Визуал сверен с листами DS `docs/design-system/sheets/`; расхождения с
      поручением записаны, пробелы листов — `TODO(ds)`
- [ ] Классы — из кита (`assets/styles/kit/`, новый слой) или Tabler + DS-надстройки
      (легаси); своих параллельных классов нет
- [ ] Нет хардкода цветов в JSX, CSS Modules, шаблонах и inline-стилях — только токены
- [ ] Нет inline-стилей со значениями вместо токенов
- [ ] Деньги в легаси — `vf_money`/`vf_amount`, числа — `vf_number` (DS-Money)
- [ ] Статусы и бейджи — классами кита или Tabler, не своим CSS
- [ ] Loading, empty и error — компонентами кита, не кастомными
- [ ] Модалки и дропдауны управляются React-состоянием
- [ ] CSS Module только для локального отступа или раскладки, без
      переопределения классов кита
- [ ] Затронута обёртка в `assets/react/ui-kit/`: JSDoc ссылается на CSS кита и лист DS

## Данные и контракт

- [ ] Запросы через `apiFetch` из `api/client.ts`, без raw `fetch`
- [ ] Состояния загрузки, пустоты и ошибки отрисованы, кнопки не залипают
- [ ] 401 ведёт на логин, 422 раскладывается по полям формы
- [ ] Менялся контракт API: `npm run api:types:check` зелёный, `schema.d.ts`
      закоммичен в том же Stage

## Монтирование, если затронуто

- [ ] Новый Vite entry добавлен в `input` в `vite.config.js`
- [ ] `data-*` экранированы через `|json_encode|e('html_attr')`
- [ ] Монтирование защищено проверкой существования элемента
- [ ] Виджет обёрнут в провайдеры и обработчик ошибок
- [ ] CSRF-токен доступен виджету

## Качество

- [ ] `npm run lint` зелёный
- [ ] Нет `console.log`, только `console.error` в обработчике ошибок
- [ ] Размер бандла не вырос неожиданно; рост больше десяти процентов
      объяснён в отчёте
- [ ] Ручной smoke проведён, в отчёте написано, что проверено
- [ ] Коммит с префиксом Conventional Commits, сообщение отражает цель Stage

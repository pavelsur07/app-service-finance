## 1. Какую задачу решаем

Еженедельный отчёт о реализации сейчас не грузится нигде (`period: "weekly"` в коде не
встречается). Он — основа недельного анализа (spec-wb §1, группа 3) и правится задним числом.

## 2. Шаг 0 — проверка `period=weekly` — выполнен 02.11.2026

Через прод-wrapper проба невозможна (в `codex-console` нет команды, идущей в WB finance-api;
токен расшифровывает только Symfony). Владелец дал тестовый токен продавца **только на
чтение**; по одному запросу `period=weekly` за W43 и W44, токен не сохранён ни в файлах, ни в
памяти. Факты — `services/wb-fetcher/docs/wb-api.md`, раздел «Недельный отчёт»:

- 200, пн…вс, та же пагинация `rrdId`, лимит `X-Ratelimit-Limit: 1`;
- неделя на стыке месяцев (W44) — два отчёта одним ответом (`dateFrom`/`dateTo`/`reportId`);
- отчёт прошлой недели был уже в понедельник 20:55 МСК (документация: «до среды»);
- документация WB: `period` — `weekly`/`daily`, по умолчанию `weekly`.

Защита на случай расхождения у других кабинетов: 400 → `invalid_request` →
`failed_permanent` только недельной задачи; дневной ресурс не затронут.

## 2a. Назначение — сверка (Владелец, 02.11.2026)

Недельный отчёт нужен **для сверки**: сумма дневных отчётов недели против недельного (финальный
документ WB, по нему акт и выплата). Отсюда требования к загрузке:

- обе стороны сверки одной недели в raw свежие одновременно: окно перечитывания недель
  (прошлая + 2 предыдущие) не шире окна дневного: у кабинета с недельным ресурсом дневное
  окно (загрузка и перечитывание) продлевается назад до понедельника самой старой
  перечитываемой недели, если `WB_DAILY_TAIL_DAYS` короче (до 27 дней в воскресенье —
  ~32 мин запросов на кабинет в сутки при 1/70 с);
- пустой недельный ответ после крайнего срока закрывает неделю `done` с пустой ревизией, но
  суточное перечитывание её не бросает: появившиеся строки дают ревизию +1 — сверка не
  должна принять «пусто» за «ноль»; в покрытии такая неделя видна (этап 4);
- сам расчёт сверки (суммы дневных против недельного, расхождения) — не в этом этапе:
  wb-fetcher только кладёт обе стороны в raw. Расчёт — потребитель raw (нормализация в
  Symfony) — отдельная задача после этапа 5, в README задачи — «открыто».

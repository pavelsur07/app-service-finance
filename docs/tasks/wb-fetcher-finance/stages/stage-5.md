## 1. Какую задачу решаем

Включить wb-fetcher на проде так, чтобы не помешать текущей загрузке WB в Symfony
(общий лимит 1 запрос/мин на продавца) и иметь откат одним переключателем.

## 2. Что будет результатом работы

- Секреты GitHub: `WB_FETCHER_API_TOKEN` (Symfony → сервис), `WB_FETCHER_SENTRY_DSN`,
  `WB_FETCHER_DB_PASSWORD`; агент заводит через `gh`, в репозитории — только имена.
- S3: тот же бакет `vashfindir-services-raw` и те же ключи пользователя бакета,
  что у ozon-fetcher (решение В1), — секреты переиспользуются, сервис пишет только под `wb/`.
- Свой проект GlitchTip `wb-fetcher` (сигналы как у ozon-fetcher).
- `docker-compose.prod.yml`: сервис `wb-fetcher` (без ingress, сеть default, профиль),
  переключатель `WB_FETCHER_ENABLED`; БД и роль создаёт деплой; env в scheduler
  (`WB_FETCHER_BASE_URL`, `WB_FETCHER_API_TOKEN`); `deploy.yml` — экспорт.
- `docs/maintenance/wb-fetcher-prod.md` по образцу ozon-fetcher: проверка статуса,
  откат, ремонт, что смотреть в GlitchTip.
- Включение по шагам:
  1. `wb_fetcher.finance_companies` = эталонный кабинет (крупный, не тестовый);
  2. 3 ночи без ERROR, сверка — шаг 3;
  3. все активные кабинеты WB.

## 3. Что считаем выполненной работой

Сервис на проде, вкладка Wildberries показывает данные; по эталонному кабинету
сверка с Symfony сошлась; 429 в Symfony не выросли; затем включены все кабинеты.
Итоговые критерии задачи (14 дней подряд) — проверка после handoff.

# Проверка отчёта на синтетических данных

Локальная PostgreSQL test DB, временная схема удалена после проверки.
10 000 проведённых обязательств, позиций и движений, 100 контрагентов одной компании,
по одной копейке на позицию. Никаких пользовательских данных.

- Выполнен реальный `SettlementReportQuery::report`, SQL перехвачен DBAL Logging Middleware.
- Страница: 50 из 100 контрагентов; общий остаток Money `100.00 RUB`.
- `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` этого же SQL: planning 1.459 ms, execution 42.728 ms.
- Агрегирование всей компании выбирает последовательные сканы и hash join; это уместно,
  поскольку fixture содержит только одну компанию и нужны все её движения.
- Книга читается через `uniq_settlement_book_company`; сортировка страницы в памяти, 51 KB.
- Отчёт выполняет один финансовый SQL и один пакетный запрос подписей, без N+1.
  Все суммы SQL передаются в PHP точными строками и проверяются до int-cast.
- Полный план: `report-explain.json`. Это локальное измерение, не гарантия production SLA.

Существующие индексы `(company_id, counterparty_id, amount_currency, effective_date)`
для позиций и `(company_id, item_id, effective_date, id)` для истории сохранены.
Полные суммы и страница рассчитываются в одном снимке PostgreSQL.

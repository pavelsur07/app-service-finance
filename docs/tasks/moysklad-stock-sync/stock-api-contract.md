# МойСклад: контракт складов и остатков

Проверено 2026-09-21 по официальной документации JSON API 1.2,
ревизия `74f6a4fa1c0021dba2df927bdd688900e97cb736`.

## Склады

`GET /entity/store` возвращает стандартную страницу `meta + rows`. Для хранения
используются только `id`, `accountId`, `name`, `externalCode`, необязательный
`code`, `pathName`, `archived` и `updated`. Адреса, владелец, отдел, зоны,
ячейки, дополнительные поля и произвольный JSON не сохраняются.

Первичный проход выполняется отдельно с `filter=archived=false` и
`filter=archived=true`, `order=id,asc`, `limit/offset`. `accountId` обязан
совпадать с проверенным аккаунтом подключения. Отсутствие склада в отдельной
странице не означает удаление.

## Остатки по складам

Используется расширенный `GET /report/stock/bystore` со следующими параметрами:

- `groupBy=variant`: отчёт содержит товары и модификации, без партий;
- `filter=stockMode=all`: отчёт включает нулевые остатки;
- `limit=1000`, `offset`: полный постраничный проход.

Каждая строка отчёта содержит `meta` товара или модификации и обязательный
`stockByStore`. Каждый элемент `stockByStore` содержит `meta` склада, `name`,
`stock`, `reserve`, `inTransit`. Документация определяет эти три величины как
`Float`; отрицательный `stock` допустим. Значения хранятся как decimal, без
вычисления доступного остатка и без финансовой интерпретации. Парсер принимает
сырой JSON, сохраняет числовые лексемы до декодирования и без float приводит
обычную и экспоненциальную запись к decimal. После нормализации допускается не
более 20 знаков целой и 10 знаков дробной части.

Размер `stockByStore` по контракту равен количеству складов системы. Загрузчик
всё равно проверяет каждую ссылку на уже импортированный склад и не публикует
снимок с неизвестным складом или ассортиментом. Допустимы только `product` и
`variant`; остальные типы завершают запуск категорией `invalid_response`.

## Полнота и время снимка

Расширенный отчёт поддерживает offset pagination, но документированные поля
сортировки не дают уникального порядка. Поэтому загрузка:

1. фиксирует `meta.size` первой страницы и требует то же значение далее;
2. запрещает повтор внешнего ID ассортимента в одном проходе;
3. требует, чтобы число уникальных строк по завершении совпало с `meta.size`;
4. публикует снимок только после успешной обработки всех страниц;
5. при сбое начинает новый снимок с первой страницы, не продвигая курсор.

Парсер возвращает проверенные `meta.size`, `meta.limit`, `meta.offset` вместе
со строками; отрицательные, отсутствующие и противоречащие размеру страницы
значения считаются `invalid_response`.

Такой проход не является транзакционным снимком источника: изменения в
МойСклад между страницами могут попасть в разные части результата. Полный
повторный проход сходится к актуальному состоянию. Время снимка хранится как
локальные `startedAt` и `completedAt`; API не сообщает единое source timestamp.

## Ограничения API

- Ответы должны запрашиваться со сжатием; HTTP-клиент Symfony выполняет
  negotiation/decompression автоматически.
- Один запрос `report/stock/bystore` расходует 5 единиц rate limit.
- Для одного пользователя допускается не более пяти параллельных запросов;
  этот поток выполняет запросы последовательно.
- 429 использует `X-Lognex-Retry-After`; 5xx и transport errors временные.
- Тела ответов, токен, имена складов и товаров не журналируются.

## Выбор расширенного отчёта

Краткий `/report/stock/bystore/current` быстрее и возвращает все строки одним
ответом, но один запрос содержит только один `stockType`. Для `stock`,
`reserve` и `inTransit` потребовались бы три независимо рассчитанных ответа;
нулевые позиции, никогда не участвовавшие в операциях, всё равно отсутствуют.
Поэтому он не используется для первого полного снимка.

## Источники

- `md/dictionaries/_store.md` официальной документации.
- `md/reports/_report_stock.md` официальной документации.
- `md/_restrictions.md` официальной документации.

Локально доступный тестовый ключ не является действующим токеном МойСклад:
контрольный запрос вернул 401. Фикстуры Stage 1 будут обезличенными
контрактными образцами по закреплённой официальной ревизии; секреты и сырые
ответы в репозиторий не попадут.

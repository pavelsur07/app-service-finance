# Этап 1. Замер причин `no_answer`

## Задача
Понять, почему модель не выбирает статью, по всем подключённым кабинетам, а не только COMPSHOP,
и зафиксировать базовую точность текущей версии (prompt v2) до изменений.

## Результат
`measurements/stage-1.md`: по каждому кабинету — доли `no_answer` по причинам (перевод между
своими счетами, пустое/короткое назначение, нет подходящей статьи в справочнике, прочее),
без текстов назначений и ФИО; базовые цифры evals на наборе `history/vumjoy` (точность при
уверенности ≥ 0,8 и доля ответов).

## Что считаем выполненным
Цифры сняты read-only на проде и в evals; причины покрывают ≥ 90 % `no_answer`; признаки
перевода для этапа 2 выписаны списком и проверены на ложные срабатывания по выборке.

## Чек-лист приёмки
- [x] замер по всем кабинетам с `ai_company_access`, дата и время снятия
- [x] ложные срабатывания признаков перевода на статьях с ответом — посчитаны (4,5 % → правило уточнено)
- [x] базовая точность v2 на `history/vumjoy` записана
- [x] в документах нет назначений платежей и персональных данных

## Итог
06.11.2026, `measurements/stage-1.md`. 100 отказов у двух кабинетов: 76 % — переводы собственных средств
(все у `fbebb285`), остальное — пустые и короткие назначения, «оплата по счёту» без предмета, нет статьи в справочнике.
Причины покрывают 98 %. Признак «только фраза» даёт 4,5 % ложных срабатываний (у `b57d7682` такие переводы разнесены в
кредиты) — правило этапа 2 уточнено: исключать, только если у компании нет своих разнесённых операций с фразой.
ИНН контрагента как признак отвергнут. Базовая точность v2 — прогон 01.11 (83 %, ответы 91 %, ≥ 0,80 — 93 % на 87 % кейсов),
промпт и модель с тех пор не менялись.

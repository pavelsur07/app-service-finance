# Stage 5: UI — вкладка «Сверка Ozon»

stage_base_commit: 223e827f
Risk: MEDIUM (UI на существующих паттернах)

## Планирование
Раздел Marketplace целиком на Tabler/Bootstrap-шаблонах (`marketplace/layout.html.twig`, карточки, `badge bg-*-lt`, `partials/_pagerfanta.html.twig`),
React-островов в нём нет. Страница — серверный Twig на тех же классах, что соседние вкладки: добавление острова/UI Kit-обёртки ради одной таблицы разошлось бы с остальным разделом.
Решения:
- Вкладка «Сверка Ozon» в `layout.html.twig` после «Закрытие месяца»; `active_tab = ozon_reconciliation` (уже передаётся контроллерами).
- Верх: выбор месяца (GET) и кнопка «Выполнить сверку» (POST+CSRF, только при `MARKETPLACE_WRITE`).
- Вердикт «можно ли доверять» одним блоком: зелёный / красный / серый + причины видимым текстом: дни сырья X из Y, «Реализация» загружена/нет, затраты вне сверки, время проверки.
- Две карточки-проверки: «Реализация ↔ сырые данные» и «Сырые данные ↔ учёт»; колонки Блок | Источник | Цель | Разница | Статус | Записи.
  Заголовки колонок берутся из `OzonReconciliationCheck::getSourceLabel()/getTargetLabel()`.
- Пояснение строки (note) и счётчики — под названием блока ВИДИМЫМ текстом, не в тултипе (урок #2520).
- Категории раскрываются кнопкой (Bootstrap collapse, aria-expanded); строки с расхождением сверху, блок с расхождением раскрыт по умолчанию.
- Разница со знаком (+/−), красным при MISMATCH; «нет данных» — серый «—», не ноль.
- Ссылки «Записи» только у проверки «Сырые данные ↔ учёт» → drill-down; страница drill-down: заголовок, фильтры текстом, таблица, пагинация, ссылка назад.
- Пустое состояние (снимка нет) с объяснением и кнопкой; ошибки/flash — штатные из layout.
Проверки: functional (вкладка видна в навигации, тексты вердикта по статусам, причины, раскрытие/ссылки, права WRITE скрывают кнопку), визуальный осмотр скриншотом (`local-visual-check`), `npm run check:ui-kit`/`lint` не затрагиваются (нет JS/CSS), twig lint.
Вне охвата: React, правка UI Kit, cron.

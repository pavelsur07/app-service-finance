# Handoff: marketplace-ozon-reconciliation

PR #2547 (Draft → Ready). Вкладка «Сверка Ozon» в Marketplace: можно ли доверять данным Ozon в системе.

## Что получилось
- Две проверки по блокам (продажи, возвраты, комиссия, логистика, FBO, партнёры, реклама, компенсации, прочие, нераспознанные):
  «Реализация ↔ сырые данные Ozon» (общая база sale_price) и «Сырые данные ↔ учёт» (база sale_amount, затраты по категориям). Допуск 1 ₽ на знаковой разнице.
- Вердикт на странице с видимыми причинами (дни сырья X из Y, «Реализация» загружена или нет, затраты вне сверки). «Сошлось» не показывается при неполной загрузке.
  Без «Реализации» заголовок честно говорит «Учёт совпадает с сырыми данными», а не «сходится с Ozon».
- Drill-down по записям учёта (Pagerfanta, limit ≤ 200, иначе 422), ручной пересчёт (POST+CSRF, `MARKETPLACE_WRITE`), команды `…ozon-reconciliation:run` и `:check`, cron 07:10.
- Затронуты: новые таблицы `marketplace_ozon_reconciliation_runs/lines` (аддитивная миграция), вкладка в `marketplace/layout.html.twig`, `ARCHITECTURE.md`, `docker/cron/app.cron`, `docs/workflow/health-gates.md`, `docs/maintenance/prod-access.md`.
  Учёт, процессоры, закрытие месяца, WB — не тронуты.

## Ограничения и риски
- «Реализация» не содержит комиссий, логистики, услуг и рекламы — эти блоки проверяются только «сырьё ↔ учёт». Реклама Performance API (`MarketplaceAdvertisingCost`) в сверку не входит; в сверке рекламные услуги из начислений by-day.
- По дням до 08.09.2026 (формат v3) сверять не с чем: они показываются как «затраты вне сверки», продажи и возвраты того периода в сверку не входят.
- Прод-SQL для замеров «до» не запускался (запрет классификатора на `codex-psql-ro`, нужно разрешение Владельца). Фича аддитивна, замеры существующих данных не требовались.
- «Реализация» с `records_created = 0` (обработка не дошла до конца, либо документ обработан до введения счётчика) считается незагруженной.
- Первый ночной запуск на проде может оказаться красным, если расхождения уже есть: это искомая информация, шум ограничен одним `error` в сутки. Расхождение, которое нельзя починить, — отдельная задача, не повод оставить гейт красным (`health-gates.md`).
- Пересчёт по кнопке синхронный: на крупном кабинете это секунды (jsonb по ~30 документам). Замерить после деплоя; при необходимости — Messenger (HIGH-LOCAL).
- Три источника читаются не в одном снимке БД; редкое расхождение во время обработки дня возможно (FOLLOW-UP: повторная проверка перед `error`).
- FOLLOW-UP: история прогонов, тест на пользователя без `MARKETPLACE_WRITE`, drill-down «есть у Ozon, нет у нас» по отправлениям.
- В истории ветки есть коммит, случайно добавивший чужой `docs/integrations/moysklad.md`, и следующий за ним коммит, убирающий файл (force-push запрещён). Итоговый diff к master файла не содержит; файл остался у Владельца неотслеживаемым.

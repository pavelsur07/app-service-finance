# Финансовый отчёт WB по загруженным данным

Страница: `/marketplace/wb-finance-report`.

## Источник и границы

Отчёт читает только дневные `sales_report` документы Wildberries, которые
связаны через `marketplace_financial_report_sync_statuses.raw_document_id`.
Это исключает незавершённые staging-документы и повторные raw-снимки одного
дня. Выборка всегда ограничена активной компанией.

Таблица `ingest_financial_transactions` и другие транзакционные проекции не
читаются и не изменяются.

## Фильтры

- период до 93 календарных дней, по умолчанию — с начала текущего месяца по
  вчерашний день в часовом поясе `Europe/Moscow`;
- необязательный числовой `reportId`;
- те же фильтры используются для CSV.

## Расчёт

Деньги парсятся через `Money` и суммируются в минорных единицах RUB.
Товарная часть следует правилам из
`site/src/Marketplace/WB_API_V5_FIELDS.md`:

- продажа без СПП: `|retailPriceWithDisc| × |quantity|`;
- продажа с СПП: `|retailAmount|`;
- комиссия: продажа без СПП `− |forPay| − |acquiringFee|`;
- перечисление за товар: продажи `forPay` минус возвраты `forPay`;
- расчётное перечисление: перечисление за товар плюс прочие доплаты и
  компенсации минус прочие удержания.

Комиссия и эквайринг уже учтены внутри `forPay`, поэтому повторно из
расчётного перечисления не вычитаются.

Для прочих расходов (`deliveryService`, `paidStorage`, `paidAcceptance`,
`penalty`, `deduction`, `rebillLogisticCost`, `ppvzReward`) используется
действующее правило WB-обработчиков проекта: расход равен абсолютному значению
поля и всегда уменьшает расчётное перечисление. Отрицательный raw-знак этих
полей сам по себе не считается сторно. `additionalPayment` и
`cashbackDiscount` сохраняют raw-знак.

Статья «Удержания» дополнительно расшифровывается по точному raw-значению
`bonusTypeName` (`bonus_type_name` для старого формата). В расшифровку попадают
только строки с ненулевым `deduction`; пустое основание отображается как
«Без расшифровки WB». Названия не преобразуются в собственные бухгалтерские
категории, а сумма расшифровки равна общей сумме статьи.

Товарная строка с некорректным количеством, ценой или денежным полем
исключается из товарных итогов целиком и явно отмечается в качестве данных,
чтобы из нулевой цены не возникала фантомная комиссия.

Поля с незафиксированной финансовой семантикой не включаются в итог и
показываются в блоке качества данных.

## Контроль качества

Отчёт показывает покрытие загрузки по дням и считает:

- повторные и отсутствующие `rrdId`;
- отсутствующие `reportId`;
- некорректные денежные значения и количество;
- исключённые некорректные товарные строки;
- строки с не классифицированным типом документа;
- отрицательную расчётную комиссию;
- не классифицированные денежные поля и неподдерживаемую валюту;
- расхождения `recordsCount` с фактическим числом raw-строк;
- отсутствующие/некорректные raw-документы и некорректные raw-строки.

Из таблицы покрытия можно открыть исходный JSON-документ; существующая
проверка активной компании на raw-view маршруте сохраняется.

# Коды ядра статей ДДС (`core.yaml`) — эталон по умолчанию

Этап 0 задачи `cashflow-group-chart`. Источник — `site/config/cash/cashflow_templates/core.yaml`
v1: 7 групп и 30 статей. На проде это дерево с 17.11.2026 стоит у ООО «Максимедиа».
Коды войдут в `core.yaml` v2 и в `cashflow_categories.group_code` на этапе 1.

## Правила кодов

- Формат `{OP|FIN|INV}_{IN|OUT}[_{SLUG}]`: секция деятельности, направление, смысл статьи.
  Только `A–Z`, `0–9`, `_`, до 64 символов.
- Группа направления — без слага (`OP_IN`). Вложенная группа — со слагом (`OP_OUT_TAXES`),
  её статьи — с общим префиксом (`OP_OUT_TAX_*`).
- Код описывает смысл статьи, а не её название: название можно поменять, код после утверждения
  не меняется никогда. Статья с новым смыслом получает новый код, старый код не переиспользуется.
- Пользователь кодов не видит: это ключ консолидации, в отчёте показываются названия эталона.

## Проверки

- Коды уникальны, все соответствуют формату.
- Похожих названий внутри секции и направления нет: попарная проверка
  `PLCategoryNameSimilarity::similar()` по `core.yaml`, 17.11.2026.
- У каждой из 30 статей есть описание с пометкой ОПиУ (обязательно по контракту
  `CashflowCoreTemplateReader`).

## Решения Владельца (17.11.2026)

1. «Возвраты покупателям» — пометка «ОПиУ — напрямую» остаётся: для компании не на
   маркетплейсе она верна. В описание добавляется уточнение для селлеров: «Селлеру:
   возвраты маркетплейсов сюда не относить — они уже в отчёте площадки». Ядро общее
   для всех профилей, поэтому уточнение условное (этап 1, `core.yaml` v2).
2. «Продажа оборудования» — как предложено: в описание добавляется подсказка про
   остаточную стоимость (этап 1).
3. Коды утверждены, правило «код не меняется никогда» принято.
4. У каждой группы компаний своя структура на основе базовой. Головная компания задаётся в
   её настройках, там же отмечаются компании кабинета, входящие в группу (`TASK.md`, п. 1).

<details><summary>Вопросы, на которые ответил Владелец</summary>

1. **«Возвраты покупателям» — напрямую в ОПиУ.** Компания на маркетплейсе получает возвраты
   в отчёте площадки, и ОПиУ уже учитывает их оттуда. Если такая компания разнесёт
   платёж в эту статью, возврат задвоится. Возвратов маркетплейсов на расчётном счёте почти
   не бывает: площадка удерживает их из выплаты.
   **Предлагаю:** пометку оставить, в описание добавить «возвраты маркетплейсов сюда не
   относить — они уже в отчёте площадки».
2. **«Продажа оборудования» — вся цена в прочие доходы.** По учёту доход — цена продажи, а
   расход — остаточная стоимость, иначе прибыль завышена на стоимость актива. Пока в
   сервисе нет учёта основных средств, остаточную стоимость взять неоткуда.
   **Предлагаю:** оставить как есть, в описание добавить «если оборудование ещё не
   самортизировано, остаточную стоимость отнесите в прочие расходы вручную».
3. **Утвердить коды и правило «код не меняется никогда».**

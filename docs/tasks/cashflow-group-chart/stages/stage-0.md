# Этап 0 — эталон плана статей ДДС

## Какую задачу решаем

Нет утверждённого дерева, к которому привязывать статьи компаний. Решение
Владельца 17.11.2026: эталон = дерево ООО «Максимедиа» + `core.yaml`.

## Что будет результатом

`docs/tasks/cashflow-group-chart/chart.md`:

- дерево по секциям `CF_OP` / `CF_FIN` / `CF_INV`, у каждого узла: `code`, название,
  направление (INFLOW/OUTFLOW), группа или статья, источник (`maximedia` /
  `core` / `оба`), для статей из Максимедиа — описание в формате `core.yaml`
  (что входит, что не входит, пометка ОПиУ);
- правила кодов: `{OP|FIN|INV}_{IN|OUT}_{SLUG}`, латиница, до 64 символов, код
  после утверждения не меняется;
- список расхождений, которые решает Владелец: дубли по смыслу, статьи Максимедиа,
  специфичные для её бизнеса, статьи ядра, которых у Максимедиа нет.

## Шаги

1. Выгрузить дерево Максимедиа: id компании, затем `name, parent, system_code,
   operation_type, flow_kind, sort, status` и число операций на статье. Нужен
   доступ: разрешение на `codex-psql-ro` или выгрузка Владельцем через `!`.
2. Сопоставить с `core.yaml` по смыслу внутри секции и направления.
3. Назначить коды, написать описания недостающих статей.
4. Владелец утверждает `chart.md`; расхождения закрываются его решениями.

## Что считаем выполненной работой

`chart.md` влит в master, Владелец его утвердил, открытых расхождений нет.

## Чек-лист приёмки

- [ ] Все активные статьи Максимедиа, на которых есть операции, есть в эталоне либо
      явно исключены решением Владельца.
- [ ] Все 30 статей `core.yaml` есть в эталоне либо исключены решением Владельца.
- [ ] Коды уникальны и соответствуют правилу.
- [ ] Внутри секции и направления нет двух узлов с похожими названиями (по
      правилам `PLCategoryNameSimilarity`).
- [ ] У каждой статьи есть описание с пометкой ОПиУ.

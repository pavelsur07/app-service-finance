# Этап 0a — базовое дерево ДДС для существующей компании (первой — ООО «Максимедиа»)

Поручено Владельцем 17.11.2026: применить «Базовое дерево ДДС» (ядро
`core.yaml`) к ООО «Максимедиа».

## Какую задачу решаем

Базовое дерево получает только новая компания: `ApplyCashflowCoreTemplateAction`
пропускает компанию, у которой есть хоть одна несистемная статья. У Максимедиа
(`01a15d05-0686-703c-9001-89fffc1cdca5`, прод, 17.11) 9 старых статей
финансовой и инвестиционной деятельности, на них нет операций, разбивок,
платежей в календаре и правил. Все 82 операции лежат в «Не распределено». На
статью «Проценты полученные» указывают 5 открытых ИИ-подсказок (поле без FK).

## Что будет результатом

Команда `app:cash:cashflow-core:apply <companyId> [--execute]`:

- без `--execute` — план: какие статьи будут удалены, сколько ИИ-подсказок
  устареет, сколько узлов создаст шаблон; отказ, если какая-то статья используется;
- с `--execute` — в одной транзакции под блокировкой компании: системные группы
  (идемпотентно), удаление неиспользуемых несистемных статей, открытые подсказки на
  них → `stale`, затем ядро `core.yaml`;
- если дерево компании уже совпадает с шаблоном — «уже применено», ничего не
  меняется;
- если хоть одна несистемная статья используется (операции, в т. ч. удалённые,
  разбивки, платёжный календарь, правила) — отказ со списком статей, данные не
  меняются. Ссылку, появившуюся в гонке, ловит FK, транзакция откатывается.

Связь с ОПиУ (`plCategory`) шаблон не ставит, как и при онбординге.

## Что считаем выполненной работой

PR влит и выкачен, команда добавлена в `codex-console` (это делает Владелец).

ядра, старых статей нет, операции не тронуты.

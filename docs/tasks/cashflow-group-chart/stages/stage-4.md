# Этап 4 — консолидированный отчёт ДДС группы

## Какую задачу решаем

Деревья статей участников привязаны к эталону (этапы 1–3), но отчёта по группе нет: чтобы
увидеть движение денег группы, приходится складывать отчёты компаний руками, а платежи между
компаниями группы задваивают обороты.

## Что будет результатом

1. **Отчёт** `GET /finance/reports/cashflow/group?from=&to=` — группа активной компании
   (`ConsolidationGroupFacadeInterface::headOf`), период «с–по» (по умолчанию текущий месяц),
   ссылка со страницы «Отчёт ДДС».
   - Строки — статьи эталона (несистемные статьи головной компании с кодом) по секциям
     деятельности, вложенность с суммами подстатей; названия — из головной.
   - Сумма статьи компании сворачивается к ближайшему предку с кодом (своя детализация
     участника, этап 1 п. 4); статьи без кода в цепочке — строка «Не сопоставлено».
   - Колонки: по компании группы, «Внутригрупповые» и «Итого по группе» = сумма компаний минус
     внутригрупповые.
   - Внутригрупповая операция — ИНН контрагента совпадает с ИНН другой компании группы
     (`companies.inn`). Если ИНН у компаний группы не заполнен — предупреждение над отчётом.
   - Только RUB; суммы в других валютах — отдельной таблицей по компаниям, без статей.
   - Охват строк тот же, что у отчёта ДДС компании (`listCashflowReportRows`): строки разбивки
     с категорией, не удалённые, `occurred_at` в периоде. Сумма колонки компании = итог её отчёта.
2. **Доступ.** Только владелец всех компаний группы (группу и так задаёт владелец, все компании —
   из его кабинета); иначе 403. Активная компания вне группы — страница с пояснением.
   Отдельных ролей нет (TASK «Не делаем в MVP»); доступ участников компаний — отдельной задачей.
3. **Excel** — `GET …/group/export.xlsx` с теми же параметрами, та же таблица.
4. **Реализация** (Cash): `CashflowGroupReportQuery` — один SQL-агрегат по компаниям группы
   (`SUM` со знаком направления `GROUP BY company, категория, валюта, внутригрупповая`);
   `BuildCashflowGroupReport` сворачивает к кодам по деревьям компаний (bcmath, без float);
   DTO отчёта; xlsx-экспортёр на OpenSpout. Только чтение, без миграции.
5. `ARCHITECTURE.md`: отчёт, правило внутригрупповых, доступ.

Вне этапа: разбивка по месяцам, фильтры по проектам и ЦФО, JSON и публичный API, доступ не-владельцам.

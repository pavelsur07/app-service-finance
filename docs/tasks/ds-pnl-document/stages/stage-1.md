# Stage 1 — данные дерева статей ОПиУ

## 1. Какую задачу решаем
Виджету нужно дерево статей ОПиУ компании (группы, листья, `flow`) одним
запросом на страницу, а форме — поле, которое рендерится виджетом, но
отправляет тот же `category` с тем же value и проходит ту же серверную
валидацию.

## 2. Что будет результатом
- Построитель дерева статей ОПиУ в модуле Finance (по образцу
  `CashflowCategoryTreeBuilder`): вход — статьи компании одним запросом,
  выход — `[{id,name,children}|{id,name,flow}]`; лист — статья, выбираемая
  сейчас в select; `flow` листа: INCOME → доход, EXPENSE → расход,
  NONE → «обе стороны»; порядок — `sortOrder`, как в отчёте.
- Тип поля / опция для `DocumentOperationType::category`: в view — JSON дерева
  и путь выбранного листа; группы в select `disabled`; пустая option
  «Выберите категорию»; имя поля и value не меняются.
- Дерево собирается один раз на форму и отдаётся всем строкам коллекции
  (включая `data-prototype`) — не по запросу на строку.
- Тема формы Twig для нового типа (по образцу
  `form/cashflow_category_tree_theme.html.twig`), переиспользующая
  `partials/_dds_tree_picker.html.twig`.
- Серверная проверка «категория обязательна и это лист своей компании» —
  если её нет, добавить в форму/Action с сообщением «Выберите категорию ОПиУ».

## 3. Что считаем выполненной работой
Unit-тесты построителя зелёные; страница правки отдаёт дерево своей компании
одним запросом (профайлер: число запросов не выросло); чужая статья в POST —
ошибка формы, не сохранение; сохранение документа с листом работает как раньше.

## 4. Чек-лист приёмки (CHECKLIST D, H)
- [x] Unit построителя: вложенность до 4 групп + лист, `flow`, порядок, пустые группы, изоляция по компании
- [x] Дерево строится одним запросом на страницу, фильтр по `company` (профайлер до/после)
- [ ] Категория обязательна на сервере; группа или чужая статья не сохраняются (functional)
- [x] Имя поля `category`, value option и CSRF не изменились; существующие тесты Finance зелёные

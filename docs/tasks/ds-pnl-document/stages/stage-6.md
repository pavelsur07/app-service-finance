# Stage 6 — «Новый документ ОПиУ»

## 1. Какую задачу решаем
Перевести форму создания (`document_new`, а также `document_copy` — тот же
шаблон) на partial/CSS/JS страницы правки, с отличиями SPEC §6 п.5, не
дублируя код и не меняя поток создания из операции ДДС (решение §8.4).

## 2. Что будет результатом
- `templates/document/new.html.twig` на общих partial: заголовок «Новый
  документ ОПиУ», крошки «Доходы и расходы / Документы ОПиУ / Новый документ»,
  кнопка «Создать документ», статус «Документ ещё не создан…».
- Справа — карточка-подсказка «Как это работает» вместо истории; «Сверка с
  основанием» и «Основание» — только если у формы есть основание (у ручного
  создания его нет).
- Одна пустая операция при открытии; новая строка берёт Проект/ЦФО шапки.
- Копия документа: значения исходного документа, включая Проект/ЦФО и
  описания операций.
- «Ещё» — только «Открыть операцию ДДС», и только при наличии основания.
- «Отмена» спрашивает подтверждение, если форма менялась; `beforeunload`.
- После создания — переход по текущему правилу (`document_list_resume`) и
  тост «Документ создан»; ключ идемпотентности (`idempotencyKey`) не трогаем.
- Functional и e2e создания (по образцу `CashTransactionNewPageTest`,
  `dds-operation-new.e2e.cjs`); скриншоты против `pnl-refs/09`–`12`.
- Строка в `plan.md`, отчёт — раздел PR 3; handoff PR 3.

## 3. Что считаем выполненной работой
Создание и копия работают как раньше, но в новом виде; e2e и functional
создания зелёные; скриншоты 09–12 сняты; CHECKLIST F отмечен; гейты зелёные.

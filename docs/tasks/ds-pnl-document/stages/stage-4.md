# Stage 4 — таблица операций: «Описание», Проект/ЦФО с наследованием

## 1. Какую задачу решаем
Сделать таблицу «Операции документа» по SPEC §5: колонки и вторая строка
«Описание», Проект/ЦФО в каждой операции, которые по умолчанию берутся из шапки
и меняются вручную (SPEC §4.1), без новых флагов в БД; мобильные карточки.

## 2. Что будет результатом
- Колонки: Тип (104) · Категория ОПиУ * · Проект * · ЦФО · Сумма, ₽ * (вправо,
  `120 000,00`) · действия «Дублировать»/«Удалить» («Удалить» неактивна для
  единственной операции); заголовок с бейджем-счётчиком и «Добавить операцию».
- Вторая строка операции: подпись «Описание» + поле `comment` (имя поля не
  меняется; `maxlength` по решению §8.2, placeholder по SPEC,
  `aria-label="Описание, операция N"`).
- Наследование на клиенте (SPEC §4.1): «изменён» = значение строки ≠ значению
  шапки (`data-*` на строке); смена шапки меняет только наследующие строки;
  тост «Проект «X» подставлен в N из M операций. В K задан вручную»; пометка
  «Изменён» + ссылка «Как в шапке»; новая строка берёт значения шапки, дубль —
  исходной; подсказка «Без ЦФО операция не попадёт в разрез по ЦФО».
- Сервер не меняет значения операций при сохранении шапки (проверить в
  нормализаторе; если меняет — зафиксировать и не ломать поведение молча).
- Подвал: Доходы / Расходы / Итого / Остаток по основанию.
- ≤760 px — карточки (SPEC §5.5), без горизонтального скролла.

## 3. Что считаем выполненной работой
e2e наследования и описания проходят; сохранённые Проект/ЦФО/описание
операций после перезагрузки на месте; скриншоты совпадают с `pnl-refs/01`,
`08` по таблице.

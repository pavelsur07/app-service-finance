# Подключение онлайн-оплаты ЮKassa

Код онлайн-оплаты на проде с этапа 5 и выключен, пока не заданы ключи
магазина. Без ключей клиенты видят только «оплатить по счёту», уведомления
ЮKassa не обрабатываются, cron сверки выходит сразу.

## 1. Магазин в ЮKassa

1. Зарегистрироваться на yookassa.ru, подписать договор, создать магазин.
2. Способ подключения — **API** (не «платёжная форма», не CMS-модуль).
3. Взять в «Интеграция → Ключи API»:
   - `shopId` — номер магазина (цифры);
   - секретный ключ — `live_…` для боевого магазина, `test_…` для тестового.

Тестовый магазин ЮKassa выдаёт сразу, до договора. С ним можно пройти
оплату целиком тестовой картой из документации ЮKassa (например, `5555 5555 5555 4477`,
любой срок в будущем, любой CVC) — деньги не списываются.

## 2. Уведомления (вебхук)

В кабинете ЮKassa: «Интеграция → HTTP-уведомления».

- Адрес: `https://app.vashfindir.ru/billing/yookassa/webhook`
- События: `payment.succeeded`, `payment.canceled`

Подпись уведомлений не нужна: сервис не доверяет телу уведомления и
перепроверяет каждый платёж запросом в ЮKassa. Если уведомление потеряется,
платёж подберёт сверка раз в 10 минут или возврат клиента на страницу тарифа.

## 3. Чеки 54-ФЗ

Если в ЮKassa подключены чеки («Решение для чеков от ЮKassa» или своя
онлайн-касса через ЮKassa), задать код ставки НДС:

| Код | Ставка |
|---|---|
| 1 | без НДС (УСН и др.) |
| 4 | 20% |

Остальные коды (в т. ч. новые ставки) — в документации ЮKassa, раздел «Параметры чека: vat_code». Код должен совпадать с ассортиментом и настройками кассы.

Чек уходит на e-mail владельца кабинета, предмет расчёта — услуга, полная
оплата. Код не задан — чек в ЮKassa не передаётся (касса не подключена или
чеки формируются отдельно). Какой код ставить — решает бухгалтер по системе
налогообложения ООО.

## 4. Где задать ключи

Переменные окружения прода заводятся в GitHub, не на сервере: деплой
(`.github/workflows/deploy.yml`) прокидывает их в контейнеры, переменная,
положенная только на хост, до приложения не дойдёт.

GitHub → репозиторий → Settings → Secrets and variables → Actions:

| Где | Имя | Значение |
|---|---|---|
| Variables | `YOOKASSA_SHOP_ID` | `shopId`, только цифры |
| Secrets | `YOOKASSA_SECRET_KEY` | секретный ключ `live_…` или `test_…` |
| Variables | `YOOKASSA_RECEIPT_VAT_CODE` | код НДС из таблицы выше или не заводить |

Затем — перезапустить последний деплой (Actions → Deploy → Re-run) или
дождаться следующего. Деплой сам проверит формат значений и откажет при
недопустимых символах.

Выключить онлайн-оплату — удалить `YOOKASSA_SECRET_KEY` (или
`YOOKASSA_SHOP_ID`) и передеплоить. Уже начатые оплаты при этом не теряются:
после повторного включения их подберёт сверка.

## 5. Проверка после включения

1. Открыть «Тариф и оплата» владельцем кабинета на платном или пробном
   тарифе — есть блок «Оплатить онлайн».
2. На тестовом магазине: оплатить Старт на 1 месяц тестовой картой →
   вернуться на страницу → «Оплата прошла, тариф продлён», в истории оплат —
   строка со способом «ЮKassa».
3. В админке кабинета (`/admin/billing/companies/{id}`) оплата видна в
   истории; блока «Онлайн-оплаты без зачисления» нет.
4. Перейти на боевой ключ — те же шаги 2–3 с реальной картой на 1 месяц
   Старта; при необходимости — возврат в кабинете ЮKassa и правка тарифа в
   админке (возврат период сам не сокращает).

## Что делать, если…

- **В админке есть «Онлайн-оплаты без зачисления».** ЮKassa списала деньги,
  но продлить автоматически не удалось (сумма не совпала с ценой, кабинету
  назначили «Друга» или другой тариф, пока клиент платил). В GlitchTip —
  ошибка «оплата ЮKassa получена, но не зачислена». Решение: отметить оплату
  вручную формой на той же странице, в поле номера — ID платежа ЮKassa из
  таблицы (строка исчезнет), либо оформить возврат в кабинете ЮKassa.
- **Клиент оплатил, а страница пишет «обрабатывается».** ЮKassa не ответила
  при возврате; сверка через ≤ 10 минут продлит тариф сама.
- **Ошибка «ЮKassa: запрос отклонён» (401/403) в GlitchTip.** Неверный
  `shopId` или ключ, или ключ отозван — проверить значения в GitHub.

# Этап 7 — доделки биллинга

## Задача

Владелец 02.11.2026 выбрал «доделки биллинга» из накопленного follow-up
`TASK.md` (все этапы 0–6 на проде):

1. «Назначить тариф» молча сокращает оплаченный период — нужна явная отметка,
   если новое окончание раньше последнего оплаченного дня.
2. Запланированный переход (понижение со следующего периода) отменить можно
   только назначением тарифа, вручную считая даты.
3. Журнал полученных денег (`billing_payments`) и попыток онлайн-оплаты
   (`billing_checkouts`) удаляется вместе с компанией (`ON DELETE CASCADE`).

Прод 02.11.2026: 21 подписка на «Друге», оплат 0, попыток 0, переходов 0 —
изменения никого не затрагивают. Удаление компании владельцем есть
(`company_delete`), но для реальной компании уже падает на FK кассы и статей
(`NO ACTION`, создаются онбордингом); удаление пользователя в админке
закомментировано. `RESTRICT` у журнала ничего не ломает дополнительно.

## Результат

Ветка `feat/billing-followups`, один PR.

1. **Сокращение периода** — `AssignTariffAction`: тариф с периодом, «по»
   раньше последнего оплаченного дня кабинета (максимум `period_until`
   журнала) и нет отметки `confirm_shorten` → отказ с датой «оплачено по»;
   в форме админки — флажок «Сократить оплаченный период». Бессрочный тариф
   период не сокращает — без отметки.
2. **Отмена перехода** — `CancelScheduledTariffAction` (точка входа, та же
   блокировка компании): снимает запланированный переход, до «оплачено по»
   остаётся текущий тариф; переход уже наступил или его нет — отказ. Кнопка в
   админке рядом с «С DD.MM — тариф X»; маршрут POST с CSRF, `ROLE_ADMIN`.
3. **Журнал не удаляется с компанией** — миграция: FK `billing_payments` и
   `billing_checkouts` → `companies` с `ON DELETE RESTRICT` (обратимая).
   Удалить компанию с оплатами можно только явным решением (сначала журнал).
4. `ARCHITECTURE.md`, `TASK.md` (follow-up закрыты), отметки этапа 6
   «после деплоя» (сделаны 02.11 локально).

## Что считаем выполненным

- Админ не может случайно обрезать оплаченный клиентом период: без флажка —
  сообщение с датой, с флажком — как раньше.
- Запланированный переход отменяется одной кнопкой. Это уступка
  администратора: дни, оплаченные дешёвым тарифом, клиент получает на
  текущем; онлайн-повышение до «оплачено по» после этого — через
  администратора (журнал и подписка расходятся намеренно).
- Удаление компании с оплатами падает на ограничении БД, а не стирает журнал.
- Тесты по таблице CLAUDE.md, гейты, внутреннее и внешнее ревью, CI зелёный.

# Этап 2 — тариф кабинета в админке

## Задача

Администратор видит тариф каждого кабинета на странице «Пользователи» и
меняет его там же: назначает любой тариф, включая скрытые, отмечает оплату по
счёту, смотрит историю оплат. Все 21 текущих кабинета прода получают тариф
«Друг».

Решения Владельца 01.11.2026: скидки 5/10/20% оставить (решение №1); всем
текущим кабинетам — «Друг», дальше правка вручную в админке на странице
пользователей и кабинетов (решение №2).

Замер прода 01.11.2026 (read-only): компаний 21, подписок 0, оплат 0.

## Результат

Ветка `feat/billing-admin`, один PR.

1. **Миграция** `Version20261101230000` (данные): каждой компании без
   подписки — «Друг» с `paid_from` = сегодня по Москве, `paid_until = NULL`.
   `INSERT … SELECT … WHERE NOT EXISTS` — повтор безопасен. Маркер строк
   миграции — `created_at = '2026-11-01 23:00:00'`; `down()` удаляет только
   подписки «Друг» с этим маркером и без оплат.
2. **Domain**: `CompanySubscription::assign(Tariff, from, ?until, now)` и
   фабрика `assignNew()`. Бессрочный тариф — без даты окончания; остальные —
   с `from ≤ until`. Так задаются «На сопровождении» (даты договора),
   «Аутсорсер» и ручная правка периода.
3. **`AssignTariffAction`** (`AssignTariffCommand`): точка входа, та же
   advisory-блокировка компании, создаёт или меняет подписку. Ввод проверяет
   до транзакции и бросает `InvalidBillingInputException`.
4. **Facade**: `BillingFacadeInterface::accessForCompanies(list<string>,
   now): array<string, BillingAccessDTO>` — один запрос на страницу.
5. **Страница кабинета** `GET /admin/billing/companies/{companyId}`
   (`src/Billing/Controller/Admin/`, маршрут в `routes.yaml`):
   - текущий тариф, статус, «оплачено с/по»;
   - форма «Назначить тариф»: тариф, даты;
   - форма «Отметить оплату по счёту»: тариф (платный), срок 1/3/6/12, сумма
     в ₽ с подсказкой цены из справочника, дата зачисления, номер счёта
     (`externalId`), скрытый UUIDv7 против двойной отправки. Если текущий
     тариф «Друг» — обязательная галочка «перевести с «Друга» на платный»
     (follow-up ревью этапа 1);
   - история оплат кабинета (Pagerfanta, по 50).
   POST-обработчики — отдельные single-action контроллеры, CSRF, ловят только
   доменные исключения Billing → flash + redirect.
6. **Страница «Пользователи»**: в строке каждого кабинета — плашка тарифа
   («Друг» / «Старт · по 14.02.2027» / «Нет тарифа», цвет по статусу) и
   ссылка «Тариф» на страницу кабинета.
7. Заглушка `/admin/billing` (`Admin\Controller\Billing\BillingDashboardController`,
   шаблон, пункт сайдбара) удаляется: управление — со страницы «Пользователи».

Перерасчёт остатка при смене тарифа посреди периода (план TASK.md) в этот
этап не входит: админ задаёт новые даты вручную формой «Назначить тариф».

## Что считаем выполненным

- Админ на странице «Пользователи» видит тариф каждого кабинета и по ссылке
  меняет тариф и отмечает оплату; результат виден сразу.
- Миграция на локальной БД: всем компаниям без подписки — «Друг», повтор
  не дублирует, `down` убирает только свои строки.
- Тесты: unit `assign`; integration `AssignTariffAction` (+негатив),
  `accessForCompanies`; functional — страница кабинета, обе формы (успех и
  ошибка), плашки на «Пользователях», доступ только `ROLE_ADMIN`.
- Гейты зелёные; внутреннее и внешнее ревью; CI зелёный.

# Этап 4 — режим «только чтение» после льготного периода

## Задача

Кабинет, у которого закончились оплаченный (или пробный) период и 5 льготных
дней, продолжает показывать данные, но перестаёт принимать изменения, пока
тариф не продлят. Данные не удаляются, загрузки из маркетплейсов и банков не
останавливаются.

Решение №5 (по предложению): только чтение, просмотр и выгрузки доступны.
Включение — переменной окружения, по решению Владельца; до включения режим
только пишет в журнал, что заблокировал бы.

Замер прода 02.11.2026 (read-only): компаний 21, все на «Друге» — ни одного
кабинета в статусе `read_only`, включение сейчас никого не затронет.

## Результат

Ветка `feat/billing-read-only`, один PR.

1. **Гейт** `Billing\Infrastructure\Http\ReadOnlyModeSubscriber`
   (`KernelEvents::CONTROLLER`, после маршрутизации и firewall):
   - только main-request, firewall `main` (кабинет клиента; админка, внешнее
     и внутреннее API — вне гейта);
   - только изменяющие методы (`POST`, `PUT`, `PATCH`, `DELETE`); `GET` и
     выгрузки не трогаются;
   - пользователь вошёл, есть активный кабинет, его статус `read_only`
     (`BillingFacadeInterface::accessFor`); `none` и `grace` — без
     ограничений;
   - статус берётся у компании, которую меняет запрос: из пути
     (`{companyId}`, `/company/{id}/edit|tax-profile`), если у пользователя
     есть доступ, иначе активной из сессии;
   - белый список маршрутов: вход/выход, смена пароля, тема интерфейса,
     принять приглашение, создание, переключение и удаление компании, отзыв
     доступа (сотрудник, приглашение, ключи API, интеграции), пересчёт и
     предпросмотр отчётов;
   - ответ: HTML — redirect на «Тариф и оплата» с сообщением; JSON / XHR /
     `/api/*` — `403 {"error":{"code":"billing_read_only","message":…}}`.
2. **Флаг** `BILLING_READ_ONLY_ENFORCED` (`.env` — `false`). Выключен —
   запрос проходит, в журнал `info` «заблокировал бы» с `companyId` и
   маршрутом: Владелец видит эффект до включения.
3. **Страница «Тариф и оплата»** и баннер: в `read_only` при включённом
   режиме — «Кабинет в режиме только чтение»; при выключенном — как сейчас.
4. `ARCHITECTURE.md` (Billing), `TASK.md`, отметки этапа 3 после деплоя.

Внешнее API (`/api/external/v1`) и фоновые загрузки в этап не входят —
follow-up в `TASK.md`.

## Что считаем выполненным

- При включённом флаге кабинет в `read_only` не может создать или изменить
  данные через интерфейс; страницы и выгрузки открываются; продление (оплата
  в админке) сразу снимает ограничение.
- При выключенном флаге поведение не меняется, в журнале видно, что было бы
  заблокировано.
- Тесты по таблице CLAUDE.md; гейты; внутреннее и внешнее ревью; CI зелёный.

## Итог

02.11.2026, ветка `feat/billing-read-only`.

**Сделано по плану**: `ReadOnlyRule` + `ReadOnlyModeSubscriber`, флаг
`BILLING_READ_ONLY_ENFORCED` (`.env` false, `.env.test` true, prod compose
`x-php-env` — `false` по умолчанию), тексты баннера при включённом режиме.
Миграции нет.

**Ревью**
- Внешнее (Codex, `external-review.sh 9389534e0`): IMPORTANT — гейт смотрел
  активную компанию, а `/company/{id}/edit`, налоговый профиль и legacy-маршруты
  участников меняют компанию из пути: обход в одну сторону и ложный блок в
  другую.
- Внутреннее (свежая сессия): BLOCKER нет. IMPORTANT — тот же обход; отзыв
  доступа (уволенный сотрудник, утёкший ключ API) блокировался. MINOR —
  порядок с модульным гейтом не задан; legacy-JS читает `data.message`;
  «пересчёт без изменения учёта» в комментарии неточен; вход/выход в белом
  списке не срабатывают (firewall раньше); тесты «прошёл» не ловили 5xx.
- Исправлено: целевая компания из пути (при доступе пользователя); отзыв
  доступа — в белом списке; приоритет −8 (после `ModuleAccessSubscriber` и
  `#[IsGranted]`); `message` верхнего уровня в 403; комментарии; тесты — две
  компании в обе стороны, XHR, 5xx в «прошёл».
- Оставлено: `company_new` в белом списке — новый кабинет того же владельца
  получает «нет тарифа» (пробный один на владельца) и не ограничивается, но
  данные старого кабинета в нём недоступны; GET-страницы, создающие
  стартовую структуру (Баланс, маппинг затрат), не блокируются — это не ввод
  учёта.

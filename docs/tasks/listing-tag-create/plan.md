# Кнопка «Добавить» на странице тегов листингов

Ветка: `feat/listing-tag-create`. Классификация: Small (один модуль Marketplace,
без схемы и миграций, новый внутренний JSON-эндпоинт).

## Задача

На странице `/marketplace/listings/tags` («Управление тегами») сейчас можно
переименовать, слить и удалить тег. Создать тег можно только на странице
листингов и только сразу с назначением на выделенные строки. Нужна кнопка
«Добавить»: модальное окно с полем «Название» создаёт тег в активной компании
без привязки к листингам — для дальнейшего обслуживания (назначение в реестре,
переименование, слияние, удаление).

## Ожидаемый результат

- Кнопка «Добавить» в шапке страницы, видна и при пустом списке.
- Модальное окно: поле 1–50 символов, «Создать» / «Отмена», Enter = создать.
- Успех → перезагрузка, новый тег в таблице с 0 листингов.
- Дубль (тот же slug: регистр и пробелы не различаются), пустое или длинное
  название → ошибка под полем в окне, окно не закрывается, тег не создаётся.
- Без `MARKETPLACE_WRITE` → 403; тег создаётся только в активной компании.

## Этап 1. Backend: создание тега

**План**
1. `CreateListingTagAction(companyId, name)` в `src/Marketplace/Application/`:
   проверка slug через `findBySlug(companyId, …)` → `ListingTagNameConflictException`;
   иначе `new MarketplaceListingTag(uuid7, companyId, name)`, `add`, `flush`.
2. `ListingTagCreateController`: `POST /api/marketplace/listings/tags/create`,
   `ROLE_USER` + `MARKETPLACE_WRITE`, тело `{name}`; 422 `tag_name_invalid`,
   409 `tag_name_conflict`, 201 `{id, name}`. Формат как у rename.
3. Тесты в `ListingTagsApiTest`: создание (201, тег в БД нужной компании),
   дубль по slug (409), пустое и > 50 символов (422), тег с тем же именем в
   чужой компании не мешает созданию.

**Результат:** эндпоинт создаёт тег в активной компании, ошибки в едином JSON-формате.

**Чек-лист «выполнено»**
- [ ] Action и контроллер созданы, `declare(strict_types=1)`, `final`.
- [ ] Repository-вызовы только с `companyId`.
- [ ] Тесты happy-path + негативные зелёные.
- [ ] PHPStan и CS по изменённым файлам чисты.

## Этап 2. Frontend: кнопка и модальное окно

**План**
1. В `templates/marketplace/listings/tags.html.twig` — кнопка «Добавить» в шапке.
2. Модальное окно Bootstrap (как `mapListingModal` в реестре листингов): поле,
   блок ошибки `invalid-feedback`, кнопки; фокус в поле при открытии.
3. JS: POST, при ошибке — текст `error.message` под полем, при успехе — reload;
   блокировка кнопки на время запроса.
4. Подсказка в пустом состоянии: «Нажмите «Добавить» или создайте тег на
   странице листингов».
5. Функциональный тест: страница содержит кнопку и модальное окно (и в пустом состоянии).

**Результат:** пользователь создаёт тег со страницы тегов без перехода в реестр.

**Чек-лист «выполнено»**
- [ ] Кнопка видна при пустом и непустом списке.
- [ ] Ошибки видны в окне, не через `alert`.
- [ ] Визуальная проверка: окно открывается, создание и дубль работают.
- [ ] Тест страницы зелёный.

## Порядок деплоя (важно)

1. Миграция `Version20260730150000` (expand, обратимая).
2. `app:counterparty:backfill-names --dry-run`, затем без флага.
3. Проверка: `SELECT count(*) FROM counterparty WHERE name_core IS NULL` = 0.
4. Только после этого — Stage 4 (contract).

Поиск по названию работает только по строкам, прошедшим backfill: `name_core IS NULL`
не матчится ничем. Поэтому шаги 1–3 обязаны пройти до того, как endpoint станет
использоваться в UI.

**Ожидаемый одноразовый эффект после релиза.** Импорт файлов теперь ищет контрагента
по нормализованному отображению названия. Для исторических строк, у которых в `name`
остались двойные пробелы, первый импорт создаст по одной новой записи, дальше поведение
стабильно. Это не новый баг дедупликации, а следствие приведения ключа поиска и
сохраняемого значения к одному виду; окончательно закрывается в Stage 4 матчингом по
(`nameCore`, `legalFormHint`).

**Известная асимметрия, вынесенная в Stage 4.** В `CashFileImportService` ключ кэша
приводится к нижнему регистру, а поиск в БД регистрозависимый: внутри одного прогона
`ООО Ромашка` и `ооо ромашка` схлопываются, между прогонами — нет. Правится тем же
переходом на `nameCore` (он регистронезависим по построению), поэтому точечно не
трогаем.

## Основание и решение

Первый проход: source 49/49 кандидатов, 47/47 сумм, 7/7 направлений;
semantic 12/13 кандидатов, категория12/13, проект12/12, ЦФО10/12, дата11/13,
exact tuple9/13. Ошибки sem004/005 (ЦФО), sem007 (forbidden_pair, отказ),
sem009 (дата после подготовки null). Raw ответы не хранятся: конкретный выбранный
неправильный ID или исходная дата не восстанавливаются и не утверждаются.
53 вызова, usage estimate4.80564709 рубля, campaign216calls, всего16.73304620.
Fresh before/after PASS, собственных контейнеров0.

Варианты: только уточнить prompt или дополнительно дать модели уже вычисленную
локальную календарную дату. Выбран второй вариант: timezone arithmetic выполняет
существующая логика Python; модель по-прежнему связывает дату с конкретным
денежным фрагментом, verifier проверяет привязку, а отсутствие даты остаётся
null/вопрос. Это не подстановка даты платежа по умолчанию.

- Вынести существующее вычисление reference_at→timezone→date в чистую функцию
  существующего checks.py; использовать в verifier и build_user.
- Внутренний model data block получает derived `reference_local_date`.
  Public PaymentInput/schema/gateway контракты не меняются; extra input keys
  по-прежнему запрещены. Значение не зависит от текстовых инструкций и gold.
- Immutable prompt v5 сохраняет v1–v4, поясняет derived date и независимый
  выбор каждого аналитического поля. Неясность одного поля не обнуляет другие.
  При нескольких одинаковых названиях без однозначного контекста поле null +
  вопрос; допустимая связь не разрешает выбрать другое явно названное значение.
  Для запрещённой пары — вопрос и null одной/обеих сторон без скрытого приоритета.
- Не ослаблять verifier и preparation, не ремонтировать forbidden_pair кодом,
  не вводить приоритет проекта/ЦФО, не менять денежные правила или gold.

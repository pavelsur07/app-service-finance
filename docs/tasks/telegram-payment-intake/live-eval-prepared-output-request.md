## Именованный объём разрешения

- До 82 дополнительных вызовов: общий campaign cap 163 → 245. Первый полный
  проход содержит 53 сообщения; оставшийся объём покрывает schema retry и
  ограниченные повторные проверки исправлений в рамках этих двух наборов.
  Между такими исправлениями повторного разрешения не требуется; лимит общий,
  не сбрасывается, новые наборы или провайдеры в него не входят.
- Та же модель `deepseek/deepseek-flash`, gateway и существующий ключ.
  Ключ остаётся только в памяти удалённого процесса; второй ключ не нужен.
- Общая оценочная граница остаётся 300 рублей. Известное использование
  предыдущих 163 вызовов: 11.92739911 рубля. Максимальный новый резерв:
  261.8179968 рубля; вместе 273.74539591 рубля. Это расчёт по тарифам и курсу,
  проверенным 14 ноября, а не гарантия итогового invoice.
- Продлить прежнее исключение root-SSH только для ограниченного eval:
  одноразовый контейнер существующего образа, пользователь 10001, 256 MiB,
  CPU 0.5, read-only filesystem, tmpfs 32 MiB, pids 64, cap-drop ALL,
  no-new-privileges. Приложение, API, workers, очереди, Docker-конфигурацию,
  секреты и постоянные права не менять. Удаляется только собственный контейнер.
- До и после каждого запуска сохранить metadata-only receipts; сравнивать
  с непосредственным before этого запуска. Хранить только метрики, версии,
  hashes и безопасные коды ошибок, без raw сообщений/ответов/финансовых значений
  в операционных логах. Не выполнять production repair или SQL writes.

Такое расширение требует отдельного решения по AGENTS.md §3.3: разрешённый
предел уже исчерпан, а root-SSH — исключение для конкретной кампании.

## Уточнение разрешённой кампании после ответа владельца

Разрешено до четырёх проходов всего в этом продолжении, с исправлениями между
ними без новых вопросов. Наборы, модель, ключ и изоляция прежние; общий оценочный
денежный предел 300 рублей не повышается. Первый проход использует неизменный
проверенный helper с max82 и cap245. Следующим проходам выделяется до82 вызовов
каждому, суммарно не более328 новых (до491 вместе с прежними163); это верхняя
граница, а не обязанность израсходовать вызовы. Перед каждым новым проходом
сверяются известная стоимость всей кампании, необъяснённые вызовы и резерв
выделяемых запросов. Условие допуска: известная стоимость + консервативный
резерв следующего прохода <=300 рублей. Неиспользованный резерв завершённого
прохода не считается списанием. Неизвестный расход блокирует продолжение до
сверки, а не считается нулём. При недостатке денежного резерва объём уменьшается;
денежный предел имеет приоритет над четырьмя проходами.

Все новые bundles/helpers/reports immutable и привязаны к конкретному source
commit. Ретесты считаются частью этих четырёх проходов; split diagnostics не
дают дополнительных проходов. Это разрешение не распространяется на merge,
deploy, production migrations, изменение workers/флага/прав или запуск пилота.

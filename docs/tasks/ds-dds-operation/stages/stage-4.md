# Stage 4 — страница: поведение полей

## 1. Какую задачу решаем
Разметка полей из этапа 3 статична: сумма приходит как `5300.00`, валюта не
следует за счётом (прежний inline-скрипт искал `#form_moneyAccount` и молча не
работал — у формы префикс `cash_transaction`), счётчик описания не живой,
«Сохранить» активна без изменений, нет признака несохранённых правок.

## 2. Что будет результатом
JS-модуль `site/assets/pages/dds_operation.js` (запускается только на
`[data-dds-op]`, импорт в `legacy-app.js`):
- сумма: при загрузке и на blur — `5300,00` (без разрядов: сервер с локалью
  `en` разрядные пробелы не принимает, запятую — принимает), tabular, вправо;
- смена счёта → знак валюты в «кармашке» и подпись «Валюта берётся из счёта: …»;
- счётчик «N из 500»;
- dirty-состояние: бейдж в шапке, статус панели «Есть несохранённые
  изменения», «Сохранить» неактивна без изменений (после ошибок сервера —
  активна сразу);
- удалён мёртвый inline-скрипт валюты.

## 3. Что считаем выполненной работой
Сценарий в браузере: открыть → «Сохранить» неактивна → изменить поле →
бейдж, статус, кнопка активна → вернуть значение → снова «сохранено»;
сумма форматируется; валюта следует за счётом; сохранение `5300,50`
записывает `5300.50`.

## 4. Чек-лист приёмки (CHECKLIST C)
- [x] Сумма: вправо, tabular-nums, на blur `5300,00`; знак валюты из счёта; подпись «Валюта берётся из счёта…» (e2e страницы)
- [x] Направление — segmented radio, значение уходит в форму как раньше (functional: сохранение с radio)
- [x] Проект/ЦФО/Контрагент — вид `.dds-field`, «×» только при значении; прежняя логика поиска/сохранения (существующие тесты пикеров зелёные)
- [x] Описание: maxlength 500, счётчик «N из 500»
- [x] «Сохранить» неактивна без изменений; бейдж и статус несохранённых правок (e2e страницы)
- [x] Сумма с запятой сохраняется точно (functional)

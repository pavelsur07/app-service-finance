# Stage 6 — «Документы ОПиУ на основании операции», адаптив, отчёт

## 1. Какую задачу решаем
Блок документов ОПиУ на странице операции — прежняя таблица Tabler без знака
суммы, без итога и без ответа на вопрос «всё ли разнесено». SPEC §2.3 п.6 и
`dds-refs/01`: таблица документов со знаковой суммой, «Открыть», итог
«Разнесено в ОПиУ» и статус остатка. Плюс адаптив 1280/1100/390 и отчёт по
задаче.

## 2. Что будет результатом
- `_edit_pnl_documents.html.twig`: колонки Документ (номер + дата) / Описание
  (+ контрагент) / Сумма (знак по направлению, `vf_amount`) / «Открыть»;
  пустое состояние; итог «Разнесено в ОПиУ» и бейдж `data-dds-op-rest`:
  `none` (документов нет), `full`, `partial` («Не разнесено X»), `over`
  («Превышение на X»).
- Контроллер считает «разнесено» и «остаток» в `Money` по суммам операций
  документов (`recalculateAllocatedAmount()` — та же база, что у лимита
  создания документа), без новых запросов на каждый документ.
- CSS `.dds-docs*`, бейджи остатка, описание прячется на ≤760.
- Отчёт `docs/plan/ds-dds-operation.md`: аудит, сделано/отложено, SQL до/после,
  скриншоты, чек-лист, вопросы владельцу (SPEC §7).

## 3. Что считаем выполненной работой
Функциональный тест на четыре состояния остатка и знак суммы зелёный;
существующие `CashTransactionEditCurrencyTest` (селекторы `th.text-end` /
`td.text-end`) зелёные; e2e страницы и скриншоты 1440/1280/390; все гейты
(stan, cs, strict-types, unit+functional, eslint, build) зелёные; отчёт написан.

- [x] Сумма документа со знаком: «−» у оттока, «+» у притока
- [x] Итог «Разнесено в ОПиУ» = сумма операций неудалённых документов
- [x] Бейдж остатка: none / full / partial / over — функциональный тест на каждое

# Stage 5 — страница: валидация, уход, удаление, особые состояния

## 1. Какую задачу решаем
SPEC §2.3: ошибки — рамка, текст под полем, сводка сверху, фокус на первое
невалидное (и для ошибок сервера); уход с несохранёнными правками — модалка
«Выйти без сохранения?» и `beforeunload`; удаление — модалка; удалённая
операция — баннер и «Восстановить»; операция из выписки — плашка и бейдж.

## 2. Что будет результатом
- `dds_operation.js`: проверка по «Сохранить» (обязательные поля из
  `data-dds-op-required`, сумма — число > 0, тексты SPEC §2.2), сводка
  `[data-dds-op-summary]` со списком и фокусом; при ответе сервера 422 — та
  же сводка (рендерит Twig) и фокус на первое поле с ошибкой;
- «Отмена»/уход по ссылкам страницы при dirty → модалка
  `_edit_leave_modal.html.twig`; `beforeunload` при dirty, кроме отправки формы;
- удаление/восстановление — разметка этапа 3 (общий confirm-modal, POST в
  прежние роуты); баннер удалённой операции, read-only;
- ошибки поля: класс `is-invalid` у контрола и `.dds-field` виджетов.

## 3. Что считаем выполненной работой
e2e страницы на стенде проходит сценарии: пустая сумма/дата → сводка, рамки,
фокус; сервер 422 → сводка; «Отмена» с правками → модалка, «Остаться»/«Выйти»;
без правок — уход сразу; удаление через модалку; восстановление.

## 4. Чек-лист приёмки (CHECKLIST E)
- [x] ⛔ Валидация: рамка + текст под полем + сводка сверху + фокус на первом невалидном; тексты как в спеке
- [x] ⛔ Уход с несохранёнными правками: модалка и `beforeunload`; без правок — уход сразу
- [x] Удаление: модалка; баннер «Операция удалена» и «Восстановить» (бэкенд есть)
- [x] Операция из выписки: плашка и бейдж; блокировка — нет (сервер не запрещает, вопрос владельцу)
- [x] Ошибки сервера выводятся тем же способом (functional 422 + e2e)

# Stage 7 — «Новая операция ДДС» в новом дизайне

## 1. Какую задачу решаем
После #2806/#2807 новый дизайн получила только правка операции. Страница
создания (`cash_transaction_new`) осталась на старом `_form.html.twig`:
«Новая транзакция», крошки «Финансы / Транзакции», select направления, серое
поле «Валюта», нет проверки до отправки и защиты от ухода с несохранёнными
правками; inline-скрипт валюты мёртвый (`#form_moneyAccount` при префиксе
`cash_transaction`).

## 2. Что будет результатом
- Карточки «Операция» и «Аналитика» вынесены из `edit.html.twig` в общий
  `transaction/_dds_op_fields.html.twig`; правка и создание рендерят одни и
  те же поля. `_form.html.twig` удалён (больше не используется).
- `new.html.twig`: `<title>`/`<h1>` «Новая операция ДДС», крошки «Деньги /
  Операции ДДС / Новая», две колонки, «Сведения» (источник «Вручную» и
  пояснение про статью), sticky-панель «Отмена / Сохранить». Блока документов
  ОПиУ, меню «Ещё» и бейджа направления нет — до сохранения для них нет данных.
- Скрытый `idempotencyKey` выводится как раньше (ключ повтора с показа формы).
- Направление по умолчанию — первое (Приток), как у прежнего select: без
  изменения поведения сервера.
- Знак и подпись валюты — из выбранного (или первого) счёта, дальше следуют
  за сменой счёта.
- JS `dds_operation.js`: режим создания (`data-dds-op-new`) — «Сохранить»
  активна сразу, статус «Операция ещё не сохранена»; проверка до отправки,
  сводка ошибок, «Выйти без сохранения?» и `beforeunload` — как у правки.
- Тексты флешей контроллера, роуты, имена полей, CSRF — без изменений.

## 3. Что считаем выполненной работой
Functional-тест страницы создания (заголовок, крошки, segmented radio,
`idempotencyKey`, валюта счёта, нет блоков правки; 422 со сводкой; сумма
`1500,50` сохраняется точно); существующие тесты создания
(`CashTransactionNewIdempotencyTest`, `CashTransactionEmptyAmountTest`,
`CashTransactionCounterpartyPickerTest`, `CashTransactionRouteRequirementTest`)
и правки зелёные без изменений; e2e на стенде (заполнить → сохранить; уход с
правками → модалка) и скриншоты 1440/390; гейты; PR → merge → deploy →
проверка после деплоя.

## Разделены два разных нуля

`costPriceUnit` вычисляется как `costPriceTotal / costPriceQuantity` при
`costPriceQuantity > 0`, иначе `0.0`. То есть ноль означал одновременно «себестоимость
единицы равна нулю» и «продаж не было, себестоимость неизвестна». Денежная оценка
остатка строилась на этом нуле.

Введён внутренний `?float $knownCostPriceUnit`: `null`, когда продаж не было.
`stockCapitalRub` считается только когда известны **и** остаток, **и** себестоимость
единицы. Публичное поле `costPriceUnit` сохраняет прежний контракт с `0.0` — менять
его в этом Stage не входило в scope.

Это закрывает нюанс, обнаруженный в Stage 2: у новых строк «Остаток на МП» показывал
ноль вместо неизвестного.

Существующий тест `testStockCapitalIsZeroWhenUnitCostIsZero` смешивал эти два случая:
в его данных `costPriceQuantity = 0`, то есть себестоимость была **неизвестна**, а не
равна нулю. Тест переименован в `testStockCapitalIsUnknownWhenUnitCostIsUnknown`, и
рядом добавлен `testStockCapitalIsZeroWhenUnitCostIsGenuinelyZero` на настоящий ноль
(`costPriceQuantity = 2`, `costPriceTotal = 0`). Без этой пары различие не проверялось бы.

## Чего не потребовалось

**XLSX-экспортёр менять не пришлось.** `UnitExtendedXlsxExporter::buildTypedCell()`
уже возвращает пустую ячейку на `null` — этим путём давно ходят `cacRub`,
`drrPercent`, `profitUnit`. План предполагал правку типа колонки `number`; по факту
нужны были только утверждения в тесте.

**Фронтенд оказался почти готов к `null`.** `formatMoney(null)` уже отдаёт `—`, а
сортировка уже использует `(a[field] as number | null) ?? -Infinity`. Единственным
падением был прямой `row.stockQty.toLocaleString(...)`; для него добавлен `formatQty`
рядом с `formatMoney`, с тем же контрактом прочерка.

источнику, зафиксировать конфликт и продолжить. Конфликт зафиксирован здесь.

## Внешнее ревью

Codex, один круг, `REVIEW_GREEN`. Ограничение то же, что в Stage 1–2: ревьюер без
шелла, дифф и факты переданы через stdin.

Три находки уровня MINOR.

**1. Текст подсказки в своде по тегам — принята.** `stockCapitalUnknownCount`
растёт по двум разным причинам: остаток не загружен **или** себестоимость единицы
неизвестна. Подсказка утверждала только первое. Формулировка исправлена и теперь
называет обе причины.

**2. «Тест не задаёт `stockQty`» — по существу неверна, но взята частично.**
`testStockCapitalIsUnknownWhenUnitCostIsUnknown` вызывает
`stubStockQty(['l-zero' => 7.0])` — это проверено по коду. Однако тест не
*утверждал* этого, и при поломке стаба молча выродился бы в другую ветку
(«остаток неизвестен»), продолжая проходить. Добавлено явное
`assertSame(7.0, $row['stockQty'])`.

**3. Нет теста смешанной группы — принята.** Проверялись только полностью известная
и полностью неизвестная группы, а частичная сумма и пометка `*` — нет. Добавлен
`testTagSummarySumsOnlyKnownStockCapitalInMixedGroup`: у одного листинга капитал
известен (3 × 50 = 150), у второго нет; сумма равна 150, счётчик неизвестных = 1.
Тест **прогнан красным** на коде с безусловным накоплением — упал на счётчике.

## Что уже действует после Stage 1–2

Протухший снапшот (старше 2 дней) не участвует в расчёте остатков. Для компании
с таким снапшотом остаток в отчёте показывается как `0` — промежуточное состояние,
прочерк появится в Stage 3.

Листинг с остатком > 0 даёт строку в юнит-экономике даже без движения за период:
на PROD это **177 новых строк** по 4 компаниям. Остатки отфильтрованы по
маркетплейсу вместе с остальными источниками.

Гейт `app:inventory:stock-freshness-check` существует, но **в cron не поставлен**.

## Следующие шаги

1. Прогнать гейт на проде read-only и убедиться, что он зелёный. Ожидание по

   день, `5d26f9aa` в проверку не входит (нет активного подключения).
2. После подтверждения — поставить гейт в cron.
3. **Решение Владельца по Stage 2** (`owner_gate: yes`): отчёт видимо меняется на
   177 строк. До решения PR остаётся Draft.
4. Stage 3: `null` вместо нуля при неизвестном остатке — бэкенд, JSON API, XLSX и
   React. Внешних потребителей API нет (подтверждено 2026-09-06), поэтому
   `stockQty: number | null` не ломающее изменение за пределами репозитория.

## Открытые вопросы к Владельцу

- Внешних потребителей API нет — подтверждено 2026-09-06, поэтому `stockQty: number | null`
  в Stage 3 не является ломающим изменением за пределами репозитория.
- Поведение сумм в `TagSummaryTable` при неизвестных значениях — решать в Stage 3.
- **Денежная оценка остатка для позиций без продаж.** `stockCapitalRub` считается из
  `costPriceUnit`, который берётся из продаж периода: у новых строк Stage 2 он равен
  нулю, поэтому колонка «Остаток на МП» у них нулевая при верном количестве.
  Обнаружено при реализации Stage 2; относится к Stage 3.

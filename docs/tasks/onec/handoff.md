## Что сделано

- `POST /api/onec/v1/packages`: только `kind=invoices`, тело части байт-в-байт в объектное хранилище (`onec/{connection}/{package_id}/{part}-{sha256}.json.gz`), метаданные в `onec_package`. Ответ `{accepted, package_id, part, status:"stored", duplicate}`. Повтор тех же байтов → `duplicate:true`, другие байты → 409. Части одного подключения сериализуются по строке подключения.
- Кабинет: список подключений, карточка (организации, выгрузки «частей N из parts_total», предупреждения, скачивание части владельцем и через админку), перевыпуск и отключение токена с аудитом.
- Контракт v1 дополнен разделом пакетов; README с владением подключением и `CompanyMember` для этапа 2; ARCHITECTURE.

## После выпуска (чек-лист приёмки)

Тестовое подключение → рукопожатие → часть пакета curl'ом → объект в бакете `ccd24eb8-1c82-4de4-bd69-9706a7b5443b` (timeweb S3, регион `ru-1`) под `onec/{connection_id}/` — подтверждение, что на проде `s3`. Доступа к бакету у агента нет: проверяет Владелец в консоли Timeweb, агент сверяет строку `onec_package` и скачивание из карточки.

# Stage 5 — «Загружать», organization_guids, путь сырья

## Задача

Владелец явно разрешает загрузку счетов по каждой организации 1С. Пакет перечисляет организации, по которым выгрузка полная; сервер принимает его, только если все они разрешены. Сырьё раскладывается по виду и месяцу.

## Результат

- `onec_organization.export_allowed` (по умолчанию `false`), отдельно от `enabled`/`mapped`. Галочка «Загружать» в карточке подключения — только с `finance:write` в компании подключения; с `finance:read` — текст «да/нет». `SetOrganizationExportAction`: блокировка подключения, AuditLog с компанией подключения, повтор того же значения без записи.
- Рукопожатие: `organizations[].export_allowed`.
- Пакет: обязательный `organization_guids` (непустой, без повторов, до 1000), входит в оболочку (части одной выгрузки совпадают), организация неизвестная или без разрешения — 422 `invalid_package` с перечнем GUID. Проверка до записи объекта и повторно под блокировкой. Повтор принятой части — `duplicate: true` даже после снятия галочки.
- Путь новых объектов: `onec/{connection_id}/{kind}/{yyyy}/{mm}/{package_id}/{part}-{sha256}.json.gz`, месяц — `snapshot_at` в UTC (одинаков во всех частях и повторах, гонка повторов пишет в тот же объект). Старые объекты не переносятся.
- Миграция `Version20261127120000`: две колонки, данные не меняет, обратима.
- Контракт: api-contract.md, schema.json, примеры, ContractV1Test; правило разбора «границы пакета — organization_guids».

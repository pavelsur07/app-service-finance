# Stage 3 — snapshot_at, открытые вне периода, правила разбора в контракте

## Задача
Закрепить решения Владельца от 26.11.2026 в контракте v1 и в приёме:
1. Открытые вне периода: `status in (not_paid, partially_paid)`, без пометки удаления, дата не старше N месяцев (N = 12, сервер отдаёт в рукопожатии), плюс счета вне периода с оплатой в периоде. Полнота этого списка — отдельное поле записи `coverage`. Наш открытый счёт вне периода, отсутствующий в последнем полном пакете → «закрыт в 1С, причина неизвестна», не удаляется.
2. Обязательное `snapshot_at` — время начала чтения в 1С, одно на все части, не меняется при повторе. По документу побеждает самый свежий `snapshot_at`. Отмена по отсутствию — только по полному пакету и только для документов с `last_seen_snapshot` старше. Нормализация пакетов подключения — последовательно, под блокировкой подключения.

## Результат
- Приём: `snapshot_at` обязателен (RFC 3339 со смещением; не позже чем через сутки от времени сервера), входит в оболочку, сверяемую между частями; колонка `onec_package.snapshot_at timestamptz` (старые строки — NULL).
- Рукопожатие: `settings.open_outside_period_months = 12` (добавляющее поле ответа).
- Контракт и JSON Schema: `snapshot_at`, `coverage[].outside_period_state`, `settings`, раздел «Правила разбора» (исполняются на этапе нормализации).

Правила разбора (п. 1–2 кроме приёма) этим этапом не исполняются — нормализации ещё нет.

# Автоправила ДДС для всех компаний

Ветка `feat/cash-rule-confirmation`. Цель и критерии приёмки — [утверждённый план](TASK.md).

## Поведение

Проверка моделирует версию формы и предыдущий набор правил над одними операциями в SAFE. Финансист отдельно подтверждает проверенную версию. Это относится к созданию, изменению и повторному включению. Пересчёт прошлых операций доступен отдельным действием. Условия назначения принимают точное совпадение и исключение, включая нормализацию е/ё.

Кандидаты по истории открывают форму с примерами. ИИ-поиск добавляет асинхронную версионированную задачу при действующих правах и бюджете. Результат проверяет Symfony. Список правил показывает назначения, исправления и конфликты по версиям за период, каждый показатель открывает операции.

## Выпуск

| Миграция | Назначение и откат |

| `Version20261117200000` | Таблица фактов конфликта. Откат удаляет только собранную историю конфликтов. |
| `Version20261118001500` | Заявки на поиск фраз, результаты и ключи повтора. Откат удаляет эти заявки и результаты. |
| `Version20261118003000` | Начало наблюдения по компании и микросекунды в `audit_log.created_at`. Автоматический down запрещён, поскольку округление уничтожит сохранённый порядок событий. |

Перед миграцией штатный release снимает полный backup PostgreSQL. Увеличение точности проверено на PostgreSQL 15.20 без перезаписи таблицы и её индекса. На получение блокировки отводится три секунды. Старый код совместим с расширенной схемой. Финансовые суммы и назначения существующих операций при миграции сохраняются.

## Приёмка после деплоя

Проверить SHA и версии миграций, доступность списка, формы и кандидатов в действующей компании. Сверить сохранённые активные правила и отсутствие нового массового задания за исторический период. Функции Cash вступают в действие для всех компаний. Запуск платного ИИ-запроса в приёмку не входит.

При оценке использования за одинаковые периоды сопоставлять долю операций с фактическим назначением статьи правилом и долю назначений этой когорты, которые затем исправил финансист. Конфликты доступны с первого вызова обработчика в компании. В историческом аудите с секундной точностью неоднозначный порядок событий консервативно исключается из исправлений.

В историческую выборку фраз входят операции с доказуемым выбором статьи человеком. Старые платежи без соответствующего аудита не реконструируются. Новые ручные создания записывают событие CREATE в той же транзакции.

## Проверки и ревью

- Symfony, полный набор в контейнере с отдельной PostgreSQL и чистым var — 9 584 теста, 54 146 проверок. Финальные изменения по одновременной отправке и лимиту примеров дополнительно проверены адресно — 17 тестов, 196 проверок. Unit gate — 4 958 тестов, 27 366 проверок.
- PHPStan level 8, PHP CS Fixer, strict_types, twigcs и lint:twig (408 шаблонов) прошли. ESLint, Vite и Vitest прошли, 152 теста. Ruff, mypy и Docker-гейты ai-service прошли, 600 основных тестов и 32 eval. Две проверки пропущены по условиям окружения, в том числе вызов живого провайдера.
- Репетиции release, deploy workflow, frontend release и auth routing прошли, включая backup/checksum на локальной PostgreSQL.
- Для полного PHP-набора потребовалось подготовить Composer-зависимости от имени владельца локального vendor и выделить отдельное файловое хранилище. В первой попытке запись в vendor/storage и изменение тестового кеша во время работы привели к ошибкам. Итоговый запуск на изолированной БД и файловом томе завершился с кодом 0.
- Внутреннее ревью в свежей сессии — 0 BLOCKER, 4 IMPORTANT исправлены, REVIEW_GREEN. Внешнее — 2 раунда (этапы и handoff), 0 BLOCKER, 7 IMPORTANT, из которых 6 подтверждены, исправлены и проверены; 1 отклонён по инварианту разбивки. Результат внешнего ревью — fixed without re-run. Claude CLI не прошёл preflight авторизации; оба раунда выполнили отдельные read-only сессии Codex. Песочница ограничила чтение исходников ревьюерами переданным диффом.

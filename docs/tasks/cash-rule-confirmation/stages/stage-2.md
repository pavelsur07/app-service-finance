# Этап 2. Кандидаты и поиск фраз

База 42491e98c, риск HIGH-LOCAL. Работа 2.1–2.3.

- Обычный отчёт по истории показывает пять платежей для каждого кандидата. Черновик получает категорию, направление и фактическое условие из повторной выборки компании.
- Поиск фразы запускается для одного контрагента. Запрос проверяет роль, CSRF, действующий доступ компании и её бюджет. Шлюз получает обезличенные тексты и признак целевой категории. Symfony проверяет ответ на ручных назначениях и показывает обе группы совпадений.
- Внешнее ревью нашло два IMPORTANT. Подборка примеров ограничена до JSON-агрегации. Отказ транспорта можно повторить; окончательный отказ провайдера создаёт новую попытку только по действию пользователя. Обратный словарь реконструируется в памяти. Регрессии проверены функционально, 3 теста / 117 проверок.
- Набор из 22 обезличенных случаев покрывает повторяющиеся фразы, переменные номера, неоднозначность и недостаточную историю. Вызовы платных провайдеров в проверках не выполнялись.
- Внутреннее ревью выявило два IMPORTANT. Глубина отправляемой истории теперь ограничена настройкой компании; локальная проверка может использовать полный период отчёта. Ручной выбор при создании и явное подтверждение в разбивке учитываются по связанным событиям аудита. Подтверждённая выборка проверена через реальные действия создания и сохранения разбивки.
- На handoff внешний ревьюер выявил гонку двойной отправки и чтение лишней истории для выгрузки. Отправитель получает право отправки через INSERT RETURNING или захват повторной попытки. Проверка реентрантного запроса подтверждает одного отправителя. SQL возвращает до 30 целевых и до 30 остальных примеров. На 63 исходных операциях локальная выборка сохранила все строки.

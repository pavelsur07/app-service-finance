# Этап 1. Проверка и подтверждение редакции

База 42491e98c, риск HIGH-LOCAL. Работа 1.1–1.3.

- Два набора правил проходят один matcher/planner в режиме SAFE. При редактировании сравнение охватывает старые и новые совпадения. Счётчики отражают изменение победителя, значения и конфликтов отдельно для каждого поля. На каждый исход сохраняется до пяти примеров.
- Проверка использует отделённый черновик и версии из действительного снимка. Подпись и квитанция аудита привязаны к субъекту, компании и полному содержимому. Подтверждение сериализовано с другими писателями правил средствами PostgreSQL.
- Текстовые условия назначения поддерживают исключения и точное совпадение. В качестве отрицательных примеров выбираются операции, прошедшие остальные условия.
- Baseline 6 тестов / 43 проверки; регрессия выключенного правила воспроизведена красным до правки. Сравнение, закрытый период, ручная разбивка и сверка с обработчиком — 22 теста / 106 проверок. Проверки формы, подписи, повтора и разных сотрудников — 27 / 151. Отдельный PostgreSQL тест двух соединений — 1 / 3.
- На внутреннем ревью выявлено накопление прочитанных операций в Doctrine. Выборка переведена на страницы по дате и UUID с отдельным EntityManager. Регрессия воспроизведена на 205 операциях; после исправления объекты формы остаются управляемыми, прочитанные операции в их identity map не появляются.
- На интеграционном внешнем ревью замечаний по подтверждению не было.

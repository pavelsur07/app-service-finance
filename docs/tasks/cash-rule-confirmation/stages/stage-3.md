# Этап 3. Качество назначений

База 42491e98c, риск HIGH-LOCAL. Работа 3.1–3.2.

- Запись первого конфликта статьи делается под блокировкой операции с уникальностью по компании, правилу, версии и операции. Повторная обработка проверена на реальной БД. Переход от счётчика к операциям использует тот же набор фактов.
- Считаются назначения в выбранном периоде и последующие ручные изменения статьи в этой когорте. Изменение суммы и применение новой версии правила проверены отдельно.
- Внешнее ревью нашло два IMPORTANT. Дата первого вызова учёта теперь записывается отдельно для каждой компании. Неоднозначные старые события внутри секунды исключаются из исторических исправлений; новые моменты аудита записываются с микросекундами. Оба регрессионных теста сначала упали и прошли после правки.
- 27 тестов / 148 проверок с тестом соответствия схемы миграциям. На PostgreSQL 15.20 проверено сохранение relfilenode таблицы и индекса при увеличении точности времени. Ограничение ожидания блокировки — 3 секунды.
- Внутреннее ревью нашло назначение системного заполнителя среди успешных назначений. По ID и обоим системным кодам в компании исключены «Не распределено» и его прежний вариант. Отдельно проверена атрибуция удалённой обычной статье. Регрессия на PostgreSQL прошла после воспроизведения на старом запросе.
- Замечание внешнего ревью о переходе от одной строки статьи A к двум строкам той же статьи A отклонено. Уникальность категории внутри одной операции проверяет агрегат CashTransaction::replaceSplits; в БД действует uniq_cts_tx_category. Это покрывает testDuplicateCategoryIsRejected.

## Что делаем и почему так

«Свернуть по тегу» = агрегат юнит-экономики по каждому тегу: выручка / затраты / прибыль / маржа
в разрезе тегов, чтобы ответить «какая коллекция прибыльнее».

Два решения из плана задачи:

1. **Где считать — на бэкенде.** Производные поля (profit, margin, ROI, ДРР, CAC) — это отношения,
   их нельзя суммировать; надо сложить абсолютные величины и пересчитать отношение на группу.
   Формулы уже живут в `UnitExtendedQuery` (totals). Считать на фронте = вторая копия денежной
   математики, которая разъедется. Поэтому агрегат строит бэкенд, переиспользуя `averagePerNetSoldQty`
   и те же формулы, что и totals. Фронт только рисует.

2. **Двойной счёт мультитегов — честная подпись, не взаимоисключающие группы.** Листинг с двумя
   тегами попадает в оба бакета → сумма по тегам может превышать итог. Резолюция: показываем это
   как есть + строка «Без тегов» + заметка в UI «листинг с несколькими тегами учтён в каждом теге».
   Взаимоисключающие группы тегов — отдельная фича, **не в scope** (ponytail: не строить, пока не
   попросят график по группам).

## Реализация

- **`UnitExtendedQuery::execute`** — новый флаг `bool $withTagSummary = false`. Когда включён:
  в цикле по ВСЕМ листингам (до search-фильтра, как totals) копим компактные записи с абсолютами
  и тегами; после цикла `buildTagSummary()` раскладывает их по бакетам (tagId + «Без тегов») и
  пересчитывает отношения теми же хелперами. Результат — ключ `tagSummary` (пустой, если не запрошен).
  adSpend в группе = сумма построчной атрибутированной рекламы (полный период по тегу неразделим —
  та же семантика, что фильтрованные totals в Stage 2).
- **`UnitExtendedController`** — параметр `withTagSummary` (`1`/`true`).
- **Фронтенд** — тумблер «Свод по тегам»; при включении хук шлёт `withTagSummary=1`, рисуется
  компактная карточка `TagSummaryTable` (Тег · Листингов · Выручка · Кол-во · Себест. · Реклама ·
  Итого затрат · Прибыль · Маржа%) + строка «Без тегов» + заметка про двойной счёт. Основная
  таблица остаётся.

## Ponytail-skip

- Свод в XLSX-экспорт не добавляю — в выгрузке есть колонка «Теги» (Stage 2), сводная по тегу
  делается в Excel одним pivot'ом.
- Взаимоисключающие группы тегов, версионирование, график по группам — вне scope.

## Тесты

- `buildTagSummary` (unit): листинг с 2 тегами учтён в обоих бакетах; «Без тегов» отдельно;
  profit/margin пересчитаны из абсолютов, а не суммированы; сортировка по выручке.
- API: `withTagSummary=1` возвращает `tagSummary`; без флага — нет.

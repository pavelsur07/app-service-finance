# Stage 2: общая ротация ключей шифрования

Risk: HIGH-LOCAL (секреты всех подключений: маркетплейсы, MoySklad, банки).
stage_base_commit: `fc3143e20` (ветка `feat/bank-sync-stage2` от `master`, merge #2798).
Поставка: A (Stage 1–3, `plan.md` §5).

## 1. Какую задачу решаем

Ключ шифрования (`APP_ENCRYPTION_*`) общий для трёх модулей, а сменить его можно
только у маркетплейсов: `app:marketplace:rotate-connection-keys` перешифровывает
`marketplace_connections`, про `moysklad_connections` и `bank_sync_connection` не
знает никто. Если выполнить инструкцию `docs/maintenance/encryption-key-rotation.md`
сейчас, на шаге «уборка» (удалить старый ключ) токены MoySklad, а потом и банков,
станут нечитаемыми навсегда.

Нужно: одна команда показывает, на каких версиях ключа лежат секреты **всех**
модулей и есть ли для каждой версии ключ, и переводит всё на активную версию, ничего
не потеряв.

Прод до начала работ (26.10, read-only, только счётчики):

| Модуль | Поле | Версия | Записей |
|---|---|---|---|
| Marketplace | `api_key` | `v1` | 11 |
| MoySklad | `access_token` | `v1` | 2 |
| MoySklad | `refresh_token` | — (пусто) | 2 строки без значения |
| BankSync | `credentials` | — | 0 подключений |

Незашифрованных значений MoySklad нет. Ротация на проде в этом этапе **не
запускается** — это действие Владельца по инструкции, когда он решит сменить ключ.

## 2. Что будет результатом

```
site/src/Shared/Security/
  Contract/SecretRotatorInterface.php     тег app.security.secret_rotator:
                                          module(), countByKeyVersion(), rotateBatch()
  Contract/SecretRotationServiceInterface  + проверка: новый шифротекст расшифрован и совпал
  ValueObject/KeyVersionCount.php         модуль, поле, версия|null, число записей
  Command/RotateKeysCommand.php           app:security:rotate-keys [--execute] [--module=…]
site/src/Marketplace/Infrastructure/Security/MarketplaceSecretRotator.php   api_key
site/src/MoySklad/Infrastructure/Security/MoySkladSecretRotator.php         access, refresh
site/src/BankSync/Infrastructure/Security/BankSyncSecretRotator.php        credentials
site/src/Marketplace/Command/RotateConnectionKeysCommand.php → обёртка: rotate-keys --module=marketplace
docs/maintenance/encryption-key-rotation.md  все модули, общая команда, условие удаления ключа
```

Устройство:
- **Ротатор модуля** живёт в своём модуле (Shared о модулях не знает, модули
  реализуют интерфейс Shared — граница не нарушается). Он только читает и пишет
  через DBAL, не коммитит.
- **Порция** — до 100 записей на старой версии. Каждая запись: расшифровать старым
  ключом → зашифровать активным → расшифровать снова и сравнить (иначе запись не
  трогается и команда падает) → `UPDATE … WHERE id = :id AND <поле> = :старый
  шифротекст`. Условие на старый шифротекст — защита от потерянного обновления:
  если пользователь в эту секунду сохранил новый ключ подключения, ротация его не
  затрёт (запись уже на активной версии и пропускается).
- **Транзакция** — у команды: одна порция = один `wrapInTransaction()`. Ошибка
  расшифровки откатывает всю порцию; уже завершённые порции остаются.
- **Dry-run по умолчанию**: таблица модуль / поле / версия / записей / ключ есть, итог
  «требуют перешифровки N». Колонка «ключ есть» — проверка `getKeyByVersion()` без
  вывода материала: перед удалением старого ключа видно, что на нём ничего не лежит.
- **`--execute`**: сначала проверка, что ключ есть для каждой встреченной версии; нет
  хотя бы одного — код 1 до первой записи. Затем порции по модулям; порция без
  единого обновления при оставшихся записях — стоп с кодом 1 (без бесконечного цикла).
  В конце — повторный подсчёт; остаток ≠ 0 — код 1.
- В вывод и лог попадают только модуль, поле, версия, счётчики. Итог `--execute` —
  `logger->info` (аудит смены ключа).
- `updated_at` подключений ротация не меняет: это не изменение данных пользователя.
- Незашифрованные значения (legacy plaintext маркетплейсов) — не трогаются, видны в
  dry-run строкой «без шифра»; их шифрует `app:marketplace:encrypt-connection-keys`.

### Решения, уточнённые при детализации

- `plan.md` предлагал `flush`/`clear` в команде (ORM). Взят DBAL с условием на старый
  шифротекст: ORM-ротация перезаписала бы ключ, сохранённый пользователем во время
  ротации (у `MarketplaceConnection` нет `#[ORM\Version]`), а гидрация не нужна.
  Порции и коммит в команде — как в плане.
- Старая команда маркетплейсов остаётся обёрткой и в этом этапе **не удаляется**:
  её имя в инструкции заменено, но удаление — отдельной строкой follow-up после
  первой смены ключа по новой инструкции (чтобы у Владельца был проверенный путь).
- `SecretRotationService::rotate()` получает проверку расшифровкой — до этого
  ротация маркетплейсов писала шифротекст без проверки.
- `ConnectionApiKeyCodec::rotateIfNeeded()` больше не нужен команде; удаляется, если
  других вызовов нет.

## 3. Что считаем выполненной работой

- `app:security:rotate-keys` без флагов показывает распределение по версиям для
  Marketplace, MoySklad (access и refresh), BankSync и наличие ключа каждой версии;
  ничего не пишет.
- `--execute` переводит все зашифрованные секреты всех модулей на активную версию;
  после него каждый секрет расшифровывается активным стеком в исходное значение;
  повторный запуск — «делать нечего».
- Отсутствующий ключ версии → ненулевой код, ни одной изменённой записи.
- `app:marketplace:rotate-connection-keys` даёт прежний результат через общую
  команду.
- Инструкция по смене ключа описывает все модули и общую команду; ключ удаляется
  только когда dry-run показывает 0 записей на нём.
- `ARCHITECTURE.md`: раздел Shared\Security — контракт ротатора, тег, команда;
  Changelog.
- Гейты зелёные, ревью внутреннее и внешнее пройдены, handoff.

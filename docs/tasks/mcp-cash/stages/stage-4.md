# Stage 4. Черновик и подтверждение Cash

База `bc9b2f7e6`. Риск HIGH-LOCAL.

- Структурированный черновик сохраняет внешний ID и подключение, связывается с проведённой операцией и виден только в своём канале. Подтверждение повторно проверяет права, счёт и период. Запись факта и существующий пересчёт остатков выполняются в одной транзакции Cash.
- Тесты сначала упали на отсутствующем API, затем прошли. После развёртывания 336 миграций на чистой PostgreSQL прошли 118 тестов, 727 утверждений, в том числе регрессия Telegram, схема и два сценария конкуренции на отдельных соединениях.
- Целевой PHPStan прошёл. CS Fixer выявил прежние выравнивания PHPDoc в существующих файлах. Отчёт о внешнем ревью готовится к handoff.
- Самопроверка — 0 BLOCKER, 0 IMPORTANT. Расхождение частичного индекса с introspection Doctrine устранено полным уникальным индексом с обычной семантикой NULL. Миграция добавляет nullable-колонки без трансформации ранее сохранённых черновиков. При появлении MCP-данных удаление колонок привело бы к потере идентичности, поэтому down запрещён.

Внешнее ревью этого этапа — 1 раунд, 0 BLOCKER и 2 IMPORTANT. Исправлены явное подтверждение факта оплаты и пробелы проверки компании и уникального индекса. Целевой прогон исправлений прошёл. Повтор по §7.2 не требуется. Учтён стабильный код отказа при несовпадении автора. Построение уникального индекса удерживает блокировку записи таблицы черновиков до завершения миграции. Время выполнения проверяется при репетиции схемы и фиксируется в релизе.

# MCP для ДДС

Ветка `feat/mcp-cash`. База PR — `master`. [PR #3088](https://github.com/pavelsur07/app-service-finance/pull/3088)

## Результаты этапов

| Этап | Что проверено |
| --- | --- |
| Внешний доступ | Фактический владелец выдаёт и отзывает OAuth-подключение к одной компании. При `NONE` доступ закрыт. При ограничении записи scopes записи снимаются. Повтор использованного refresh отзывает подключение. |
| Справочники | Активные счета и статьи своей компании, включая BTC-счета, поиск, вложенность, права и постраничную выдачу. |
| Фактический ДДС | Операции периода с полными разбивками, денежными суммами в строках и устойчивой сортировкой. Удалённые операции и черновики отсутствуют в выдаче. |
| Черновики | Платёж сохраняется один раз для компании, подключения и внешнего ID. Повтор возвращает прежний черновик, изменённые данные дают конфликт. У черновика есть источник `mcp`. |
| Подтверждение | Оплата подтверждается отдельным действием в кабинете. Два параллельных подтверждения создают одну операцию. Отмена сохраняет остаток. Telegram покрыт регрессией. |

Реализация в `site/src/Mcp/`, `site/src/Cash/` и Twig. Утверждённые [схемы v1](contract-v1.md) перенесены в `site/contracts/mcp/v1/` без изменения содержимого. Настройка стенда и клиентов описана в [oauth.md](oauth.md).

## Миграции и запуск

- `Version20261121103000` добавляет поля происхождения и уникальный индекс черновиков. Исторические данные сохраняются. На время создания индекса PostgreSQL блокирует запись в таблицу черновиков. Откат удалил бы происхождение и нарушил бы защиту повторов, поэтому отключён.
- `Version20261121110000` создаёт таблицы OAuth. Обратная миграция удаляет выданные подключения и их токены.
- Релиз выполняется через штатный `release` с резервной копией перед миграциями. После релиза сверяются версии схемы, SHA и health. [Процедура релиза](../../workflow/release.md)
- Для включения `/mcp` в production отдельно нужны настройки `MCP_OAUTH_*`, ключи и зарегистрированные клиенты. Пока настройки отсутствуют, `/mcp` отвечает 404. Очистка накопленных записей OAuth требует отдельного решения по хранению данных для защиты от повтора токенов.

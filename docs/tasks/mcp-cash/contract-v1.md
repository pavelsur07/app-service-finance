# Внешний MCP для справочников и ДДС, контракт v1

Внешний MCP-клиент подключается к Symfony по HTTPS (Streamable HTTP, путь `/mcp`). Компания разрешает конкретному подключению читать справочники, читать фактические операции ДДС и создавать структурированные черновики. Проведение выполняет сотрудник в VashFinDir. Эта поставка фиксирует контракт и план реализации.

Документ расширяет пользовательский каталог из [базового проекта MCP](../mcp-access/TASK.md). Для трёх инструментов используются тот же endpoint, user audience, OAuth grant и согласие. Административный MCP остаётся отдельным. Существующий grant на чтение сохраняет свои права. Создание черновика требует отдельного согласия на новый scope и действующего права записи. Bearer API-ключи не принимаются этим endpoint. Вариант справочника счетов делит запрос данных с запланированным `list_accounts`.

## Инструменты

Каждый файл — готовое описание инструмента для `tools/list` с независимыми `inputSchema` и `outputSchema` (JSON Schema 2020-12). Валидатор обязан проверять форматы UUID и календарных дат. Успех `tools/call` возвращает объект по выходной схеме в `structuredContent` и его JSON в текстовом блоке `content`. Версия v1 относится к прикладному контракту. Версию MCP согласуют с клиентом отдельно. [Спецификация инструментов MCP](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

| Инструмент | OAuth scope | Результат |
|---|---|---|
| [list_reference_items](contracts/v1/list_reference_items.json) | `accounts.read` для счетов, `cash_categories.read` для статей | Один тип справочника. Активные денежные счета с валютой или дерево статей плоским списком с `parentId`. Поиск по подстроке имени без учёта регистра. Родитель может оказаться на другой странице. |
| [list_cash_transactions](contracts/v1/list_cash_transactions.json) | `cash_transactions.read` | Факты за включительный диапазон дат операции, максимум 366 календарных дней. Исключить мягко удалённые строки. Каждая сторона перевода видна как операция своего счёта с `isTransfer=true`. |
| [create_cash_draft](contracts/v1/create_cash_draft.json) | `cash_drafts.create` | Одна строка платежа, один черновик. При первом создании статус `awaiting_confirmation`. При повторе — тот же ID и текущий статус, включая конечный. |

**Чтение.** Страница по умолчанию содержит до 50 записей, предел 100. Справочник упорядочен по ID, операции — по дате и ID по возрастанию. `nextCursor=null` завершает список. Непрозрачный защищённый от подмены курсор привязан к подключению, компании, инструменту и фильтрам. Клиент повторяет фильтры. Изменение данных между вызовами возможно. Фильтр по статье возвращает всю операцию один раз со всеми строками распределения и полной суммой. Для исторической записи с единственной статьёй в заголовке вернуть одну строку на полную сумму, если разбивки нет. Для операции без статьи вернуть пустой список. Дата соответствует полю Cash `occurredAt`. При чтении передавать сохранённую сумму с её знаком и двумя десятичными знаками. Нулевое или отрицательное историческое значение само по себе не блокирует выдачу страницы.

**Запись.** Сумма передаётся положительной десятичной строкой с двумя цифрами после точки в пределах `NUMERIC(18,2)`. Направление движения задаёт `direction`. Дата — календарная дата платежа. Если валюта опущена, сервер берёт её со счёта. Для новой записи допускаются валюты Cash RUB, USD, EUR и KZT, в том числе при выборе валюты по счёту. Переданную валюту сверяет с активным счётом компании. Если передана статья, она должна быть доступной листовой статьёй для данного направления. Статья необязательна при вводе. Правила допустимости для проведения определяет Cash. Произвольный текст описания хранится как данные и экранируется при показе.

**Доступ.** Одно подключение принадлежит одной компании. OAuth-токен предназначен данному MCP-серверу. При каждом вызове сервер проверяет токен, активность подключения и пересечение scope с правами делегировавшего пользователя в компании. В v1 черновик закрепляется за этим сотрудником. Подтвердить или отменить его может тот же пользователь при действующем праве записи. Этим сохраняется действующее ограничение владельца черновика в Cash. Доверенный контекст задаёт компанию, пользователя, подключение и источник. Входные схемы закрыты для дополнительных полей. Для инструмента справочников scope проверяется по переданному `kind` при каждом вызове. Все запросы, разрешение ссылок, поиск дубля и работа с курсорами ограничены компанией. [Авторизация MCP](https://modelcontextprotocol.io/specification/latest/basic/authorization)

**Происхождение и повторы.** Сервер сохраняет в одной транзакции черновик, источник `mcp`, ID подключения, компании и пользователя, внешний ID, время приёма и каноническое представление исходных параметров для сравнения. БД гарантирует уникальность тройки (компания, подключение, внешний ID). Ключ регистрозависим. При сравнении учитываются все поля платежа, порядок JSON-ключей незначим, валюта по умолчанию эквивалентна явно указанной валюте счёта. Пропущенное и пустое описание канонизируются в пустую строку. На повторе сравнение ведётся с исходной записью, включая сохранённую валюту, до проверки изменяемых условий нового платежа и после проверки доступа. Конфликт содержимого оставляет исходный черновик без изменений.

**Подтверждение.** Открытие, просмотр и подтверждение доступны из раздела ДДС VashFinDir. MCP-ввод оставляет факт оплаты неподтверждённым. Владелец явно отмечает факт оплаты перед проведением. При подтверждении проверить под блокировкой владельца, актуальные права, версию черновика, период, счёт, валюту и ссылки. Атомарно создать одну операцию, зафиксировать автора и время подтверждения, связать с черновиком. В операции сохранить `importSource=mcp`. Внутренний ключ импорта образуется из ID черновика и строки по образцу Cash. Исходный внешний ID доступен по связи с черновиком. Так одинаковые внешние ID двух подключений совместимы с существующим уникальным индексом операций. До подтверждения отсутствуют запись в реестре фактов, события проведения и изменения балансов.

## Ошибки и повтор запроса

| Условие | Что видит клиент |
|---|---|
| Невалидный/просроченный токен, нехватка scope | HTTP 401 или 403 соответственно, стандартный OAuth challenge. При каждом вызове действуют также текущие права Cash. |
| Неизвестный инструмент или повреждённый конверт | Стандартная ошибка JSON-RPC. |
| Ошибка инструмента | `isError=true`, один блок `content` типа `text`, содержащий сериализованный JSON с двумя строками `code` и `message`. Схемы успешных данных применяются к успешным вызовам. |
| Нарушение входной схемы, диапазона дат, курсора или валюты | Код `invalid_input`. Для закрытого периода при создании — `period_closed`. |
| Чужая или отсутствующая ссылка | Одинаковый код `reference_unavailable` и одинаковое сообщение. |
| Занятый ключ с другим содержимым | `idempotency_conflict`. После сетевого сбоя клиент повторяет исходный вызов с прежним ключом. |
| Превышение лимита запросов | HTTP 429 и `Retry-After`. Лимит применяется к подключению. |

## Пример создания

Аргументы инструмента для расхода по рублёвому счёту, затем успешный объект из `structuredContent`:

```json
{"externalId":"crm:payment-42","moneyAccountId":"00000000-0000-4000-8000-000000000001","date":"2026-11-20","direction":"OUTFLOW","amount":"1250.00","currency":"RUB"}
```

```json
{"draftId":"00000000-0000-4000-8000-000000000099","source":"mcp","status":"awaiting_confirmation"}
```

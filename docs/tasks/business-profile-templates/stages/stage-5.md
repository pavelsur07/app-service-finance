# Stage 5. Нет второго дерева и параллельных структур

Риск: HIGH-LOCAL (импорт ОПиУ — общий для всех режимов; поведение дозаполнения денежных счетов).
`stage_base_commit`: `7dda0f7f4`. Ветка `feat/no-parallel-structures`. Поручение Владельца 21.10.2026:
правила 1–4 и 6 из предложения «без второго дерева». Прежний Stage 5 (смена профиля, подсказка о
маркетплейсе) — теперь Stage 6, после правила происхождения (5) и ночной проверки (7).

## 1. Какую задачу решаем

Справочник компании может получить вторую, параллельную структуру:

- **ОПиУ.** Импорт сопоставляет узлы по коду (узлы без кода — по родителю и имени), а
  несовпавшие корни просто создаёт. Пять компаний на проде со своим деревом без кодов получили бы от
  «Базового шаблона» все 72 статьи рядом со своими (dry-run 21.10). Ещё две («Ваш ФинДир»,
  «Вумджой») — своё «Налог на прибыль» рядом с шаблонным.
- **Денежные счета.** Дозаполнение создаёт «Основной счет»/«Основную» кассу, если нет счёта этого
  типа: COMPSHOP с 8 банковскими счетами получил бы пустую кассу.

Проверено на проде (21.10, только чтение): корневых статей, опознанных шаблоном по коду, —
21/27, 18/22, 21/21 у компаний на шаблоне; 6/13, 4/10 и 0 у остальных семи (пересчитано
по окончательному определению — корень компании засчитывается, только если совпал с корнем шаблона).

ДДС и Баланс отдельных правок не требуют: 4 системные статьи ДДС создаются по уникальному
`system_code`; структура Баланса — только в пустой справочник, одна книга на компанию, счета шаблона —
только при нуле счетов (проверено в коде). Импорта или шаблона ДДС нет.

## 2. Что будет результатом

**Правило 2 — без второго скелета (все режимы импорта ОПиУ: шаблон, другая компания, файл).**
Если у компании уже есть статьи и импорт создаёт хотя бы один корневой узел, импорт разрешён,
только когда источник опознал не меньше половины корневых статей компании (и хотя бы одну).
Опознанный корень — статья компании, совпавшая с корневым узлом источника.
Иначе — отказ (`DomainException`, тот же путь, что у прежних отказов: flash на экране, exit 1 в
команде) с числами: «Шаблон опознал 0 из 8 корневых статей компании…» и подсказкой про
сопоставление. Создание вложенных статей под опознанными группами не ограничивается.

**Правило 3 — похожее название не дублируется (режим шаблона).** Узел, который шаблон создал бы,
не создаётся вместе со своим поддеревом, если у компании есть неопознанная статья с тем же или
похожим названием: совпадают после нормализации (регистр, «ё», знаки препинания, пробелы) или
одно совпадает с началом другого до разделителя (`/ ( , : ; |` или тире с пробелами), не короче 6 символов
(«Налог на прибыль» ≈ «Налог на прибыль / УСН»; «Расходы» и «Расходы ниже EBITDA» — разные).
Одна статья компании гасит не больше одного узла шаблона. Пропущенные узлы попадают в результат (`similar`: статья шаблона,
код, путь, похожая статья компании; `skippedWithSimilar` — их потомки) — на экране и в выводе команды.

**Правило 4 — сопоставление вместо второго дерева.** Экран «Сопоставить с шаблоном»
(`/pl-categories/import/template-mapping`): список статей шаблона профиля компании, которых у неё нет по
коду, и для каждой — выбор своей статьи без кода того же типа и уровня (корень — с корнем; группе,
которая суммирует потомков, — только суммирующая статья; подсказка — похожая по названию).
Сохранение — `BindPLCategoriesToTemplateAction(companyId, [code => categoryId])`: присваивает
коды одной транзакцией; отказ, если статья чужая или уже с кодом, тип не совпадает, кода нет в
шаблоне или он занят, одна статья выбрана дважды. После сопоставления шаблон дополняет дерево
штатно. Ссылка на экран — из отказа правила 2 и из списка похожих (правило 3); экран — `FINANCE_WRITE`
на запись.

**Правило 1 — денежные счета только в пустой справочник.** `EnsureDefaultMoneyAccountsAction`
создаёт «Основной счет» и «Основную» кассу, только если у компании нет ни одного денежного счёта
(любого типа, в том числе неактивного). Новая компания — без изменений.

**Правило 6 — отчёт пробного прогона.** `app:finance:pl-tree:apply-default` печатает строки
`similar …` и итог `plan (dry run): create N, keep existing M, similar S; company roots recognized
K of R`; отказ правила 2 — exit 1 с тем же текстом.

`ARCHITECTURE.md` (Finance — правила импорта, экран сопоставления, Action; Cash — правило
дозаполнения; Changelog), `plan.md`, `checkpoint.md`.

## 3. Что считаем выполненной работой

Ни один режим импорта ОПиУ не создаёт второй скелет рядом с деревом компании; шаблон не дублирует
статьи с похожими названиями и показывает их; компанию со своим деревом можно привести к шаблону
сопоставлением без потери её статей и данных; дозаполнение денежных счетов не трогает компании со
счетами; dry-run показывает всё это числами. Компании на шаблоне (78f0cc9f, 3f4d87cc, b57d7682)
дополняются как раньше. Тесты и гейты зелёные.

## 4. Чек-лист приёмки

- [ ] Шаблон в дерево без кодов (8 корней, 0 опознано) — отказ с числами, ничего не записано; превью — тот же отказ, кнопки применения нет.
- [ ] Шаблон в дерево, где опознано ≥ половины корней, — создаёт недостающие корни и статьи (как у 3f4d87cc).
- [ ] Импорт из другой компании и из файла в чужое дерево без совпадений — тот же отказ; в пустую компанию и в совпадающее дерево — как раньше (прежние тесты зелёные).
- [ ] Похожее название («Налог на прибыль / УСН») — шаблонная статья не создана, есть в `similar`; точное совпадение без кода — тоже; короткие (< 6) и несвязанные названия — не похожи.
- [ ] Статья компании, уже опознанная по коду другим узлом шаблона, в похожие не попадает.
- [ ] Сопоставление: happy-path присваивает коды, после него шаблон создаёт только недостающее; отказы — чужая статья, статья с кодом, другой тип, код не из шаблона, код занят, дубль статьи; ничего не записано при отказе.
- [ ] Экран сопоставления: GET показывает статьи и выбор; POST без CSRF — отказ; чужая компания — отказ (IDOR); без `FINANCE_WRITE` — 403.
- [ ] Денежные счета: компания только с банковским счётом — дозаполнение ничего не создаёт; пустая — счёт и касса.
- [ ] Вывод `apply-default`: строки `similar`, итог с `similar` и `roots recognized`.
- [ ] Полный phpunit, PHPStan (весь проект), CS и strict_types — зелёные.
- [ ] Ревью в отдельной сессии и Codex — без BLOCKER/IMPORTANT.
- [ ] `ARCHITECTURE.md`, `plan.md`, `checkpoint.md`, итог в этом файле.

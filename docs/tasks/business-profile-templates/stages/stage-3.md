# Stage 3. Универсальные шаблоны ОПиУ и Баланса

Риск: HIGH-LOCAL (финансовая семантика: структура и формулы итогов).
`stage_base_commit`: `f86e98d28`. Ветка `feat/universal-templates`.

## 1. Какую задачу решаем

Компания с профилем `UNIVERSAL` («Базовый») получает сейчас маркетплейсные справочники:
СПП, комиссию МП, ФФ, CM1–CM4, склады маркетплейсов. Нужны свои шаблоны для бизнеса без
маркетплейсов, подключённые к реестру вместо маркетплейсных.

Содержание — по наброску §5 плана. Открытые вопросы §5 закрыты простейшими вариантами,
их нужно подтвердить на handoff (поправить до мержа — правка JSON/YAML):

| Вопрос §5 | Решение этапа |
|---|---|
| Разбивка выручки по направлениям | Нет: одна статья «Выручка от продаж» и «Возвраты и скидки (−)»; направления — через проекты |
| Себестоимость одной статьёй | Подытог «Себестоимость товаров и услуг» (продаж / возвратов), плюс доставка и эквайринг — как в маркетплейсном |
| Блок «Производственные расходы» | Есть, внутри операционных: аренда, содержание, ЗП производственного персонала (без «Честного знака») |

## 2. Проверка маркетплейсного шаблона (п. 1 плана Stage 3) — выполнена до работ

`flow = NONE` у `PRODUCT_INFRA_TOTAL`, `BELOW_EBITDA_INCOME_TOTAL`, `PROFIT_DISTR_TOTAL` и
`BELOW_EBITDA_OTHER_INCOME` на числа не влияет:

- `PlReportCalculator` поток не читает: подытог без формулы — сумма потомков × `weightInParent`,
  знак даёт сам факт (расход отрицательный).
- Поток читают только списки «Документы ОПиУ» и «Операции» (`DocumentRepository`,
  `DocumentOperationRepository`): `NONE` → доход/расход по знаку суммы. Операции бывают только на
  конечных статьях, поэтому `NONE` у подытогов не используется; у «Прочих доходов» — классификация
  по знаку, допустимо для статьи, которая бывает и плюсом, и минусом.

Дефекта нет, маркетплейсный шаблон не меняется. Коды, общие с ним, универсальный шаблон берёт с
теми же типом, потоком, форматом и родителем (словарь кодов, `TemplateRegistryTest`).

## 3. Что будет результатом

- `config/finance/pl_templates/universal.json` (`profile: UNIVERSAL`, `templateVersion: 1`):

  - **Выручка** `REV_TOTAL` (KPI = `REV_SALES + REV_SALES_RETURNS`)
    - Выручка от продаж `REV_SALES`* · Возвраты и скидки покупателям (−) `REV_SALES_RETURNS`*
  - **Себестоимость** `COGS_TOTAL`
    - Себестоимость товаров и услуг `COGS_PRODUCT` (продаж `COGS_PRODUCT_REV`, возвратов `COGS_PRODUCT_RET`)
    - Доставка до клиента `COGS_DELIVERY` · Эквайринг `COGS_ACQUIRING`
  - **Валовая прибыль** `GROSS_PROFIT`* = `REV_TOTAL + COGS_TOTAL`; **Валовая маржа, %** `GROSS_MARGIN`* = `GROSS_PROFIT / REV_TOTAL`
  - **Операционные расходы** `OVERHEAD_TOTAL`
    - Производственные `OVERHEAD_PROD_TOTAL`: аренда, содержание, ЗП производственного персонала
    - Административные `OVERHEAD_ADMIN_TOTAL`: ЗП, налоги на ФОТ, связь, подрядчики, сервисы, банк, прочие
    - Коммерческие `OVERHEAD_SALES_TOTAL`: реклама и маркетинг `OVERHEAD_SALES_MARKETING`*, ЗП коммерческого персонала, контент, сервисы
  - **EBITDA** `EBITDA` = `GROSS_PROFIT + OVERHEAD_TOTAL`; **Рентабельность EBITDA, %** `EBITDAK` = `EBITDA / REV_TOTAL`
  - **Расходы ниже EBITDA** `BELOW_EBITDA_TOTAL`: НДС, УСН/АУСН, проценты по кредитам
  - **Доходы ниже EBITDA** `BELOW_EBITDA_INCOME_TOTAL`: прочие доходы, проценты по депозитам
  - **Чистая прибыль** `NET_PROFIT` = `EBITDA + BELOW_EBITDA_TOTAL + BELOW_EBITDA_INCOME_TOTAL`
  - **Распределение прибыли** `PROFIT_DISTR_TOTAL`: дивиденды

  `*` — новые коды; остальные совпадают с маркетплейсным по типу, потоку, формату, родителю.
- `config/balance/templates/universal.yaml` (`version: 3`, `profile: UNIVERSAL`): структура
  маркетплейсного без `AR_MARKETPLACES` и `INV_MARKETPLACE` (31 статья), группа запасов —
  «Запасы» (склад, в пути); те же счета банка и кассы.
- Реестр: `UNIVERSAL` → новые файлы.
- Тесты: шаблоны валидны и согласованы (`TemplateRegistryTest`, теперь сравнивает два разных
  файла); расчёт отчёта по универсальному дереву на фактах-примере даёт ожидаемые валовую
  прибыль, EBITDA, чистую прибыль и проценты; регистрация `UNIVERSAL` → универсальные дерево и
  Баланс (сквозной тест), `MARKETPLACE` — прежний набор.
- `ARCHITECTURE.md`, `plan.md`, `Changelog`.

# ИИ не переспрашивает «нет ответа» после смены дерева ДДС

## Какую задачу решаем

ИИ-подсказку «нет ответа» часовой `app:cash:ai-categorize` повторно не запрашивает, пока не сменится
версия промпта. Если у компании сменилось дерево статей (замена ядром `app:cash:cashflow-core:apply`),
ответ на новом дереве мог бы найтись, но операция навсегда остаётся без подсказки. На проде 17.11.2026:
у Максимедиа 77 из 87 операций — «нет ответа» 14.11 на старом дереве, дерево заменено ядром 17.11.

## Что будет результатом

1. `CashCategorySuggestion::reopen(reason)` — переход `no_answer → stale` (stale снова попадает в
   кандидаты ИИ). Остальные переходы не меняются.
2. `ReplaceUnusedCashflowTreeWithCoreAction` при замене дерева переоткрывает «нет ответа» компании
   (`category_tree_replaced`) в той же транзакции, под той же блокировкой.
3. Команда `app:cash:ai-suggestions:reopen-no-answer <companyId> [--execute]` — для компаний, у которых
   дерево уже сменилось; без `--execute` только счёт. Блок wrapper `codex-console`.

## Что считаем выполненной работой

PR влит и выкачен, wrapper установлен, Владелец выполнил `--execute` для Максимедиа; после ближайшего
часового запуска у Максимедиа новые подсказки вместо 77 «нет ответа».

## Чек-лист приёмки

- [x] Тест: замена дерева ядром переоткрывает «нет ответа» своей компании, чужую не трогает.
- [x] Тест команды: dry-run считает и не меняет; `--execute` переоткрывает только «нет ответа» своей
      компании; повтор — «переоткрывать нечего».
- [ ] Прод: `--execute` для Максимедиа, после запуска :25 — подсказки вместо «нет ответа».

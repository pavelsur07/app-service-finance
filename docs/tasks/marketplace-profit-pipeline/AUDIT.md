# Аудит: контур данных маркетплейсов для роста прибыли

Дата: 13.11.2026. Аудит только по коду и документации, без проверки данных прода.
Пути — от `site/src/`, если не указано иное.

## Целевая схема (с уточнениями Владельца)

```
fetcher → [1] Raw (S3, версии) → [2] Канон → [3] Разнесение по SKU
        → [4a] Аналитика на лету: SKU × день, любой период, недели   ← отчёты, динамика
        → [5] Маппинг → [6] ОПиУ (учётный контур, не источник аналитики)
        → [7] Сверки: день / неделя / месяц
```

- Аналитика и еженедельные отчёты собираются из нормализованных данных, без ОПиУ.
- Экономика SKU в двух режимах: **маржинальный доход** (только прямые затраты SKU) и **полная** (плюс разнесённые общие затраты по ключу).
- Сверки: ежедневные технические, еженедельные (отчёт WB, выплаты), месячные (реализация Ozon, акты, M-1, закрытые месяцы).

## Сводка

| Слой | Статус | Где сейчас | Пробел |
|---|---|---|---|
| 1. Raw | частично | Легаси `MarketplaceRawDocument`: JSON в БД, перезаписывается на месте (`refreshRawData`). Ingestion `IngestRawRecord` + S3, sha256, версии. ozon-fetcher / wb-fetcher пишут в S3 неизменяемо | ОПиУ кормится изменяемым легаси-сырьём без версий. Хвост Ozon в легаси — D-2. Symfony не потребляет S3 фетчеров (контракт `source-facts` не согласован) |
| 2. Канон | частично | Ozon `OzonCostCategory` (enum), неизвестные → `ozon_unknown_<id>` + `PreliminaryCostFilter`. WB `WbCostCategory`, калькуляторы, гейт 06:40. Ingestion: `OzonAccrualType` в БД, `known=false`. Перепрогон `app:marketplace:reprocess` | Справочник легаси в коде, а не в БД. Жёсткий карантин только у Ozon. Два параллельных справочника |
| 3. Разнесение по SKU | частично | Прямые: `MarketplaceCost.listing_id`. | 4. Экономика SKU | частично | `/marketplace-analytics/unit-extended`, любой период, теги, xlsx. Строки товаров = фактически маржинальный доход | Нет режима «полная экономика» и переключателя. Нет СПП, налога, ROMI, % выкупа, хранения отдельной колонкой. Нет дневной динамики. `ListingDailySnapshot` в legacy UI, пересчёт только вручную, cron нет |
| 4a. Аналитика на лету | частично | `PlPreviewFactsQuery` считает из `marketplace_sales/returns/costs` по текущему маппингу, до 366 дней | `GROUP BY` без даты — нет дней/недель. Нет агрегатов под частые запросы. Нет еженедельного отчёта (Telegram шлёт только баланс/ДДС, команды нет в cron) |

| 7. Сверки | частично | Ozon «сырые ↔ учёт» 07:10 (текущий + M-1), свежесть, реализация 07:20/07:25, Ingestion raw ↔ норм. 06:45, регистр ОПиУ 07:44, покрытие фетчеров | В cron **нет ни одной недельной или месячной задачи**. WB «сырые ↔ учёт» не сверяется. Нет «сырые = канон = ОПиУ». Нет «отчёт МП ↔ выплаты в ДДС». Дрейф закрытых месяцев не ловится |

## Смежные данные

| Пункт | Статус | Пробел |
|---|---|---|
| Себестоимость | частично: `MarketplaceInventoryCostPrice` с датами, применяется на дату продажи | Ручной ввод/файл; нет партий/FIFO; `ProductPurchasePrice` и МойСклад не подключены |
| Воронка, поиск | Ozon — только сырьё в S3 (этап 9); WB — нет | Нормализации и экрана нет; корзины нет |
| Остатки, оборачиваемость | есть (`Inventory`, `/inventory/stock-turnover`) | Нет дней OOS и упущенных продаж; склады/кластеры Ozon — только сырьё |
| Цены, акции | нет в Symfony (только сырьё Ozon) | Нет истории цен — не объяснить изменение маржи |
| Возвраты | есть | Причины возвратов Ozon — только сырьё |
| SKU ↔ товар | частично: листинг, баркоды, теги, проекты | Один кабинет на МП в компании; нет комплектов |
| Выплаты, дебиторка МП | нет (D1 в counterparty-settlements: без расчётов МП) | Нет сопоставления выплат с отчётами |
| Компенсации, претензии | только категории затрат | Нет реестра претензий и контроля выплат |
| Затраты вне МП (ФФ, упаковка, самовыкупы, блогеры, внешняя реклама) | нет | Только ручной документ ОПиУ на проект, без SKU |
| Финпродукты МП, баллы | только категории затрат | Не связаны с ДДС и `Loan` |
| НДС по операциям МП | нет (этап 3 vat отложен) | — |
| План-факт | частично: факт из регистра ОПиУ | Нет разреза МП/SKU; МП в факте только после закрытия |
| Мониторинг устаревания API | нет | Покрытие кабинетов есть, алерта на `obsolete`/4xx нет |
| Безопасный реплей | частично: `reprocess` с компанией/МП/периодом, `--dry-run` | `deleteOpenByExternalIds` ограничен по srid, а не по raw-документу |
| Бизнес-алерты (маржа < 0, ДРР, OOS лидеров) | нет | Все гейты технические |

## Главные выводы

1. **Два контура данных.** ОПиУ и аналитика читают легаси (изменяемое сырьё в БД), а S3-сырьё фетчеров и Ingestion в бизнес-результат не доходят. Решение «какой контур канонический» — первое.
2. **Аналитика на лету — ближе всего к готовому.** `PlPreviewFactsQuery` уже считает из нормализованных данных; нужен разрез по дням/неделям и режимы экономики SKU.
3. **Маржинальный доход SKU уже есть** (строки unit-extended без общих затрат); нет полного режима с ключами распределения.
4. **Сверок недели/месяца нет совсем**, WB не сверяется с сырьём, выплаты МП не сверяются с ДДС.
5. **Сырьё есть, нормализации нет**: воронка, цены, акции, склады, причины возвратов Ozon.

## Предлагаемый порядок этапов (на обсуждение)

1. Решение по контуру: канонический источник сырья для ОПиУ и аналитики (легаси vs Ingestion/S3).
2. Аналитика на лету: SKU × день/неделя, режимы «маржинальный доход» / «полная», СПП, налог, % выкупа, хранение.
3. Ключи распределения общих затрат с сохранением ключа и строкой «нераспределено».
4. Сверки: WB «сырые ↔ учёт», недельная (отчёт WB, выплаты), месячная (M-1, закрытые месяцы), тождество raw = канон = ОПиУ.
5. Еженедельный аналитический отчёт (xlsx + рассылка) и бизнес-алерты.
6. ОПиУ: пересбор M-1 и «грязные периоды» при смене маппинга/сырья; версии маппинга.
7. Нормализация воронки, цен, акций Ozon; воронка WB.
8. Выплаты МП ↔ ДДС, реестр компенсаций, затраты вне МП на SKU, себестоимость из каталога/МойСклад.

# Этап 8. WB в новом контуре

Задача `docs/tasks/marketplace-profit-pipeline`, этап 8 из `TASK.md`.

## 1. Задача

WB считается так же, как Ozon: факты из wb-fetcher → переводчик `MarketplaceWb` → канон → витрина →
R1–R3 и R10 по обоим каналам. Легаси WB (`Marketplace/Wildberries`, `Ingestion` WB, реклама WB в
`MarketplaceAds`) работает параллельно и не меняется; его правила — только образец.

Что есть (исследование кода 14.11):

- wb-fetcher грузит `wb.finance.sales-report.daily` и `.weekly` (finance-api `sales-reports/detailed`,
  страница — JSON-массив строк, курсор `rrdId`, день — `period_key` `YYYY-MM-DD` МСК). Факты **не
  публикует**: нет `internal/facts`, `PublishResources`, `deps.Facts`; своих миграций нет (инвариант
  `AGENTS.md`). Рекламы в сервисе нет.
- Общий код fetchkit (outbox, `httpapi/facts.go`, `rawstore.Reader`) переиспользуется как есть.
- `SourceFactsGatewayFacade` знает один сервис (`ozon-fetcher`) и сверяет кабинет только с Ozon.
- Легаси-разбор: калькуляторы `Marketplace/Wildberries/.../CostCalculator/*` (затраты по названию
  операции) и маппер `Ingestion` `WbFinanceSalesReportDetailedPreviewMapper` (компоненты по полям,
  Σ компонентов = `forPay`) — второй ближе к канону и берётся образцом.
- Реклама легаси: `/adv/v1/upd` (расход кампании) + `/adv/v3/fullstats` (веса по nmId), cron 06:15.

Замеры прода 14.11 (read-only): активных кабинетов WB — 3 (19621cff, 3f4d87cc, b57d7682); строк
отчёта в день — в среднем 177 / 105 / 13, максимум 248. Объём не риск.

## 2. Результат

### 8.0. Эталон WB и таблица видов

- Read-only снимок легаси WB по 3 кабинетам за 16.09 – вчера (продажи, возвраты, затраты по
  категориям, реклама по дням) — вне git, как этап 1.
- Таблица «поле / операция строки → `source_type` → `kind` → уровень» в `stage-1-category-levels.md`
  (раздел WB). Новые виды, которых нет в `OperationKind` (приёмка `paidAcceptance`, возмещение
  складской логистики `rebillLogisticCost`, ПВЗ `ppvzReward`, лояльность `cashback*`,
  `additionalPayment`), — предложение здесь, решение администратора на экране кодов (как у Ozon 13.11).

Решения по умолчанию (меняются ответом Владельца):

| # | Вопрос | Решение |
|---|---|---|
| W1 | Дата операции | `rrDate` — день отчёта (= `period_key`), как дата начисления у Ozon (D1). Легаси датирует продажи по `saleDt` — в сверке с эталоном дни сдвинутся, месяц сходится |
| W2 | Выручка | `retailPriceWithDisc × quantity` (цена продавца до СПП, как легаси и D2); СПП (справочно) = выручка − `retailAmount` |
| W3 | Комиссия | `выручка − forPay − acquiringFee` (`vw`/`vwNds` не используются — правило Владельца 06.07); знак — как в источнике, отрицательная не отбрасывается |
| W4 | `source_type` | `wb:field:{поле}` для денежных полей строки; удержание — `wb:deduction:{причина}` из `bonusTypeName` (без ID); операция без правила с ненулевыми деньгами — карантин |
| W5 | Ключ факта | `wb:sales-report.daily:{rrdId}`; стабильность `rrdId` между перечитываниями проверяется в 8.1, иначе — хеш строки |

### 8.1. wb-fetcher публикует факты

- `internal/facts`: Split JSON-массива (пустая страница `[]` — 0 записей), ключ W5, `payload_hash`.
- Подключение по образцу ozon-fetcher: `PublishResources`, `RawRead`, `deps.Facts`.
- Своя папка миграций сервиса (как `ozonstore`) — backfill `outbox_batch` уже загруженных дней;
  инвариант `AGENTS.md` «своей схемы нет» меняется на «схема ядра + миграции публикации».
- Контракт `source-fact-envelope` v1.2.0 — строка WB в таблице `source_key`.
- Тесты Go: Split (table-driven + пустая страница), обработчики, backfill.

### 8.2. SourceFacts принимает второй сервис

- `SourceFactsGatewayFacade`: клиенты списком по тегу, `RESOURCES['wb-fetcher']`, сверка кабинета по
  `getActiveOzonSellerConnections()` ∪ `getActiveWbSellerConnections()`; второй `SourceFactsHttpClient`
  на `WB_FETCHER_BASE_URL` / `WB_FETCHER_API_TOKEN`.
- `SOURCE_FACTS_COMPANIES=*` уже включён — факты WB начнут приниматься сразу после деплоя; переводчик WB
  включается отдельно (8.3).

### 8.3. `MarketplaceWb` — переводчик

- Модуль по образцу `MarketplaceOzon`: `mwb_source_type` (код → вид, статус, черновик ИИ),
  `mwb_day` (`total = canon + quarantine`, где `total` — Σ денежных полей строк), `mwb_quarantine`;
  `RULES_VERSION`; команда перевода (cron `*/15`), гейт (как Ozon 09:20: карантин > 24 ч, день не
  переведён, перевод ≠ канон, отставание кабинета).
- Строка → компоненты по полям (W2–W4); стартовые решения по кодам — из таблицы 8.0 в миграции,
  новые — черновик ИИ + подтверждение на экране администратора (общий экран кодов с фильтром канала или
  свой `/admin/marketplace/wb-source-types`).
- Листинг: `(nmId, techSize)`, при пустом `nmId` — баркод; новые методы `MarketplaceFacade` (только
  поиск, переводчик листинги не создаёт; не найден — без SKU).
- Включение — `MARKETPLACE_WB_COMPANIES` (пусто — выключено).
- PHPat: `MarketplaceWb` не знает `MarketplaceOzon` и легаси WB.

### 8.4. Реклама WB

- wb-fetcher: ресурс `wb.ads.daily` (upd + fullstats за день, токен «Продвижение»), отдельный слот
  (`SeparateSlotPrefix` `wb.ads.`, миграция индекса как ozon 00006), публикация фактами.
- Переводчик: расход кампании (`updSum`) по nmId пропорционально `fullstats … nms[].sum`, остаток —
  наибольшему весу; нет весов — без SKU. Ключ разнесения `ads_statistics_share`, как у Ozon.

### 8.5. Отчёты по обоим каналам

- R1/R2/R3 — проверить, что запросы витрины не фильтруют Ozon; фильтр «канал» рядом с «кабинетом».
- R10 — строки WB (`DataQualityReportBuilder` + фасад `MarketplaceWb`); гейты витрины без изменений.

### 8.6. Приёмка на данных

- Сверка с эталоном 8.0 по месяцам и дням (сдвиг W1 объяснён); Σ канона дня = Σ денежных полей строк.
- Включение: 3f4d87cc → остальные кабинеты WB.

Релизы: 8.1 — сервис (миграции сервиса применяются деплоем); 8.2 — без миграций; 8.3 — миграция,
отдельный релиз; 8.4 — сервис + переводчик; 8.5 — без миграций.

## 5. Риски

- Стабильность `rrdId` не проверена — если WB перенумеровывает строки при перечитывании, ключ — хеш
  (W5), и каждая перезагрузка даст новую ревизию дня.
- Реклама WB — другой хост, токен и лимиты; ошибка авторизации рекламы не должна останавливать
  финансы (отдельный слот).
- Легаси создаёт категории `wb_<slug>` по причине удержания без карантина; в новом контуре каждая новая
  причина — код в карантине до решения.
- Недельный отчёт (`.weekly`) и сверка дни ↔ неделя — вне этапа (месячные / недельные сверки —
  `MarketplaceReconciliation`).

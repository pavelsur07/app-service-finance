# Этап 8. WB в новом контуре

Задача `docs/tasks/marketplace-profit-pipeline`, этап 8 из `TASK.md`.

## 1. Задача

WB считается так же, как Ozon: факты из wb-fetcher → переводчик `MarketplaceWb` → канон → витрина →
R1–R3 и R10 по обоим каналам. Легаси WB (`Marketplace/Wildberries`, `Ingestion` WB, реклама WB в
`MarketplaceAds`) работает параллельно и не меняется; его правила — только образец.

Что есть (исследование кода 14.11):

- wb-fetcher грузит `wb.finance.sales-report.daily` и `.weekly` (finance-api `sales-reports/detailed`,
  страница — JSON-массив строк, курсор `rrdId`, день — `period_key` `YYYY-MM-DD` МСК). Факты **не
  публикует**: нет `internal/facts`, `PublishResources`, `deps.Facts`; своих миграций нет (инвариант
  `AGENTS.md`). Рекламы в сервисе нет.
- Общий код fetchkit (outbox, `httpapi/facts.go`, `rawstore.Reader`) переиспользуется как есть.
- `SourceFactsGatewayFacade` знает один сервис (`ozon-fetcher`) и сверяет кабинет только с Ozon.
- Легаси-разбор: калькуляторы `Marketplace/Wildberries/.../CostCalculator/*` (затраты по названию
  операции) и маппер `Ingestion` `WbFinanceSalesReportDetailedPreviewMapper` (компоненты по полям,
  Σ компонентов = `forPay`) — второй ближе к канону и берётся образцом.
- Реклама легаси: `/adv/v1/upd` (расход кампании) + `/adv/v3/fullstats` (веса по nmId), cron 06:15.

Замеры прода 14.11 (read-only): активных кабинетов WB — 3 (19621cff, 3f4d87cc, b57d7682); строк
отчёта в день — в среднем 177 / 105 / 13, максимум 248. Объём не риск.

### 8.3. `MarketplaceWb` — переводчик

- Модуль по образцу `MarketplaceOzon`: `mwb_source_type` (код → вид, статус, черновик ИИ),
  `mwb_day` (`total = canon + quarantine`, где `total` — Σ денежных полей строк), `mwb_quarantine`;
  `RULES_VERSION`; команда перевода (cron `*/15`), гейт (как Ozon 09:20: карантин > 24 ч, день не
  переведён, перевод ≠ канон, отставание кабинета).
- Строка → компоненты по полям (W2–W4); стартовые решения по кодам — из таблицы 8.0 в миграции,
  новые — черновик ИИ + подтверждение на экране администратора (общий экран кодов с фильтром канала или
  свой `/admin/marketplace/wb-source-types`).
- Листинг: `(nmId, techSize)`, при пустом `nmId` — баркод; новые методы `MarketplaceFacade` (только
  поиск, переводчик листинги не создаёт; не найден — без SKU).
- Включение — `MARKETPLACE_WB_COMPANIES` (пусто — выключено).
- PHPat: `MarketplaceWb` не знает `MarketplaceOzon` и легаси WB.

Правила строки (по фактам прода 15.11: 12 операций, 94 поля; деньги — строки). `s` = +1 «Продажа»,
−1 «Возврат»; знаки полей — как в источнике, без `abs()` (иначе «Корректировка эквайринга» с
`forPay` = −`acquiringFee` даёт ложную комиссию):

| Компонент | Сумма | Вид |
|---|---|---|
| `wb:field:sale` / `wb:field:return` | `s × retailPriceWithDisc × quantity` | `sale` / `return` |
| `wb:calc:spp` | `s × (выручка − retailAmount)` | `spp` (справочно) |
| `wb:field:acquiringFee` | `−s × acquiringFee` | `acquiring` |
| `wb:calc:commission` | `−s × (выручка − forPay − acquiringFee)`; при выручке 0 — нет | `commission` |
| `wb:payout:{операция}` | `s × (forPay + acquiringFee)` при выручке 0 («Добровольная компенсация…») | карантин |
| `wb:field:deliveryService` / `…:return` (есть `returnAmount`) | `−deliveryService` | `logistics_to` / `logistics_back` |
| `wb:field:paidStorage`, `wb:field:penalty` | `−x` | `storage`, `fine` |
| `wb:field:rebillLogisticCost`, `paidAcceptance`, `cashbackCommissionChange`; `ppvzReward` — только в строках «Возмещение за выдачу и возврат товаров на ПВЗ» | `−x` | ❓ карантин → администратор |
| `wb:field:cashbackAmount` | `−x` | `promo_reviews` |
| `wb:field:cashbackDiscount`, `additionalPayment` | `+x` | `compensation` |
| `wb:deduction:{причина}` (без «, документ №…» и « за <месяц> <год>») | `−deduction` | «WB Продвижение» → новый справочный вид `ads_settlement` (W6), «Джем» → `subscription`, утилизация → `disposal`; иначе карантин |

Итог строки без справочных = `s × forPay` + поля затрат; `mwb_day.total` = Σ компонентов без
справочных = `canon + quarantine`. `ppvzReward`, `vw`, `ppvzSalesCommission` в строке продажи — внутри
комиссии, отдельно не берутся.

Листинг: `marketplace_sku = nmId`, `size = techSize` (пусто → `UNKNOWN`); нет точного размера и у
`nmId` один листинг — он; иначе без SKU (`unresolved`). `findListingsByMarketplaceSkus` дополнительно
отдаёт `size`. Канал канона — `wildberries` (= `MarketplaceType`).

Отложено в 8.3b: черновики ИИ для кодов WB — пока администратор решает на экране без черновика.

### 8.4. Реклама WB

- wb-fetcher: ресурс `wb.ads.daily` (upd + fullstats за день, токен «Продвижение»), отдельный слот
  (`SeparateSlotPrefix` `wb.ads.`, миграция индекса как ozon 00006), публикация фактами.
- Переводчик: расход кампании (`updSum`) по nmId пропорционально `fullstats … nms[].sum`, остаток —
  наибольшему весу; нет весов — без SKU. Ключ разнесения `ads_statistics_share`, как у Ozon.

План 8.4 (15.11):

- **Symfony → сервис.** Снимок кабинетов WB выдаёт `wb.ads.daily` тем же компаниям, что отчёт (ключ тот же —
  токен подключения seller, как у легаси `WildberriesAdClient`); контракт `marketplace-connections` v1 — новое
  значение `resource_types`.
- **wb-fetcher.** Клиент `advert-api`: `/adv/v1/upd` за день, затем `/adv/v3/fullstats` по кампаниям из него
  порциями по 50 (как легаси); лимиты своего семейства (не через квоту отчёта Symfony): upd — раз в 10 с,
  fullstats — раз в 20 с на кабинет. Страница дня — объект `{schema: wb-ads-daily-v1, expenses, statistics}`.
  Отдельный слот `wb.ads.` (миграция сервиса `00002`, своя папка поверх ядра); 401/403 рекламы ставит паузу
  только задаче, кабинет не останавливает (как Ozon). План: 45 дней назад однократно, вчера и 7 дней —
  перечитывание раз в сутки. Факты: запись = кампания дня (`expenses` кампании + её строка `fullstats`),
  ключ `wb:ads.daily:{advertId}`; контракт `source-fact-envelope` v1.3.0.
- **Symfony.** `SourceFactsGatewayFacade::RESOURCES['wb-fetcher']` += `wb.ads.daily`. Переводчик WB: расход
  кампании `−Σ updSum` вид `ads_cpc` по nmId пропорционально Σ `nms[].sum`, остаток — наибольшему весу; нет
  весов — без SKU; ключ `ads_statistics_share` (копейки — методом наибольшего остатка, как у Ozon). nmId с несколькими размерами — первый листинг по id
  (`ponytail`). `mwb_day.ads_revision` (миграция) — день переводится заново при новой ревизии рекламы.
  Удержание «WB Продвижение» остаётся справочным (W6).
- Релиз — один PR с миграцией Symfony («run the migration and deploy»); миграция сервиса — деплоем.

## 5. Риски

- Стабильность `rrdId` не проверена — если WB перенумеровывает строки при перечитывании, ключ — хеш
  (W5), и каждая перезагрузка даст новую ревизию дня.
- Реклама WB — другой хост, токен и лимиты; ошибка авторизации рекламы не должна останавливать
  финансы (отдельный слот).
- Легаси создаёт категории `wb_<slug>` по причине удержания без карантина; в новом контуре каждая новая
  причина — код в карантине до решения.
- Недельный отчёт (`.weekly`) и сверка дни ↔ неделя — вне этапа (месячные / недельные сверки —
  `MarketplaceReconciliation`).

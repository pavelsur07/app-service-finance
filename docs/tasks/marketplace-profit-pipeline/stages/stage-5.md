# Этап 5. `MarketplaceEconomics` — витрина SKU × день и отчёт R1 (Ozon)

Задача `marketplace-profit-pipeline`, этап 5 из `TASK.md`. План — 14.11.2026.

## 1. Задача

Экономика каждого SKU Ozon за любой период по уровням каскада (выручка → валовая → МД1 → МД2 →
полная) — на новом контуре (канон `mo_operation`), **отдельным экраном**.

Условие Владельца (14.11): новый отчёт и легаси работают параллельно. Легаси «Unit — Экономика»
(`/marketplace-analytics/unit-extended`), его API, xlsx и данные не меняются ни в одной строке.
Новый экран — своя страница, свой API, свой модуль; переход с одного на другой — ссылкой.

## 2. Результат

### 2.1. Модуль `site/src/MarketplaceEconomics` (по `docs/workflow/new-module.md`)

Читает канон, себестоимость, теги, рекламу легаси — только через фасады. Не пишет в ОПиУ, не ходит
к провайдерам, не знает правил каналов (уровень берёт из `OperationKind::level()`).

| Таблица | Что | Ключ |
|---|---|---|
| `me_day_line` | витрина: кабинет × день × листинг (пусто — без SKU) × показатель → уровень, сумма в копейках, количество, ключ распределения; разнесение — парой строк (доля на SKU и обратная без SKU) | `id`, индекс `(company_id, operation_date)`; день заменяется целиком под блокировкой |
| `me_day` | обновлённый день кабинета: когда, версия правил, контрольные итоги (Σ канона дня, нераспределено, себестоимость, листингов без себестоимости) | `(company_id, channel, connection_ref, operation_date)` |

`measure` — вид канона (`sale`, `return`, `commission`, …) плюс расчётные:
`cost_price` (себестоимость проданного минус возвращённого), `ads_allocated` (реклама по долям легаси),
`storage_share` (хранение без SKU по остатку),
`overhead_share` (доля общих затрат на SKU). Уровень показателя — из `OperationKind::level()`,
для расчётных — константа в модуле.

### 2.2. Как считается день кабинета

1. Операции канона за день → строки по `listing_id × kind` (чтение — новый метод фасада
   `MarketplaceOperationsFacadeInterface::dayOperations(company, channel, connection, date)`).
2. **Себестоимость (D5):** количество продаж − возвратов по листингу × цена на дату
   (`MarketplaceFacade::getCostPricesForListingsOnDate`, один запрос на день). Нет цены — листинг
   считается в `me_day.without_cost_price`, себестоимость 0, на экране пометка.
3. **Реклама МД2 (временно, до этапа 6):** CPC и оплата за заказ в by-day — без SKU (кабинет).
   Итог — из канона, распределение по SKU — пропорционально рекламе SKU в легаси
   (`MarketplaceAdsFacade::getAdSpendByListingForPeriod(day, day, ozon)`, ключ `legacy_ads_share`), в легаси
   ничего не добавляется. Нет рекламы SKU в легаси за день (лаг D+2) — сумма остаётся «нераспределено».
4. **Общие затраты (D3):** уровень `overhead` и прямые виды без SKU распределяются по доле выручки
   SKU **в этот день**; хранение без SKU — по доле остатка на дату (`InventoryFacade`, шт.), нет
   остатков — по выручке. Ключ (`revenue_share` / `stock_share`) пишется в строку. День без выручки —
   всё в «нераспределено». Инвариант: Σ SKU (полная) + нераспределено = итог кабинета за день,
   значит и за любой период.
5. Замена дня целиком под `pg_advisory_xact_lock` (`me:company:channel:connection:date`), одна
   транзакция на день — команда.

Обновление:
- `app:marketplace-economics:refresh` — cron `10-59/15` (после перевода): дни из `mo_dirty_window`;
  `takeDay` канона берёт блокировку дня и снимает отметку в транзакции пересчёта — замена дня
  переводчиком ждёт commit и отметит день снова.
- Ночью (`07:15`, после `--relink` переводчика) — пересчёт последних 45 дней: себестоимость и реклама легаси меняются без
  отметки в каноне. `ponytail:` правка себестоимости старше 45 дней ждёт ручного
  `--from/--to`; если станет частым — отметка из фасада себестоимости.
- `--company --from --to` — ручной пересчёт окна.

### 2.3. Отчёт R1 — новый экран

- Страница `/marketplace/economics` (контроллер модуля, шаблон на новом слое `_layout/app.html.twig`,
  React-остров `marketplace-economics/features/sku-economics`, вход `sku_economics_page`).
- API `GET /api/marketplace-economics/sku`: период (до 366 дней, больше → 422), кабинет, теги,
  поиск, сортировка, `page/limit` (Pagerfanta, ≤ 200). Ответ: строки SKU и строка «нераспределено»,
  итог кабинета, те же показатели за прошлый период равной длины (Δ ₽, Δ %).
- Колонки: продажи/возвраты шт., выручка, себестоимость, валовая, комиссия, логистика туда/обратно,
  эквайринг, прочие МД1, МД1, реклама, МД2, доля общих, полная; маржа МД1/МД2/полная %, ДРР, ROI;
  СПП справочно. Переключатель «без разнесения / с разнесением общих».
- xlsx — `GET /api/marketplace-economics/sku/export`, OpenSpout, те же фильтры.
- Ссылки: в боковом меню нового слоя и в легаси-меню маркетплейсов — «Экономика SKU (новая)»;
  на экране — «открыть прежний отчёт». Легаси-пункт «Unit — Экономика» остаётся как есть.
- Доступ — `MARKETPLACE_READ` (префикс `App\MarketplaceEconomics\` в `ModuleAccessMap`).
- Компания без данных в каноне — пустое состояние «кабинет ещё не переведён на новый контур»,
  не нули.
- Дизайн-система: `DS-Table`, `DS-Money`, `DS-Tabs`, `DS-Controls`; деньги — до копейки,
  без красного для сумм.

## 3. Отклонения от `TASK.md` / `REPORTS.md` (по умолчанию, пересмотреть по слову Владельца)

- **Налог (D4) — не в этапе 5.** Профиль компании хранит режим (`TaxRegime::USN`), но не объект
  (6 % «доходы» / 15 % «доходы − расходы») — ставку взять неоткуда. «Прибыль после налога» — P2;
  нужен подтип УСН в налоговом профиле отдельной задачей.
- **Распределение — по дням**, не по периоду отчёта: так инвариант держится на любом периоде и
  витрина не пересчитывается на каждый запрос. Доля SKU за период = Σ долей по дням.
- **Хранение без SKU — по остатку в штуках**, без объёма (объёма у листингов нет).
- Фильтр «проекты» — после `MarketplacePlProjection` (проект от кабинета; пока фильтр по кабинету).

## 6. Риски

- Реклама легаси с лагом D+2 и через `Ingestion` — МД2 последних двух дней «предварительно»
  (пометка на экране); полностью уходит на этапе 6.
- Неподтверждённые коды в карантине переводчика не попадают в канон — итог кабинета в R1 меньше
  легаси на сумму карантина. Экономика переводчик не знает; карантин виден в гейте и на экране
  администратора, на экране R1 — на этапе 7 (R10).
- Объём `me_day_line`: ~ SKU × виды × дни; по Вумджой порядка 10⁵ строк за квартал — замерить после
  включения.

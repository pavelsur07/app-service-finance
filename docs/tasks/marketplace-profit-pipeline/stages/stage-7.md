# Этап 7. R10 и ежедневные сверки нового контура

Задача `docs/tasks/marketplace-profit-pipeline`, этап 7 из `TASK.md`.

## 1. Задача

Видеть качество данных нового контура без ручных SQL: каждое звено «факты → перевод → канон →
витрина» сверяется каждый день, расхождение — красный гейт с суммой; клиент и администратор видят
состояние на экране R10.

Что уже есть (этапы 2–6):

| Гейт | Время | Что ловит |
|---|---|---|
| `app:source-facts:health-check` | 09:10 | карантин пачек; поток без применённых пачек > 6 ч |
| `app:marketplace-ozon:health-check` | 09:20 | код без решения > 24 ч; день фактов не переведён на текущей ревизии / правилах |
| `app:marketplace-economics:health-check` | 09:30 | Σ витрины дня ≠ Σ канона; изменённый день не пересчитан > 60 мин |

Чего нет:

1. **Перевод = канон.** Переводчик записывает в `moz_day` Σ, отправленную в канон, но никто не
   сверяет её с тем, что реально лежит в `mo_operation` (потеря строк при замене дня, ручная правка,
   ошибка другого переводчика в том же окне).
2. **Отставание кабинета.** Поток может применять пачки (гейт приёма зелёный), но последний день
   фактов — неделю назад (сервис застрял на хвосте). Нужна проверка «последний день кабинета не
   старше D−2».
3. **Доля нераспределённого.** Сейчас 0 у всех компаний; рост означает, что разнесение сломалось
   (нет выручки, остатков или долей рекламы) — нужен порог.
4. **Экран R10** — сводка по кабинетам компании и список проблемных дней.

Замеры прода 14.11 15:17 МСК (read-only, `~/vf-measurements/.../2026-11-14-stage7/`):

- 296 дней × 4 кабинета: `moz_day.total = canon + quarantine` — 0 нарушений; Σ `mo_operation` без
  справочных (`spp`, `coinvestment`) = `moz_day.canon` — 0 расхождений из 296;
- `me_day.unallocated_minor ≠ 0` — 0 дней;
- последний день фактов, перевода и витрины у всех кабинетов — 13.11 (D−1).

Новые гейты, значит, зелёные с первого дня; пороги ниже выбраны так, чтобы срабатывать только на
поломке.

## 2. Результат

### 7.1. Гейт «перевод = канон» и отставание кабинета — `app:marketplace-ozon:health-check`

- `MarketplaceOperationsFacadeInterface::daySums(channel, from, to): list<CanonDaySum>` —
  Σ `amount_minor` по (компания, кабинет, день) без видов уровня «справочно» (`OperationKind` →
  `INFO`). Чтение, без транзакции.
- В гейте Ozon: для каждого `moz_day` за последние 45 дней (окно ночной перезагрузки) — `canon_minor`
  против `daySums`; расхождение → `error` с числом дней и Σ |разницы| в рублях; день канона без
  `moz_day` и наоборот — тоже расхождение.
- Отставание: у кабинета с фактами by-day последний `period_key` < сегодня − 2 (МСК) → `error`
  со списком кабинетов и датой. Отключённый кабинет попадёт сюда — решение по каждому случаю
  (как карантин), в runbook гейта.

### 7.2. Порог нераспределённого — `app:marketplace-economics:health-check`

- За 7 последних дней по компании: Σ |строк без SKU| (`unallocated_minor`) / Σ |затрат| витрины
  > 1 % → `error` с компанией, суммой и долей.

### 7.3. Экран R10 «Качество данных» — `/marketplace/economics/quality`

- Вкладка рядом с R1/R2, активная компания, доступ `MARKETPLACE_READ`, период по умолчанию 45 дней.
- По каждому кабинету: последний день фактов / перевода / витрины; дней без перевода; кодов в
  карантине; Σ фактов (переводчик), Σ канона, Σ витрины за период и разница; доля нераспределённого.
- Таблица проблемных дней (любое расхождение > 0 или день не переведён) — дата, звено, сумма.
- Данные — через фасады: `SourceFactsFacadeInterface::periods` (+ фильтр компании),
  новый `MarketplaceOzonFacadeInterface::dayStates(companyId, from, to)`,
  `MarketplaceOperationsFacadeInterface::daySums(..., companyId)`,
  новый `MarketplaceEconomicsFacadeInterface::daySums(companyId, from, to)`.
  Контроллер и сборщик — в новом маленьком модуле `MarketplaceQuality` (только чтение, только
  фасады; PHPat). Причина: витрине запрещено знать факты и переводчик, переводчику — витрину;
  сводка всех звеньев — отдельная ответственность. WB (этап 8) добавится строкой в сборщике.

# Переменные налоговых ставок в формулах статей ОПиУ

Поручено Владельцем 17.11.2026: «в Категории ОПиУ добавить переменные —
действующую ставку НДС, налога на АУСН или УСН».

## Задача

Формулы статей ОПиУ ссылались только на коды статей и числа: ставку налога
приходилось зашивать числом, при смене режима формула молча считала по старой.

## Результат

- В формулах доступны `VAT_RATE` и `TAX_RATE` — действующие ставки компании в
  процентах: `REV_TOTAL * TAX_RATE / 100`, `REV_TOTAL * VAT_RATE / (100 + VAT_RATE)`.
- `VAT_RATE` — из режима НДС налогового профиля: без НДС 0, УСН 5 / 7, общие
  ставки по дате (20 до 2026, 22 с 2026).
- `TAX_RATE` — новое необязательное поле «Ставка налога, %» периода налогового
  профиля (карточка компании, блок «Налоги»; форма создания компании).
- В форме статьи — вкладка «Налоги» в палитре переменных.

## Решения (приняты по умолчанию, Владелец план утвердил)

| Вопрос | Решение |
|---|---|
| Единицы | Проценты (22, 6), не доли |
| Источник `TAX_RATE` | Вводит владелец в налоговом профиле; подвид УСН не храним, поле доступно при любом режиме |
| Ставка не задана | 0 и предупреждение в отчёте, если формула её использует |
| Дата ставки | Последний день периода отчёта; для месяца точно. Период через смену ставки (согласовано Владельцем 17.11): денежные статьи с переменной считаются помесячно и складываются — итог равен сумме месячных колонок; проценты и коэффициенты — по ставке конца периода |
| Конфликт с кодом статьи | Имена зарезервированы: переменная выигрывает, форма статьи код не принимает |
| Статья «Налог» в шаблонах ОПиУ | Не добавлялась — отдельной задачей, когда будут правила |

## Что выполнено

- Company: `CompanyTaxProfile::$taxRatePercent`, миграция `Version20261117210000`
  (обратима), DTO фасада, форма и карточка; `VatMode::ratePercentOn()` вместо
  `Cash\…\VatRates` — один источник ставок НДС.
- Finance: `PlFormulaVariables`, поддержка в `PlReportCalculator`, импорт дерева,
  запрет зарезервированного кода, палитра переменных.
- Типы `PlReportCalculator` уточнены, baseline PHPStan сокращён на 19 записей.

## Открытое

- Предпросмотр ОПиУ и бюджет считают колонки на заранее посчитанных суммах
  (`PlReportCalculator::withFacts()`) с одним периодом на все колонки: переменная
  ставки там берётся на конец этого периода, в том числе для месячных колонок
  бюджета. Точный расчёт требует периода у каждой колонки (`PlPreviewColumn`) —
  отдельная задача, когда переменные начнут использоваться в бюджете.

## Чек-лист приёмки

- [x] Ставка налога сохраняется и показывается в профиле; пустая допустима; вне 0…100 — ошибка формы (`CompanyTaxProfileTest`).
- [x] `REV * TAX_RATE / 100` считает по ставке профиля на месяц; смена профиля между месяцами учитывается (`PlFormulaVariablesCalculationTest`).
- [x] `VAT_RATE`: 0 / 5 / 7 / 20 до 2026 / 22 с 2026.
- [x] Без НДС до октября, 5% с октября, период — год: статья НДС равна сумме трёх месячных значений, а не 5% от выручки года.
- [x] Незаданная ставка — 0 и предупреждение, не ошибка.
- [x] Статью с кодом `VAT_RATE` / `TAX_RATE` создать нельзя; импорт дерева о них не предупреждает.
- [x] НДС операций ДДС считается как раньше (`VatPolicyTest`).

# Вумджой: дерево ОПиУ к базовому шаблону маркетплейса

Компания `19621cff-b028-45d9-9193-11f47ad9a8b2`. Аудит 29.10.2026 (только чтение прода),
решение Владельца 29.10: «Делай командой, страхование в отдельную статью».
`stage_base_commit`: `d0cc8ab21`.

## 1. Какую задачу решаем

Своё дерево ОПиУ компании собрано из шаблона поверх старого дерева, и отчёт считает
ключевые строки неверно (`PlReportCalculator`: подытог без формулы — сумма детей,
KPI — значения по коду):

- правила себестоимости ведут в группу «Себестоимость» — себестоимость 2026 (835 530 ₽) в отчёте 0;
- «Выручка» = `REV_NOT_SPP + REV_RETURNS`, а продажи с 20.10 в листе `REV_NOT_SPP_SALES`;
- EBITDA = `CM4 + OVERHEAD_TOTAL`: под ним пустые шаблонные группы, реальные расходы в
  отдельном корне «Операционные расходы (OPEX)»;
- «Чистая прибыль» без «Доходов ниже EBITDA»; проценты по кредитам в отдельном корне вне формулы;
- затраты маркетплейсов частично в CM1 (свои статьи), частично в CM3 (шаблон), брендовая
  комиссия и поставки Ozon — в «Хранении»;
- дубли статей и KPI, листы без кода, неверные направления.

## 2. Что будет результатом

Одноразовая команда `app:finance:repair-pl-tree-19621cff [--execute]` — одной транзакцией
по ID, сверенным с продом 29.10:

1. правила продаж (4) и затрат (28) — на статьи шаблона (`default_cost_mapping.yaml`;
   страхование — в свою «Страхование товаров», досрочная выплата / гибкий график — в
   «Прочие административные», маркировка — в «Сертификация, Честный знак»);
2. проценты кредитов (2) и статья ДДС «Дивиденды» — на шаблонные статьи;
3. операции документов из старых статей — в новые (ручные документы по ID, документы
   маркетплейса по названию категории затрат, себестоимость по знаку); документы
   маркетплейса текущего месяца не трогаются — их пересобирает ночное оперативное закрытие
   04:45 уже по новым правилам; регистр ОПиУ пересчитывается за затронутые дни;
4. структура: группы OPEX — под «Косвенные расходы», формула «Чистой прибыли» как в
   шаблоне, коды двум листам, направления двум листам, удаление пустых дублей, код
   `REV_NOT_SPP` рабочему листу продаж;
5. статьи, на которые ещё ссылаются операции текущего месяца (`MP_STORAGE`,
   `MP_OTHER_DEDUCTIONS`), откладываются; повторный запуск после 04:45 удаляет их.

Без `--execute` — предпросмотр с откатом. Расхождение с ожидаемым состоянием — откат
целиком, exit 1. Повторный запуск ничего не меняет.

Вне команды (интерфейс, решения Владельца): привязка статей ДДС к ОПиУ, «Не распределено»,
документы ОПиУ из ДДС за 2026.

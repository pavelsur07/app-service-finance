# cost-pl-mapping-sibling-fallback: маппинг по образцу компании

Бриф Владельца (10.10.2026): маппинг затрат в ОПиУ должен быть полностью
автоматическим, без UI, в том числе у компаний со своим деревом ОПиУ, где нет
статей шаблона. Продолжение #2605.

Правило (согласовано в чате): если статьи шаблона (`pl_code`) у компании нет
вовсе, берётся статья, куда компания уже относит другие коды
затрат того же маркетплейса с тем же `pl_code` в шаблоне — только если все такие
правила (включённые, со статьёй LEAF_INPUT) указывают на одну статью. Статья
шаблона есть, но группа или дублируется → не угадываем (компания разбила её
намеренно; решение внутреннего ревью). Разнобой
или отсутствие образцов → правило остаётся blocked, его показывает гейт
unmapped-check. Только частичный режим (ночной sync-default); UI и ручная
команда не меняются. Ручные и отключённые правила защищены writer'ом, как раньше.

Baseline: см. checkpoint в handoff.md.

## Stage 1: подбор статьи по образцу (единственный)
Risk: HIGH-LOCAL (финансовая семантика маппинга)
Definition of Done:
- `DefaultCostMappingSiblingResolver` (чистая функция) + unit-тесты на ветки:
  единогласно / разнобой / нет образцов / образец только в другом pl_code.
- Query образцов компании: включённые правила со статьёй LEAF_INPUT своей компании.
- `ApplyDefaultCostMappingAction` (partial): blocked-правило с выведенной
  статьёй создаётся/заполняется, отчитывается отдельным списком `inferred`.
- `sync-default` печатает выведенные правила; интеграционные тесты.

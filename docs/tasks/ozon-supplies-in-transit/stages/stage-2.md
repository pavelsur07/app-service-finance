# Этап 2. Symfony: поставки Ozon в отчёте «Остатки»

## Задача

Забрать у `ozon-fetcher` снимок `ozon.supplies` (этап 1) и показать товар активных заявок на поставку
FBO в отчёте «Остатки» отдельной колонкой «В поставке», не меняя «доступно» и ничего, что читает остатки.

## Найдено до работ

- `StockQtyByListingOnDateQuery` (юнит-экономика, оборачиваемость через `InventoryFacade`) и
  `SessionsToRenormalizeQuery` берут **последнюю сессию дня по источнику**. Отдельная сессия поставок
  с `source = ozon` (05:50 позже снимка 04:05) стала бы «последней», и остаток `available` у всех
  обнулился бы. Поэтому строки поставок пишутся **в сессию дневного снимка остатков Ozon** той же
  даты (её `snapshot_session_id` и `snapshot_at`): выбор последней сессии не меняется, фильтр
  `status = available` поставки не видит.
- Сырьё страниц в Symfony не копируется: оно хранится в `ozon-fetcher` (S3), повторное чтение —
  тем же эндпоинтом. `InventoryRawSnapshot` не создаётся — иначе перенормализация сессии отдала бы
  страницы поставок нормализатору остатков.
- Отчёт «Остатки» по Ozon суммирует строки без фильтра статуса — `in_supply` исключается из
  «Остаток/Резерв/Доступно», разбивки FBO/FBS и итогов, выводится своей колонкой.
- Состав поставки (`/v1/supply-order/bundle`) не содержит `bundle_id`: страницы состава идут по
  одной поставке в порядке возрастания `bundle_id` (`executor/reference.go`), каждая до
  `has_next: false`. Разбор повторяет этот порядок; число групп ≠ числу поставок — снимок отклоняется.
  Порядок записан в README контракта.

## Результат

- `StockStatus::InSupply` (`in_supply`, «В поставке»). Миграции нет.
- `OzonSupplySnapshotClient` — `GET {OZON_FETCHER_BASE_URL}/internal/snapshots/latest`, токен
  `OZON_FETCHER_API_TOKEN`; 404 → «снимка нет», прочее → исключение.
- `OzonSupplyOrdersParser` — страницы → позиции (SKU, артикул, количество, заявка, статус, склад);
  черновики (`DATA_FILLING`) пропускаются.
- `SyncOzonSuppliesAction` — снимок кабинета → строки `in_supply` за `period_key` в сессию остатков
  той же даты; повтор за день заменяет строки поставок (DELETE + INSERT в одной транзакции).
  Снимок старше 2 дней или нет сессии остатков за его дату — WARNING и пропуск.
- Команда `app:inventory:ozon-supplies-sync`, cron 05:50 МСК (после гейтов 05:30/05:40).
- Отчёт «Остатки»: колонка «В поставке» и итог по фильтру — только когда поставки есть.
- `ARCHITECTURE.md`: Inventory (поставки), Cron, Changelog.

## Что считаем выполненным

Unit-тест разбора (порядок поставок, несколько страниц состава, черновик, склад без данных,
несовпадение групп), функциональный тест команды (строки в сессии остатков, повтор — то же число строк,
нет сессии — пропуск, 404 — пропуск, остаток через `InventoryFacade` не изменился), тест отчёта
(колонка, «доступно» без поставок). PHPStan, CS, затронутые тесты зелёные.

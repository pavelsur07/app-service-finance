# Этап 4. Правила по категориям площадок

Модуль `Marketplace` · риск HIGH-LOCAL (миграция, массовая запись) · PR с миграцией — отдельный релиз.

## Задача

Не размечать сотни листингов руками: одно правило «категория площадки → моя категория»
назначает её всем листингам с этим ключом, сейчас и после каждой загрузки каталога.

## Результат

- Ключ категории площадки в `marketplace_data.category_key` (пишет загрузка каталога):
  Ozon — `ozon:<description_category_id>:<type_id>` (`type_id` теперь сохраняется);
  WB — `wb:<subjectID>`, рядом `subject_id` и `subject_name` (раньше WB-каталог в листинг их не писал).
- Таблица `marketplace_listing_category_rules` (`company_id`, `source_key`, `category_id` FK `ON DELETE CASCADE`),
  unique `(company_id, source_key)`. Entity `ListingCategoryRule`.
- `ApplyListingCategoryRulesQuery`: одним `UPDATE` ставит категорию по правилам листингам компании
  с `category_source` NULL или `rule`; ручное назначение не трогает; уже совпадающие строки не пишет.
- `SaveListingCategoryRuleAction`: создать или заменить правило по ключу и сразу применить его.
- Применение после загрузки каталога: Ozon — в транзакции чанка после upsert, WB — в транзакции обновления.
- Вкладка «Категории»: таблица «Категории площадок без вашей категории» (ключ, площадка, название WB,
  число листингов, до трёх примеров названий) с выбором категории и кнопкой «Назначить правилом»,
  ниже — действующие правила с заменой категории.

Не входит: названия категорий Ozon из `/v1/description-category/tree` — вместо них примеры
названий листингов (без нового вызова API); «как у связанного товара» — на проде 0 связей с товаром (этап 0).

## Что считаем выполненным

Тесты на приёмку зелёные, миграция up/down/up, гейты по изменённым каталогам чистые,
ARCHITECTURE обновлён, сценарий на стенде пройден.

## Чек-лист приёмки

- [x] Одно правило размечает все листинги компании с этим ключом.
- [x] Ручное назначение правило не перезаписывает; листинг с категорией от правила — перезаписывает при замене правила.
- [x] Повторное сохранение того же правила: 0 изменённых листингов, правило одно.
- [x] Правило другой компании к листингам компании не применяется.
- [x] После загрузки каталога Ozon/WB новые листинги с ключом получают категорию по правилу.
- [x] Нормализация: Ozon `type_id` и `category_key`; WB `subject_id`, `subject_name`, `category_key`.
- [x] Удаление категории удаляет её правила (если категория не используется листингами).

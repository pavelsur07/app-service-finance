# Этап 3. «Экономика SKU» по категориям

Модуль `MarketplaceEconomics` · риск HIGH-LOCAL (агрегация денег) · без миграции.

## Задача

Показать экономику по категориям листингов: сумма категорий плюс «Нераспределено» равна итогу
кабинета до копейки. Из категории можно перейти к её листингам.

## Результат

- `/marketplace/economics`: фильтр «Категория» (`category=<uuid>|none`) и переключатель
  «Группировка: По SKU / По категориям» (`group=category`).
- Режим «По категориям»: строка на категорию и «Без категории», затем «Нераспределено» и «Итого».
  Название категории — ссылка на тот же отчёт в режиме «По SKU» с фильтром по ней: там видны листинги,
  канал и артикул. Пагинации нет: категорий немного.
- Показатели группы — `SkuMetrics::merge()` строк. Проценты (СМ %, ДРР) считаются из сумм группы.
  Сортировка групп — по выбранной колонке, «Без категории» последней.
- Строка «Доля выручки с категорией, %» в пояснении.
- XLSX в режиме категорий: первая колонка «Категория», строки листингов упорядочены по группам,
  затем «Нераспределено» и «Итого». Групповых подытогов нет, чтобы суммы в Excel не задваивались.
- Категория определяется при чтении (`ListingCategoryFacadeInterface::categoriesForListings`).
  Витрина и запрос к ней не меняются.

## Что считаем выполненным

Функциональные тесты сверки итогов зелёные, проверка на стенде пройдена, гейты по
изменённым каталогам чистые, ARCHITECTURE обновлён.

## Чек-лист приёмки

- [x] Без фильтров: Σ категорий + «Без категории» + «Нераспределено» = «Итого» = итог режима «По SKU» (выручка, СМ1, СМ2, СМ3).
- [x] Листинги Ozon и WB одной категории суммируются в одну строку.
- [x] Проценты группы — из сумм, а не среднее по листингам.
- [x] Фильтр `category=<uuid>` и `category=none` сужает строки; при фильтре итог — Σ выбранного, без «Нераспределено».
- [x] Ссылка с категории ведёт в «По SKU» с этим фильтром.
- [x] XLSX в режиме категорий: колонка «Категория», итог совпадает с экраном.
- [x] Чужие категории не попадают (область компании через фасад).

# WB finance report: товары, себестоимость и результат SKU

## Owner brief

Добавить в финансовый отчёт WB новый блок «Товары и себестоимость»:

- после блока «Расшифровка удержаний и выплат»;
- перед блоком «Сводка по reportId»;
- показать общие товарные итоги;
- обязательно показать продажи, возвраты, себестоимость и финансовый результат по каждому SKU;
- финансовые транзакции не читать и не изменять.

## Зафиксированные правила

- SKU отчёта — один вариант товара. Сопоставленный SKU определяется через
  `MarketplaceListing`; несопоставленный — через raw-идентификаторы
  `nmId + размер` или штрихкод.
- Разные размеры одного артикула продавца не объединяются.
- Продажа использует себестоимость на `saleDt`, затем `rrDate`, затем дату
  дневного raw-документа.
- Возврат использует себестоимость на `orderDt`, затем `saleDt`, затем
  `rrDate`, затем дату дневного raw-документа.
- Если дата предшествует первой записи истории себестоимости, используется
  самая ранняя доступная цена с видимым признаком fallback.
- Нулевая, отсутствующая или не-RUB себестоимость считается неизвестной.
- `нетто-себестоимость = себестоимость продаж − себестоимость возвратов`.
- `результат SKU = товарное «К перечислению» − нетто-себестоимость`.
- Результат и рентабельность SKU не отображаются как достоверные при неполном
  покрытии себестоимостью.
- Результат SKU не является чистой прибылью: логистика, хранение, штрафы и
  прочие нетоварные расходы WB по SKU не распределяются.

## Acceptance criteria

- Каждый товарный вариант с продажей или возвратом виден отдельной строкой.
- По каждому SKU видны количества, суммы, себестоимость, покрытие и результат.
- Сумма строк SKU сходится с общими товарными итогами.
- Несопоставленные и конфликтные SKU видимы и не теряются.
- HTML и CSV используют одинаковые данные и формулы.
- Фильтры периода и `reportId` применяются ко всему блоку.
- Нет N+1-запросов, новой схемы БД, новых зависимостей или нового frontend
  runtime.
- Существующие итоги отчёта сохраняют обратную совместимость.
- Таблицы финансовых транзакций не читаются и не изменяются.

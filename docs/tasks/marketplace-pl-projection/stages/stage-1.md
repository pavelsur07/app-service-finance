# Этап 1. Правила компании, шаблон платформы, подбор статьи

## 1. Задача

Дать проекции (этап 3) ответ на вопрос «в какую статью ОПиУ компании идёт операция канона»:
хранить правила компании, преднастройку платформы и выбирать правило для операции.

## 2. Результат

- Модуль `site/src/MarketplacePlProjection`, таблица `mpp_rule`:

  | Поле | Смысл |
  |---|---|
  | `kind` | вид канона; пусто у правила по коду источника |
  | `channel` | канал; пусто у правила по виду для всех каналов |
  | `source_type` | код источника (всегда с каналом) |
  | `valid_from` | с какого дня действует; базовое правило — `2000-01-01` |
  | `pl_category_id` | статья компании; пусто — «исключено из ОПиУ» |
  | `origin` | `preset` (из шаблона, обновляется шаблоном) / `custom` (решение компании) |
  | `template_version` | версия шаблона, записавшая `preset` |

  Одно правило на ключ и дату: unique `(company_id, kind, channel, source_type, valid_from)`
  `NULLS NOT DISTINCT`.
- Подбор — `Domain\RuleResolver`: среди правил, действующих на день, — код источника, затем вид × канал,
  затем вид; при равной точности — с более поздним `valid_from`. Нет правила — `null` («не сопоставлено»).
- Шаблон — `Domain\MappingTemplate` (код, версия `VERSION`): статья стандартного дерева на каждый вид
  канона и исключения по каналу и коду. Взят из легаси `default_cost_mapping.yaml` /
  `default_sale_mapping.yaml` по таблице `stage-1-category-levels.md`. Справочные виды (`spp`,
  `coinvestment`, `ads_settlement`) — исключены. Новый вид канона без строки шаблона роняет тест.
- `SyncTemplateAction` + `app:marketplace-pl-projection:sync-template --company-id=… [--execute]`:
  создаёт и обновляет `preset`-правила компании по кодам статей её дерева (`LEAF_INPUT`); ключ с
  правилом `custom` не трогает; статьи с кодом нет — правила нет (ключ в отчёте команды); ключ,
  ушедший из шаблона, — `preset` удаляется. Без `--execute` — только план.

Не входит: правка правил компанией (этап 4), перенос легаси (этап 2), расчёт (этап 3), cron.

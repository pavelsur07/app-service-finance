# Этап 3–4. Расчёт проекции и экран «ОПиУ» рядом с текущим расчётом

## 1. Задача

Показать ОПиУ маркетплейсов, посчитанный из канона по правилам «вид операции → статья», рядом с тем,
что сейчас попадает в ОПиУ, — чтобы сверять статьи до переключения.

## 2. Решение: без хранимой проекции

План был — таблица `mpp_day`, своя отметка «день изменился» в каноне и пересчёт по расписанию. Замер
прода 16.11.2026: группировка канона по (канал, кабинет, день, вид, код источника) у самой большой
компании (463 тыс. операций, 2,5 месяца) — 0,5 с, 1 883 строки. Разнесения по SKU здесь нет, поэтому:

- проекция считается при открытии отчёта (`ProjectionBuilder`), таблицы, миграции и cron пересчёта нет;
- правка правила видна сразу; тождество «канон = на статьи + исключено + не сопоставлено» — по построению;
- потолок: отчёт за год у крупной компании — 2–3 с. Станет мешать — витрина по дням, экран не меняется.

Этапы 3 и 4 (экран чтения) идут одним PR: без экрана расчёт на проде проверить нечем.

## 3. Результат

- `MarketplaceOperationsFacadeInterface::plSums(companyId, from, to, ?channel)` — Σ канона компании по дням,
  видам и кодам источника; `companyIds()` — компании с операциями канона.
- `ProjectionBuilder::build()` → `ProjectionReport`: строки «канал × вид × код × статус × статья»; статус —
  `mapped` / `excluded` (правило без статьи) / `unmapped` (правила нет).
- `Marketplace\Facade\LegacyPlPreviewFacadeInterface::amountsByCategory()` — суммы текущего расчёта по
  статьям (те же, что «Итого» предпросмотра ОПиУ). Единственная правка в легаси, только чтение.
- Экран `GET /marketplace/economics/pl` (вкладка «ОПиУ» раздела «Экономика маркетплейсов»): период, канал;
  дерево статей компании — «Новый расчёт», «Текущий расчёт», «Разница»; блок «Куда ушли операции»;
  таблицы «Не сопоставлено» и «Исключено из ОПиУ» по видам и кодам маркетплейса.
- Правила компаний: cron `40 * * * *` — `sync-template --all --execute` по компаниям с операциями канона.

Не входит: разрез по проектам (канал почти всегда равен проекту; добавить при сверке, если понадобится),
правка правил компанией (следующий этап), себестоимость, блок «Выручка с СПП».

# Stage 7: выгрузка xlsx

stage_base_commit: `bcbad7244`

## План этапа

### Что нужно

Кнопка «Скачать xlsx» на вкладке: тот же отчёт с теми же фильтрами в файл.

### Решения

1. **Маршрут** — `GET /marketplace/pl-preview/xlsx`, `marketplace_pl_preview_xlsx`, те же права.
   Фильтр — тот же `PlPreviewFilter::fromQuery()`, отчёт — тот же
   `BuildMarketplacePlPreviewAction`: экран и файл не могут разойтись.
2. **Писатель** — `Marketplace\Infrastructure\Export\PlPreviewXlsxExporter` на OpenSpout, по
   образцу `Finance\Infrastructure\Export\PlReportXlsxExporter`: шапка синим, отступ уровня
   неразрывными пробелами, строки с потомками жирные, числовые форматы по `PLValueFormat`
   (деньги `#,##0.00;(#,##0.00)` — как в выгрузке ОПиУ), «Итого» жирным. Значения — числами, а не
   текстом: файл должен считаться в Excel.
3. **Листы** (четыре — к трём из общего плана добавлена «Сверка»: это те же данные экрана, без
   неё файл не самодостаточен):
   - «ОПиУ по тегам» — период и маркетплейс строкой над таблицей, пометка о пересечении тегов,
     дерево по колонкам; пустые строки скрыты так же, как на экране (`empty=1` — показаны);
   - «Не попадёт в ОПиУ» — затраты без решения, продажи без правила, статьи вне отчёта (раздел на
     вид, у каждого своя шапка);
   - «Исключено» — затраты `include_in_pl = false`;
   - «Сверка» — итог, размечено, исключено, не размечено, расхождение; предупреждения ниже.
4. **Файл** — во временный файл, `BinaryFileResponse` с `deleteFileAfterSend`, имя
   `pl-preview_<from>_<to>.xlsx`, `Cache-Control: no-store` (как выгрузка ОПиУ).
5. **Ошибка периода** — ловится конкретное `MarketplacePlPreviewPeriodException`: flash и
   redirect на вкладку с теми же параметрами.

### Конечный результат

Владелец скачивает файл, где цифры совпадают с экраном, и может пересчитывать их в Excel.

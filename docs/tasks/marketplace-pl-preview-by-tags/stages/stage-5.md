# Stage 5: сборка отчёта по тегам

stage_base_commit: `d53691228`

## План этапа

### Что нужно

Один вызов, который по периоду, маркетплейсу и выбору тегов отдаёт весь отчёт: дерево ОПиУ с
колонками тегов, «Общие / без тега», «Итого», блоки «Не размечено», «Исключено», сверку и
предупреждения. Экран (этап 6) и xlsx (этап 7) только показывают этот результат.

### Решения

1. **Action** — `App\Marketplace\Application\Action\BuildMarketplacePlPreviewAction`
   (`final readonly`, `__invoke(BuildMarketplacePlPreviewCommand): MarketplacePlPreviewReport`).
   Только чтение: без `persist` / `flush`.
2. **Команда** — `companyId`, `from`, `to`, `?MarketplaceType marketplace`, `?list<string> tagIds`
   (`null` — все теги компании; список — только эти; чужие и несуществующие id молча
   отбрасываются — сверка со списком тегов компании).
3. **Период** — `from > to` или длиннее 366 дней → `MarketplacePlPreviewPeriodException`
   (доменное, `final`, код `invalid_period`): длинный период — полный скан по строкам и
   бессмысленный модуль по году.
4. **Колонки** — ключи `tag:<id>`, `common`, `total`; порядок — теги по имени, затем «Общие / без
   тега», затем «Итого».
   - Тег: сумма фактов листингов с этим тегом (полная сумма в каждый тег листинга).
   - «Общие / без тега»: факты без листинга и листингов **без единого тега** компании (а не
     «вне выбранных»): иначе колонка менялась бы от фильтра.
   - «Итого»: отдельный вызов фактов без разреза по листингам (этап 3, решение 5).
5. **Теги листингов** — `ListingTagAssignmentRepository::tagsForListings()` порциями по 5000 id
   (запрос с `IN`, один на порцию, без N+1).
6. **Дерево** — `FinanceFacade::calculatePlPreview()` одним вызовом со всеми колонками.
7. **Пересечение тегов** — флаг `tagsOverlap` (есть листинг с фактами и двумя и более
   выбранными тегами): экран пишет в шапке, что сумма колонок тегов ≠ «Итого».
8. **Блоки** — из этапа 4: `costCoverage` (все статусы; экран и xlsx сами берут `unmapped` /
   `excluded`), `costTotal` и `costReconciliationDelta` = total − Σ статусов, `salesCoverage`.
   Суммы статей, которые не попадут в отчёт (`unplaced` от Finance), — тоже в отчёт.
9. **Предупреждения** — ошибки формул дерева (Finance) и маркетплейсы с данными периода, у
   SELLER-подключения которых не задан проект: регистр ОПиУ пропускает операции без проекта
   (`PLRegisterUpdater`), такие суммы в отчёт ОПиУ не попадут. Правила продаж с собственным
   проектом это частично перекрывают — предупреждение говорит «могут не попасть».
10. **Результат** — `Application/DTO/MarketplacePlPreviewReport` + `MarketplacePlPreviewColumn
    (key, label, kind)`; `kind` — enum `PlPreviewColumnKind` (`tag` / `common` / `total`).

### Конечный результат

`BuildMarketplacePlPreviewAction` строит полный отчёт по данным компании; итог совпадает с
проведением, теги и «Общие» собраны по правилам Владельца.

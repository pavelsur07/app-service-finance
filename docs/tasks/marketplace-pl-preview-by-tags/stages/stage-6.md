# Stage 6: экран «Предпросмотр ОПиУ»

stage_base_commit: `55527aa29`

## План этапа

### Что нужно

Вкладка раздела «Маркетплейсы»: фильтры, таблица дерева ОПиУ по тегам и блоки «что не попадёт
в ОПиУ», «исключено», «сверка», предупреждения. Только показ результата
`BuildMarketplacePlPreviewAction`.

### Решения

1. **Слой** — легаси (Tabler): раздел Marketplace живёт в `marketplace/layout.html.twig`. Новая
   вкладка «Предпросмотр ОПиУ» после «Маппинг затрат» (вкладок > 6 — уходят в «Ещё»,
   `partials/_tabs`).
2. **Маршрут** — `GET /marketplace/pl-preview`, имя `marketplace_pl_preview_index`, `ROLE_USER` +
   `ModuleAccess::MARKETPLACE_READ` (как у соседних вкладок). Компания —
   `ActiveCompanyService::getActiveCompany()` до любого запроса.
3. **Фильтр** — `Application\PlPreview\PlPreviewFilter::fromQuery(array, today)`: `dateFrom` /
   `dateTo` (Y-m-d; по умолчанию — текущий месяц с 1-го по сегодня, как у оперативного закрытия),
   `marketplace` (значение `MarketplaceType` или пусто = все), `tags[]` (нет параметра = все теги),
   `empty=1` — показывать пустые строки. Невалидная дата или маркетплейс — значение по
   умолчанию, не 500. Тот же фильтр возьмёт выгрузка xlsx (этап 7).
4. **Пресеты периода** — `partials/_period_presets` в режиме ссылок (работают без JS).
5. **Ошибка периода** — контроллер ловит **конкретное** `MarketplacePlPreviewPeriodException` и
   показывает его текст в `alert-danger` вместо отчёта (правило HTML-контроллера в `CLAUDE.md`).
6. **Таблица** — как у отчёта ОПиУ (`finance/report/preview.html.twig`): колонка «Статья»
   закреплена слева, «Итого» — справа, отступ по уровню, строки с потомками жирные, отрицательные
   — в скобках (согласованный для ОПиУ бухгалтерский формат), деньги — `vf_amount`, процент /
   коэффициент — `vf_number`. Пустые строки (все колонки 0) скрыты, пока не выбран `empty=1`.
   Стили — небольшой `<style>` на семантических токенах (`--tblr-*`, `--vf-*`), без хардкода цвета.
7. **Пересечение тегов** — при `tagsOverlap` под заголовком таблицы строка: «Листинг с несколькими
   тегами входит в каждый — сумма колонок тегов не равна „Итого“».
8. **Блоки под таблицей** (`data-testid` для тестов):
   - «Не попадёт в ОПиУ»: затраты `unmapped` (маркетплейс, категория, строк, сумма) со ссылкой на
     «Маппинг затрат»; виды продаж без активного правила со ссылкой на «Маппинг ОПиУ»; суммы на
     статьях, которые не попадут в отчёт (`unplaced`, причина).
   - «Исключено из ОПиУ (справочно)»: затраты `excluded`.
   - «Сверка затрат»: итог, размечено, исключено, не размечено, расхождение (0 — «сходится»,
     иначе `alert-danger`).
   - Предупреждения — `alert-warning`.
   - Пустые блоки не выводятся; если всё размечено — короткое «Все данные периода попадут в ОПиУ».
9. Кнопка «Скачать xlsx» — на этапе 7.

### Конечный результат

Владелец открывает вкладку, выбирает период / маркетплейс / теги и видит будущий ОПиУ по тегам и
всё, что в него не попадёт.

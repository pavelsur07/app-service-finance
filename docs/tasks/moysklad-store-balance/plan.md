# МойСклад: склады → строки Баланса, ежедневная оценка и проводка

Склады приходят из МойСклад (`moysklad_stores`, у ИП Сухоносов 36 активных). Остатки по складам
синкаются вручную (`report/stock/bystore`, только количество, последний снимок 15.11.2026).
В Балансе книги не начаты ни у одной компании; проводки идут только из HTTP-сессии
(`BalanceAccess::require` требует текущего пользователя и активную компанию).

Решения Владельца (24.11.2026): склады МойСклад; оценка ежедневно; в деньгах — себестоимость
МойСклад; запись в Баланс — в этой задаче. Каждому складу назначается **счёт** Баланса.

## 1. Задача

Каждому складу МойСклад назначить счёт Баланса (или «не учитывать»), каждый день считать остаток
склада по себестоимости МойСклад и устанавливать остаток назначенного счёта в Балансе на дату.

## 2. Результат

### Этап 1. Назначения и настройки (MoySklad, миграция) — HIGH-LOCAL
- Таблицы `moysklad_store_balance_settings`, `_links`, `_runs`, `moysklad_store_valuations`,
  `moysklad_store_balance_postings` (`MoySkladSchemaExtension` + миграция `Version20261124180000`).
- `SaveStoreBalanceLinkAction` (склад → счёт актива или «не учитывать»), `SaveStoreBalanceSettingsAction`
  (корр. счёт, включено, автор). ID счетов проверяются через `BalanceFacade`.

### Этап 2. Баланс: счета, статус книги, проводка от имени автора — HIGH-LOCAL (auth, финансы)
- Методы существующего `final BalanceFacade` (отдельный интерфейс не вводится — единственная реализация):
  `getPostingAccounts`, `getBookStatus`, `canPostFromSource`, `setAccountBalanceFromSource`.
- `BalanceLedgerService::postDelegatedTargetBalance`: Δ = цель − остаток на дату, вторая строка —
  корреспондирующий счёт; Δ = 0 — ничего; повтор по ключу запроса → тот же документ.
- `BalanceAccess::lockForDelegatedMutation` / `allowsDelegatedPosting` — права автора без сессии.

### Этап 3. Оценка и ежедневный прогон — HIGH-LOCAL (cron, Messenger)
- Себестоимость — отдельной фазой оценки, не внутри снимка (синк снимка не меняется):
  `MoySkladClient::fetchStockCostPage` (`report/stock/all`), нет `price` → `forbidden`.
- После completed-снимка `ValueStoreStocksMessage` → `async_sync`; `ValueStoreStocksAction`:
  себестоимость (HTTP вне транзакции) → оценка складов (транзакция, замена) → проводка по счетам,
  итог счёта-дня в `moysklad_store_balance_postings`. Автор без прав → `skipped: actor_forbidden`.
- `app:moysklad:store-balance:daily` 23:30 МСК, `app:moysklad:store-balance:requeue` */15.

### Этап 4. Страница «Склады» (Twig, DS) — MEDIUM
- `/moy-sklad/connections/{id}/stores`: склад, выбор счёта (актив) или «не учитывать», остаток ₽ и
  дата последней оценки, статус проводки. Фильтр «без счёта», архивные скрыты, итог по счетам.
- Блок «Запись в Баланс»: корреспондирующий счёт, включить/выключить (автор = включивший), статус книги
  («Баланс не начат», ссылка на Баланс), последний прогон.

### Этап 5. Документация и handoff — LOW
- `ARCHITECTURE.md` (MoySklad, BalanceFacade, cron, Messenger), `handoff.md`.

Не меняем: синк каталога, маппинг, расчёты Баланса, ручные проводки.

## 4. Чек-лист приёмки

- [ ] Страница: 36 активных складов Сухоносова, архивные скрыты; в выборе только неархивные счета
      актива этой компании; чужой/архивный счёт не сохраняется (422).
- [ ] Повторное сохранение назначения и настроек не создаёт дублей.
- [ ] Оценка грузит себестоимость; без права «Видеть себестоимость» — понятная ошибка, прогон failed, снимок не трогается.
- [ ] Оценка склада = Σ остаток × себестоимость; повторная оценка снимка — те же строки и суммы.
- [ ] Проводка: остаток счёта на дату = сумма его складов; повтор прогона — тот же документ, число
      операций не растёт; Δ = 0 → `unchanged`.
- [ ] Книга не начата / период закрыт / нет корр. счёта / автор без прав → статус с причиной, без проводки.
- [ ] Права автора проверяются без сессии только для этой проводки; ручные пути Баланса не меняются.
- [ ] Тесты, PHPStan, CS зелёные; миграция отдельным релизом.
- [ ] После деплоя: сумма по 2–3 складам совпадает с отчётом «Остатки» МойСклад по себестоимости
      (сверяет Владелец).

Риск: себестоимость в МойСклад может быть общей на компанию, а не по складу — тогда оценка склада =
остаток склада × общая себестоимость единицы, что совпадает с тем, как МойСклад считает «Сумму
себестоимости» по складу. Проверяется на приёмке.

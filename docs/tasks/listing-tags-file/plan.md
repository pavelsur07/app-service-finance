# Теги листингов через файл (выгрузка → правка в Excel → загрузка)

Класс: Small (один модуль Marketplace, без схемы, Messenger и миграций). Риск: MEDIUM.

## 1. Какую задачу решаем

Тег назначается листингам только из UI реестра: выделить строки, выбрать тег.
Разметить сотни листингов разными тегами так долго. Нужна массовая правка
через файл: выгрузить листинги, вписать теги в Excel, загрузить обратно.

## 2. Что будет результатом

- Кнопка «Скачать для разметки» в реестре `/marketplace/listings`: xlsx по
  текущему фильтру (не больше 5000 строк). Лист «Листинги»: `listing_id`,
  Маркетплейс, Артикул продавца, SKU площадки, Размер, Название, **Теги** (через `;`).
  Лист «Теги» — существующие теги, лист «Инструкция».
- Кнопка «Загрузить разметку»: файл → **предпросмотр** (ничего не пишет):
  сколько связей добавится и снимется, какие теги будут созданы, ошибки по
  строкам. Два режима:
  - «Добавить» (по умолчанию): теги из ячейки дописываются, существующие остаются;
  - «Заменить»: у листинга остаются ровно теги из ячейки.
  Пустая ячейка не меняет ничего ни в одном режиме; `-` в ячейке снимает все
  теги листинга. Строки, которых нет в файле, не трогаются никогда.
- «Применить» — одна транзакция; применяется только план с тем же отпечатком,
  что был на экране, иначе «данные изменились, загрузите файл заново».

## 3. Что считаем выполненной работой

- `ImportListingTagsAction` (план + применение), `ListingTagsFileReader`
  (xlsx → строки), `ListingTagsXlsxExporter`, два контроллера и шаблон предпросмотра.
- Тесты зелёные, гейты зелёные, `ARCHITECTURE.md` («теги листингов») обновлён.
- Внутреннее ревью свежим взглядом без BLOCKER/IMPORTANT, PR открыт.

## 4. Чек-лист приёмки

- [ ] Выгрузка повторяет фильтр реестра; > 5000 → понятный отказ.
- [ ] Строки выгрузки записаны текстовыми ячейками: `=…` не превращается в формулу, SKU не теряет нули.
- [ ] Ключ строки — `listing_id`; файл без колонок `listing_id`/`Теги` → понятный отказ.
- [ ] Чужой/несуществующий `listing_id` → ошибка строки, ничего не пишется по нему (IDOR).
- [ ] Пустая ячейка ничего не меняет; `-` снимает все теги.
- [ ] «Добавить» не снимает существующие теги; «Заменить» снимает только у строк файла.
- [ ] Новые теги создаются один раз (slug), «Зима»/«зима » — один тег.
- [ ] Тег длиннее 50 символов, дубль `listing_id` → ошибка строки.
- [ ] Повторная загрузка того же файла → «Изменений нет», число связей не меняется.
- [ ] Изменения между предпросмотром и применением → отказ по отпечатку, без записи.
- [ ] Лимиты: только xlsx, до 2 МБ, до 5000 строк.
- [ ] Права: выгрузка — `MARKETPLACE_READ`, загрузка и применение — `MARKETPLACE_WRITE` + CSRF.

## Не делаем (follow-up)

- CSV: русский Excel сохраняет его в cp1251 с `;` — источник кракозябр; xlsx достаточно.
- Сопоставление по артикулу без `listing_id`, фоновая обработка > 5000, журнал с отменой.
- Выпадающий список в ячейке (Data Validation): лист «Теги» как справочник.

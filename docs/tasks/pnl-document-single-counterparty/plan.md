# Задача: один документ ОПиУ — один контрагент

Поручение Владельца (29.10.2026): контрагент выбирается только в шапке
документа и передаётся в операции при создании; бизнес-правило «один документ
на одного контрагента» — проверка на уровне сущности/домена; в форме поле
контрагента — только в шапке; проверить операции на проде; починку
расходящихся документов на проде Владелец разрешил (AGENTS §3.3, 29.10.2026).

Каждый этап — файл `stages/stage-N.md` из четырёх частей (задача, результат,
что считаем выполненным, чек-лист приёмки); план пишется до работ, итог
дописывается в тот же файл и сверяется с чек-листом.

| Этап | Что | Статус |
|---|---|---|
| 0 | Аудит кода, замеры прода «до», решения | готово |
| 1 | Правило в агрегате `Document` (контрагент операции = контрагент шапки), все пути создания, контракт команды; поле убрано из формы операции и ячейка из шаблона (без них правило не собрать) | готово |
| 2 | Клиент: скрипты подстановки/дубля, сетка строки 1440/1024/390, e2e правки и создания, скриншоты | — |

| 4 | Гейты, ревью, `ARCHITECTURE.md`, handoff «run the migration and deploy» | — |

Ветка `feat/pnl-document-single-counterparty`, один PR: правило без формы и
форма без правила смысла не имеют, миграция должна пройти до кода (порядок
`migrations` → `deploy`, `docs/workflow/release.md`). Коммиты этапов локально,
push и PR — одним шагом на handoff.

## Решения
1. Источник правды — `documents.counterparty_id`. Колонка
   `document_operations.counterparty_id` остаётся копией, которую ведёт только
   агрегат (её читают журнал операций, экспорт JSON, RawPl-отчёт). Удаление
   колонки — отдельная задача (contract-шаг), не здесь.
2. У `DocumentOperation` нет публичного способа задать контрагента. Значение
   берётся только из документа: при привязке к документу и при смене
   контрагента шапки (`Document::setCounterparty()` переносит его на все
   операции). Состояние «операция с чужим контрагентом» через API построить
   нельзя — правило держит структура агрегата, а не проверка после факта.
3. Форма: поле `counterparty` только в `DocumentType`; из
   `DocumentOperationType` удаляется вместе с опцией `header_counterparty_id`.
4. Починка: шапка пустая и у операций ровно один контрагент своей компании →
   он переходит в шапку; затем всем операциям — контрагент шапки. Документ с
   несколькими разными контрагентами операций — миграция останавливается
   (на проде таких 0). Старые значения — в таблицу бэкапа, `down()`
   восстанавливает.

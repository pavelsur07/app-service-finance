# Stage 3 — миграция с данными: починка расходящихся документов

## 1. Какую задачу решаем
На проде 5 ручных документов, где контрагент операции расходится с шапкой
(Stage 0). После Stage 1 первое сохранение такого документа молча
перезаписало бы операции контрагентом шапки — у четырёх с пустой шапкой
контрагент пропал бы. Починить данные до выкладки кода, без потерь и с
возможностью отката. Разрешение Владельца на починку — 29.10.2026 (§3.3).

## 2. Что будет результатом
- Миграция `Version20261029120000`:
  - проверка до изменений: документ с пустой шапкой и несколькими разными
    (или чужой компании) контрагентами операций — `abortIf`, без изменений;
  - бэкап всех операций затронутых документов в
    `document_counterparty_repair_backup` (старые значения шапки и операции);
  - шапка пуста и у операций один контрагент → он в шапку;
  - всем операциям — контрагент шапки;
  - `down()` восстанавливает значения из бэкапа и удаляет таблицу.
- Integration-тест миграции: сценарии «поднять в шапку», «шапка побеждает
  пустую операцию», «согласованные документы не трогаются», «неоднозначный
  документ → abort», `down()` возвращает исходное.
- Прогон на локальной БД стенда: замеры до/после.
- Ожидание на проде (Stage 0): документов с контрагентом 480 → 484,
  операций с контрагентом 490 → 491, расхождений 5 → 0, сумма операций
  187 824 127,09 без изменений, в бэкапе 5 строк.

## 3. Что считаем выполненной работой
Тест миграции зелёный; локальный прогон up → down → up сходится с
ожиданием; регистр ОПиУ не затронут; план сверки после прода записан.

## 4. Чек-лист приёмки
- [x] Неоднозначные данные останавливают миграцию до изменений
- [x] Бэкап содержит все операции затронутых документов до изменения
- [x] Пустая шапка + один контрагент операций → контрагент в шапке
- [x] Заданная шапка → операции получают её контрагента
- [x] Согласованные документы не меняются
- [x] `down()` возвращает исходные значения и удаляет бэкап
- [x] Локальный прогон up/down/up: счётчики и суммы сходятся
- [x] Сверка после прода описана (запросы и ожидаемые числа)

       (SELECT count(*) FROM document_operations o JOIN documents x ON x.id = o.document_id

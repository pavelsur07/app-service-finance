# Stage 2 — клиент: скрипты, сетка строки, e2e

## 1. Какую задачу решаем
После Stage 1 у строки операции нет поля контрагента. Убрать из клиента всё,
что его обслуживало, проверить раскладку строки на 1440/1024/390 и закрепить
поведение браузерными сценариями правки и создания.

## 2. Что будет результатом
- `_page_scripts.html.twig`: без `documentCounterpartyField`, без подстановки
  контрагента в новую строку и без `[data-operation-counterparty]` в дубле;
  неиспользуемый `prefill` удалён, если больше не нужен.
- `vf-custom-classes.css`: правила `.vf-docform-op__cell--counterparty`
  удалены; комментарий к сетке («третьей строкой — контрагент операции»)
  исправлен. Сетка строки: две строки (поля + «Описание»).
- e2e `pnl-document-page.e2e.cjs` и `pnl-document-new.e2e.cjs`: проверка
  «в строке операции нет поля контрагента, в шапке — есть»; оба сценария
  зелёные на стенде; скриншоты правки 1440 и 390, создания 1440.
- eslint, `lint:twig`, сборка — OK.

## 3. Что считаем выполненной работой
Клиент не ссылается на удалённое поле; e2e обоих сценариев зелёные без
ошибок JS; на скриншотах строка операции — без пустой третьей строки и без
горизонтального скролла на 390.

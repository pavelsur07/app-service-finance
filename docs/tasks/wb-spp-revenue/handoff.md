# Handoff: WB — выручка без СПП / с СПП при закрытии месяца

**Дата:** 2026-07-06
**PR:** #2108 (формулы и ключи), #2109 (кнопка «Обработать месяц»)
**Статус:** код смержен и задеплоен; данные PROD исправлены; закрытия по b57d7682 перепроведены, по 19621cff — ожидают Владельца.

## Проблема

При закрытии июня 2026 статьи «Продажи без СПП» (REV_NOT_SPP) и «Продажи с СПП»
(REV_SPP_SALES) были равны (1 584 515.68), хотя реальная выручка с СПП — 916 861.78
(СПП ≈ 45%).

## Причины (3 бага)

1. **Формула «без СПП»**: `grossWithoutSpp = |forPay| + комиссия + эквайринг` —
   реконструкция не сходится с ценой продавца в finance API (forPay учитывает
   СПП-компенсации WB; 0 совпадений из 2423 строк). Правильно: `retailPriceWithDisc × qty`.
2. **Ключи комиссии**: finance API отдаёт `vw`/`vwNds`, нормализатор читал
   `ppvzVw`/`ppvz_vw` → комиссия WB = 0 (ломало и WbCommissionCalculator, затраты).
3. **Исторические данные**: июнь был импортирован кодом до 709ad606, где оба поля
   заполнялись из retailPriceWithDisc → статьи идентичны.

Дополнительно: кнопка «Обработать месяц» (/marketplace) не переобрабатывала
существующие строки — диспатчила шаги без `forceRefresh`, srid-дедупликация
молча пропускала продажи/возвраты (#2109).

## Изменённые контракты / публичное поведение

- `WbSalesReportRowNormalizer::grossWithoutSpp()` — новая семантика: цена продавца × qty.
- `ppvzVw()`/`ppvzVwNds()` — читают также `vw`/`vwNds`.
- Кнопка «Обработать месяц» — теперь force-переобработка (только WB, только

- Миграций БД нет. messenger.yaml не менялся.

## Дополнение 2026-07-06 вечер: Комиссия МП (PR #2111)

Статья «Комиссия МП» считалась как `|vw| + |vwNds|` — занижение вдвое: `vw` в
finance API это вознаграждение за вычетом СПП-компенсаций WB (при СПП > кВВ —
отрицательное). Утверждённая Владельцем формула (официальная формула WB,
тождество на 2423/2423 строках июня):

    Комиссия МП = retailPriceWithDisc × qty − |forPay| − |acquiringFee|

Реализовано в `WbSalesReportRowNormalizer::commissionAmount()` +
`WbCommissionCalculator` (возврат — сторно той же формулой) + legacy-адаптер.
Ожидание за июнь (b57d): 463 850.52 charge − 1 144.09 сторно = 462 706.43 нетто
(29.3% от продаж без СПП, 50.6% от выручки с СПП). СПП-скидка и вознаграждение
ПВЗ входят в эту сумму; ПВЗ-калькулятор двойного счёта не создаёт (берёт только
строки «Возмещение за выдачу…»).

# Вкладка «Склады» МойСклад — удобный разбор

**Risk:** LOW-LOCAL — шаблон, контроллеры и Action модуля MoySklad, без миграций и Messenger.

## 1. Задача
Разбор 30–40 складов сейчас — форма и перезагрузка на каждую строку, предложение отдельным блоком под списком,
настройки всегда раскрыты, фильтр «Все / Без счёта». Сделать разбор одной отправкой (предложение Владельцу 28.11, «Делай»).

## 2. Результат
- Одна форма на таблицу: `links[<склад>][target]` + `links[<склад>][was]` (состояние на момент показа), POST
  `moysklad_store_balance_links`; `SaveStoreBalanceLinksAction` пишет только изменённые строки, каждую своей транзакцией
  `SaveStoreBalanceLinkAction(..., expected: was)`: склад, изменённый после показа страницы, пропускается.
- Уверенное предложение подставлено в список (`was` = пусто) — «Сохранить» его принимает; неуверенное — подсказкой
  «проверьте», список пуст. Причина и предупреждение видимы. «Принять» и «Принять все уверенные» убраны
  (`moysklad_store_balance_link`, `moysklad_store_accept_suggestions`, `AcceptStoreAccountSuggestionsAction`).
- Метка статуса строки; вкладки «Требуют решения / Назначены / Не учитываются / Все» (по умолчанию — первая, если не пусто;
  старый `filter=unassigned` = «Требуют решения»); сортировка по убыванию остатка; счета группами «Запасы» / «Другие счета актива».
- Закреплённая панель «Сохранить · N» / «Сбросить»; Stimulus `store-links` считает изменения и подсвечивает строки
  (без JS форма работает).
- Настройки записи — `<details>`, свёрнуты в строку, когда заданы и книга начата.

## 3. Выполнено, когда
Пакет сохраняет только изменённое, не перетирает чужие правки, отказ по складу не отменяет остальные; без права
проводить — ничего не записано; тесты и гейты зелёные; скриншот со стенда.

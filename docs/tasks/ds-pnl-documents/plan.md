## Stage 1: фильтры и итоги списка (бэкенд)
Risk: HIGH-LOCAL (легаси-контроллер, денежные итоги)
Definition of Done:
- `DocumentListDTO`: `q`, `projectDirection` (uuid), `responsibilityCenter` (uuid), `direction` (`income`/`expense`); мусор = «не задан».
- `findByCompany`: `q` — описание, номер, контрагент документа, статья операции (LIKE с экранированием); проект и ЦФО —
  у документа или у любой его операции; направление — есть операция со статьёй этого `flow`. Фильтры по операциям —
  `EXISTS`, а не `WHERE` по fetch-join'у (иначе коллекция операций гидрируется неполной и суммы врут).
- Итог по всей выборке: число документов, операций, Доход/Расход/Результат — один агрегатный запрос в репозитории,
  readonly-DTO. Операция без статьи в Доход/Расход не входит (как сейчас в шаблоне).
- Названия ЦФО страницы — новый метод `FinancialResponsibilityCenterFacade::getNamesByIds()` одним запросом;
  `ARCHITECTURE.md` обновлён.
- Число запросов не растёт с числом документов (тест); company-изоляция каждого фильтра и итога (тест).
Work items:
- 1.1 — DTO + unit-тесты нормализации.
- 1.2 — репозиторий: фильтры + агрегат итогов; функциональные тесты.
- 1.3 — Facade ЦФО (батч) + тест; контроллер передаёт итоги, названия ЦФО, списки проектов/ЦФО/типов для фильтров.
Stage checks: `tests/Functional/Finance`, unit DTO, PHPStan и cs по изменённым файлам.
Reviewer focus: IDOR в EXISTS-подзапросах, корректность сумм при фильтре по операциям, стабильность пагинации.

## Stage 2: вёрстка списка
Risk: MEDIUM
Definition of Done:
- Название «Документы ОПиУ»: `title`, H1, крошки, `_tabs`, тексты удаления/восстановления; адреса не меняются.
- Карточка: вкладки → строка фильтров (поиск, пресеты-ссылки, период, сегмент Все/Доходы/Расходы, пилюли Тип/Проект/ЦФО/
  Контрагент, «Ещё фильтры» = offcanvas со статусом и номером) → чипсы «Применено» / «Сбросить всё» → полоса итога →
  таблица → пагинация 20/30/50 с фильтрами.
- Колонки по SPEC, раскрытие операций через `<details>` без JS, сворачивание ≤1340 px, меню строки с модалкой удаления,
  пустые состояния «нет документов» и «ничего не найдено».
- Деньги — `vf_amount`; токены `--vf-*`, без хардкода цветов и `style=`.
- Скриншоты 1440 / 1280 / 1100, без горизонтального скролла страницы.
Work items:
- 2.1 — переименование + шапка + вкладки со счётчиком.
- 2.2 — строка фильтров, чипсы, полоса итога.
- 2.3 — таблица, раскрытие, адаптив, меню, пустые состояния; правка затронутых тестов.
Stage checks: `tests/Functional/Finance`, `lint:twig`, `npm run lint`, `npm run build`, smoke в headless Chromium.

## Stage 3: страница документа (PR 2)
Risk: MEDIUM
Definition of Done:
- `edit`/`new` (и `copy`, он рендерит `new`): шапка «Документ ОПиУ № …» с бейджами и «Ещё» (JSON, Копировать, Удалить),
  секции «Основные данные», «Основание» (если есть `cashTransaction`), «Сверка с основанием» (`transactionAllocation`),
  «Операции документа» таблицей на всю ширину с итогами Доход/Расход/Итог (клиент, подсказка) и «+ Добавить операцию».
- Ошибки: под полем + сводка наверху, фокус на первое невалидное; подтверждение ухода с несохранёнными правками.
- Сохранены prototype коллекции, префилл контрагента/проекта/ЦФО, все `data-*`-хуки, имена полей, CSRF.
- `show`, `deleted_index` — те же токены и таблица, без новых функций. «История» не делается.
Stage checks: `tests/Functional/Finance`, `lint:twig`, `npm run lint/build`, smoke создания/правки/ошибки/ухода.

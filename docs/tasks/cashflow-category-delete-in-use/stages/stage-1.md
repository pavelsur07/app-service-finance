# Этап 1 — удаление статьи ДДС, по которой есть операции (GlitchTip #449)

Класс: Small (модуль Cash, без схемы). База этапа: `fae6885a6` (master).

## Какую задачу решаем

`POST /cashflow-categories/{id}/delete` отдаёт 500, если на статью ссылаются
строки других таблиц: FK `cash_transaction`, `cash_transaction_split`,
`payment_plan`, `cash_transaction_auto_rule` без `ON DELETE`.
`CashflowCategory::assertCanDelete()` проверяет только «системная» и «есть
дочерние». 29.10.2026: 30 событий #449, 5 статей, одну пытались удалить больше
20 раз.

## Что будет результатом

- Action перед удалением считает, сколько раз статья используется (Query с
  `company_id`). Если используется — бросает `CashflowCategoryInUseException`
  с числами. FK-отказ в гонке переводится в то же исключение.
- Контроллер показывает flash `danger` вместо 500.
- Вместо `confirm()` открывается модалка (`partials/_confirm_modal`). Если
  статья используется: заголовок «Статью нельзя удалить», в тексте числа,
  кнопки «Удалить» нет, есть ссылка «Показать операции» (список ДДС с фильтром
  по статье). Если не используется — обычное подтверждение с красной кнопкой.
- Переноса операций и архива в этапе нет.

## Что считаем выполненной работой

Код, тесты, гейты на изменённых файлах, внутреннее ревью, PR. После деплоя на
проде повторное удаление такой статьи даёт flash, а не новое событие #449.

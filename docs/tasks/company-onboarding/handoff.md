# Handoff — онбординг новой компании

Ветка `feat/company-onboarding`, база `7939a22f6`. Миграций нет.

## Что получает новая компания

После регистрации, создания через админку и `/company/new`, в одной транзакции с компанией:

| Пункт | Кто создаёт | Было |
|---|---|---|
| «Основной счет» BANK RUB | Cash по `CompanyCreatedEvent` | был, создавал Company |
| Касса «Основная» CASH RUB | Cash | **новое** |
| Проект «Общий», ЦФО «Общий» | Company | был, без изменений |
| 7 системных статей ДДС | Cash | был, без изменений |
| Дерево ОПиУ (70 статей шаблона) | Finance | **новое** (раньше только вручную) |
| Книга и 33 статьи Баланса | Balance | был |
| Учётные счета Баланса «Расчётный счёт (основной)», «Касса (основная)» | Balance | **новое** |

Сбой любого шага откатывает создание компании целиком (проверено тестом).

## Существующие компании

- При первом открытии Баланса компания без структуры получает структуру и счета (ленивый сид).
- Остальное — командой `app:company:onboarding-backfill`: по умолчанию dry-run (отчёт по
  пунктам, `-v` — по компаниям); запись — `--execute --expected-count=<из dry-run>`.
  Дозаполняет только где данных этого вида нет совсем: касса — нет кассового счёта; ОПиУ — нет
  ни одной статьи; счета Баланса — нет ни одного счёта.
- **На проде команда не запускалась.** Запуск — отдельное одобрение (AGENTS §3.3), плюс для
  запуска через `codex-console` её нужно добавить в whitelist wrapper'а (тоже отдельное
  одобрение). Перед `--execute` стоит посмотреть dry-run: касса и счета Баланса появятся и у
  компаний, где пользователь удалил все свои счета сам.

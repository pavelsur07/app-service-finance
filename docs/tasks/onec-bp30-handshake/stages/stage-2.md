# Этап 2. Создание подключения в кабинете

Риск HIGH-LOCAL. Форма владельца открывается из меню компании. Проверяются владелец активной компании, право записи при POST и CSRF. Владелец видит адрес и одноразовый токен; показываемый токен отсутствует в последующих GET. Маршруты выдачи и приёма токена защищены от записи в профайлер. Функциональные проверки используют штатный HTTP-клиент Symfony.

Внутреннее ревью выявило риск двойного POST формы. Теперь ID формы, связанный с CSRF, становится первичным ключом подключения. Повтор даже с действительным CSRF оставляет один аудит и прежний токен. Контракт v1 и документация кабинета находятся в docs/integrations/onec/.

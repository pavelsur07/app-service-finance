## 1. Какую задачу решаем

Сервер уже умеет искать по всем листингам и назначать тег по фильтру
(этапы 1–2), но страница этим не пользуется: поле поиска всё ещё фильтрует
строки в браузере, select маркетплейсов строит ссылки без `q`/`tag`,
фильтра по тегу нет, «выбрать все» ограничено страницей, а после назначения
тега страница молча перезагружается.

## 2. Что будет результатом

Шапка таблицы — одна GET-форма фильтров:

- скрытый `filter` (вкладки-карточки сверху не меняются);
- `select name="marketplace"`: «Все маркетплейсы» + значения enum;
- `select name="tag"`: «Все теги», «Без тегов», теги компании;
- `input name="q"`, placeholder «Поиск по названию, артикулу, SKU»;
  отправка по Enter; select'ы отправляют форму по `change`;
  пустые поля перед отправкой отключаются — в адресе нет `q=&tag=`.

Под шапкой — строка «Найдено: N» и ссылка «Сбросить» (если активны
`q`, `tag` или `marketplace`). Пустой результат при активном фильтре —
«Ничего не найдено. Измените запрос или сбросьте фильтры», а не «загрузите
данные».

Панель массовых действий:

- отмечены все строки страницы и N больше числа строк → строка
  «Выбраны K на странице. **Выбрать все N по текущему фильтру**»;
- режим «все по фильтру»: «Выбраны все N по фильтру. **Снять выбор**»,
  счётчик показывает N; снятие любой галочки возвращает режим страницы;
- назначение в режиме фильтра → диалог подтверждения в разметке
  DS-Feedback (`vf-confirm`): «Присвоить тег «X» N листингам?», в теле —
  описание фильтра (поиск, маркетплейс, привязка, тег);
  тело запроса — `{filter: <применённый сервером>, tagId | name}`;
- фильтр для API берётся из `data-applied-filter` (JSON `filter_params`,
  экранирован `e('html_attr')`), не из поля ввода;
- ошибки назначения и снятия — видимым текстом в панели
  (`alert alert-danger`, `role="alert"`), не только `alert()`;
- после успеха — перезагрузка и `alert alert-success` над таблицей:
  «Тег «X»: назначен A листингам» + «, у B уже был» при B > 0. Сообщение
  передаётся через `sessionStorage` в `try/catch`; без хранилища
  перезагрузка проходит без сообщения.

Удаляется клиентский поиск по строкам и `onchange`-навигация select'а.

Отклонения от плана этапа:

- Ошибки показываются не в панели массовых действий, а отдельным
  `alert-danger` над таблицей: панель скрыта, когда ничего не выбрано, и
  ошибка снятия тега (`detach`) была бы невидима.
- Повтор назначения без новых связей формулируется «Тег «X» уже был у всех
  N листингов» — «назначен 0 листингам» читалось как сбой.
- Подтверждение — собственная разметка `vf-confirm` в шаблоне, а не partial
  `_confirm_modal`: тот отправляет форму с CSRF, здесь JSON-запрос. Без
  Bootstrap — `window.confirm` как запасной путь.

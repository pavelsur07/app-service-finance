# Перенос категорий ОПиУ файлом между компаниями и аккаунтами

## Задача

1. Выгрузить категории ОПиУ компании в файл.
2. Загрузить категории ОПиУ из файла в другую компанию — как в том же аккаунте,
   так и в другом.

## Контекст

Перенос уже существует, но только внутри одного аккаунта: экран
`/pl-categories/import` копирует дерево напрямую из другой компании, доступной
текущему пользователю (`PLCategoryController::import()`,
`site/src/Finance/Controller/PLCategoryController.php:54`). Между разными
аккаунтами переноса нет — явный follow-up предыдущей задачи
(`docs/tasks/pl-category-import/handoff.md`).

Выгрузка формально есть (`GET /pl-categories/export/json`), но это не файл:
экран забирает JSON через `fetch()` и выводит в `<pre>` для копипаста.

Движок переноса (`ImportPLCategoryTreeAction`) написан и покрыт тестами:
матчинг по `code` с фолбэком на `(parent, name)`, диффы, валидация глубины,
освобождение кодов, одна транзакция. Единственное, что мешает переносу между
аккаунтами, — Action сам ходит в БД за деревом компании-источника.

Набор полей в `serializeCategory()` уже точно совпадает с тем, что применяет
`applyFields()`. Экспорт уже является валидным payload'ом импорта.

Отсюда суть: не новый импорт, а **развязка источника от движка** и доставка того
же дерева через файл.

## Решения Владельца

- Формулы со ссылками на коды, отсутствующие в целевой компании: предупредить в
  предпросмотре, импорт не блокировать.
- Объём — только ОПиУ. `CashflowCategory` (ДДС) и `BalanceCategory` не трогаем.
- Только UI, консольной команды не делаем.

## Ограничения

- Категории целевой компании, отсутствующие в источнике, не удаляются и не
  изменяются (импорт, а не синхронизация).
- Режим «из другой компании» остаётся в UI.
- Импорт всегда в активную компанию; `id` и любые идентификаторы компании из
  файла не используются.
- Миграций нет, схема не меняется.

## Acceptance

- Файл, выгруженный в компании A (аккаунт 1), загружается в компанию B
  (аккаунт 2) с предпросмотром «создать / обновить / без изменений».
- Повторная загрузка того же файла идемпотентна.
- Битый, чужой или слишком большой файл даёт понятную ошибку, а не 500; БД при
  этом не меняется.
- Поведение переноса компания→компания не изменилось.

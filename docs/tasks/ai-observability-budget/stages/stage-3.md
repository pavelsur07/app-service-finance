# Этап 3. Лимиты расходов и глубина выгрузки

## Задача
Не дать ИИ потратить больше заданного на компанию и в сумме; не отправлять при включении
больше истории, чем нужно.

## Результат
- `ai_company_access`: `monthly_limit_rub` (по умолчанию 500), `lookback_days` (7/30/90,
  по умолчанию 90).
- `RequestCashAiCategorizationAction`: перед запуском — расход компании за месяц ≥ лимита
  или общий расход ≥ `ai.monthly_limit_rub` → остановка, `skippedReason = budget_exceeded`,
  warning; окно кандидатов — `lookback_days` компании.
- Переотправка задач без ответа лимитом не останавливается (тот же ключ — сервис не платит
  повторно за уже выполненное).
- `SetAiCompanyAccessAction` принимает лимит и глубину; новый `UpdateAiCompanyLimitsAction`.

## Что считаем выполненным
Код, миграция, тесты в той же ветке.

## Чек-лист приёмки
- [x] расход ниже лимита — запрос идёт; достиг лимита — новые пачки не отправляются
- [x] общий лимит останавливает все компании
- [x] новый месяц — лимит снова доступен
- [x] глубина 7 дней — операции старше 7 дней не отправляются
- [x] лимит ≤ 0 или глубина вне 7/30/90 — отказ валидации

## Итог
Готово. Миграция `Version20261106110000` — `monthly_limit_rub` (500) и `lookback_days` (90) с CHECK.
Лимит проверяется раз на запуск компании: перерасход — не больше одной пачки (200 операций). Пока есть
запросы без ответа или истёкшие без ответа за 7 дней — новые пачки не уходят (`awaiting_results`),
истечение пишется ERROR. Общий лимит — параметр `ai.monthly_limit_rub` (5000 ₽).
Тесты: `AiCompanyLimitsTest`, `CashAiCategorizationTest`.

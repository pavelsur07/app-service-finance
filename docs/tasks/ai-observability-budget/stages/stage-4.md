# Этап 4. Страница «ИИ» кабинета в админке

## Задача
Администратор видит работу ИИ по кабинету и задаёт лимит и глубину.

## Результат
- `GET /admin/ai/companies/{companyId}`: статус подключения, последний запуск и его итог,
  запуски за 7 дней, подсказки за 7 дней по статусам и доля принятых, расход за месяц /
  лимит, токены; форма «лимит, глубина» (POST, CSRF).
- Подключение с выбором глубины и лимита — формой на странице кабинета; быстрая отметка в
  `/admin/users` подключает со значениями по умолчанию (500 ₽, 90 дней), это написано в диалоге.
- В `/admin/users` у кабинета — ссылка «ИИ ›» на страницу и пометка «Лимит ИИ исчерпан».
- Страница — в модуле Admin: Cash зависит от ServiceGateway, страница в ServiceGateway с
  чтением Cash дала бы цикл модулей.

## Что считаем выполненным
Код, functional-тесты.

## Чек-лист приёмки
- [x] страница: данные кабинета, без N+1 (фиксированное число запросов)
- [x] форма лимита: сохраняет, неверные значения → ошибка, не 500
- [x] не-админ → 403, чужой/несуществующий id → 404
- [x] подключение со страницы с глубиной 30 → `lookback_days = 30`
- [x] пометка «лимит исчерпан» при расходе ≥ лимита

## Итог
Готово. `/admin/ai/companies/{companyId}` (модуль Admin): состояние, расход/лимит, подсказки за 7 дней,
последние 50 запусков, форма лимитов; подключение со страницы с выбором глубины. В «Кабинетах» — ссылка
«ИИ ›» и пометка «Лимит ИИ исчерпан». Запросы страницы — фиксированный набор, без циклов по строкам
(проверено по коду). Тест: `AdminAiCompanyPageTest`. Внешнее ревью Codex — 4 раунда, итог REVIEW_GREEN.

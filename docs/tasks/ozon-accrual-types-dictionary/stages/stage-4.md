# Stage 4: очередь новых типов, загрузка отчёта и споры в админке

## 1. Какую задачу решаем

После Stage 1–3b новый тип Ozon сам получает код, название и группу (из отчёта
кабинета или правил), но остаётся `known = false` — в очереди разбора. Нужно:
- увидеть новые типы с предложением и подтвердить их одним действием;
- загружать отчёт «Детализация начислений» без консоли;
- разбирать спорные группы (отчёт подтвердил другую группу, чем уже подтверждённая);
- закрыть дыры из ревью Stage 3b: ручной маппинг без актора выглядит автоматическим
  и перекрывается группой Ozon; группа маппинга — свободный текст (на проде уже есть
  «Другие услуги и⏎штрафы»); параллельная загрузка отчёта.

Страница — существующая `/admin/ingestion/external-categories` (`src/Admin`,
`ROLE_ADMIN`; правка админки разрешена Владельцем).

## 2. Что будет результатом

- **Очередь «Новые типы Ozon»** — `OzonAccrualTypeQueueQuery` (DTO): типы из
  справочника с транзакциями `known = false`: `type_id`, `name`, `description`, число
  строк, первая/последняя дата, текущий тип транзакции; предложение — код, название,
  группа и её источник («отчёт Ozon» / «правило» / нет).
- **`ConfirmOzonAccrualTypeAction(typeId, groupCode, label, actorUserId)`**: для каждой
  неразобранной `ExternalCategory` этого типа создаёт маппинг по умолчанию через
  `UpdateExternalCategoryMappingAction` — код и название из справочника, группа из
  закрытого списка, `known = true`, **тип транзакции = текущий тип строк** (ключ не
  меняется; перетипизация — отдельная операция), актор обязателен.
- **Загрузка отчёта** (форма: компания + файл, dry-run / execute) → читатель +
  `ImportOzonAccrualDetailsAction`; таблица результата на странице. Импорт под
  `pg_advisory_xact_lock` в транзакции.
- **«Спорные группы»** — `ResolveOzonAccrualTypeGroupDisputeAction(typeId, accept,
  actorUserId)`: принять новую группу или оставить прежнюю; запись в лог с актором.
- **Группа маппинга — из закрытого списка**: `UpdateExternalCategoryMappingAction`
  отвергает группу Ozon вне `ingest_category_groups`; в форме — select.
- **Актор обязателен** для ручной правки маппинга в админке (без него — ошибка, а не
  «автоматический» маппинг).

## 3. Что считаем выполненной работой

- Integration-тесты: очередь (тип из справочника с неизвестными строками есть, известный
  — нет); подтверждение (маппинг создан, тип транзакции = текущий, актор записан, без
  актора — исключение); спор (принять/оставить); группа вне списка — исключение;
  импорт под блокировкой не ломает прежние тесты.
- Functional-тесты контроллера: страница открывается админу и 403 не-админу; confirm,
  resolve, upload (dry-run) — CSRF, редирект/рендер.
- Гейты, ревью.

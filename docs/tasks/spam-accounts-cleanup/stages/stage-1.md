# Этап 1 — команда чистки спам-аккаунтов и защита регистрационного письма

Дата 2026-10-20. Решение Владельца: удалять без блокировки, по варианту
«dry-run → бэкап → удаление порциями». Замер — `../measurements/stage-0-before.md`.

## 1. Какую задачу решаем

В БД 1326 спам-аккаунтов атаки 14–15.01.2026. У каждого — один пустой кабинет
(одна строка в `project_directions`, `financial_responsibility_centers`,
`financial_responsibility_center_projects`). Инструмента удаления нет:
`UserDeletionService` устарел (не удаляет `company_members`, знает 18 таблиц
из 36+) и выключен в админке.

Канал атаки открыт: письмо «Регистрация завершена» печатает `company.name`, длина
названия формой не ограничена, ссылки не запрещены.

## 2. Что будет результатом

Один PR, две части. **Команда `app:company:prune-spam-accounts`** (модуль `Company`):

- Обязательное окно `--registered-from=YYYY-MM-DD --registered-to=YYYY-MM-DD`
  (to — исключительно); без `--execute` — только отчёт (dry-run).
- Кандидат — пользователь из окна, у которого:
  - нет ролей `ROLE_ADMIN`/`ROLE_SUPER_ADMIN`;
  - нет строк ни в одной таблице, ссылающейся на `user` (FK из `pg_constraint` +
    любые колонки `user_id`), кроме `companies.user_id`;
  - есть свой кабинет, и у каждого его кабинета нет строк ни в одной таблице
    со ссылкой на `companies` (FK + любые колонки `company_id`), кроме
    трёх таблиц автосида выше.
  Проверка строится по схеме БД во время запуска: новая таблица с данными
  автоматически исключает аккаунт, а не теряется.
- Отчёт: окно, всего пользователей в окне, кандидатов, отсеянных — с причиной
  (таблица), без адресов почты и названий.
- `--execute`: удаление порциями по 100, каждая порция — в транзакции команды:
  три таблицы автосида → `companies` → `user`. В конце — пересчёт: в окне не
  осталось кандидатов, висячих ссылок на удалённые ID нет.
- Тесты: кандидат удаляется со всем автосидом; аккаунт с данными в любой
  таблице, членством, админ-ролью или вне окна — не трогается; dry-run ничего не
  меняет; невалидное окно → ошибка.
- `docs/maintenance/codex-console.sh` (референс) — разрешить команду с ровно
  двумя аргументами окна и необязательным `--execute`; установку на прод делает
  Владелец.

**Закрыть канал спама через письмо:**

- Название компании при регистрации: `Length(max: 120)` и запрет ссылок
  (`http`, `www.`, `t.me`, домен вида `слово.слово`).
- Письмо «Регистрация завершена» больше не печатает название компании.
- В форме регистрации включён вывод серверной ошибки поля (был закомментирован,
  статичная подсказка всегда говорила «Введите имя компании»).
- Тесты формы и шаблона письма.

## 3. Что считаем выполненной работой

PR влит и выкачен. Затем, по отдельному одобрению (§3.3 AGENTS:
необратимое удаление данных на проде):

1. Владелец ставит обновлённый wrapper `codex-console`.
2. Бэкап пяти таблиц (`user`, `companies` и три таблицы автосида) в
   `/var/backups/app-service-finance/` — команду готовлю, выполняет Владелец.
3. Dry-run на проде: кандидатов 1326, отсеянных 0.
4. `--execute`, сверка с замером «до»: пользователей 1347 → 21, кабинетов
   −1326, строки автосида −1326 в каждой из трёх таблиц, у 21 живого
   пользователя всё на месте.

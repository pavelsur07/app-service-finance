# МойСклад — подключение и проверка доступа

Источник: согласованный владельцем план в чате 2026-09-14; указание Implement the plan.
Старый Twig/Tabler интерфейс, без UI Kit/React. Меню МойСклад → Интеграция.
Несколько подключений компании к разным аккаунтам; аккаунт закреплён за одной компанией, уникален глобально даже в отключённых записях. Пользовательский Bearer token, GET context/employee. READ/WRITE существующего MARKETPLACE. Создание только после проверки; безопасная замена только для того же аккаунта; проверка, отключение, включение после проверки, удаление только отключённого подключения. CSRF и company scope обязательны. Секреты зашифрованы через Shared и никогда не возвращаются в HTML/логи. 10 секунд timeout и cooldown, без HTTP redirects/retries. Optimistic concurrency при сохранении результата HTTP. Старые записи требуют проверки, accountId назначается только по API. Нет фонового обмена, импорта, новых прав или внешних записей.
Состояния: unverified, connected, invalid_token, forbidden, tariff_restricted, unsupported_token, rate_limited, unavailable, invalid_response. isActive отдельно. Неподтверждённое истечение срока не показывать.
Аддитивная миграция. Команда encrypt-secrets dry-run/--execute: шифрование обоих старых токенов, проверка расшифровки, очистка plaintext атомарно; идемпотентность. Производственные миграция, deploy и backfill требуют названного одобрения на handoff.

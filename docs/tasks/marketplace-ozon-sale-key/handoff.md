# Handoff: marketplace-ozon-sale-key (подмножество «один день»)

PR #2556. Миграций нет.

## Что сделано
Разные начисления одного отправления и товара **в один день** больше не схлопываются в одну запись продажи/возврата Ozon by-day: первая запись держит прежний ключ, остальные — ключ `…-acc{accrual_id}`; новые записи несут метку `raw_data._accrual_id`. Историческая запись без метки, то же начисление и запись другого дня блокируют ключ как раньше — закрытые периоды и возможные переоформления в другие дни не меняются. Возврат по-прежнему находит продажу по базовому ключу.
Находки сверки на проде, которые это закрывает: «Вумджой» −3 800 ₽ (две продажи 30.09), «ИП Лазарева» −16 346 ₽ (два возврата 27.09 с разными суммами).

## Доказательства
- Полный набор 5472 OK, PHPStan level 8 без ошибок, cs/strict-types — 0.
- Сквозной тест на настоящих процессорах (две продажи по 3 800 + возвраты 16 346 и 9 242 в одном дне): записаны все (7 600 и 25 588), сверка «сырьё ↔ учёт» без расхождений, повторная обработка дня не наращивает строки; на старом коде тест красный (2 расхождения).
- Unit: `OzonAccrualRecordKey` (6), процессоры продаж/возвратов (свободный ключ, второе начисление, повтор, историческая запись, другой день), интеграционный тест `getAccrualStamps` (JSON-метка, чужая компания).
- Ревью в свежей сессии: BLOCKER нет; MINOR учтены (собственный суффиксный ключ не пишется повторно под базовым, метка начисления не перезаписывается, лог числа суффиксных записей). Внешнее ревью (Codex): `REVIEW_GREEN`.

# План: загрузка данных Ozon в `ozon-fetcher` (Go)

Статус: **план на согласование**, 21.10.2026. Только **загрузка** (raw в S3 + журнал), без
нормализации. Детали требований — `spec-ozon.md`.

## Принцип

- Всё, что сейчас грузит из Ozon Symfony, **дополнительно** грузит `ozon-fetcher`.
- **Symfony не отключаем и не правим**: его загрузки, cron и отчёты работают как сейчас. Из Symfony
  меняется только список ресурсов, который сервис получает по кабинету, и подписи карты покрытия.
- Данные `ozon-fetcher` пока никто не читает; переключение потребителей на них — отдельный план
  после загрузки.
- Каждый ресурс включается так: код и тесты → **один кабинет** (`3f4d87cc`, малый объём) →
  проверка на проде → **все кабинеты** и догон истории.

### Этап 1. Заказы FBO / FBS

Подробно — `docs/tasks/ozon-orders-posting-list/stages/stage-1.md`, шаги 1.1–1.5.

**Результат.** По всем кабинетам отправления FBO и FBS приходят в raw новыми методами; пропуск с
18.10 догружен; данные за сегодня не старше часа.

**Чек-лист**
- [ ] Тесты Go: страницы по курсору до конца; в запросе нет `offset`/`dir`; «есть ещё страницы, но нет
      курсора» → ошибка; продолжение после сбоя с той же страницы; отключённый метод → остановка
      ресурса с текстом ответа.
- [ ] Один кабинет на проде: задачи за 18.10…сегодня `done`, нет 400, форма ответа записана в `docs/ozon-api.md`.
- [ ] Все кабинеты: задачи `done`; у `b57d7682` ≈ 750 отправлений в день.
- [ ] Начисления за вчера грузятся в обычное время; новых ERROR в GlitchTip нет.

- [ ] Гейты Go (`test -race`, `vet`, `lint`) и Symfony (если менялся список ресурсов) — зелёные.

- [ ] Ревью без BLOCKER/IMPORTANT.

## Риск, общий для всех этапов

Symfony и `ozon-fetcher` ходят в Ozon **с одним ключом**, лимит кабинета у них общий. Пока Symfony
не отключён, сервис на новых ресурсах держит RPS ниже обычного, а после каждого включения сверяем
429 у Symfony. Рост 429 — откат включения ресурса (убрать из списка ресурсов кабинета), не правка
Symfony.

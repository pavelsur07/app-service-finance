# Этап 6 (Ozon). Реклама: кампании, расход, дневная статистика — raw в `ozon-fetcher`

Риск: HIGH-LOCAL (второй API в сервисе: OAuth-токен, секрет в памяти, миграция индекса очереди;
БД Symfony и загрузка рекламы Symfony не затрагиваются). Ветка `feat/ozon-fetcher-ads-sync`.
Поручение Владельца 22.10.2026: «Этап 5-7 — составь подробный план для каждого этапа, чек-лист
проверки готовности и приступай автономно». Общий план и решения по рекламе — `../plan-ozon.md`
(«Реклама (этапы 6–7): решения»).

## 1. Какую задачу решаем

Расход на рекламу Ozon — крупная статья ОПиУ; сейчас его грузит только Symfony (MarketplaceAds:
`app:marketplace-ads:daily-sync` 04:30, сверка 06:10–23:40, асинхронные отчёты `/api/client/statistics`).
По принципу плана то же **дополнительно** грузит `ozon-fetcher`. Этот этап — синхронные методы
Performance API (без отчётов): список кампаний, расход по дням, дневная статистика по кампаниям.
Отчёты по товарам — этап 7.

## 2. Что известно (код Symfony, 22.10.2026)

- **Хост** `https://api-performance.ozon.ru`; **токен** — `POST /api/client/token`,
  `{"client_id","client_secret","grant_type":"client_credentials"}` → `access_token`, `expires_in`
  (≈ 1800 с); Symfony кэширует на `expires_in − 300` с; запросы — `Authorization: Bearer`.
  401 на запросе — сброс токена и один повтор (`OzonAdClient::withAuthRetry`).
- **Кампании:** `GET /api/client/campaign` → `list[]` (`id`, `title`, `state`, `advObjectType`, даты).
  Symfony MarketplaceAds берёт только `advObjectType = SKU`; Ingestion — ещё `SEARCH_PROMO`.
- **Расход:** `GET /api/client/statistics/expense/json?dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD`
  (Ingestion-коннектор; без фильтра кампаний — весь аккаунт).
- **Дневная статистика по кампаниям:** `GET /api/client/statistics/daily/json?dateFrom&dateTo`
  (`plan-ozon.md`: «версию сверить»). Symfony её не вызывает — **форма ответа не проверена**.
- **Ключи** у сервиса уже есть в снимке кабинетов (`credentials.performance` — `client_id`,
  `client_secret`), но сервис секрет отбрасывает (`connections.go`), ресурс `ozon.ads.statistics`
  не обрабатывает.
- **Тестового ключа Performance нет**: живая форма ответов снимается на шаге «один кабинет» (прод,
  только чтение — сам сервис пишет только raw); до этого клиент проверяет только необходимое
  (объект JSON, массив `list` / `rows`), остальное — как пришло.
- **Лимиты** Performance не опубликованы; Symfony делает единицы синхронных запросов на кабинет в
  сутки. 429 у Symfony — только на заказе отчёта (этап 7).

## 3. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Где | пакет `internal/ozonperf` (токен, клиент) в `ozon-fetcher` | решение плана: ядро общее |
| Ресурсы | `ozon.ads.campaigns` (снимок дня), `ozon.ads.expense` (день), `ozon.ads.daily` (день) | разные методы; дневные — по дню, как начисления by-day |
| `period_key` | кампании — день МСК снимка (как каталог: прошедший день не грузится); расход и статистика — день МСК данных | единая модель покрытия |
| Расписание | кампании — сегодня, `RunAt` 01:00; расход и статистика — вчера ежедневно (с 01:00) и перечитывание 14 дней раз в сутки (`PlanOnce`), догон с 01.10.2026 (константа `planner.DefaultAdsFrom`) | Ozon дописывает атрибуцию задним числом; 01:00 — после закрытия дня, до отчётов Symfony в 04:30 |
| Запрос дня | `dateFrom = dateTo = день` | один день — одна страница, ревизии дня сравнимы |
| Токен | один на `client_id`, в памяти, обновление за 5 мин до `expires_in`; одновременные запросы ждут один запрос токена; 401 на запросе — сброс токена и один повтор; 401/400 на токене — `auth` | как Symfony; секрет не в логах/БД/raw |
| Секрет | `PerformanceCredentials{ClientID, ClientSecret}` в `Cabinet`, `String/GoString/LogValue/MarshalJSON` → `[redacted]` (как `ozon.Credentials`); токен — тот же приём | правило сервиса: ключи только в памяти |
| Слот очереди | одна `running`-задача на **(кабинет, семейство API)**: семейство `ads` — ресурсы `ozon.ads.*`, остальное — `seller`; миграция 00006 пересоздаёт уникальный индекс по `(connection_ref, resource_type LIKE 'ozon.ads.%')`, `ClaimNext` проверяет то же выражение | отчёт этапа 7 ждёт до 10 мин и дольше — в общем слоте задерживал бы заказы и начисления |
| Пауза по 401 | отказ ключа Performance **не** приостанавливает кабинет целиком (`connection_state` — для seller): задача рекламы → `failed_retryable` на `AuthSuspend` (1 ч), со второго подряд отказа — ERROR; успех рекламы не сбрасывает счётчик отказов seller | реклама и продажи — разные ключи |
| Лимитер | отдельные пары `(кабинет, endpoint)` Performance; старт 0,2 запроса/с, пол 0,05, потолок 1, пауза 60 с | лимиты не опубликованы; объём — единицы запросов |
| Кабинет только с performance | планируется и исполняется (у планировщика и исполнителя проверка ключа — по семейству ресурса) | контракт допускает такой кабинет |
| Включение | Symfony: новые ресурсы `ozon.ads.campaigns`, `ozon.ads.expense`, `ozon.ads.daily` — компаниям `ozon_fetcher.ads_companies` с ключом performance; сначала `3f4d87cc`, затем `['*']`; `ozon.ads.statistics` пока ни на что не влияет (этап 7) | единое правило этапов |
| Карта покрытия | три строки в `OPTIONAL_RESOURCES` («Реклама: кампании», «Реклама: расход», «Реклама: статистика по дням»), день | как остальные этапы |
| Проверка ответа | кампании — объект с массивом `list`; расход и статистика — JSON-объект или массив; иначе `invalid_response`; HTML/пустое тело — `invalid_response` | форма не проверена вживую — проверяем только то, без чего страница бесполезна |
| Сосуществование с Symfony | синхронные методы, единицы запросов на кабинет в сутки, отчётов не заказывает | слоты отчётов Symfony не задеваются |

## 5. Что считаем выполненной работой

По всем кабинетам с ключом Performance в raw `ozon-fetcher` — список кампаний раз в сутки, расход и
дневная статистика по кампаниям за каждый день с 01.10 с перечитыванием 14 дней; реклама не
занимает слот продаж и не приостанавливает их при отказе ключа; секрет и токен не попадают в
журнал, БД и raw; у Symfony нет новых 429 Performance; гейты зелёные; ревью Codex без
BLOCKER/IMPORTANT.

## 7. Риски

- **Форма ответов не проверена вживую** (нет тестового ключа Performance): `/statistics/daily/json`
  может не существовать или отвечать иначе. Тогда на шаге «один кабинет» ресурс останавливается
  (`invalid_request` / `obsolete_endpoint`), остальное включается, метод сверяется по документации
  Ozon отдельным шагом.
- **Отказ «Продвижение» в ключе (403)** — `auth`, пауза рекламы кабинета; ERROR со второго отказа.
- **Миграция индекса** — пересоздание частичного уникального индекса на маленькой таблице
  (сотни строк), обратима (`Down` возвращает прежний индекс, если нет двух `running` одного кабинета).

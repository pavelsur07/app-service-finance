# Этап 10 (Ozon). Возвраты и отмены построчно — raw в `ozon-fetcher`

Риск: MEDIUM (один новый ресурс сервиса; миграций нет; БД Symfony и загрузки Symfony не
затрагиваются). Ветка `feat/ozon-fetcher-returns`. Поручение Владельца 24.10.2026: «делай этапами,
под каждый этап разрабатывай план, цель, что является результатом, чек-лист проверки готовности
этапа, действуй автономно». Общий план — `../plan-ozon.md`, требования — `../spec-ozon.md` §2
(группа 1: «Возвраты и отмены построчно», `/v1/returns/list`), §3 (приоритет 5).

## 1. Какую задачу решаем

Для недельного анализа нужны возвраты и отмены по товарам: сколько, по какой причине, FBO/FBS, где
товар сейчас, компенсирован ли. Сейчас их нет нигде: в начислениях видна только логистика возврата
деньгами. Метод — `/v1/returns/list`. Цель этапа — каждый день возвратов (по дате логистического
возврата) в raw, с перечитыванием недавних дней: статус возврата меняется неделями.

Справочники и снимки из того же пункта плана (акции, поставки в пути, кластеры и склады) — этап 11.

## 2. Что известно о методе (живая проверка 24.10.2026, тестовый ключ Владельца, только чтение)

**`POST /v1/returns/list`**
- Запрос: `{"filter": {"logistic_return_date": {"time_from": "2026-10-10T00:00:00+03:00",
  "time_to": "2026-10-10T23:59:59.999999999+03:00"}}, "limit": 500, "last_id": 0}`; `limit` в
  `(0, 500]` (501 → 400 `code 3`). Обе границы включительные, с миллисекундами: окно, кончающееся
  ровно на отметке возврата, его содержит; дробные секунды принимаются. Смещение МСК в фильтре учитывается: возврат `2026-10-09T21:19:36Z`
  (10.10 00:19 МСК) входит в день 10.10.
- Ответ: `{"returns": [...], "has_next": bool}`. Возврат — `id`, `type` (`Cancellation`,
  `ClientReturn`, `Unknown`), `schema` (`Fbo`/`Fbs`), `return_reason_name`, `order_id`,
  `order_number`, `posting_number`, `product{sku, offer_id, name, price, commission, quantity, …}`,
  `logistic{return_date, final_moment, technical_return_moment, …}`, `visual{status, change_moment}`,
  `compensation_status`, `storage{…}`, `place`/`target_place` (склады Ozon), `exemplars`,
  `additional_info{is_opened, is_super_econom}`, `clearing_id`, `return_clearing_id`, `source_id`,
  `courier_delivery`. **Персональных данных покупателя нет** (адреса — складов Ozon).
- Пагинация: `last_id` = `id` последнего возврата страницы; `id` по возрастанию; `has_next: false`
  — конец (день 10.10: 41 возврат; при `limit` 10 — страницы `1001852505…1001853268`,
  `1001853269…`).
- История глубокая: дни 01.06 и 10.01.2026 отдаются.
- Объём (`19621cff`): 20–40 возвратов в день, за 01–12.10 — больше 500 → один день — одна страница.
- Квота — `ratelimit-remaining: 49`.

## 3. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Ресурс | `ozon.returns` | один метод, одна выдача |
| `period_key` | день МСК `logistic.return_date` | дата возврата неизменна, день перечитывается целиком |
| Пагинация | `last_id` (= `id` последнего возврата страницы) до `has_next: false`; страница — raw; курсор — `last_id`; `has_next: true` при пустой странице, `last_id` не сдвинулся, повтор `id` в дне, нет `returns`/`has_next` — `invalid_response`; потолок 1000 страниц. Порядок `id` не проверяется (§8) | без тихой обрезки |
| Проверка дня | `logistic.return_date` каждого возврата — внутри запрошенного дня МСК, иначе `invalid_response` | фильтр, молча проигнорированный Ozon, не должен сохранить чужие дни (урок фильтра заказов этапа 1) |
| Догон | с `DefaultReturnsFrom` = 2026-08-01 до вчера, приоритет догона | начало витрины покрытия; история API глубже |
| Перечитывание | последние 30 дней раз в сутки (`refresh`), ревизия при изменении | статус и компенсация меняются неделями |
| Сегодня | не грузится | день неполный; вчера — в перечитывании |
| Лимит | 0,2 запроса/с (`SharedQuota`) | ключ общий; 1 страница на день |
| Форма ответа | набор полей возврата сверяется с живой формой; расхождение — один WARNING | `spec-ozon.md` п. 14 |
| Включение | Symfony: `ozon_fetcher.returns_companies`, только с ключом seller; сначала `3f4d87cc`, затем `['*']` | единое правило |
| Карта покрытия | строка «Возвраты» | как у остальных |

## 7. Риски

- **Возврат меняет статус после 30 дней** (хранение, утилизация) — в raw останется последнее состояние
  в окне перечитывания; для недельного анализа достаточно, длиннее окно — по решению.
- **Ozon игнорирует фильтр молча** (как фильтр смены статуса у заказов) — ловится проверкой дня
  каждого возврата.

## 8. Исправление 24.10 — порядок `id`

Первая версия (#2793) требовала `id` по возрастанию — так было у кабинета тестового ключа (только
FBO). На проде у `3f4d87cc` часть дней ушла в `invalid_response` с ERROR: `id` внутри страницы не
упорядочены. Исправление (#2794): порядок не проверяется, проверяются уникальность `id` в дне и сдвиг
`last_id`; миграция `00007` возвращает упавшие дни возвратов (`failed_permanent`, `invalid_response`)
в очередь.

# Этап 11 (Ozon). Акции, поставки в пути, кластеры и склады — снимки в `ozon-fetcher`

Риск: MEDIUM (три новых ресурса сервиса; миграций нет; БД Symfony и загрузки Symfony не
затрагиваются). Ветка `feat/ozon-fetcher-actions-supplies`. Поручение Владельца 24.10.2026: «делай
этапами, под каждый этап разрабатывай план, цель, что является результатом, чек-лист проверки
готовности этапа, действуй автономно». Общий план — `../plan-ozon.md`, требования — `../spec-ozon.md`
§2 (группа 1 — акции; группа 4 — склады и кластеры; группа 5 — товар в пути), §3 (приоритет 5).

## 1. Какую задачу решаем

Последние данные Seller API из ТЗ, которых нет нигде:
- **акции** — в каких акциях кабинет, какие товары участвуют и по какой цене, какие могут
  участвовать; цена акции объясняет просадку маржи недели;
- **поставки в пути** — активные заявки на поставку FBO и их состав: товар, который едет на склады
  Ozon, но ещё не в остатках;
- **кластеры и склады Ozon** — справочник для остатков по складам (этап 8): кластер, склад, тип.

Всё это — **состояние «на сейчас»**, истории в API нет: ежедневный снимок с 05:00, как остатки.

## 2. Что известно о методах (живая проверка 24.10.2026, тестовый ключ Владельца, только чтение)

**Акции**
- `GET /v1/actions` → `{"result": [...]}`; акция — `id`, `title`, `action_type` (`ELASTIC_BOOSTING`,
  `STOCK_DISCOUNT`, …), `date_start`, `date_end`, `freeze_date`, `is_participating`,
  `participating_products_count`, `potential_products_count`, `banned_products_count`,
  `discount_type`, `discount_value`, `order_amount`, `with_targeting`, `is_voucher_action`,
  `auto_add_dates`, `description`. Кабинет `19621cff` — 5 акций. `POST` → 405.
- `POST /v1/actions/products` (участники) и `/v1/actions/candidates` (кандидаты):
  `{"action_id": N, "limit": 1000, "last_id": ""}`, `limit` в `[0, 1000]`; ответ —
  `{"result": {"products": [...], "total": N, "last_id": "…"}}`; товар — `id`, `price`,
  `action_price`, `max_action_price`, `add_mode`, `stock`, `min_stock`, `current_boost`,
  `price_min_elastic`, `price_max_elastic`, `min_boost`, `max_boost`, `alert_*`.
  **Конец — пустая страница**: последняя страница с товарами отдаёт непустой `last_id`
  (27 из 27 → `last_id` есть; следующий запрос — `products: []` с тем же `last_id`).

**Поставки**
- `POST /v3/supply-order/list`: `{"filter": {"states": [...]}, "limit": 100, "sort_by":
  "ORDER_CREATION", "sort_dir": "DESC", "last_id": "…"}` → `{"order_ids": [...], "last_id": "…"}`;
  `states` обязательны; активные — `DATA_FILLING`, `READY_TO_SUPPLY`, `ACCEPTED_AT_SUPPLY_WAREHOUSE`,
  `IN_TRANSIT`, `ACCEPTANCE_AT_STORAGE_WAREHOUSE`, `REPORTS_CONFIRMATION_AWAITING`,
  `REPORT_REJECTED` (у `19621cff` — 3 заявки, `last_id: ""`); со всеми статусами — сотни.
- `POST /v3/supply-order/get`: `{"order_ids": [≤ 50]}` → `{"orders": [...]}`; заявка — `order_id`,
  `order_number`, `created_date`, `state`, `state_updated_date`, `drop_off_warehouse`, `timeslot`,
  `order_tags`, `supplies[]` (`supply_id`, `state`, `storage_warehouse`, `bundle_id`,
  `macrolocal_cluster_id`, …).
- `POST /v1/supply-order/bundle`: `{"bundle_ids": [...], "is_asc": true, "limit": 100, "last_id": ""}`
  → `{"items": [...], "has_next": bool, "last_id": "…", "total_count": N}`; позиция — `sku`,
  `offer_id`, `product_id`, `quantity`, `barcode`, `volume_in_litres`, `placement_zone`, …
  (3 поставки — 9 позиций).

**Кластеры и склады**
- `POST /v1/cluster/list`: `{"cluster_type": "CLUSTER_TYPE_OZON" | "CLUSTER_TYPE_CIS"}` (без типа —
  400) → `{"clusters": [...]}`; кластер — `id`, `name`, `type`, `macrolocal_cluster_id`,
  `logistic_clusters[].warehouses[]` (`warehouse_id`, `name`, `type`). Россия — 22 кластера, 1340
  складов; СНГ — 5 и 39. `/v1/warehouse/list` — 400 `obsolete method` (склады продавца FBS, не Ozon).

**Квота**: `ratelimit-remaining` 49…2 — общая; персональных данных покупателя нет (адреса —
складов и пунктов приёма Ozon).

## 3. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Ресурсы | `ozon.actions` — список акций, участники и кандидаты каждой; `ozon.supplies` — активные заявки, их детали и состав; `ozon.clusters` — кластеры и склады России и СНГ | по ресурсу на группу ТЗ |
| `period_key` | день МСК снимка, окно с 05:00, `snapshot_missed` после полуночи | как остатки (этап 5) |
| Состав снимка | все ответы снимка — страницы raw по порядку: акции — список, затем по каждой акции (по возрастанию `id`) участники и кандидаты до пустой страницы или до набранного `total` без `last_id`; поставки — страницы списка, детали порциями по 50, состав поставок по `bundle_id`; кластеры — Россия, СНГ | снимок разбирается нормализацией без API |
| Рестарт | снимок — единицы запросов: прерванная попытка (429, сбой) начинает снимок заново (`snapshot_restart`, без курсора), а не продолжает: страницы разных моментов не смешиваются | проще и честнее, чем курсор по трём уровням |
| Пагинация | акции: до пустой страницы; страница с товарами без `last_id` — конец, только если набран `total`, иначе `invalid_response`; `last_id` не сдвинулся — `invalid_response`. Список поставок: до `last_id: ""` или пустой страницы; повтор `last_id` — `invalid_response`. Состав: до `has_next: false`. Потолок 1000 страниц на снимок | без тихой обрезки; форма конца у крупного кабинета не проверена (тестовый кабинет мал — правило Владельца 24.10), поэтому принимаются оба варианта конца |
| Проверки | заявка в деталях — из запрошенных; позиции состава — с `sku`; кластер — с `logistic_clusters` | чужие данные не сохраняются молча |
| Лимит | все endpoint'ы — `SharedQuota` 0,2 запроса/с | ключ общий |
| Включение | Symfony: `ozon_fetcher.reference_companies` (все три), ключ seller; сначала `3f4d87cc`, затем `['*']` | единое правило |
| Карта покрытия | «Акции: снимок 05:00», «Поставки в пути: снимок 05:00», «Кластеры и склады: снимок 05:00» | как у остальных |

без новых 429; гейты зелёные; ревью Codex без BLOCKER/IMPORTANT.

## 7. Риски

- **Много акций или поставок** у кабинета — снимок растёт линейно; потолок 1000 страниц на снимок —
  `invalid_response` с ERROR, а не тихая обрезка.
- **Снимок заново при каждом 429** — при сплошных 429 снимок может не уложиться в день; виден как
  `snapshot_missed`. При повторении — курсор по шагам (решение по замеру).

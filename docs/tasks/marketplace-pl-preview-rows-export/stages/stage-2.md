# Stage 2: Exporter — листы «Данные» и «Паспорт»

stage_base_commit: `42592a8c6`. Risk: MEDIUM — формат файла становится контрактом для книги «ФМ».

## 1. Какую задачу решаем

Разложить `PlPreviewRowsExport` в плоскую таблицу «одна сумма — одна строка» (ТЗ §4.1) и
выписать паспорт файла с контрольными суммами (ТЗ §4.2), чтобы потребитель загружал файл без
разбора и мог проверить полноту.

## 2. Что будет результатом

`Marketplace\Infrastructure\Export\PlPreviewRowsXlsxExporter::export(PlPreviewRowsExport, \DateTimeImmutable $generatedAt, string $path)`
(OpenSpout, как `PlPreviewXlsxExporter`):

- лист `Данные` — 18 полей §4.1 в порядке ТЗ; сетка канал × колонка × строка дерева по
  `report->rows` целиком (фильтр `empty` не применяется); порядок — каналы (уже по значению из
  Action) → колонки отчёта → `row_order`; шапка закреплена;
- лист `Паспорт` — колонки `key`, `value`, `label` (русская подпись); ключи §4.2; ниже — подписи
  полей «Данных» (`field_<имя>`).

Решения по формату, которые ТЗ оставило на реализацию:

- `value`: `MONEY`/`QTY` — `round(…, 2)`, `PERCENT`/`RATIO` — как есть; отсутствующий ключ колонки — 0.
- `iso_week` = `o-\WW` только если `from` — понедельник и `to = from + 6 дней`.
- `generated_at` — момент выгрузки, переданный контроллером в Europe/Moscow, ячейка дата-время
  `yyyy-mm-dd hh:mm:ss`; даты периода — `yyyy-mm-dd`.
- `check_channels_vs_all_*` — только строки `MONEY`/`QTY`: проценты и коэффициенты по каналам
  не складываются, их разность ничего не проверяет. Пишутся все такие строки (и нулевые), чтобы
  набор ключей был стабилен; при явном канале (`all = null`) контроля нет.
- `tags` — колонки тегов первого отчёта (у всех отчётов выгрузки один фильтр тегов).

Отдельный «чистый» метод раскладки, упомянутый в `plan.md`, не делаю: тест читает готовый xlsx
и проверяет то же самое (полнота, порядок, ключи) плюс типы ячеек — второй публичный вход не нужен.

## 3. Что считаем выполненной работой

Exporter пишет два листа по контракту; unit-тест читает файл и проверяет чек-лист; PHPStan и CS
по изменённым файлам чистые; набор тестов предпросмотра зелёный.

## Итог этапа

`tests/Unit/Marketplace/Infrastructure/Export/PlPreviewRowsXlsxExporterTest.php` (4 теста, 48 assertions).

Находка по ходу: читатель OpenSpout сам превращает любую строку на «=» в `FormulaCell`
(`Cell::fromValue()` в `CellValueFormatter`), поэтому «название остаётся текстом» тест проверяет по
XML листа: `t="inlineStr"`, нет `<f>`. Сам файл пишется верно — проверено отдельной генерацией.

Проверки: unit-тест OK; PHPStan по двум файлам — No errors (исправлены `nullsafe.neverNull` и
`list<>` в тесте); php-cs-fixer — 0 замечаний.

Внутреннее ревью: компания в файл не пишется; тексты — `StringCell`; суммы не пересчитываются,
только округление `MONEY`/`QTY` до 2 знаков; сверка каналов — только `MONEY`/`QTY` (решение §2).
BLOCKER/IMPORTANT нет.

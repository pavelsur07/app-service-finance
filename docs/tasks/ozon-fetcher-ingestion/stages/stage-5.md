**Risk:** HIGH-LOCAL (конкурентность)

#### Цель
Каждый кабинет работает в своём лимите на каждый endpoint и не мешает
остальным; 429 снижает скорость только у своей пары.

#### Результат
Пакет `internal/ratelimit`, `Registry` реализует `ozon.Limiter`:
- ключ — `(connection_ref, endpoint)`; на ключ — `golang.org/x/time/rate`
  (burst 1) + адаптированная скорость + пауза
- лимиты endpoint'а `{Start, Floor, Ceiling, DefaultPause}` из конфига
  (значения — `docs/ozon-api.md`), неизвестный endpoint — `Fallback`
- ручное значение по кабинету (`Seed`/`SetOverride`): потолок пары и старт
- AIMD: 429 → скорость ÷ 2 (не ниже `Floor`) + пауза `Retry-After` или
  `DefaultPause`; `GrowAfter` успехов подряд → `+IncreaseStep` (не выше
  потолка); прочие ошибки скорость не меняют
- `OnChange(ref, endpoint, rps)` — колбэк для сохранения адаптированной
  скорости (реализация хранения — этап 7), вызывается вне блокировки
- ожидание прерывается отменой контекста

#### Решения
- Потолок пары = ручное значение, если задано, иначе `Ceiling` endpoint'а.
  Старт = сохранённая адаптированная скорость → ручное значение → `Start`;
  всё зажато в `[Floor; потолок]`.
- Пауза после 429 — общая для пары: параллельные запросы того же кабинета к
  тому же endpoint'у ждут её вместе.
- Часы и сон — параметры (`services/go.md`): тесты детерминированы.
- `golang.org/x/time/rate` — не в проверенном стеке `go.md`; обоснование для
  PR: стандартный token bucket Go-команды с изменением лимита на лету
  (`SetLimit`), своя реализация — те же ~60 строк с риском ошибок во
  времени.

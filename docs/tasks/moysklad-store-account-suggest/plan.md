# МойСклад: предложение счёта Баланса для склада

**Класс:** Large — новая таблица и миграция, новая ИИ-задача в `ai-service`, cron-триггер.
**Task base:** `16a9ec7ac` (origin/master, 27.11.2026).
**Ветка:** `feat/moysklad-store-account-suggest`.

## 1. Какую задачу решаем

На вкладке «Интеграции → МойСклад → Склады» (`/moy-sklad/stores`) каждый склад надо вручную
назначить на счёт актива Баланса или пометить «не учитывать». У Сухоносова (b57d7682) 36 складов,
назначений 0 — проводок нет. Пользователь застревает на рутинной разметке.

## 2. Что будет результатом

У каждого склада без назначения — предложение: счёт типового справочника (`INV_WAREHOUSE`,
`INV_MARKETPLACE`, `INV_IN_TRANSIT`) или «не учитывать», с причиной одной фразой и пометкой
источника «правило» / «ИИ». Кнопки «Принять» в строке и «Принять все уверенные».
Назначение по-прежнему пишет только `SaveStoreBalanceLinkAction` от имени нажавшего.

## 3. Решения (утверждены Владельцем 27.11)

- Правила первыми, ИИ только для складов, которые правила не разобрали.
- ИИ выбирает только из переданного списка кодов счетов актива компании, «не учитывать» или «не знаю».
- Предложение ничего не записывает в `moysklad_store_balance_links`. Автоприменения нет.
- Склады маркетплейсов: только предупреждение в строке, не «не учитывать». Отдельного счёта брака нет.
- Счета под склады не создаются; несколько складов одного подключения могут смотреть в один счёт.
- Предложение хранит **код** счёта, не id: счёт разрешается по коду при показе и принятии.
  Нет счёта с таким кодом у компании — предложение показывается недоступным.

**Уточнение к обсуждению:** остатки ozon-fetcher / wb-fetcher сейчас в Баланс не проводятся
(единственный источник запасов в Балансе — МойСклад), поэтому реального двойного учёта сегодня нет.
Предупреждение говорит именно это: «остатки площадки по API в Баланс не идут — проводится только этот склад».

## 4. Устройство

**Правила** — чистая доменная политика `StoreAccountRulePolicy` (`MoySklad/Domain`), вход — название,
путь, код; выход — код счёта / excluded / unknown + причина + флаг предупреждения. Считается на лету
при показе страницы, в БД не хранится. Версия правил — константа.

| Признак в названии или пути | Предложение |
|---|---|
| ozon, озон, wb, wildberries, вайлдберриз, fbo, маркетплейс, яндекс маркет | `INV_MARKETPLACE` + предупреждение |
| в пути, транзит, поставка | `INV_IN_TRANSIT` |
| брак, списание, утиль, тест, резерв, виртуальн | не учитывать |
| склад, основной, офис, магазин | `INV_WAREHOUSE` |
| иначе | unknown → ИИ |

**ИИ** — задача `moysklad_store_account_suggest` в `ai-service` по образцу
`marketplace_source_type_draft`: pydantic-схема ответа, проверка «код из списка», evals.
Symfony: `RequestStoreAccountSuggestionsAction` через `AiTaskFacadeInterface::requestTask`,
`StoreAccountSuggestionConsumer implements AiTaskResultConsumerInterface`.

- Payload: склады (external_id, name, path_name, code) только со статусом unknown, список счетов
  актива (code, name, article_path). Без контрагентов, цен и токенов.
- Ключ повтора: `connectionId + sha256(отсортированные fingerprint складов) + prompt_version`.
- Триггер — конец синхронизации складов в `SyncStockSnapshotAction` (после commit, best-effort:
  потеря запроса не страшна, следующий синк пошлёт снова). Не из GET-контроллера.
- Компания без доступа к ИИ (`ai_company_access`) — запроса нет, на странице «нет предложения».

**Хранение (только ИИ):** `moysklad_store_account_suggestions`
PK `(company_id, connection_id, store_external_id)`, `account_code varchar(64) NULL`, `excluded bool`,
`confidence varchar(8)` (`high|low`), `reason varchar(255)`, `store_fingerprint char(64)`,
`prompt_version varchar(16)`, `ai_task_id uuid`, `updated_at`. Upsert в consumer по PK.
Fingerprint = sha256(name, path_name, code); не совпал с текущим складом — предложение устарело, не показывается.

**UI:** колонка «Предложение» (код → название счёта, причина, бейдж источника, предупреждение видно
текстом, не в тултипе). «Принять» = существующий POST назначения с подставленным счётом.
«Принять все уверенные» — новый POST: для складов без назначения с уверенным предложением
вызывает `SaveStoreBalanceLinkAction` по одному; итог «принято N, пропущено M (причина)».
Права те же — `canPostFromSource`.

## 6. Тесты

- Unit: политика правил — каждая строка таблицы + регистр + «ё» + путь vs название.
- Unit: consumer — код вне списка отбрасывается; повторный результат того же task_id → та же строка.
- Functional: страница показывает предложение; устаревший fingerprint не показывается;
  «Принять все» пишет только уверенные и только склады без назначения; без права — 403/ошибка, 0 строк.
- Functional: повторное «Принять все» → то же число назначений.
- ai-service: unit задачи + evals.

## 7. Чек-лист приёмки

- [ ] Склад без назначения показывает предложение с причиной и источником.
- [ ] Склад с назначением предложения не показывает и не меняется.
- [ ] Предложение ни при каких условиях не создаёт строку в `moysklad_store_balance_links` без нажатия.
- [ ] «Принять все уверенные» применяет только high и только к складам без назначения; повтор — без изменений.
- [ ] Пользователь без права проводить в Балансе не может принять ни одного предложения.
- [ ] ИИ возвращает только коды из списка компании; иное отбрасывается.
- [ ] Компания без доступа к ИИ получает предложения правил, страница без ошибок.
- [ ] Переименованный склад получает новое предложение, старое не показывается.
- [ ] Предупреждение у складов маркетплейсов видно текстом в строке.
- [ ] Эталон Сухоносова: правила + ИИ покрывают ≥ 90 % складов, ошибок среди high — 0.
- [ ] Гейты: `make site-stan`, `site-cs-check`, `site-cs-strict-types`, `site-cs-twig`, `site-test`, тесты `ai-service`.
- [ ] `ARCHITECTURE.md` обновлён; миграция выпускается отдельным release (см. процесс миграций).

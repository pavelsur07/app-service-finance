# marketplace-ozon-realization-autoload: автоопрос, загрузка и обработка «Реализации» Ozon

Класс: Large (Messenger-маршрут, cron, финансовая обработка, интеграция с внешним API). Решения Владельца (02.10.2026): окно опроса — **с 18:00 МСК 1-го числа до конца 8-го числа** следующего месяца; **автообработка разрешена для открытых месяцев**.

## Проблема
- Отчёт «Реализация» (`POST /v2/finance/realization`, Ozon отдаёт его не ранее 5–8 числа следующего месяца) загружает один cron `0 6 5 * *` — **одна попытка** в месяц. Если на 5-е отчёт не готов, месяц остаётся без «Реализации» до ручной загрузки.
- Обработка («Применить выручку», `ProcessOzonRealizationAction`) запускается только вручную из интерфейса: у «Вумджой ООО» и «Музыкальные инструменты» август и июль загружены, но не применены (`records_created = 0`).
- Сверка с Ozon («Реализация ↔ сырые данные») не может подтвердить продажи и возвраты, пока отчёт не загружен и не применён.

## Цель
Опрашивать Ozon каждый час в окне, при появлении отчёта загрузить его, обработать и пересчитать сверку, а при непоявлении к концу окна сообщить один раз.

## Факты Phase 0 (из кода)
- `app:marketplace:ozon-realization-sync` ставит `SyncOzonRealizationMessage(companyId, connectionId, year, month)` в `async_sync`; `SyncOzonRealizationHandler` загружает отчёт через `OzonRealizationFetcher` и сохраняет `marketplace_raw_documents` (`document_type = realization`), при повторной загрузке перезаписывает документ. Статуса и повторов нет.
- `OzonRealizationFetcher` на любой не-200 бросает общий `\RuntimeException` без типа — «ещё не готово» неотличимо от сбоя и лимита.
- `ProcessOzonRealizationAction` идемпотентен: первичная обработка пишет `records_created` в финале (строки вставляются пакетами без общей транзакции), переобработка атомарна и сохраняет `pl_document_id`. Консольной команды обработки нет — только контроллер `POST /raw/{id}/process-realization` и `ReprocessMarketplacePeriodAction`.
- Для состояния по паре «компания × период» есть `MarketplaceFinancialReportSyncStatus` (статусы `queued/loading/raw_loaded/processing/success/empty/failed/failed_final/auth_failed/conflict`, попытки, `nextRetryAt`, `rowsHash`, ключ `company × marketplace × reportType × businessDate`) — миграция не нужна.
- Закрытие месяца: `MarketplaceMonthClose::isStageClosed(CloseStage::SALES_RETURNS)`.
- Сверка Ozon читает «Реализацию» из `marketplace_ozon_realizations` только при `records_created > 0` — зависит от ручного шага.

## Решения по дизайну
1. **Окно и частота — в коде.** Cron запускает команду каждый час круглый год; команда сама определяет окно и выходит за миллисекунды вне него. Окно проверяется юнит-тестами (граница 18:00 МСК 1-го, 8-е 23:59, смена года, високосный февраль), cron при смене окна не правится.
2. **Состояние** — `MarketplaceFinancialReportSyncStatus` (`reportType = ozon_realization`, `businessDate` = первый день месяца отчёта).
3. **Команда тонкая**: выбирает активные Ozon seller-подключения, пропускает пары в `success`, у которых `nextRetryAt` не наступил, ставит `SyncOzonRealizationMessage` в `async_sync`. Лимит Ozon: одна задача на подключение за прогон.
4. **Загрузчик различает исходы**: типизированные исключения вместо `\RuntimeException` (повтор через `MarketplaceRateLimitException` с `Retry-After`; временный сбой; авторизация → `auth_failed`; пустой ответ / «не готово» → `empty` + повтор через час).
5. **Обработка отдельным сообщением** в `async_pipeline` (локальная DB-тяжёлая обработка): `ProcessOzonRealizationMessage` → handler вызывает тот же `ProcessOzonRealizationAction`. Запускается только если хеш строк изменился.
6. **Защита закрытых периодов:** если этап `SALES_RETURNS` месяца закрыт — не обрабатывать, статус `conflict`, `warning` (не `error`). Для открытых месяцев автообработка разрешена.
7. **После обработки** handler пересчитывает сверку за месяц (`RunOzonReconciliationAction`).
8. **Сверка читает «Реализацию» из сырого документа**, а не из обработанной таблицы (суммы по `delivery_commission`/`return_commission` как в `ProcessOzonRealizationAction`): независимость источника и работа при ручной обработке.
9. **Гейт конца окна:** на 9-е число и позже, если за прошлый месяц у активного подключения нет `success` — один агрегированный `error` (охват гейта равен охвату починки: ручная загрузка из интерфейса или повторный запуск).
10. Прежний cron `0 6 5 * *` заменяется новой строкой (иначе двойная загрузка); устаревший комментарий про «10-е число» удаляется.

## Не входит
Обработка закрытых месяцев; пересчёт исторических непримененных месяцев (август и июль у двух компаний) — отдельное одобрение Владельца (§3.3), вне этой задачи; WB.

## Открытые вопросы
- Что Ozon отдаёт до готовности отчёта (HTTP-код / пустые `rows`): на проде это не проверялось — запрос требует боевых ключей. Дизайн закрывает оба варианта; точный исход зафиксируем по первому окну (логи старта и исхода попытки).

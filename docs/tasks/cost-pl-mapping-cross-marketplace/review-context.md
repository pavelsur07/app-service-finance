# Контекст для внешнего ревью

Спецификация — plan.md рядом. Продолжение #2605 (ночной `sync-default`, гейт
`unmapped-check`) и #2608 (статья по образцу компании внутри маркетплейса). Cron и
гейт не менялись.

## Внутреннее ревью (свежая сессия) — исправлено
- IMPORTANT: «свои образцы» считались только по включённым правилам со статьёй
  LEAF_INPUT; если компания исключила этот тип затрат WB из ОПиУ (или отнесла в
  группу), своих образцов не было, и образец Ozon перекрывал её решение. Теперь
  query отдаёт и такие правила (статья null), resolver считает их решением своего
  маркетплейса и fallback на чужие не делает. Тесты красные без фикса (unit + integration).
- MINOR: тесты на исключённое правило, ARCHITECTURE.md про цепочку выводов.

## Решения
- Риск «у компании отдельные статьи по маркетплейсам»: `pl_categories` не знает
  маркетплейса, отличить нельзя. Fallback срабатывает только когда у своего
  маркетплейса нет ни одного решения по этому `pl_code`; аудит-лог и вывод команды
  отмечают `cross_marketplace`. Принято Владельцем как правило («делай маппинг по
  образцу другого маркетплейса»). У целевой компании 19621cff… статьи общие (без
  маркетплейса в названии) — проверено на проде.
- Образцы нескольких чужих маркетплейсов объединяются и должны совпадать.
- Отключённое правило без статьи шаблона попадает в `blocked` — поведение до этой
  задачи, влияет только на счётчик вывода; вне scope.
- Остальное как в #2608: только частичный режим, только MISSING_PL_CATEGORY, чтение
  образцов в транзакции записи, writer не трогает ручные/отключённые правила.

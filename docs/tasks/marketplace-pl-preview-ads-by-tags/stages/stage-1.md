# Этап 1: какие учётные категории покрывает рекламная статистика

stage_base_commit: `161d12e64`

## План этапа

### Решения

1. **Без флага в БД — изменение общего плана.** Общий план предлагал поле в
   `marketplace_cost_pl_mappings` с переключателем на экране. Отказ: то, какую учётную категорию
   покрывает рекламная статистика, — свойство источника данных (рекламные API отдают оплату за клик
   Ozon и продвижение WB), а не выбор компании. Флаг у компании позволил бы включить его на
   категории, которой в статистике нет, и тихо обнулить её на тегах. Плюс — без миграции и
   отдельного dispatch на проде.
2. **Где** — `App\Marketplace\Domain\PlPreview\AdStatisticsCostCategories` (`final`, без состояния):
   `codesFor(MarketplaceType): list<string>`, `covers(MarketplaceType, string $code): bool`.
   Ozon — `ozon_cpc`, WB — `wb_okazanie_uslug_wb_prodvizhenie` (решение Владельца 17.10.2026),
   остальным маркетплейсам — пусто. Констант кодов в `OzonCostCategory` / `WbCostCategory` нет (коды —
   строки в конструкторах), поэтому строки; сверены с этапом 0 и `default_cost_mapping.yaml`.
3. Расширение списка — правка кода с тестом: так добавление новой категории проходит ревью.

### Конечный результат

Один класс отвечает на вопрос «эта учётная категория покрыта рекламной статистикой?».

# Этап 3: реклама по тегам из статистики в предпросмотре (расчёт)

stage_base_commit: `86666b09c`

## План этапа

### Как считается (на статье ОПиУ, куда маппинг относит рекламную категорию)

Для маркетплейса M с рекламной категорией K (`AdStatisticsCostCategories`), у которой есть правило
маппинга со статьёй и `include_in_pl` (иначе ничего не меняется — K и так в блоках «не размечено» /
«исключено»):

- `s` — знак правила (`is_negative` → −1), как у проведения;
- `S_l` — расход статистики листинга l за период, `T` — вся статистика M за период;
- `L` — учётная сумма K за период со знаком документа (как сейчас считает факт).

| колонка | реклама K |
|---|---|
| тег | `s × Σ S_l` по листингам тега (полная сумма листинга в каждый его тег, как всё остальное) |
| «Общие / без тега» | `s × Σ S_l` листингов без тегов **+ (L − s × Σ S_l всех листингов)** |
| «Итого» | `L` — учёт, как было: «Итого» остаётся равным проведению |

Вторая часть «Общих» = статистика без товара + расхождение учёта и статистики. Колонки без
пересечения тегов складываются в «Итого».

### Решения

1. **Факты по листингам без K.** `PlPreviewFactsQuery::fetch()` получает список исключаемых кодов
   затрат (`excludedCostCodes`) — только для разреза по листингам; вызов без разреза («Итого»)
   не меняется.
2. **Учёт K и правило K** — новый метод запроса: по маркетплейсу — статья, знак правила,
   `include_in_pl`, учётная сумма K за период (та же формула модуля группы «категория × сторно»).
3. **Одна категория на маркетплейс.** Статистика не делится между несколькими учётными
   категориями, поэтому `AdStatisticsCostCategories` переходит на `codeFor(): ?string`.
4. **Теги листингов** берутся для объединения листингов из фактов и из статистики.
5. **Сверка рекламы** в отчёте: по маркетплейсу — учёт, статистика всего, на товарах, без товара,
   расхождение (учёт − статистика); суммы — положительный расход.
6. Фильтр маркетплейса ограничивает и статистику. Период статистики — `report_date`, учёта —
   `cost_date` (сдвиг недели WB виден в расхождении, этап 0).
7. Без статистики (T = 0) колонки тегов получают 0, вся учётная сумма — в «Общих» как расхождение:
   честно и видно в сверке.

### Конечный результат

`BuildMarketplacePlPreviewAction` раскладывает рекламу Ozon (клики) и WB («Продвижение») по тегам
точно по рекламной статистике, «Итого» = учёт, разница — в «Общих» и в сверке рекламы.

# Промт для Kimi CLI — PATTERNS.md: метки иллюстративности и статус §22

Задача: 2 правки в PATTERNS.md (только документация, разметка существующего текста). Fast Path. Workflow репозитория: ветка docs/patterns-examples-clarity от master, коммит, push, Draft PR.

ОГРАНИЧЕНИЯ: меняется ровно один файл — PATTERNS.md. AGENTS.md, CLAUDE.md, ARCHITECTURE.md, код — не трогать. Нумерацию разделов не менять. Текст примеров кода не редактировать — только добавлять поясняющие строки.

ШАГ 0. git status — рабочее дерево может содержать файлы владельца, это норма, не останавливайся. Требование: в коммит попадает только PATTERNS.md; чужие modified/untracked файлы остаются нетронутыми (stage по файлу, не git add -A).

Контекст: по результатам предыдущей задачи (PR #2470) выяснилось, что часть «эталонных» классов в PATTERNS.md не существует в кодовой базе. Реальные эталоны уже помечены строкой «Эталон: ..., проверено 2026-09-13». Эта задача убирает двусмысленность для всего остального.

ПРАВКА 1 — §22 «Idempotency в Messenger»: статус спецификации.
Классы ProcessedMessage, IdempotentHandlerTrait, ImportBankStatementHandler в коде отсутствуют — раздел описывает нереализованную инфраструктуру. Сразу после заголовка раздела 22 (до первого абзаца) вставь:

> **Статус: спецификация, инфраструктура не реализована.** Классов `ProcessedMessage`, `IdempotentHandlerTrait`, `ImportBankStatementHandler` в кодовой базе нет (проверено 2026-09-13). Не импортировать их в новый код. Применять паттерны раздела только после реализации Shared-компонентов либо реализовать их в scope задачи, явно указав это в плане.

ПРАВКА 2 — метки иллюстративных примеров.
2.1. В шапку файла, после строки о запрете перенумерации (добавлена в PR #2470), добавь строку:

> Примеры на Product/Deal/Order и т.п. — иллюстративные, не из кодовой базы. Реальные эталоны помечены строкой «Эталон: ..., проверено <дата>» и подтверждены grep по коду.

2.2. В разделы 2, 10, 16, 17, 25 — одна строка сразу после заголовка раздела (перед первым абзацем):

> Примеры в разделе иллюстративные, не из кодовой базы.

Не добавляй эту строку в разделы, где уже есть подтверждённая метка «Эталон: ...» у всех примеров, и не добавляй в раздел 22 (там уже строка статуса из правки 1).

ВЕРИФИКАЦИЯ (обязательно, до коммита):
1. grep -n "Статус: спецификация" PATTERNS.md — ровно одно вхождение, в разделе 22
2. grep -n "иллюстративные" PATTERNS.md — одно вхождение в шапке + по одному в разделах 2, 10, 16, 17, 25 (итого 6), иначе отчёт с объяснением
3. grep -n '^## ' PATTERNS.md — заголовки 1–25 на месте, нумерация не изменилась
4. git diff --stat — ровно один файл: PATTERNS.md
5. git diff — только добавления строк-пометок; ни одного изменения или удаления существующего текста и кода примеров
6. git show --stat HEAD после коммита — в коммите только PATTERNS.md

Отчёт: что добавлено (файл:строка по каждой правке), подтверждение верификации 1–6, ссылка на PR. На handoff — стандартный вопрос «merge and deploy» по AGENTS.md §3.2.

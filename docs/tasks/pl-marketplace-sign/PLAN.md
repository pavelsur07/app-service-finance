# Знак строк marketplace_pl в регистре ОПиУ

## 1. Задача
Регистр ОПиУ (`PLRegisterUpdater`) и итоги документа (`DocumentPlContribution`,
`DocumentOperationRepository`) берут модуль нетто статьи документа marketplace_pl. Когда
сторно затрат перевешивает начисления (или Ozon забирает компенсацию), расход пишется
доходом и наоборот (декомпенсации маркетплейса, прочие удержания МП, штрафы). Случаи на
проде подтверждены 23.11, цифры — вне git.

Причина — два правила знака в одном документе:
- этап `costs`: строка уже в знаке отчёта (начисление −X, сторно +X, компенсация +X);
- этап `revenue`: знак строки задаёт флаг `is_negative` маппинга продаж, и флаги
  противоречивы (REV_RETURNS встречается и с t, и с f). Смысл строки — величина в
  природе статьи, без разворотов.

## 2. Результат (лучшая практика: одно правило знака, без abs)
- Строка marketplace_pl хранит **значение для отчёта**: доход +, расход −; сторно —
  та же статья с обратным знаком («красное сторно»).
- Этап `revenue` при создании документа переводится в это правило:
  `±|amount|` по природе статьи. Затраты не меняются.
- Регистр: статья расхода — `amount_expense = −Σ`, дохода — `amount_income = Σ`;
  расход за день может быть отрицательным (CHECK `≥ 0` на `pl_daily_totals` снимается).
- Итог документа и строки «Операции» — та же арифметика.
- Миграция данных: строки существующих документов этапа `revenue` → `±|amount|`
  по природе статьи (сохраняет текущий результат регистра); бэкап таблицы строк.
  Затем пересчёт регистра окон затронутых документов.

### Где меняется код
| Место | Сейчас | Станет |
|---|---|---|
| `FinanceFacade::createPLDocument` | знак по `is_negative` | этап `revenue`: `±|amount|` по природе статьи; затраты как есть |
| `PLRegisterUpdater` | `abs(Σ)` статьи | расход `−Σ`, доход `Σ` |
| `DocumentPlContribution` | знак по итогу статьи | вклад строки = `amount` (доход) / `−amount` (расход) |
| `DocumentRepository::summarizeByCompany`, `DocumentOperationRepository::summarizeForList` | `marketplaceBucketSums` + знак полной суммы | та же арифметика, `marketplaceBucketSums` удаляется |
| миграция | CHECK `≥ 0` на `pl_daily_totals` | CHECK снят; строки `revenue` нормализованы, бэкап |
| пересчёт | — | регистр затронутых компаний (команда пересчёта, запускает Владелец) |

Вне scope: `PlPreviewCalculator` (предпросмотр из фактов, тот же `abs` по колонке) — отдельной задачей;
разовые repair-команды не трогаем. `is_negative` маппингов продаж после правки не влияет на знак —
удалить флаг отдельной задачей.

## 3. Что выполнено
- Масштаб снят (только чтение), причина подтверждена в данных; строк разного знака в одной
  статье потока revenue на проде нет — нормализация не меняет результат регистра по выручке.
- Код: `DocumentPlContribution::contribution()` — общее правило для регистра, итога документа и
  итогов списков; `createPLDocument` — знак revenue по природе статьи; миграция
  `Version20261123120000`; разовая команда ремонта дерева ОПиУ (ARCHITECTURE 2.89) удалена — применена 30.10.
- Тесты: регрессия сторно > начислений и декомпенсации (регистр, итог документа), знак при
  создании документа; в тесте ремонта реализации Ozon смешение себестоимости и сторно затрат
  одной статьи теперь −2 вместо −8.
- Замер «до» регистра (компания × месяц) снят 23.11, вне git.
- Follow-up: issue #3113 — единое правило знака во всём проекте (предпросмотр ОПиУ и др.).

### После миграции на проде
Пересчёт регистра затронутых компаний (`app:finance:recalc-pl-register <companyId> --from --to`,
сначала `--dry-run`), затем сверка с замером «до»: меняются только найденные дни.

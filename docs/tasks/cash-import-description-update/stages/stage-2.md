## Что изменено

- Подтверждение привязано к immutable-плану, компании/счёту/файлу/mapping/инициатору. Выбор канонизируется как множество; повтор использует один jobId и advisory transaction lock.
- Action проверяет исходные bytes до записи и актуальный snapshot под блокировкой. Обновляется только описание/updatedAt/маркер защиты, с явным аудитом в той же транзакции. Суммы, категории, splits, документы и остатки не меняются.
- Пачки по 100: блокируются отсортированные ID текущей компании/счёта, затем пакетно читаются операции с контрагентами. Снимки кандидатов — scalar DBAL projection. После commit освобождается весь новый managed-граф, исходные объекты вызывающего кода сохраняются.
- description_finished фиксируется вместе с пачкой; rollback не продвигает прогресс. Повтор/возобновление не дублируют аудит. Автокатегоризация подавляется существующим guard.
- Новые строки после полного повторного распределения проходят без повторного вычитания legacy-квот; actual-create строго сравнивает approved InputRow, включая дату, до создания любых сущностей. Превышение1024 Unicode-символов — invalid, без обрезки. Не выбранные обновления и конфликты не становятся create. Счётчики ImportLog сохраняют смысл ошибок/дублей; created не включает обновления.
- Boolean imported_description_overridden защищает текст при overwrite в 1С; externalId/source/rawData при замене описания сохраняются. Банковский повтор использует существующее пропускание externalId.
- Старые jobs сохраняют legacy-путь. Существующий XLS-конвертер переиспользован ради совместимости; основная новая возможность проверена на XLSX/CSV.

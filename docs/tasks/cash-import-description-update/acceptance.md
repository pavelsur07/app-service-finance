# Чек-лист приёмки и план тестирования

Статус всех пунктов: **не выполнено**, это требования к будущей реализации. Ранее выполненный baseline (32 tests / 116 assertions) описан в baseline.md и не закрывает новые сценарии автоматически.

Для каждого ID при выполнении записать: имя теста или шаги smoke, команду, commit, результат и путь к отчёту в `stages/stage-N.md`. PASS без вывода/наблюдений запрещён. При неприменимости — техническое обоснование; обязательный бизнес-сценарий нельзя объявить N/A.

U = unit, I = integration с реальной тестовой БД, F = functional HTTP, M = ручной браузерный smoke. Тесты проверяют наблюдаемое поведение, а не список вызовов приватных методов.

## A — анализ и сопоставление (Stage 1)

| ID | Тип | Данные / действие | Что проверяем |
|---|---|---|---|
| A01 | U/I | Новая строка; точный повтор | create либо unchanged; верная квота, отсутствие записи на preview |
| A02 | U/I | Те же реквизиты, другое описание | update_description с правильным ID, old/new и объяснением |
| A03 | U/I | null, пустая ячейка, только пробелы при непустом старом тексте | нет очищения и предложения пустой замены; строка не становится create |
| A04 | U | Разные края/CRLF-LF-CR, затем регистр/пунктуация и внутренние пробелы | технические различия игнорируются; содержательные видны; внутреннее форматирование не схлопывается |
| A05 | U/I | Две одинаковые реальные операции; файл с двумя и затем с третьей такой строкой | существующие не схлопнуты; дополнительная законная строка учитывается по прежним правилам |
| A06 | U/I | Два возможных кандидата; несколько разных новых текстов для одного ID | конфликт всей неоднозначной группы, без произвольного назначения |
| A07 | U/I | Номер у обеих сторон, только у одной, разные непустые номера; перестановка строк | точные совпадения в приоритете; пропущенный номер не крадёт совпадение; результат независим от порядка |
| A08 | U/I | Тот же документ/счёт/день, другая сумма; другое направление/валюта; явно другой контрагент | нет предложения обновить финансово другую операцию; доказанный конфликт не создаёт новую |
| A09 | I | Похожие операции другой компании, другого счёта, другого года | чужие операции не становятся кандидатами; номер не глобальный ID |
| A10 | I | Кандидат каждого источника: файл, банк, 1С; удалённые строки | допустимые источники представлены; deleted не обновляются; прежняя soft-delete семантика не меняется |
| A11 | I/F | Файл более 100 строк, предложение в конце; строки на границе 199/200/201; XLSX и CSV | анализ всего файла, стабильные rowId, корректная сводка, страницы до 200 |
| A12 | I | Прочитать весь preview и сохранить план | в БД не создано/изменено ни операции, ни контрагента, ни категории, ни audit; план полный или не опубликован |

## B — применение, финансы, повторы (Stage 2)

| ID | Тип | Действие | Что проверяем |
|---|---|---|---|
| B01 | I | Подтвердить одну замену | тот же ID и число операций, новый текст, полный финансовый снимок неизменен |
| B02 | I/F | Не выбрать предложение; передать пустой выбор | существующий текст сохранён, skipped_by_user; новые строки продолжают импортироваться |
| B03 | I | Повтор нового файла после успешного обновления | нет create/update/audit для уже применённого текста |
| B04 | I | Повтор старого файла после обновления | нет дубля; обратная замена только новым явным согласием |
| B05 | I/F | Два подтверждения с одним ключом, одинаковой и разной selection | одинаковая selection возвращает один job; другая под тем же ключом отклоняется |
| B06 | I | Повтор доставки сообщения до/после окончания | нет повторных операций, audit и счётчиков |
| B07 | I | Принудительный сбой до commit пачки и после commit до следующей пачки | до commit всё откатилось; после commit повтор не применяет пачку снова; курсор/счётчики совпадают с БД |
| B08 | I | Изменить текст/сумму/другие реквизиты либо удалить операцию после preview | stale conflict, правка не затёрта, удалённая не восстановлена, fallback-create отсутствует |
| B09 | I | Два соединения: импорт одного счёта одновременно, ручная правка во время apply | lock/retry и блокировка строки исключают гонку; нет дубля или потери правки |
| B10 | I | Update-only; затем смешанный файл | update-only не меняет остатки и распределения; для новых строк смешанного файла прежние пересчёты сохранены |
| B11 | U/I | Обновление description при совпадающем автоправиле | нет назначения другой категории; ровно один audit с old/new/инициатором; rollback убирает и изменение, и audit |
| B12 | I | Обновить банковскую операцию, затем повторить дневной импорт банка с прежним текстом | подтверждённый текст сохранён; ID/count/source/externalId/rawData и финансовые поля не изменены от повтора |
| B13 | I | Обновить операцию 1С, повторить тот же импорт; повтор после нескольких замен | та же защита текста и исходных данных; нет накопления дублей |
| B14 | I | Старый job без версии плана; processing после сбоя | прежняя обработка совместима, восстановление завершается, старые тесты зелёные |
| B15 | I | Другой job создал предполагаемую новую операцию после preview; повреждённый/отсутствующий план | нет слепого create/update; явный конфликт/ошибка, без несанкционированного нового плана |

Финансовый снимок B01/B10: amount, direction, currency, occurredAt/bookedAt, account/company, counterparty, docNumber, projectDirection, responsibilityCenter, категории/splits, связи с ОПиУ/распределения, allocated amounts, дневные остатки, importSource/externalId/rawData. Сравнивать бизнес-значения и ссылки; исключать только заранее перечисленные служебные изменения (description, updatedAt, обоснованный dedupeHash и маркер защиты, если введён). Не исключать произвольные новые поля из assertion ради зелёного теста.

B12/B13 проверяют повтор с неизменными банковскими финансовыми данными: поведение банковской корректировки суммы не переопределяется этой задачей. Защиту описания проверить при каждом реально существующем пути записи источника, не только на skip-ветке, если есть update-ветка.

## C — UI и безопасность (Stage 3)

| ID | Тип | Действие | Что проверяем |
|---|---|---|---|
| C01 | F/M | Открыть предпросмотр | правильные old/new, реквизиты, источник, причины, ни одного выбранного обновления |
| C02 | F/M | Выбрать строку, сменить страницу/фильтр, выбрать все, снять выбор | selection сохраняется; select-all охватывает доступные обновления всего плана, конфликт не выбирается |
| C03 | F/M | Сменить файл/счёт/mapping; применить сохранённый профиль | старый выбор сброшен, новое согласие не наследуется |
| C04 | F | Подменить company/account/planId/rowId/transactionId; другой пользователь без прав; утрата доступа после preview | отказ на сервере без записи; IDOR закрыт, включая скачивание/чтение плана |
| C05 | F/M | Нет/неверный CSRF; описание с HTML/script; неверный тип/повтор rowId | запрос отклонён или безопасно нормализован по контракту, HTML экранирован, код не исполняется |
| C06 | F/M | Отмена, запуск с 0 updates и новыми строками, двойной клик | отмена без job; новые строки импортируются; один job при повторе |
| C07 | F/M | Очередь, обработка, ошибка, конфликт после preview, завершение | понятные состояния, retry UI не зависает, фактические итоги отличаются от прогноза при необходимости |
| C08 | M | Пустой файл/только ошибки/только конфликты, длинный многострочный текст, мобильный экран | корректные empty/error состояния, читаемость и доступность полного текста |
| C09 | M | Только клавиатура и проверка форматирования | labels/focus/selection доступны, суммы и статусы соответствуют дизайн-системе |

## F — файлы, нагрузка и схема (Stage 1–4)

| ID | Тип | Проверка | Критерий |
|---|---|---|---|
| F01 | I | Большой синтетический файл 1 000 и 10 000 строк, одинаковые распределения | записать время, peak memory, SQL count и размер плана; нет запроса на строку, нет загрузки всех кандидатов компании без диапазона; доступен последний результат |
| F02 | I | XLSX/CSV с некорректными датой/суммой, отсутствующим обязательным mapping, неподдерживаемый XLS | понятные errors, нет неявного изменения parser-правил, повреждённый файл не запускает импорт; бинарный XLS не объявлен поддержанным |
| F03 | I | Storage write/read failure, недоступная часть плана, подмена fingerprint/version | нет частично опубликованного подтверждаемого плана, отказ без бизнес-записи, нет утечки чужих данных |
| F04 | I | Миграция только если фактически добавлена | существующие строки сохраняются, старые jobs совместимы, локальные up/rollback проверены; release dispatch описан |

Для F01 численные результаты фиксируются до/после на одинаковом окружении. SLA не выдумывать: если измерение выявило неприемлемую стоимость, устранить запросы на строку/неограниченную память до закрытия этапа; ограничения объёма файла согласовать с существующим контрактом. Не вводить новый пользовательский лимит молча.

## Где размещать тесты

- Unit: расширить `tests/Unit/Cash/Service/Import/File/CashFileRowNormalizerTest.php`, `CashFileImportServiceTest.php`; чистому новому matcher — соседний отдельный тест. Аудит/guard: существующие Unit/Cash/EventSubscriber tests.
- Integration: переиспользовать `CashFileImportTestCase`, расширить `CashFileImportIdempotencyTest`, `CashFileImportHandlerFlowTest`, `CashFileImportBatchBoundaryTest`. Для preview/apply отдельные классы в тех же каталогах, если сценарии не укладываются в существующие.
- Банк: `tests/Integration/Cash/Application/ImportBankStatementDayTest.php`; 1С — существующие тесты в `Integration/Cash/Service/Import/`, общий ClientBank1CImportServiceTestCase.
- Functional: `tests/Functional/Cash/Controller/Import/` и существующие mapping/profile/storage tests.
- XLSX fixture создавать локально синтетически; не копировать реальные выписки, описания или production payload.

## Команды и evidence

Использовать работающий CLI-контейнер для повторных запусков (`docker compose exec -T -e XDEBUG_MODE=off site-php-cli ...`). Если сервис не запущен — `docker compose run --rm --no-deps -e XDEBUG_MODE=off site-php-cli ...`; сначала проверить тестовую БД и окружение. Ниже аргументы внутри контейнера:

```text
php bin/phpunit tests/Unit/Cash/Service/Import/File
php bin/phpunit tests/Integration/Cash/MessageHandler/Import
php bin/phpunit tests/Integration/Cash/Service/Import/File
php bin/phpunit tests/Integration/Cash/Application/ImportBankStatementDayTest.php
php bin/phpunit --filter ClientBank1CImport
php bin/phpunit --filter CashFileImport --testsuite functional
php bin/console lint:twig templates/cash/file_import_preview.html.twig templates/cash/file_import_queued.html.twig
```

Новые классы проверять явно: фильтр существующих названий не гарантирует их включение. На Work item — узкий набор; на Stage — затронутые модули и focused lint/static analysis; полные make gates только на handoff. Конкурентные тесты запускать с реальными отдельными соединениями, учитывая транзакционную обёртку тестового окружения.

## Финальный checklist (Stage 4)

- [ ] A01–A12: анализ и поиск соответствий подтверждены evidence.
- [ ] B01–B15: применение, повторы, транзакции, audit, банк/1С подтверждены evidence.
- [ ] C01–C09: Functional и ручной UI smoke выполнены.
- [ ] F01–F03 выполнены; F04 выполнен либо обоснованно N/A при отсутствии миграции.
- [ ] Красная регрессия исходного поведения и зелёная реализованного сохранены в отчётах.
- [ ] `make site-stan`, `make site-cs-check`, `make site-cs-strict-types`, `make site-test-unit`, `make site-test` завершены; failures не скрыты.
- [ ] Frontend gates при соответствующих изменениях завершены, ручной smoke записан.
- [ ] Свежий internal review и обязательный external review завершены; BLOCKER/IMPORTANT открытых нет.
- [ ] TASK/ARCHITECTURE/checkpoint/Stage Reports/handoff и PR актуальны.
- [ ] Merge/deploy не выполнялись без отдельного одобрения; если есть миграция, отдельный dispatch включён в запрос.

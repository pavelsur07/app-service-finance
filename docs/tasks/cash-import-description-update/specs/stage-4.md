# Stage 4 — сквозная приёмка и передача

Статус: проверки выполнены, release BLOCKER ожидает named CI/CD approval. Критерии сохранены; результаты — в ../acceptance-results.md и ../handoff.md. Риск: HIGH-LOCAL. Вход: интегрированные Stage 1–3.
`stage_base_commit`: записать перед началом. Это этап проверки и исправлений, не расширения возможностей.

## Work items

### 4.1 — полный сценарий

Пройти acceptance.md от загрузки до результата на XLSX и CSV: смесь новых строк, неизменных, выбранных/невыбранных описаний, неоднозначностей и ошибок. Повторить новый/старый файл, обработку задания, банк/1С. Собрать evidence по ID операций, количеству, финансовому снимку и аудиту. Использовать только синтетические данные; production и внешние банковские API не нужны.

### 4.2 — gates

Один раз на handoff выполнить `make site-stan`, `make site-cs-check`, `make site-cs-strict-types`, `make site-test-unit`, `make site-test`. Frontend gates — по Stage 3. После новых исправлений повторять релевантные проверки; не повторять одинаковую упавшую команду без изменения причины. Pre-existing failure отделять доказательством baseline, не объявлять зелёным.

### 4.3 — ревью

Финальное внутреннее ревью в свежей сессии с TASK, полным diff и checklist. Внешнее — по docs/workflow/external-review.md. Дополнительное внешнее ревью в конце HIGH-LOCAL этапа с diff >500 строк по AGENTS.md; ручного согласования между этапами нет. Исправить BLOCKER/IMPORTANT и безопасные MINOR; сохранить результаты/метрики и ограничения. Failed reviewer command не считать зелёным.

### 4.4 — handoff

Актуализировать ARCHITECTURE.md по реально появившимся контрактам, Stage Reports, checkpoint, handoff.md и описание одного PR. Перепроверить base master, отметить PR Ready только после завершения реализации. В handoff указать миграции/rollback, проверки, review, риски и ссылку на evidence. Запросить один раз merge + deploy; при миграции одновременно отдельный dispatch по release.md. Подготовка этих документов не разрешает merge/deploy.

## Приёмка этапа

- [ ] Все обязательные acceptance-ID закрыты доказательством, а не только отметкой.
- [ ] Финансовые поля/остатки/документы не меняются от update-only.
- [ ] Повторы, конкуренция, банки/1С и новые операции проверены.
- [ ] Полные gates завершены, результаты сохранены.
- [ ] Внутреннее/внешнее ревью выполнено, открытых BLOCKER/IMPORTANT нет.
- [ ] Нет новых зависимостей, production/config/permission changes вне согласованного объёма.
- [ ] Миграция, если есть, проверена локально и отражена в плане релиза.
- [ ] PR готов, handoff содержит точный запрос merge/deploy; до одобрения релиз не выполнялся.

Stage Report — `stages/stage-4.md`, итог — handoff.md, только после фактических проверок.

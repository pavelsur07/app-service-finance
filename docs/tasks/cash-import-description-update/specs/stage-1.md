## Результат

Сервер анализирует весь файл XLSX/CSV и формирует неизменяемый план: create, unchanged, update_description, conflict, invalid. Бизнес-данные при анализе не меняются. Каждый кандидат имеет объяснение сопоставления, исходный и новый текст; согласие ещё не получено.

## Work items

### 1.1 — регрессия и правила

Добавить наблюдаемую регрессию по baseline.md: прежний импорт + файл с новым описанием не должны создавать вторую операцию. Доказать красный результат на исходном поведении, а не на ошибке загрузки нового класса. Матрица design.md — источник тестовых примеров. Нормализация сравнения: trim по краям и одинаковое представление CRLF/LF/CR; не удалять переносы, внутренние пробелы, регистр или пунктуацию. Пустой новый текст не предлагает очищение. Техническое равенство не требует UPDATE.

### 1.2 — распределение кандидатов

Весь файл анализируется до записи, точные совпадения получают приоритет. Одна операция расходуется максимум один раз. Сохранить количественные совпадения, включая законные одинаковые строки и повтор с дополнительной такой строкой. Проверять направление и валюту явно. Разные непустые номера не склеивать. Пустой номер не должен отнимать точное соответствие другой строки. Изолировать компанию/счёт до поиска.

Кандидат на замену текста требует совпадения финансовых реквизитов и однозначного распределения. Если есть несколько возможных назначений — conflict. Признак конфликта суммы: тот же непустой номер документа в рамках счёта/дня при несовпадающей сумме; не считать номер глобальным ID. Без номера не объявлять любую другую сумму в этот день той же операцией. Сведения о контрагенте уточняют совпадение существующим нормализатором, но не создают/переименовывают контрагентов на preview. Любое неразрешимое противоречие — conflict, без выбора первого ID.

### 1.3 — план и его хранение

План содержит версию, ID, компанию/счёт/инициатора, fileHash, mappingHash, fingerprint, сводку. Строка содержит rowId (лист/строка), результат анализа, причину, financial snapshot и для update — transactionId, oldDescription, newDescription. Immutable fingerprint включает содержимое и контекст; opaque ID не заменяет проверку доступа.

Чтение — страницами не более 200 строк, анализ — всего файла. Если нужны части плана, хранить неизменяемый manifest; публиковать ссылку только после успешной записи всех частей. Ошибка/отсутствующий объект не приводит к импорту. Смена файла/счёта/mapping инвалидирует прежний выбор. Использовать существующий жизненный цикл временных импортов; не добавлять отдельный production cron без необходимости и согласования.

# Обновление описаний при файловом импорте ДДС

## Поручение и граница текущей работы

Владелец подтвердил сценарий: предлагать обновить описание существующей операции, не меняя сумму и не создавая дубль. Текущее поручение — полная подготовка перед кодом (пункты 1–5). Реализация приложения и написание тестового кода пока не разрешены этим этапом. Документы подготовки сохраняются в единственной ветке будущей задачи.

## Подтверждённые требования

- Новые операции импортируются; существующим предлагается обновление описания с явным подтверждением.
- Изменяются только описание и необходимые служебные поля. Финансовые поля и связи неизменны.
- Неоднозначные соответствия не изменяются автоматически.
- Повторные импорты и повторная доставка сообщения не создают дубли.

## Решения владельца — согласованы 2026-11-06

1. Пустое описание не очищает существующий текст (включая текст из одних технических пробелов).
2. Неоднозначные строки пропускаются с конфликтом, без автоматического создания операции и без ручного выбора кандидата в первой версии.
3. Содержательные изменения, включая регистр и пунктуацию, показываются для подтверждения. Пробелы по краям и технические различия переносов строк игнорируются при сравнении; внутреннее форматирование сохраняется.
4. Поддерживаются текущие XLSX/CSV; старый бинарный XLS в объём не входит.
5. Обновления разрешены для файлового импорта, банка и 1С. Источник, внешний ID и исходные данные сохраняются; последующая синхронизация не должна перезаписывать подтверждённое описание.
6. Все обновления — только по явному выбору; по умолчанию ничего не выбрано. Доступны отдельный выбор и «Выбрать все доступные».

## Приёмка

Существующая операция сохраняет ID, сумму, направление, дату, валюту, счёт, контрагента, категории, распределения, документы и остатки. Пользователь видит старый/новый текст и реквизиты кандидата. Невыбранное предложение пропускается. Конфликты видны в предпросмотре и итогах. Две законные одинаковые операции остаются двумя. Повтор старого и нового файла не создаёт дубль; старый текст не возвращается без нового подтверждения. Конкурентное ручное изменение не затирается. Повторная синхронизация банка и импорт 1С сохраняют подтверждённое описание, источник, внешний ID и исходные данные. Пустой текст и только технические отличия не предлагают замену.

## Вне объёма

Изменение сумм и других финансовых полей; массовое исправление исторических дублей; изменение банковских протоколов (защита описания при существующей синхронизации входит в задачу); общий редизайн; production-команды; merge/deploy на этапе подготовки.

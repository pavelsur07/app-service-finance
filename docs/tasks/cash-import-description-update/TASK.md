# Обновление описаний при файловом импорте ДДС

## Поручение и граница текущей работы

Владелец подтвердил сценарий: предлагать обновить описание существующей операции, не меняя сумму и не создавая дубль. Текущее поручение — полная подготовка перед кодом (пункты 1–5). Реализация приложения и написание тестового кода пока не разрешены этим этапом. Документы подготовки сохраняются в единственной ветке будущей задачи.

## Подтверждённые требования

- Новые операции импортируются; существующим предлагается обновление описания с явным подтверждением.
- Изменяются только описание и необходимые служебные поля. Финансовые поля и связи неизменны.
- Неоднозначные соответствия не изменяются автоматически.
- Повторные импорты и повторная доставка сообщения не создают дубли.

## Решения владельца — ожидаются

В чате отправлены два вопроса. До ответа не считать предложения согласованными:

1. Пустой текст не очищает описание; неоднозначные строки пропускаются без ручного выбора кандидата; регистр/пунктуация считаются изменением; форматы XLSX/CSV, без добавления бинарного XLS.
2. Разрешены ли предложения обновления для операций из банка/1С и других источников либо только для файлового импорта?

## Приёмка

Существующая операция сохраняет ID, сумму, направление, дату, валюту, счёт, контрагента, категории, распределения, документы и остатки. Пользователь видит старый/новый текст и реквизиты кандидата. Невыбранное предложение пропускается. Конфликты видны в предпросмотре и итогах. Две законные одинаковые операции остаются двумя. Повтор старого и нового файла не создаёт дубль; старый текст не возвращается без нового подтверждения. Конкурентное ручное изменение не затирается.

## Вне объёма

Изменение сумм и других финансовых полей; массовое исправление исторических дублей; изменение банковских протоколов; общий редизайн; production-команды; merge/deploy на этапе подготовки.

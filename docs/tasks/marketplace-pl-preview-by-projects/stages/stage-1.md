# Предпросмотр ОПиУ: колонки по проектам — этап 1 (единственный)

Экран `/marketplace/pl-preview` (`PlPreviewController`) и обе выгрузки xlsx.

## 1. Какую задачу решаем

Сейчас колонки предпросмотра — только теги листингов. Владельцу нужен второй разрез: по
**проектам ОПиУ** (`ProjectDirection`) — увидеть, как данные периода лягут в ОПиУ по проектам
до проведения.

Решения Владельца (03.11.2026):

- переключатель «Колонки: Теги / Проекты», разрезы одновременно не показываются;
- в режиме «Проекты» — чек-боксы проектов компании (какие проекты выводить колонками);
- колонка «Без проекта» видна только когда в ней есть суммы;
- режим «Теги» не меняется.

## 2. Что будет результатом

- Фильтр: `columns=tags|projects` (по умолчанию `tags`), `projects[]` + `projects_set=1` — по
  аналогии с `tags[]`/`tags_set`. Ссылки пресетов периода и выгрузок несут режим.
- Проект суммы — **как при проведении** (`CloseMonthStageAction`): проект правила маппинга
  продажи/возврата/реализации (`marketplace_sale_mappings.project_direction_id`), иначе — проект
  из настроек Seller-подключения маркетплейса. У затрат своего проекта нет — всегда проект
  подключения. Реклама в режиме проектов не раскладывается по статистике (это нужно только для
  листингов): она идёт учётной суммой на проект подключения, как при проведении.
- Колонки: выбранные проекты (в порядке дерева, с отступом уровня в подписи) → «Без проекта»
  (только если ненулевая) → «Итого». Сумма попадает в свой проект, без свёртки в родителя.
- У суммы один проект, поэтому колонки проектов (все выбраны) + «Без проекта» = «Итого».
  «Без проекта» — ровно то, что при проведении в регистр ОПиУ не попадёт (уже есть
  предупреждение `projectWarnings`).
- Чужой или несуществующий id проекта в ссылке отбрасывается (IDOR — список берётся по компании).
- Выгрузки: `PlPreviewXlsxExporter` — колонки как на экране; `PlPreviewRowsXlsxExporter` —
  `column_kind` получает `project`/`no_project`, колонки «ID тега»/«Тег» становятся «ID колонки»/
  «Колонка» (тег или проект).

## 3. Что считаем выполненной работой

- Режим «Проекты» доступен на экране и в обеих выгрузках, режим «Теги» ведёт себя как раньше
  (существующие тесты зелёные без правок по смыслу).
- Тесты (CLAUDE.md «Тесты — минимум»):
  - unit `PlPreviewFilterTest` — разбор и сборка `columns`/`projects`/`projects_set`, мусор → по умолчанию;
  - integration `BuildMarketplacePlPreviewActionTest` — проект из правила; проект из подключения;
    затрата → проект подключения; нет проекта → «Без проекта»; «Без проекта» скрыта при нуле;
    сумма колонок = «Итого»; проект другой компании в `projectIds` отброшен; невыбранный проект
    в колонки не попадает;
  - functional `PlPreviewControllerTest` — `?columns=projects` рендерит переключатель и колонки;
  - unit экспортёров — колонки проектов в xlsx;
  - тест нового метода `CompanyFacade` (через вызывающий код или unit).
- Гейты: `make site-stan` (baseline не растёт), `make site-cs-check`, `make site-cs-strict-types`,
  затронутые наборы тестов.
- `ARCHITECTURE.md`: раздел предпросмотра ОПиУ и Company Facade — текущее состояние, строка в Changelog.
- Скриншот экрана в обоих режимах на локальном стенде.

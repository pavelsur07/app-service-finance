# baseline-guard-renames: учёт переименований в CI-гейте роста baseline

`site/bin/phpstan-baseline-guard.sh` сравнивал записи `(path, identifier, message)` и считал
записи переименованных файлов новыми (#2506, #2507: 248 «новых» при неизменных 2410),
вынуждая ставить `[baseline-grow]`, которая выключает проверку целиком.

Решение: CI строит карту `git diff -M --name-status --diff-filter=R base HEAD`, и
`site/bin/phpstan-baseline-rename.php` переписывает записи **базы** (path, FQCN по PSR-4 в
формах `\`/`\\`/`\\\\`, второстепенные классы из новых версий файлов, пути `…\.php:NN`).
Текущий baseline не трогается — новая ошибка или рост count в перенесённом файле
остаются NEW/GREW.

Риск: HIGH-EXTERNAL (поведение CI-гейта, AGENTS.md §3.3) — отдельное согласие на handoff.
stage_base_commit: d5e9eee3

Проверено на реальных данных: #2506 и #2507 с картой — «не вырос»; без карты — отказ;
с картой + искусственная запись — ровно 1 NEW. Попутно исправлен выход 141 (SIGPIPE в
`printf | head` при pipefail) вместо штатного 1.

Защита от склейки (по ревью): если переписывание превращает две разные записи базы в один
ключ (например, `App\A\Bar` и `App\B\Bar` при переносе файла с `class Bar`), guard сложил
бы их count, и рост одной прошёл бы как перенос. Такой случай — отказ helper'а (fail closed)
с подсказкой провести PR меткой `[baseline-grow]`. Цепочки A→B и B→C git без `-B` в карту
не выдаёт.

## Какую задачу решаем

После деплоя калькулятор работает только для новых обработок. Строки ИП Лазаревой
(`3f4d87cc-a967-43a7-9b5e-8a9113c0a910`) с 13.10 уже обработаны и лежат в

убедиться, что затраты идут в «Раздачи / самовыкупы / отзывы», а гейт #387 зелёный.

## Что будет результатом

1. Замеры «до» (read-only, `codex-psql-ro`), до любых записей:
   - по сырью: число строк операции и сумма `cashbackAmount` (плюс/минус отдельно) за 13.10–дата деплоя;
   - по `marketplace_costs` 3f4d87cc WB за тот же период: число строк и сумма по каждой категории;
   - документы с непустым `unprocessed_cost_types` в окне.
2. Пересчёт (запись на проде, одобрен в «делай все этапы автономно», 19.10):
   `codex-console app:marketplace:reprocess 3f4d87cc-a967-43a7-9b5e-8a9113c0a910 wildberries 2026-10-13 <дата деплоя>` —
   сначала `--dry-run`, затем без него, по одной компании.
3. Замеры «после» и сверка:
   - `wb_review_points_withheld`: строк = строк сырья с ненулевой суммой; CHARGE − STORNO = нетто `cashbackAmount`;
   - остальные категории за период — те же строки и суммы, что «до» (с поправкой на свежие дни, пришедшие между замерами — сверять по `processed_at`/дню);
   - `unprocessed_cost_types` в окне пуст.
4. Маппинг: правило `wb_review_points_withheld` у 3f4d87cc → «Раздачи / самовыкупы / отзывы».
   Создаёт ночной `cost-pl-mapping:sync-default` (04:35); при необходимости раньше —
   `cost-pl-mapping:apply-default --company-id=3f4d87cc… --marketplace=wildberries`
   сначала предпросмотром, `--execute` — только если предпросмотр не трогает чужие правила.
5. Гейт: `codex-console app:marketplace:wb-costs:unrecognized-check --days-back=14` → exit 0;
   утром 20.10 после 06:40 — нового события #387 в GlitchTip нет.

#### Ключевое решение: запретный список, а не «только Facade»
Первый вариант правила — «снаружи модуля виден только Facade» — отвергнут по
замеру, а не по вкусу. Facade этого проекта возвращают Entity и Enum
(`CompanyFacade` → `App\Company\Entity\Company`, `FinancialResponsibilityCenterFacade`
→ DTO), поэтому легальное использование Facade требует импортировать эти типы:
правило пометило бы плохим состояние, из которого нет выхода без переписывания
всех Facade. Это ровно тот дефект, о котором предупреждает `CLAUDE.md` в разделе
«Health-гейты».

Распределение 781 внешнего импорта в модули с Facade и цена вариантов:

Выбран запретный список: он опирается на уже написанное правило проекта
(«Запрещено импортировать `Service/`, `Repository/`, `Application/`,
`Infrastructure/` чужого модуля»), и у каждого нарушения есть понятная операция
починки — увести вызов через Facade.

Одно осознанное отступление от буквы: из закрытого `Application/` исключён
подслой `Application/DTO` — типы, которыми Facade описывает свой контракт. Без
этого типизированный вызов Facade сам был бы нарушением. Чтобы правило и гейт не
расходились, исключение внесено в нормативный раздел `CLAUDE.md` («Facade») и в
список глобальных запретов, а не оставлено только в коде правила.

PHPat после исключения `Application/DTO` — **118**. PHPat видит не только `use`,
но и типы параметров и наследование.

# Активация OAuth MCP в production

Основание — разрешение владельца на OAuth для `https://app.vashfindir.ru/mcp`, передачу `MCP_OAUTH_*` в PHP-FPM и создание ключей в GitHub Secrets. База `f422c1c1c`. Базовый прогон — `make test-release-pipeline test-deploy-workflow test-frontend-release test-frontend-auth-routing`.

Продолжить по действующему workflow выпуска и переиспользовать правила настройки Альфа, ЮKassa и уведомления Billing там, где подходят GitHub Actions и отдельное окружение сервиса. Для многострочных PEM использовать окружение шага и Bash-экранирование при передаче по уже существующему SSH-каналу. Адрес и два публичных клиента фиксированы в workflow. [Текущий контракт OAuth](../mcp-cash/oauth.md)

## Этап 1. Доставка конфигурации

Риск HIGH-LOCAL. База этапа `f422c1c1c`.

**Результат.** В стандартной выкладке PHP-FPM получает адрес, список из двух клиентов, пару RSA и ключ Defuse.

**Приёмка**

- [ ] Исполняемый тест workflow доказывает побайтовую передачу многострочных значений через SSH. Синтетические значения с кавычками и символами shell остаются данными и отсутствуют в журнале.
- [ ] Compose передаёт все пять параметров только в PHP-FPM. При отсутствии всех ключей MCP выключен. Неполный набор отклоняется до передачи конфигурации. SSH сверяет сервер с закреплённым ключом.
- [ ] Порядок гейтов и rolling deploy сохранён. Локальные тесты release, Compose и OAuth проходят на синтетических данных.

**Работы**

1.1 — тест actual workflow через fake SSH, тест изоляции окружения PHP-FPM и отказа при неполном наборе.  
1.2 — передача через GitHub Actions env и SSH в FPM, тесты в Docker Compose.  
1.3 — сквозная проверка маршрутов через Nginx и PHP-FPM и актуализация инструкции.

## Этап 2. Подготовка production-секретов

Риски HIGH-LOCAL и HIGH-EXTERNAL. Запись ключей в GitHub Secrets одобрена владельцем.

**Результат.** Сформирован отдельный production-набор RSA и Defuse, проверена пара RSA, три записи доступны по именам в GitHub Secrets. PR готов к обычному выпуску.

**Приёмка**

- [ ] Три имени секретов зарегистрированы. Существующие записи сохраняются. Значения передаются в GitHub по stdin, отсутствуют в выводе, диффе и артефактах.
- [ ] Ревью закрыло подтверждённые BLOCKER и IMPORTANT. Гейты PR прошли. После одобрения выкладки проверяются discovery и запрос к `/mcp` без bearer-токена через установленный канал приёмки.

**Вне обоих этапов.** Миграции, правила подписок и выдачи доступа, схемы MCP, инструменты ДДС, тестовая запись финансовых данных на production и настройки клиентских аккаунтов.

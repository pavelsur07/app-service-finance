# МойСклад: массовое принятие предложений, отмена пакета, автоприменение

Страница `/moy-sklad/connections/{id}/mappings/{ozon|wildberries}`. Сейчас подбор и
применение — только 25 листингов текущей страницы, синхронно, предпросмотр в сессии на
15 минут. Диагностика уже считает решения по всему кабинету в фоне.

## 1. Задача

Принимать однозначные предложения сразу по всему кабинету, безопасно и с отчётом;
уметь откатить пакет; по желанию — принимать новые однозначные совпадения автоматически.

## 2. Результат

### Этап 1. Пакет из отчёта (фон, прогресс, отчёт)
- Таблицы `moysklad_mapping_bulk_jobs` (пакет: scope, автор, характеристика, прогресс,
  счётчики, статус, отмена) и `moysklad_mapping_bulk_job_items` (строка пакета: ожидаемая
  позиция, итог, сообщение, ревизия, итог отмены). Схема — `MoySkladSchemaExtension`.
- `StartMappingBulkJobAction`: id пакета — скрытый UUIDv7 формы (повтор → тот же пакет);
  под advisory-lock scope (company, connection, marketplace) — один активный пакет;
  scope `report` (все READY последнего completed-отчёта) или `selected` (отмеченные
  строки, только READY этого отчёта). Отчёт должен быть не устаревшим. Строки пакета
  снимаются из отчёта в той же транзакции (`INSERT … SELECT`), поэтому новая диагностика
  посреди пакета его не обрывает. Dispatch после commit; потерю сообщения закрывает
  cron-requeue.
- `ApplyMappingBulkJobMessage(companyId, jobId)` → `async_pipeline`. Handler: фазы claim →
  порции по 100 → finalize. Для порции свежий `AutomaticMappingPreviewQuery::evaluate`;
  строка пишется через существующий `ChangeListingMappingAction` с `AutomaticMappingGuard`
  (previewId = id пакета), только если свежее решение READY с той же позицией, иначе
  «пропущено: изменилось». requestId = UUIDv5(пакет, листинг) — повтор delivery не
  создаёт дублей и распознаёт уже принятую строку. Итог строки и счётчики пакета —
  одной транзакцией; heartbeat. Техническая ошибка останавливает пакет (failed).
- `app:moysklad:mapping-bulk:requeue` (`*/10`): повторный dispatch queued/running
  пакетов и отмен без heartbeat > 10 мин.
- UI: на вкладке «Предложения» — «Принять все предложения (N)» через общий диалог
  подтверждения с разбивкой по признаку (артикул, штрихкод, код…), чекбоксы строк и
  «Принять выбранные»; панель пакета над таблицей (идёт: X из N; итог: принято /
  пропущено / конфликт / ошибка); страница отчёта пакета с фильтром по итогу.
  При устаревшем отчёте или активном пакете кнопки заблокированы с объяснением.
  «Подобрать на странице» убрана вместе с кодом предпросмотра (контроллеры, Action, Redis pool) —
  пакет его заменяет, недостижимый из UI код не оставляем.

### Этап 2. Отмена пакета
- `StartMappingBulkUndoAction` + `UndoMappingBulkJobMessage`: для принятых строк, если
  текущая ревизия листинга — та, что создал пакет, пишется CLEAR (requestId =
  UUIDv5(пакет, листинг, undo)); иначе «пропущено: связь меняли после пакета». Снятая
  связь не предлагается снова (как ручное снятие). Прогресс и итог — в панели и отчёте.

### Этап 3. Автоприменение
- Таблица `moysklad_mapping_auto_apply` (включено, кто включил, характеристика размера).
  Галка в «Параметрах», POST с CSRF и правом записи.
- `app:moysklad:mapping-auto-apply` (`30 5 * * *`): для включённых и активных подключений
  пакет scope `cabinet` (обход всех листингов keyset'ом, применяются только READY),
  origin `auto`, автор — включивший пользователь; id = UUIDv5(scope, дата) — один пакет в
  сутки. Если у автора больше нет права записи маркетплейса — пакет не создаётся,
  warning в лог. Проверка права — новый `CompanyFacade::userHasModuleAccess`.

Не меняем: правила сопоставления и guard writer'а, ручной выбор, диагностику.

## 4. Чек-лист приёмки

1. «Принять все предложения (N)» создаёт один пакет; повторная отправка формы — тот же пакет.
2. Пакет обрабатывает все READY отчёта, не только страницу; прогресс виден на странице.
3. Строка, у которой после диагностики изменились листинг, каталог или правило, пропускается
   с причиной; связь не пишется.
4. Повтор обработки (retry/requeue) не создаёт дублей ревизий.
5. При устаревшем отчёте и при активном пакете запуск отклоняется с понятным текстом.
6. Отчёт пакета: принято / пропущено / конфликт / ошибка с фильтром и ссылками на строки.
7. «Принять выбранные» применяет только отмеченные строки.
8. Отмена снимает связи пакета, кроме изменённых после него; повтор отмены безопасен.
9. Автоприменение: один пакет в сутки на подключение и маркетплейс; без права записи у автора
   пакет не создаётся.
10. Пользователь только с чтением не видит кнопок и получает 403 на POST.
11. Миграции обратимо не откатываются (forward-only, как диагностика); схема в синхроне.

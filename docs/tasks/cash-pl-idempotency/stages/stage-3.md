# Этап 3 — запись документов ОПиУ и импорты выписок

Дата: 2026-10-22. Решение Владельца — «Делай этап 3, блоки А и Б». Блок В
(платёжные планы, ужесточение PHPStan-гейта) — отдельно, после ответов Владельца.

## 1. Какую задачу решаем

**Блок А — запись документов ОПиУ.**

- `DocumentController` (`new` / `copy` / `edit`) сам делает `flush()` документа,
  а регистр пересчитывает отдельным commit'ом. Сбой пересчёта оставляет
  документ без строк регистра.
- В `edit` остаток транзакции ДДС проверяется без блокировки и по коллекции
  документов, загруженной до отправки формы. Параллельный документ на тот же
  остаток проходит проверку.
- `CreatePLDocumentAction` сохраняет документ через `DocumentRepository::save()`
  с `flush()` в Repository.
- `PLSnapshotBuilder` (месячный снимок ОПиУ) делает `flush()` в сервисе
  и сохраняет чужой UnitOfWork. Строка «без статьи» на каждой пересборке
  вставляется заново: NULL в уникальном индексе различны.
- `PLCategoryController` делает `flush()` в контроллере.

**Блок Б — импорты выписок.**

- Импорт 1С (`ClientBank1CImportService`, синхронный HTTP) не сериализован ни с
  файловым импортом, ни с самим собой. Поиск дубля по `external_id` и вставка не
  атомарны. Уникальный индекс импорта 1С не защищает: `import_source` пуст.
- Банковский импорт по API (`BankImportService`) не сериализован по счёту.
  Тот же `uuid` на следующей странице дня до `flush()` не виден в БД.
  Вторая вставка роняет `flush()` дня на `uniq_cashflow_import`, и день вместе
  с курсором повторяется на каждом прогоне.
- Кандидат этапа 0 — 1С, 24 000 ₽, 19.06.2026: нужен вывод.

## 2. Что будет результатом

1. `CreateManualDocumentAction` (создание и копия) и `UpdateManualDocumentAction`
   (правка): документ, распределённая сумма и регистр прежнего и нового дня
   сохраняются одним `wrapInTransaction()`. Кэш дашборда сбрасывается после commit.
2. Правка документа с основанием ДДС берёт строку транзакции под
   `PESSIMISTIC_WRITE` + `refresh()`, перечитывает соседние документы и их
   операции и проверяет остаток по свежим данным. Затем строка документа
   `FOR UPDATE`: сохранённое состояние, из которого строится регистр (день,
   статус, тип, проект, ЦФО, операции), сверяется с загруженным формой.
   Параллельная правка того же документа — отказ «Документ изменён другим
   пользователем». Любой отказ под блокировкой — flash и форма заново.
3. `CreatePLDocumentAction` — `persist` + `flush` + регистр в
   `wrapInTransaction()`. Внутри закрытия месяца это точка сохранения;
   `DocumentRepository::save()` удалён.
4. `PLSnapshotBuilder::rebuildMonthly()` — DELETE месяца и upsert в
   `Connection::transactional()`, без `flush()`, под advisory-блокировкой
   (компания, месяц).
   `SavePLCategoryAction` для формы статьи.
5. `CashImportAccountLock` (сессионная блокировка этапа 2) — в импорте 1С
   и в банковском импорте:
   - 1С при занятом счёте получает `CashImportAccountBusyException`
     (flash, предпросмотр сохраняется);
   - банк пропускает занятый счёт с `warning`, следующий прогон догружает его
     с курсора.
6. Банковский импорт помнит `external_id`, записанные прогоном до `flush()` дня.
   При сбое посреди дня строки дня и курсор отсоединяются до снятия блокировки:
   `flush()` журнала импорта их не сохранит.
7. Baseline PHPStan: −4 записи `vashfindir.flushOutsideBoundary` (7 вхождений).

## 3. Что считаем выполненной работой

- Ни один путь записи документа ОПиУ в Finance не коммитит документ отдельно
  от регистра.
- Правка не превышает остаток транзакции ДДС при параллельном документе.
- Два импорта одного счёта не идут параллельно ни в одной комбинации
  файл / 1С / банк. Повтор `uuid` в дне не блокирует банковский импорт.
- Тесты красные на старом коде, гейты, CI и ревью Codex `REVIEW_GREEN`.
  Смержено и задеплоено. Сверка регистра «после» = «до».

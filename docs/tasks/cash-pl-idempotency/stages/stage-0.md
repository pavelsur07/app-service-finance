# Этап 0 — замеры на проде до изменений (Cash / Finance, идемпотентность)

Дата: 2026-10-22. Код и данные не меняются; только read-only SQL через
`codex-psql-ro`. Время в БД — МСК без зоны.

## 1. Какую задачу решаем

План идемпотентности ДДС/ОПиУ (прошёл независимое ревью Codex,
`PLAN_NEEDS_CHANGES`, учтено) опирается на предполагаемые дефекты. До кода
нужно узнать, какие из них есть в данных прода, и снять замеры «до», которые
после изменений восстановить будет нечем.

Проверяемые риски:

| # | Риск | Что ищем |
|---|---|---|
| R1 | Документ ОПиУ из ДДС без блокировки | транзакции ДДС, где сумма операций активных документов > суммы транзакции; расхождение `allocated_amount` с документами |
| R2 | Пересчёт регистра ОПиУ без транзакции / отставание | реальные unique-индексы `pl_daily_totals`; сверка регистра с документами по дню |
| R3 | Ручная транзакция ДДС без ключа | группы одинаковых ручных транзакций (счёт, сумма, дата, описание), созданных ≤ 10 с друг от друга — эвристика |
| R4 | Повторяющиеся платежи check-then-insert | дубли `payment_plan` по правилу и дате |
| R5 | Файловый импорт ДДС, dedupe_hash без unique | дубли `(company_id, dedupe_hash)` среди неудалённых транзакций; несколько jobs на один файл; зависшие `processing` |
| R6 | Сопоставление с планом без блокировки плана | > 1 match на один план |
| R7 | Остатки ДДС | расхождение `money_account_daily_balance` и `current_balance` с транзакциями |
| — | Окружение | версия PostgreSQL, фактические unique-индексы таблиц Cash/Finance |

  компаний, сумма» и вывод о составе этапов 1+.

## 3. Что считаем выполненной работой

- По каждому риску R1–R7 есть цифра или явное «запрос не выполнен» с причиной.
- Сняты замеры «до»: counts и суммы денежных полей `pl_daily_totals`,
  `documents`/`document_operations`, `cash_transaction`, `payment_plan`.
- Ни одной пишущей операции на проде.

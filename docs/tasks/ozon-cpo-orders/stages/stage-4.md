# Оплата за заказ Ozon — этап 4: источник SKU для кампаний `ALL_SKU_PROMO`

## Задача

Этап 3 установил: второе списание тип 54 — кампании `ALL_SKU_PROMO` (CPO, авто), их расход в
`expense` = тип 54 по дням до копейки (b57d7682 49903075, 3f4d87cc 23660699 — 37 тыс. ₽ за 01–10.11).
Отчёт по заказам Ingestion запрашивает только по кампаниям `SEARCH_PROMO`, поэтому SKU этих
кампаний нет. Нужно найти метод Ozon Performance, который отдаёт их расход по SKU.

## Результат

1. `campaigns-probe` получает опцию `--campaign=<id>` (вместе с `--from/--to`). Для кампании —
   живые read-only запросы, без записи в БД и S3:
   - `GET /api/client/campaign/{id}/objects` — число объектов и имена полей;
   - `POST /api/client/campaign/search_promo/v2/products` — то же;
   - отчёт по заказам `POST /api/client/statistic/orders/generate` с этой кампанией → опрос →
     скачивание: строк, колонки, расход по дням, строк без SKU, различных SKU.
   Ошибка каждого запроса печатается (класс, текст до 200 символов) и не останавливает остальные.
2. `codex-console` пускает `--campaign=<цифры>`; установка — по разрешению Владельца.
3. Прогон по 23660699 (3f4d87cc) и 49903075 (b57d7682) за 01–10.11, вывод — в этот файл:
   - отчёт по заказам с SKU и суммой = `expense` → этап 5: Ingestion добавляет `ALL_SKU_PROMO` в
     кампании отчёта, разнесение этапа 2 подхватывает без изменений;
   - нет → вариант «строка в Сверке / пропорция» (stage-3-research, §Предложение п. 3).

Почему отчёт по заказам: он уже принимает список кампаний, Ingestion просто не передаёт туда
`ALL_SKU_PROMO`. Если это работает — правка Ingestion в одну строку.

## Ограничения

- Отчёт Ozon один на аккаунт одновременно: прогон после 08:30, когда ночная загрузка закончена.
- Опрос — каждые 15 с, не дольше 15 мин; не готов → команда печатает UUID и завершается.

# Оплата за заказ Ozon по SKU — этап 2: разнесение по товарам

## Задача

Расход «Оплаты за заказ» (продвижение в поиске, кампании `SEARCH_PROMO`) в отчётах по товарам —
юнит-экономика, виджеты, колонки тегов предпросмотра ОПиУ — сейчас не виден:

- со счёта (начисление тип 54, категория `ozon_marketing_action`) — одна сумма за день без товара,
  в «Прочих» / «Общих» («Не распределено» у аналитика);
- из предоплаты рекламного баланса (`ozon_marketing_services`) — нигде: предоплата исключена из
  отчётов по товарам как «уже есть в статистике», а в статистике только клики.

Сверка этапа 1 на проде 11.11.2026, ноябрь:

| Кабинет | Отчёт по заказам | Начисления тип 54 | Вывод |
|---|---|---|---|
| b57d7682 | 111 073,08 ₽ (01–10.11), без SKU 0 | основная операция дня = отчёт до копейки | разносится целиком |
| 78f0cc9f | 132 818,00 ₽, без SKU 0 | в ноябре 0 — списание из предоплаты 01–03.11 | сейчас в отчётах по товарам не видно |
| 3f4d87cc | 1 044,00 ₽ | 01–09.11 ≈ 40 тыс. ₽, совпала одна операция | остальное — не оплата за заказ |
| 19621cff | 0 | 0 | — |

У b57d7682 с 07.11 и у 3f4d87cc с октября есть вторая операция тип 54 в день, которой в отчёте по
заказам нет. Что это, этап не выясняет. Она остаётся там же, где сейчас, — в «Общих» / «Прочих».

## Результат

Решение Владельца 11.11.2026: расход относим на **заказанный** SKU («SKU»). SKU продвигаемого
товара хранится в сырье рядом (Ingestion и `AdRawDocument`) для будущего отчёта эффективности.

1. **Загрузка в статистику.** Новая команда MarketplaceAds
   `app:marketplace-ads:ozon-search-promo:sync [--company-id=] [--from= --to=]` (без дат — месяц
   по вчера, 1-го числа — весь прошлый месяц). Строки берёт из Ingestion: новый метод фасада
   читает последние версии отчёта по заказам; разбор CSV-строк вынесен из сводной команды этапа 1
   и общий для обеих. На каждый (кабинет, день) — `AdRawDocument` с `source_key`
   `ozon-search-promo:<день>` и payload в nested-форме `OzonAdRawDataParser`, кампания
   `search-promo` «Оплата за заказ», строки `sku`, `spend`, `promoted_sku`. Проекция —
   существующий `ProcessAdRawDocumentAction`: SKU → листинг, повтор заменяет документы дня; сумма
   неизвестного SKU сохраняется без строки листинга (как у WB), чтобы итог дня = отчёт. День без
   строк — документ с пустым списком: прежние документы дня удаляются.
2. **CPC-конвейер Ozon не видит CPO-документы.** `findByMarketplaceAndDate` и
   `countByCompanyMarketplaceAndDateRange` исключают `source_key` `ozon-search-promo:%`: иначе
   скачивание CPC перезаписало бы CPO-документ, а финализатор job ждал бы его обработки.
3. **Вид расхода — по кампании, без миграции.** `MarketplaceAdsFacade` отдаёт расход по листингам
   и всего с фильтром вида: все / клики / оплата за заказ (`campaign_id = 'search-promo'`).
4. **Предпросмотр ОПиУ.** `AdStatisticsCostCategories`: у Ozon две категории под статистикой —
   `ozon_cpc` ← клики, `ozon_marketing_action` ← оплата за заказ. Порт
   `PlPreviewAdSpendProviderInterface` получает вид. Сверка — строкой на категорию. Остаток
   «учёт − статистика» (вторые операции, лаг D+2, предоплата) — в «Общих», «Итого» = учёт.
5. **Юнит-экономика и виджеты.** Реклама = статистика (клики + оплата за заказ). Учётная категория
   `ozon_marketing_action` не исключается целиком: в «Прочих» без товара остаётся
   `max(0, учёт − оплата за заказ из статистики)` за период, иначе пропали бы вторые операции.
6. **Расписание.** cron 08:30 — после загрузки отчётов (07:25, заканчивается к ~07:55).
7. **Расхождение SKU.** Команда печатает по кабинету строк, сумму и сколько строк с заказанным SKU
   ≠ продвигаемому.

## Задержка

| Что | Когда для дня D |
|---|---|
| Отчёт по заказам в Ingestion | D+1, ~07:45–07:55 (cron 07:25) |
| Расход по SKU в отчётах | D+1, 08:30 |
| Начисление тип 54 в учёте | D+2, 04:00 |
| Сверка «учёт = статистика» за D | с D+2 |
| Последнее обновление месяца | 1-е число следующего месяца |

## Охват

Все кабинеты с подключением Ozon Performance, без allowlist (`ActiveOzonPerformanceConnectionsQuery`).
Пустой отчёт → ничего не меняется. Кабинетов с тип 54 без Performance на 11.11.2026 нет.

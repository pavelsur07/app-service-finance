# Оплата за заказ Ozon — этап 5: «все товары» (ALL_SKU_PROMO) по товарам

## Задача

Расход кампаний `ALL_SKU_PROMO` (второе списание тип 54) Ozon отдаёт только по кампании за день,
без SKU (этап 4). Он лежит в «Прочих» / «Общих» без товара: у 3f4d87cc это большая часть оплаты за
заказ (205 тыс. ₽ с июня). Решение Владельца 12.11.2026 — вариант А: распределять по товарам кампании
пропорционально продажам.

## Результат

1. **Ingestion.** Список кампаний (`ozon_performance_campaigns`) включает `ALL_SKU_PROMO`; товары этих
   кампаний грузятся тем же ресурсом `ozon_performance_search_promo_products`. Отчёт по заказам —
   по-прежнему только `SEARCH_PROMO` (фильтр кампании Ozon игнорирует). Новый метод
   `IngestionFacade::getOzonAllSkuPromoSpend()` — расход по кампании и дню из `expense`
   (`moneySpent + prepaymentSpent`) и SKU товаров кампании.
2. **MarketplaceAds.** `SyncOzonAllSkuPromoSpendAction` в той же команде
   `app:marketplace-ads:ozon-search-promo:sync` (cron 08:30), после отчёта по заказам:
   - расход дня кампании → листинги её товаров пропорционально продажам (штуки) за день;
   - нет продаж за день → доли за период синхронизации (месяц);
   - нет продаж и за период или нет листингов → без товара (`__unallocated__`);
   - сырой документ дня `ozon-search-promo:all-sku:<день>`, кампания `all-sku-promo`
     «Оплата за заказ (все товары)»; повтор — как у этапа 2.
3. **Вид расхода.** `AdSpendKind::PAY_PER_ORDER` = обе служебные кампании: предпросмотр ОПиУ сверяет
   `ozon_marketing_action` со всей оплатой за заказ, юнит-экономика вычитает её из «Прочих».
   `__unallocated__` у оплаты за заказ — не ошибка маппинга (документ `processed`).

# Оплата за заказ Ozon по SKU — этап 1: загрузка и сверка

## Задача

Расход Ozon «Оплата за заказ» (начисление `Promotion`, `non_item_fee` тип 54, категория
`ozon_marketing_action`) приходит одной суммой за день без SKU, поэтому не разносится по товарам и в
предпросмотре ОПиУ лежит в «Рекламе вне статистики». Нужно проверить, что отчёт Performance по заказам
даёт тот же расход с SKU.

Загрузка уже есть: cron 07:25 `app:ingestion:ozon-performance:daily-load --window=month-to-date`
(модуль Ingestion) каждый день сохраняет отчёт `POST /api/client/statistic/orders/generate` в
`ingest_raw_records` (`ozon_performance_search_promo_statistics`, `…:orders:…`). Но
`OzonPerformanceReportClient::decodeCsv` принимал первую строку отчёта Ozon («;Отчёт по заказам, период …»)
за заголовок и по ней же выбирал разделитель — все строки сохранялись без колонок. То же у отчёта по
товарам. Данных в сырье за 01.06–10.11.2026 нет.

## Результат

1. `decodeCsv` пропускает строку-название Ozon (первая ячейка пустая), правило — как у
   `OzonPerformanceCsvParser` в MarketplaceAds.
2. Команда только для чтения `app:ingestion:ozon-performance:search-promo-orders-summary --company-id= --from= --to=`:
   по дням — строки заказов, расход, строки без SKU; итог; число отчётов и разных SKU. Номера заказов
   не печатает. Эталонная копия wrapper — `docs/maintenance/codex-console.sh`.
3. После деплоя утренний прогон 07:25 перезагрузит месяц с 01.11 уже с колонками.

Таблицы и миграции нет: для сверки хватает сырья, решение о хранении — этап 2.

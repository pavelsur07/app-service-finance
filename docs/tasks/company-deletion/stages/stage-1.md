# Этап 1 — запрос удаления компании и восстановление

## Задача

Кнопка «удалить компанию» сейчас всегда отвечает 500 (#458). Нужно, чтобы
удаление проходило без ошибки, было обратимым 30 дней и сразу останавливало
работу с компанией: она не видна, не выбирается активной, её подключения не
синхронизируются, биллинг не пишет владельцу.

## Результат

Ветка `feat/company-deletion`, один PR с миграцией.

1. `Company`: `deletion_requested_at`, `deletion_requested_by`;
   `requestDeletion()` (повтор — no-op, дата не сдвигается),
   `cancelDeletion()`, `isDeletionRequested()`, `getDeletionDueAt()`
   (+30 дней). Миграция: две nullable-колонки, обратимая.
2. `RequestCompanyDeletionAction` / `RestoreCompanyDeletionAction` — точки
   транзакции; событие `CompanyDeletionRequestedEvent` синхронно внутри
   транзакции. Слушатели: Marketplace (`marketplace_connections.is_active`),
   MoySklad (`moysklad_connections.is_active`), BankSync (`disable()`).
   Восстановление подключения обратно не включает — пользователь включает сам.
3. Контроллеры (один action на класс): `GET/POST /company/{id}/delete` —
   страница подтверждения с вводом названия; `POST /company/{id}/restore`.
   Только владелец, поиск компании с владельцем. Доменные исключения →
   flash/ошибка формы. Старый `CompanyController::delete` удаляется.
4. Видимость: `ActiveCompanyService`, переключатель, `company_set_active`,
   первая компания участника — без помеченных. Список компаний — помеченные
   отдельным блоком «Будет удалена DD.MM.YYYY» с кнопкой «Восстановить».
5. Billing: `CompanySubscriptionRepository::findEndingOn` пропускает
   помеченные; маршруты удаления/восстановления — в белом списке read-only.
6. `ARCHITECTURE.md` (Company), `TASK.md`.

## Что считаем выполненным

- Удаление онбординговой компании — redirect с сообщением, не 500;
  в БД — метка и отключённые подключения; данные не удалены.
- Повторный запрос — то же состояние, без ошибки; не владелец — 404;
  неверное название — ошибка формы, метки нет.
- Помеченная компания не видна в переключателе, не становится активной,
  не попадает в напоминания биллинга; восстановление возвращает её.
- Тесты по таблице CLAUDE.md, гейты, внутреннее и внешнее ревью, CI зелёный.

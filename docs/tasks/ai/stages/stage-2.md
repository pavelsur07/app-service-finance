голосование только для рискованных задач; появится с первой такой задачей.

## Задача (2.1)

Операции ДДС, которые не распознали автоправила, получают подсказку статьи
от ИИ-сервиса. Человек видит подсказку в списке операций и принимает её или
отклоняет; решение — метка точности. Без автоприменения.

## Результат

**Сервис** — задача `categorize_transactions` (`tasks/categorize_transactions/`):

- вход: справочник статей компании (id, путь, направление) и до 50 операций
  (id, направление, сумма строкой, валюта, дата, назначение, контрагент);
  ИНН и счета не передаются;
- выход: на каждую операцию `category_id` или `null` («недостаточно данных»),
  уверенность 0..1;
- проверки: полнота (каждая операция ровно один раз, лишних нет) — block;
  статья из справочника — block; направление статьи совпадает с операцией —
  review; порог уверенности — по минимальной уверенности пачки;
- промпт `categorize_transactions/v1`: temperature 0 (там, где провайдер
  принимает), ответ «недостаточно данных» разрешён явно, данные — в блоке
  данных;
- маршрут `fallback` по трём провайдерам в `routes.yaml`, без ключей —
  выключены; риск — низкий;
- evals: ≥ 20 синтетических обезличенных кейсов, включая ловушки
  «недостаточно данных»; тест порога точности гоняется по каждой доступной
  модели маршрута и пропускается без ключей.

**Контракт** `ai-task/v1`: `$defs` payload/output категоризации, примеры.

**Symfony, модуль Cash:**

- сущность подсказки `cash_category_suggestion` (миграция): компания,
  операция, `task_id`, статус (`requested` → `suggested` / `no_answer` /
  `failed` / `stale` → `accepted` / `dismissed`), предложенная статья,
  уверенность, вердикт сервиса, модель, версия промпта, решение человека и
  кто его принял; unique по (`task_id`, операция);
- постановка — `app:cash:ai-categorize --company-id=` (cron — при выводе в
  прод): операции компании без статьи (нет или `CF_UNALLOC`, без
  мультиразбивки, не перевод, не удалена, не в закрытом периоде, старше
  10 минут — автоправила отработали), без открытой подсказки; пачки по 50;
  строки `requested` пишутся в транзакции до постановки, постановка — после
  commit; зависшие `requested` переотправляются с тем же ключом;
- потребитель результата: проверяет, что статья — активная конечная статья
  компании и операция всё ещё без статьи, иначе `stale`;
- список операций: у операции без статьи — подсказка «ИИ: статья, %» с
  кнопками «Принять» и «Отклонить»; принять — проставить статью как ручная
  правка (закрытый период, разбивка `MANUAL`, `CashTransactionsChanged`),
  только если операция всё ещё без статьи;
- метка точности: принято / отклонено явно; исправлено — операция получила
  другую статью при открытой подсказке (считается запросом);
- `app:cash:ai-categorize-stats --company-id=` — доли статусов и точность
  по решениям людей.

## Что считаем выполненным

- гейты сервиса: ruff, mypy, pytest (unit, интеграционные), evals на stub;
- гейты PHP: PHPStan, CS, strict_types, unit, функциональные затронутых
  экранов, миграция на пустой БД и откат;

  подсказку; повторная постановка не создаёт дублей;

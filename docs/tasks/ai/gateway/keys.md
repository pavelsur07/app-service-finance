# Ключи и секреты для шлюза ИИ

План — `plan.md`. Ключи провайдеров хранятся **только в GitHub Secrets и на
шлюзе**; на app-сервер они не попадают. Значения нигде не пересылать (чат,
почта, тикеты) — только вставить в GitHub.

Где заводить: GitHub → репозиторий → Settings → Secrets and variables → Actions.

## 1. Ключи провайдеров (секреты шлюза)

| Секрет | Где взять | Заметки |
|---|---|---|
| `AI_OPENAI_API_KEY` | platform.openai.com → API keys → Create new secret key | Проект только под сервис; в Limits — месячный лимит расходов |
| `AI_DEEPSEEK_API_KEY` | platform.deepseek.com → API keys | Баланс пополняется заранее — пополнить на небольшую сумму |
| `AI_KIMI_API_KEY` | platform.moonshot.ai → API Keys | Международная платформа (`api.moonshot.ai`), не `.cn` |

Для каждого провайдера:

- отдельный ключ только для «Ваш Финдир», с понятным именем
  (`vashfindir-gateway`);
- лимит расходов или ограниченный баланс в кабинете провайдера — это первая
  линия защиты бюджета (§12 ТЗ);
- символы ключа — `A-Za-z0-9._~-` (у всех трёх так); деплой проверит.

## 2. Токен шлюза

| Секрет | Значение |
|---|---|
| `AI_GATEWAY_TOKEN` | случайная строка 48 символов; один и тот же секрет читают деплой шлюза (принимает) и деплой app (предъявляет ai-service) |

Сгенерировать (у себя, вывод сразу вставить в GitHub):

```bash
openssl rand -hex 24
```

На время ротации — второй секрет `AI_GATEWAY_TOKEN_NEXT` (шлюз принимает оба;
порядок — `gateway/README.md` после G0).

## 3. Секреты ai-service на app-сервере

Из `docs/maintenance/ai-service-prod.md`; ключей провайдеров среди них нет.

| Секрет / переменная | Значение |
|---|---|
| `AI_SERVICE_API_TOKEN` (secret) | случайная строка ≥ 32 символов — токен «Symfony → ai-service» (`openssl rand -hex 24`); не совпадает с `AI_GATEWAY_TOKEN` |
| `AI_SERVICE_DB_PASSWORD` (secret) | случайный пароль (`openssl rand -hex 24`) |
| `AI_SERVICE_SENTRY_DSN` (secret) | DSN проекта `ai-service` в GlitchTip; пусто — только лог |
| `AI_SERVICE_ENABLED` (variable) | `true` — когда всё выше заведено и шлюз проверен |
| `AI_SERVICE_COMPANY_ALLOWLIST` (variable) | UUID первой компании; пусто — ни одной, `*` — все |

## 4. DNS и сертификат (один раз)

- DNS: A-запись `ai.vashfindir.ru` → `109.73.204.179`.
- Сертификат на хосте шлюза (`ssh sv_bots_tw_root`), когда DNS разошёлся:

```bash
certbot certonly --nginx -d ai.vashfindir.ru
```

## Порядок

1. DNS (п. 4) — можно сразу, расходится до нескольких часов.
2. Ключи провайдеров (п. 1) и `AI_GATEWAY_TOKEN` (п. 2).
3. Сертификат (п. 4) — после G0.
4. Деплой шлюза (G1) — проверка 1 из `plan.md` покажет, что каждый ключ рабочий.
5. Секреты ai-service (п. 3) — после G2; `AI_SERVICE_ENABLED=true` — последним.

## Ротация и отзыв

- Ключ провайдера: выпустить новый в кабинете → заменить секрет → деплой шлюза
  (проверка 1) → удалить старый ключ в кабинете.
- Утечка токена шлюза: заменить `AI_GATEWAY_TOKEN` → деплой шлюза и app;
  ключи провайдеров при этом не меняются.

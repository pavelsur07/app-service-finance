# G1 — домен `ai.vashfindir.ru` на шлюзе

Общий план — `plan.md`, ключи — `keys.md`, предыдущий этап — `g0.md`.

## Задача

Добавить в `gateway/` сайт `ai.vashfindir.ru`: ai-service (с app-сервера)
ходит к OpenAI, DeepSeek и Kimi только через него, предъявляя токен шлюза;
ключи провайдеров живут только на шлюзе.

- Секреты: `AI_OPENAI_API_KEY`, `AI_DEEPSEEK_API_KEY` — есть; `AI_KIMI_API_KEY`
  — ждём (issue #2837); **`AI_GATEWAY_TOKEN` — нет**.
- Сертификата `ai.vashfindir.ru` на хосте нет.
- G0 на проде: сниппеты, `deploy-gateway.yml`, `install.sh` с откатом набора.

## Результат

```
https://ai.vashfindir.ru/{openai|deepseek|kimi}/<путь API>
  Authorization: Bearer <AI_GATEWAY_TOKEN>      (только с IP app)
        ▼ шлюз: IP → токен → провайдер настроен → limit_req
  https://api.openai.com/<путь>  · api.deepseek.com · api.moonshot.ai
  Authorization: Bearer <ключ провайдера>
```

base_url для клиентов (G2): `https://ai.vashfindir.ru/openai/v1`,
`…/deepseek/v1`, `…/kimi/v1`.

## Поведение (контракт, на него пишутся тесты)

| # | Запрос | Ответ |
|---|---|---|
| B1 | `GET /health` с любого IP, 80 и 443 | 200 `alive` |
| B2 | любой путь провайдера не с IP app (даже с верным токеном) | 403, токен не проверяется |
| B3 | с IP app без `Authorization` или с неверным токеном | 401 `{"error":{"code":"unauthorized"}}` |
| B4 | с IP app, токен = `AI_GATEWAY_TOKEN` или `AI_GATEWAY_TOKEN_NEXT` | проксируется |
| B5 | проксирование | upstream получает путь без префикса провайдера и с query, `Host` провайдера, `Authorization: Bearer <ключ>`; не получает токен шлюза, `Cookie`, `X-Forwarded-For`, `X-Real-IP`, `OpenAI-Organization`, `OpenAI-Project` |
| B6 | ответ upstream | `Set-Cookie`, `openai-organization`, `openai-project` скрыты; статус и тело — как у провайдера |
| B7 | провайдер без ключа (Kimi сейчас) | 503 `{"error":{"code":"provider_not_configured"}}` |
| B8 | тело больше 1 МБ | 413 |
| B9 | всплеск выше `limit_req` (10 r/s, burst 20 на провайдера) | 429 |
| B10 | неизвестный путь, `/openai` без слэша | 404 |
| B11 | access log | строки запросов есть; токена, ключей, тел нет |
| B12 | Telegram: `/bot-api/` не с app → 403, с app → `api.telegram.org`, вебхук → app | как в G0 |

## Решения

- **IP-фильтр — `geo` + `if`, а не `allow/deny`.** Токен проверяется в фазе
  rewrite, а `allow/deny` — позже, в фазе access: с `allow/deny` чужой IP без
  токена получил бы 401 вместо 403. `geo $gateway_from_app` в
  `conf.d/gateway-app.conf` (IP app — по-прежнему в одном месте), сниппет
  `app-only.conf` = `if ($gateway_from_app = 0) { return 403; }`. Заодно
  пропадает строка `access forbidden by rule` с путём запроса в error log —
  для `/bot-api/` это путь с токеном бота.
- **Секреты — `/etc/nginx/gateway-secrets.conf`, root:root 0600.** Собирает
  `scripts/render-secrets.sh` на раннере из GitHub Secrets: `map` токена
  (текущий и следующий) и по `map` на ключ провайдера. Значения проверяются по
  алфавиту `A-Za-z0-9._~-` (кавычки, `$`, `;`, перевод строки в конфиг не
  попадут). Токен в `map` — регулярка `~^Bearer …$`: строковые ключи `map`
  nginx сравнивает без учёта регистра (находка ревью, тест B3). `AI_GATEWAY_TOKEN` обязателен и ≥ 32 символов; ключ провайдера
  может быть пустым → B7. Файл входит в набор отката `install.sh`.
- **Upstream — константы с `resolver` и переменной** (как в Telegram): DNS
  провайдера, недоступный при reload, не роняет nginx и Telegram.
- **SSH деплоя — с закреплённым ключом хоста** (`gateway/known_hosts`,
  `StrictHostKeyChecking=yes`): архив несёт ключи провайдеров (находка ревью).
- **Staging на хосте — `mktemp -d` до загрузки**, архив и `install.sh` не
  лежат по предсказуемому пути в `/tmp` (находка ревью).
- **Error log провайдеров выключен** — ошибки 413/429/upstream пишут строку
  запроса с query; диагностика — access log (`upstream_status`,
  `request_time`). Тест — маркер в query на 413/429/502.
- **Путь в access log — исходный** (`$request_uri` без query): `$uri` после
  rewrite — уже путь upstream без префикса провайдера.
- **Таймауты** — connect 5 с, read/send 120 с; `proxy_buffering off`
  (стриминг ответов).
- **Проверка 1 при деплое** — с хоста шлюза `GET /v1/models` напрямую у
  каждого провайдера с ключом (ключ — в заголовке через `curl -K -`, не в
  аргументах). Результат печатается; не-200 у настроенного провайдера делает
  деплой красным, но **не откатывает** конфиг: откат не чинит ключ, а Telegram
  не должен зависеть от провайдера.
- **Проверки хоста** (с откатом при провале): `ai` `/health` 200 по 80/443,
  `/openai/v1/models` с хоста → 403, неизвестный путь → 404; проверки Telegram G0.
- **Не входит:** `00-default` (закрыть неизвестные Host — меняет ответ
  `mybots`, отдельное решение Владельца); проверки 2, 4, 5 с app-сервера — G2,
  когда токен шлюза появится на app.

## Действия Владельца до мержа

1. Секрет `AI_GATEWAY_TOKEN`: `openssl rand -hex 24` → GitHub Secrets.
2. Сертификат на хосте шлюза:
   `ssh sv_bots_tw_root 'certbot certonly --nginx -d ai.vashfindir.ru'`.

Без них деплой G1 остановится до установки (проверка сертификата и токена) —
шлюз Telegram не затрагивается.

деплой; экстренно на хосте: `rm /etc/nginx/sites-enabled/ai-gateway && nginx -t
&& systemctl reload nginx` (Telegram не затронут).

# Автомаппинг листингов Ozon/Wildberries на МойСклад

Статус: проект требований и план. Владелец попросил разработать план;
продуктовый код и production в этой задаче не меняются.
Основание: ручной маппинг из PR #3016 уже выпущен. Требуется находить
соответствия и массово применять однозначные результаты.

## Результат первой версии

В существующих legacy-вкладках Ozon/Wildberries пользователь выбирает
подключение, получает предпросмотр соответствий для текущей страницы
листингов и одним действием применяет выбранные однозначные результаты.
Для каждой строки видны основание, целевая позиция либо причина отказа.
Это запуск по кнопке с предпросмотром, без фонового автосохранения.

Правила ниже — предложения для первой версии, а не уже согласованные
финансовые или товарные правила. Принятие плана для реализации означает
принятие именно этих ограничений; до реализации их можно изменить.

## Данные и границы

- В Marketplace есть supplierSku (Ozon offer_id, WB vendorCode), размер,
  marketplaceSku, marketplaceVariantId, название и отдельные баркоды.
- В текущем импорте МойСклад есть article/code/name, product/variant,
  parentExternalId и characteristics[{id,name,value}]. Баркодов МС нет.
- Marketplace владеет листингами; чтение и блокировка источника — через Facade.
- MoySklad владеет кандидатами, решениями, связями и историей.
- Внутренний Catalog, Finance, Inventory, отчёт комиссионера, FIFO и любые
  HTTP-записи в МойСклад исключены. Новых зависимостей и транспортов нет.

## Предлагаемые правила сопоставления

1. Артикулы сравниваются после удаления ASCII whitespace (0x09–0x0D и 0x20)
   по краям; PHP и SQL используют один набор символов. NBSP не заменяется.
   Регистр, ведущие нули и все остальные символы сохраняются. Пустой артикул не ключ.
2. Правило A: supplierSku = собственный article товара или модификации МС.
   Товар допустим только без модификаций: variants_count=0 И нет дочерних строк.
3. Правило B: supplierSku = article родительского товара МС и точный размер
   листинга = значение выбранной характеристики конкретной модификации.
4. Характеристику размера выбирает пользователь по внешнему id из локального
   каталога этого подключения. По имени «Размер» программа её не угадывает.
   Выбор действует только в данном предпросмотре, сохраняется сервером и
   показывается рядом с правилом; постоянной настройки/миграции в v1 нет.
5. Размер сравнивается как строка после той же обработки ASCII whitespace, без замены алфавитов,
   смены регистра, пересчёта единиц и таблиц L=48. UNKNOWN в DTO уже null;
   значения «0» и «Без размера» автоматически в null не превращаются.
6. При известном размере вариант должен иметь ровно одно значение выбранной
   характеристики. Отсутствующая/повторяющаяся характеристика — ручной разбор.
   Простой товар без сравнимого размера при известном размере листинга также
   требует ручного разбора. При неизвестном размере правило B недоступно;
   правило A по собственному артикулу остаётся доступным.
7. Однозначность проверяется по объединению обоих правил. Один target,
   найденный двумя путями, считается один раз. Разные targets — конфликт,
   без приоритета одного правила над другим. Архивные совпадения не скрываются
   до проверки неоднозначности; единственная архивная цель недоступна.
8. Модификации с доказанно другим размером исключаются; варианты, для которых
   размер нельзя проверить, остаются неразрешённой неоднозначностью. Нельзя
   объявить цель единственной, просто отбросив неизвестные характеристики.
9. Родитель с модификациями никогда не конечная цель. Несколько цветов одного
   размера без отдельного точного ключа остаются неоднозначными.
10. Обрабатываются только активные листинги без единой ревизии связи.
    Существующие mapped/needs_review не заменяются; clear с revision>0
    автоматически не восстанавливается. Ручной экран по-прежнему доступен.
11. Несколько листингов могут указывать на одну цель; уникальность требуется
    у решения для конкретного листинга, не у использования цели.
12. Названия, цены, внутренний Catalog.product, Ozon SKU, WB nmId/chrtId и UUID
    МойСклад не используются как взаимозаменяемые идентификаторы.

## Применение и контроль

- Только выбранная компания, подключение и один marketplace за запрос.
- Preview/диагностика: 25 листингов текущей страницы; причины и счётчики
  относятся к этим 25 строкам, не ко всему каталогу. Покрытие реальных данных
  сейчас не измерено; проценты эффективности не обещаются.
- Apply: максимум 25 уникальных listingId из серверного preview, права WRITE
  и CSRF; состав/цели/артикулы/actor/company от клиента не принимаются.
- Preview живёт 15 минут в отдельном серверном Redis cache pool и привязан
  к сессии и actor/company/connection/marketplace. Максимум 3 на сессию;
  индекс хранится под общим mutex, каждый preview неизменяем. Результаты
  разных попыток разделены attemptId, максимум 3 результата на preview.
- Перед записью повторяются решение и проверки внутри транзакции. Импорт
  сериализуется существующим catalog lock, источник блокируется через Facade,
  ожидаемая revision=0, цель обязана совпасть с показанной пользователю.
- Одна транзакция на строку. Часть строк может сохраниться, часть получить
  конфликт. Необработанный остаток при технической ошибке показан явно.
- Повтор в пределах жизни preview использует прежний requestId каждой строки;
  принятый запрос не создаёт вторую ревизию и не восстанавливает последующий
  ручной clear. После истечения preview нужен новый; история записей остаётся.
- В snapshot ревизии сохраняются источник auto, версия правила, previewId,
  fingerprint источника и выбранная характеристика размера. Это время
  изменения связи в системе, а не дата продажи.

## Следующие версии — отдельные задачи

- Штрихкоды: импорт баркодов product/variant МойСклад, отдельный контракт
  единиц/упаковок и конфликтов нескольких кодов. Нельзя использовать текущий
  flattened barcode→listing Facade как доказательство отсутствия дублей.
- Синонимы размеров, дополнительные характеристики/цвет, сопоставление по
  code МС, поиск по названию, полный каталог одной фоновой операцией.
- Автозапуск после импорта, постоянные настройки и отдельный журнал batch.

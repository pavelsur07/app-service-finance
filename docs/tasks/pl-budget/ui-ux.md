# ТЗ на UI/UX модуля «Бюджет ОПиУ»

Модель, правила и этапы — `TASK.md`. Здесь только экраны: что на них есть, как
они себя ведут и что считать готовым. Визуал — дизайн-система «Ваш Финдир»
(`docs/design-system/sheets/`), правила реализации — `CLAUDE.frontend.md`.

## 0. Общие правила

**Интерфейс.** Легаси-слой (`_layout/legacy.html.twig`), как остальные
страницы финансов (отчёт ОПиУ, документы ОПиУ). Страницы — Twig. Сетка ввода
плана (экран 3) — React-остров: без него не сделать навигацию с клавиатуры,
вставку из Excel и автосохранение.

**Эталон визуала — DS раздела ОПиУ** (страницы «Документы ОПиУ»,
`templates/document/_list_layout.html.twig`, `docs/plan/ds-pnl-documents.md`):
шапка `vf-page-head` (крошки «Доходы и расходы / Бюджет ОПиУ», `h1`, пояснение
`vf-page-head__lead`, кнопки справа в `btn-list`); тело — `card vf-card` с
вкладками `partials/_tabs` (`card-header-tabs`) и полосой фильтров
`vf-card-bar` с сегментами `vf-seg` (год, позже разрез); таблицы `vf-table`;
бейджи статуса `vf-status`; подтверждения — `partials/_confirm_modal`.
Новых компонентов и цветов не вводится: всё, чего нет в DS ОПиУ, сначала
сверяется с листами `docs/design-system/sheets/`.

**Меню.** Группа «Доходы и расходы» → пункт «Бюджет ОПиУ» (список вариантов),
рядом с «Документы ОПиУ»; пункт активен на всех страницах `budget_*`.
«План–факт» открывается вкладкой внутри раздела (`_tabs`): «Варианты» /
«План–факт».

**Доступ** (модуль FINANCE):

| Роль | Видит | Правит черновик | Утверждает, возвращает утверждённый в черновик |
|---|---|---|---|
| Чтение | всё | нет | нет |
| Запись | всё | да | нет |
| Владелец компании | всё | да | да |

Недоступное действие не прячется, а показывается неактивным с подсказкой
причины («Утверждает только владелец компании»). Права пользователя ничего не
скрывают.

**Деньги.** По листу DS-Money: `vf_money` / `vf_amount` в Twig, тот же
формат в React (неразрывный пробел, запятая, минус U+2212, «₽» в заголовке
колонки, приглушённые копейки). Красный цвет для сумм не используется.
В сетке ввода копейки не показываются (`vf_amount` без копеек), в ячейке при
редактировании — как ввёл пользователь.

**Знак суммы.** Суммы показываются так же, как в отчёте ОПиУ: значение
статьи = доход − расход, расходные статьи — со знаком минус. Ввод: в статье
расхода (`flow = EXPENSE`) пользователь вводит положительное число, система
сохраняет его со знаком минус; в статье дохода — как есть; в статье без
направления (`NONE`) — со знаком, как ввёл. Решение Владельца 04.11 (`TASK.md`, п. 5).

**Подтверждения** — `_confirm_modal`, не `confirm()`. **Ошибки сервера** —
текстом на экране рядом с местом ошибки, не в тултипе (см. откат #2520).

**Состояния каждого экрана:** загрузка, пусто, ошибка, только чтение,
мобильная ширина (от 360 px).

## 1. Список вариантов

**Адрес:** `/budget` (по умолчанию текущий год), `/budget?year=2027`.

**Задача пользователя:** увидеть варианты бюджета на год, понять, какой
утверждён, открыть нужный или создать новый.

**Состав:**

- Шапка: заголовок «Бюджет ОПиУ», переключатель года — сегменты `vf-seg` в
  `vf-card-bar` (годы, где есть варианты, плюс текущий и следующий), кнопка «Новый
  вариант».
- Таблица вариантов за год:

| Колонка | Содержимое |
|---|---|
| Название | ссылка на экран бюджета; под ней — «копия „Базовый“», если создан копией |
| Статус | бейдж: «Утверждён» (акцент), «Черновик» (нейтральный), «Архив» (приглушённый) |
| Итог года | чистая прибыль варианта за год (строка-итог дерева ОПиУ с кодом чистой прибыли; если её нет — колонка не показывается) |
| Изменён | дата и время последнего изменения |
| Действия | меню «⋯»: Открыть, Копировать, Утвердить / Вернуть в черновик, В архив / Восстановить |

- Сначала утверждённый, затем черновики по дате изменения, архив — свёрнутым
  блоком «Архив (N)» внизу.

**Поведение:**

- «Утвердить» при уже утверждённом варианте года — отказ с текстом «На 2027
  год уже утверждён „Базовый“. Сначала верните его в черновик». Автоматически
  старый не снимается.
- «Утвердить» и «Вернуть в черновик» — через подтверждение с названием
  варианта.
- Пустой год: иллюстрация не нужна; текст «На 2027 год вариантов нет» и две
  кнопки — «Создать пустой» и «Заполнить из факта 2026» (второе — после
  этапа 3; до него только «Создать пустой»).

**Мобильная ширина:** таблица превращается в карточки (название, бейдж,
итог года, меню).

**Готово, когда:** видны все варианты года с верными статусами; утверждённый
вариант стоит первым; все действия меню работают с проверкой прав; пустой год,
ошибка и мобильная ширина проверены скриншотами.

## 2. Окно «Новый вариант» (модалка на экране 1)

**Поля:**

- Название — обязательно, до 120 символов, по умолчанию «Вариант N».
- Способ: «Пустой» / «Копия варианта» (радио).
- При «Копия» — выбор варианта этого года (по умолчанию утверждённый);
  год копии берётся из исходника и не редактируется.
- Год — при «Пустой», по умолчанию год со страницы.

**Поведение:**

- Скрытый UUID в форме: двойное нажатие «Создать» не создаёт двух вариантов.
- После создания — переход на экран бюджета нового варианта.
- Ошибки — под полями (`form-error`), окно не закрывается.

**Готово, когда:** пустой вариант и копия создаются, двойной клик даёт один
вариант, ошибки показываются у полей.

## 3. Экран бюджета (ввод плана)

**Адрес:** `/budget/{id}`, параметры пары: `?project=…&center=…`.

**Задача пользователя:** быстро заполнить план по статьям на 12 месяцев и
видеть итоги по дереву ОПиУ.

### 3.1 Шапка

- Хлебные крошки: Бюджет ОПиУ › 2027 › «Базовый».
- Название (правится по клику в черновике), бейдж статуса.
- Кнопки по статусу:
  - черновик: «Утвердить» (только владелец), «Помощники ▾» (этап 3), «⋯»
    (Копировать, В архив);
  - утверждён: «Вернуть в черновик» (только владелец), «⋯» (Копировать);
  - архив: «Восстановить», «⋯» (Копировать).
- Индикатор сохранения справа: «Сохранено» / «Сохраняю…» / «Не сохранено —
  повторить».

### 3.2 Баннеры

- Утверждён: «Вариант утверждён — изменения недоступны. Чтобы править,
  верните его в черновик» (для не-владельца: «…это может сделать владелец
  компании»).
- Архив: «Вариант в архиве. Восстановите, чтобы править».

### 3.3 Фильтр разреза

- Две пилюли: «Проект» и «ЦФО» (ядро `picker_core.js`); выбор ЦФО
  ограничивает список проектов допустимыми парами.
- Ввод возможен только при выбранной паре. Режим «Все проекты» — только
  просмотр суммы по всем парам, ячейки нередактируемые, с подсказкой «Выберите
  проект и ЦФО, чтобы вводить план».
- У компании с одной парой («Общий × Общий») фильтр не показывается вовсе.
- По умолчанию — пара «Общий × Общий».
- Выбор пары сохраняется в адресе (ссылку можно отправить коллеге).

### 3.4 Сетка

| | Янв | Фев | … | Дек | Итого |
|---|---|---|---|---|---|
| ▾ Выручка | Σ | Σ | | Σ | Σ |
| — Выручка WB | ввод | ввод | | ввод | Σ |

- Строки — дерево ОПиУ компании в порядке отчёта; уровни отступом, группы
  сворачиваются (▾/▸), состояние свёртки запоминается в браузере.
- Листовые статьи (`LEAF_INPUT`) — редактируемые ячейки. Итоговые
  (`SUBTOTAL`) — жирным, пересчитываются сразу при вводе с учётом веса в
  родителе. Показатели (`KPI`) — по формуле, курсивом, формат по статье
  (`%` и т. п.).
- Строки — те же, что в отчёте ОПиУ: флаг статьи «скрыта» (`isVisible = false`)
  отчёт не учитывает, бюджет тоже (шаблоны ставят его «Выручке» REV_TOTAL).
- Колонка «Итого» — сумма месяцев, не редактируется.
- Первая колонка и шапка закреплены при прокрутке.

### 3.5 Ввод

- Клик или Enter — редактирование; Enter / Tab — сохранить и перейти вниз /
  вправо; стрелки — перемещение; Esc — отмена; Delete — очистить (ноль).
- Принимаются «600000», «600 000», «600000,50»; что-то другое — ячейка
  подсвечивается ошибкой с текстом под сеткой, значение не сохраняется.
- **Вставка из Excel:** диапазон, скопированный из таблицы, вставляется
  начиная с текущей ячейки по строкам и месяцам; нередактируемые ячейки
  пропускаются, итог вставки — сообщение «Вставлено N ячеек, пропущено M».
- Автосохранение: изменённые ячейки отправляются пачкой через ~1 с после
  последней правки и при уходе со страницы; повтор пачки безопасен.
- Ошибка сохранения: ячейки остаются с пометкой «не сохранено», индикатор
  предлагает «Повторить»; при уходе со страницы — предупреждение браузера.
- Вариант утвердили в другой вкладке: следующее сохранение получает отказ —
  экран переключается в режим только чтения с баннером, несохранённые ячейки
  перечислены.

### 3.6 Комментарий к ячейке

- Пункт в контекстном меню ячейки или Shift+Enter → поповер с полем (до
  500 символов).
- Ячейка с комментарием — уголок-маркер; текст — по наведению и в поповере.
- Ноль без комментария = пустая ячейка; ноль с комментарием хранится.

### 3.7 Пустые и крайние состояния

- В дереве ОПиУ нет листовых статей — «Сначала настройте статьи ОПиУ» со
  ссылкой на справочник.
- Статья удалена после заполнения плана — её строки не показываются; итоги
  считаются без неё.

### 3.8 Мобильная ширина

Просмотр: сетка прокручивается внутри контейнера, закреплена колонка статей.
Ввод на телефоне работает, но не оптимизируется (MVP).

**Готово, когда:** план вводится с клавиатуры и вставкой из Excel, итоги
дерева совпадают с правилами отчёта ОПиУ, автосохранение переживает
повтор и ошибку, утверждённый вариант не редактируется, компания без
разрезов не видит фильтра, все состояния сняты скриншотами.

## 4. Помощники заполнения (этап 3, модалки на экране 3)

Меню «Помощники ▾», активно только в черновике и при выбранной паре.
Каждый помощник: выбор статей (по умолчанию — выделенные строки или все),
выбор месяцев, предпросмотр «будет изменено N ячеек», затем «Применить».
Если в затронутых ячейках есть суммы — подтверждение «Перезаписать N
заполненных ячеек?».

| Помощник | Поля | Что делает |
|---|---|---|
| Из факта прошлого года | статьи, месяцы | факт того же месяца прошлого года в той же паре |
| Среднее за N месяцев | N (3/6/12), статьи, месяцы | среднее факта за последние N закрытых месяцев |
| Распределить годовую сумму | сумма, статьи | поровну на 12 месяцев, остаток копеек — в декабрь |
| Копировать месяц вправо | исходный месяц, статьи | значение месяца — во все месяцы правее |
| X% от выручки | X, статья-база (по умолчанию «Выручка»), статьи | разово считает суммы от плана базы; дальше это обычные суммы |

После применения — сообщение «Заполнено N ячеек». Отмены нет (MVP):
предпросмотр и подтверждение заменяют её.

**Готово, когда:** каждый помощник показывает верный предпросмотр, меняет
только выбранные ячейки, не трогает строки с источником «план продаж».

## 5. План–факт

**Адрес:** `/budget/plan-fact?year=2027&version=…&project[]=…&center[]=…`.

**Задача пользователя:** понять, где факт разошёлся с планом и насколько.

**Фильтры:** год; вариант (по умолчанию утверждённый, если утверждённого
нет — подсказка «Утвердите вариант или выберите черновик»); проект
(множественный, с поддеревом); ЦФО (множественный); период — месяцы года /
кварталы.

**Таблица:**

- Строки — дерево ОПиУ, как на экране 3.
- Переключатель показателя для колонок месяцев: «План» / «Факт» /
  «Отклонение» / «%». Блок «Итого за период» справа показывает все четыре
  сразу.
- Отклонение = факт − план в знаке отчёта; % = факт / план × 100 (пусто, если
  план 0).
- Оценка отклонения — значком, не цветом суммы: ▲ «лучше плана» / ▼ «хуже
  плана»; для доходов лучше — больше, для расходов — меньше по модулю. Порог
  подсветки строки — |отклонение| > 10%.
- Будущие месяцы — факт пустой, отклонение не считается.
- Клик по сумме факта — переход в отчёт ОПиУ за этот месяц с теми же
  фильтрами.

**Мобильная ширина:** по умолчанию показатель «Отклонение» и только итог
периода; таблица прокручивается с закреплённой колонкой статей.

**Готово, когда:** факт совпадает с отчётом ОПиУ за тот же период и фильтры
(расхождение 0), «Не задано» ЦФО ведёт себя как в отчёте ОПиУ, переключатель
показателей и оценка отклонения работают, все состояния сняты скриншотами.

## 7. Решения Владельца (04.11.2026)

1. **Знак при вводе** — принято предложение: в статье расхода вводится
   положительное число, система показывает и хранит его со знаком минус.
2. **Порог подсветки отклонения** — 10%, настройка на компанию — после MVP.
3. **Итог года в списке вариантов** — нужен: строка-итог дерева с кодом чистой
   прибыли; если её нет — колонка не показывается.

# Stage 6: экспорт плана в Excel

**Risk:** LOW–MEDIUM (только чтение, новый эндпоинт)
**Stage base commit:** `591a1631e`

## 1. Какую задачу решаем

План бюджета нельзя унести в Excel: показать собственнику, обсудить,
поправить офлайн. Нужна выгрузка варианта в xlsx — по паре или по всей
компании, в формате, который этап 7 загрузит обратно.

## 2. Что будет результатом

| Часть | Что |
|---|---|
| API | `GET /finance/budget/versions/{id}/export?project=&center=` (`budget_version_export`, чтение `ROLE_USER`, компания из сессии) → `budget_<год>_<вариант>.xlsx` |
| Infrastructure | `Budget\Infrastructure\Export\BudgetPlanXlsxWriter` — лист «План»: шапка (вариант, год, статус, пара или «Вся компания», дата выгрузки), таблица «Код · Статья · Янв … Дек · Год · ID статьи»; суммы — числами, формат `#,##0.00`; KPI — в своём формате; расходы — в знаке ввода (положительные) |
| Данные | тот же `BudgetGridBuilder`, что сетка: суммы и итоги совпадают с экраном |
| UI | кнопка «Excel» в панели сетки (вкладка «План»), ссылка на текущую пару |

## 3. Что считаем выполненной работой

- TDD: functional — выгрузка пары (лист, шапка, лист расхода положительный,
  итог как в сетке, ID статьи), вся компания, чужой вариант 404, неактивная
  пара 422, гость → логин. Проверка xlsx — чтением OpenSpout и XML листа
  (название на «=» не становится формулой).
- PHPStan/CS по изменённым файлам; Budget-тесты; lint/tsc/vite build.
- `ARCHITECTURE.md` (Budget, Changelog), итог в этот файл.

## 4. Чек-лист приёмки

- [x] Файл открывается, суммы и итоги совпадают с сеткой той же пары.
- [x] Статьи расходов положительные, как при вводе; итоги и KPI — как на экране.
- [x] «Вся компания» выгружается (сумма всех пар), шапка это говорит.
- [x] Чужой вариант — 404, неактивная пара — 422.
- [x] Кнопка «Excel» есть на вкладке «План» и качает текущую пару.

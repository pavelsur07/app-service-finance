# Stage 13: DS-пакет — окно «Быстрое заполнение» (PR 4)

**Risk:** LOW–MEDIUM. Только фронт острова `budget-grid`: панель помощников над
сеткой заменяется модальным окном. Сервер, `POST …/fill` и его контракт не
меняются. План пакета — `docs/plan/ds-budget-ui.md` (пункты 16–19).

## 1. Какую задачу решаем

Помощник заполнения — панель над сеткой со списком из 50+ флажков подряд и
предпросмотром «первые 8 изменений строкой». По макету (BUDGET-SPEC §5, refs 13,
26) это окно в два шага: настройка с группами статей и чипами месяцев, затем
таблица «было → стало» по статьям и месяцам с предупреждением о перезаписи.
На длинном дереве статей текущая панель неудобна, а предпросмотр не даёт
увидеть, что именно перезапишется.

## 2. Что будет результатом

| Часть | Что |
|---|---|
| Окно | 960 px, `role=dialog`, `aria-modal`, заголовок «Быстрое заполнение», строка «Разрез: проект × ЦФО · вариант «…» · год», шаги «1 Настройка» · «2 Проверка», «×»; Esc и клик по фону закрывают, фокус-ловушка, фокус возвращается на «Помощники ▾»; прокрутка страницы под окном заблокирована |
| Шаг 1, слева | пять карточек-радио (`role=radiogroup`, стрелки ↑↓ переключают), активная подсвечена; открывается на помощнике из меню |
| Шаг 1, справа | описание; параметры помощника с ошибкой под полем (сумма, процент); «Статьи · Выбрано N из M», «все / ни одной» (на найденные), поиск, группы ОПиУ с трёхсостоянным флажком и «N из M», список со скроллом ≈210 px; статьи с правилом «% от строки» неактивны, подпись «правило», сноска; «Месяцы»: чипы «1–4 кв.», «Все», «Сбросить» и сетка 12 месяцев (6 в ряд); для «Распределить» и «Копировать вправо» — пояснение вместо выбора |
| Подвал шага 1 | «Будет затронуто N ячеек: A статей × B месяцев» (или «Выберите хотя бы одну статью и месяц»), «Отмена», «Показать изменения» — неактивна, пока нечего менять или параметр неверен |
| Шаг 2 | «Изменится N ячеек, из них перезапишет заполненные: K»; при K > 0 — жёлтое предупреждение «Перезаписать K заполненных ячеек? Отмены нет — …»; таблица: статьи с изменениями × затронутые месяцы + «Изменение» (сумма по статье со знаком); в ячейке новое значение, под ним зачёркнутое «было …», перезапись заполненного подсвечена, неизменённая ячейка — «без изменений»; таблица прокручивается внутри окна, колонка статей закреплена |
| Подвал шага 2 | «← Назад», «Отмена», «Применить (N)» (N = 0 → «Закрыть без изменений»); пока в сетке идёт сохранение — кнопка неактивна с подписью; ошибка сервера — в окне; итог — «Заполнено N ячеек» в строке сетки |
| ≤ 760 px | окно на всю ширину, карточки помощников — лентой с прокруткой вбок над параметрами, месяцы по 4 в ряд, без прокрутки страницы вбок |
| Чистая логика | `fill-logic.ts`: группы статей, поиск, состояние группы, выбор, кварталы, цели (статьи × месяцы по помощнику), проверка параметров, таблица предпросмотра; vitest |

Вне этапа: бейдж и блокировка «план продаж» — источника `sales_plan` в данных
сетки нет (как и в этапе 12; сервер такие ячейки и так пропускает и считает в
`skipped`, шаг 2 это показывает строкой). Загрузка из Excel и правило остаются
панелями (не в макете пакета).

  вбок. Скриншоты `screenshots/stage-13/`, сверка с refs 13 и 26.

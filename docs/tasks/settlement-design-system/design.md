## Архитектурное решение для предложенного плана

**Переиспользовать существующий слой ДДС.** `settlement/layout.html.twig` наследует
`base.html.twig`, как страницы ДДС. Это решение автора плана для точного совпадения
оболочки и готовых компонентов, а не требование владельца использовать определённую
технологию. В legacy-sidebar уже есть ссылка и active-state `settlement_*`.

Сохраняются Twig/Symfony Forms; используются существующие Tabler+DS styles и JS.
Общие `app` kit, React, picker core, API client и backend для этого не переделываются.
Небольшие особенности Settlement изолируются `.settlement-ui` в отдельном page CSS;
локальный JS нужен только для UI-поведения поповера периода/фокуса.

Альтернативы: адаптировать DDS-внешний вид внутри app shell — потребуется перенос
стилей и поведенческого слоя; отдельный React-picker ещё увеличивает объём.
Они не выбраны: уже работающие DDS-компоненты покрывают текущую задачу.

## Целевой вид

```text
Деньги / Взаиморасчёты
Взаиморасчёты                              [Новый документ]
Пояснение назначения раздела
┌ Сводка | Документы | Начало учёта ───────────────────────┐
│ Период [01.11 — 10.11]  Контрагент [поиск]  На странице  │
│ Применено: [Период ×] [Контрагент ×]   Сбросить фильтры  │
│ Контрагентов: N · Итоги по всей выборке                 │
│ Шесть отдельных остатков: долг/авансы/нераспределённые   │
│ Таблица в плотности и оформлении ДДС                    │
│ Показано с X по Y из N                      [1] [2] [→] │
└────────────────────────────────────────────────────────┘
```

На сводке сохраняются шесть отдельных показателей; на карточке — также начальные
остатки/увеличения/уменьшения/конец и движения. Список документов имеет свои колонки,
но оформление карточки, строк, статусов, действий и футера соответствует ДДС.
Формы имеют смысловые группы полей, карточку сведений и нижнюю панель действий
по образцу операции ДДС, с собственными подписями и прежними полями Settlement.

## Что значит «только UI»

Разрешённые product-файлы будущей реализации: Twig-шаблоны, scoped page CSS/JS,
подключение этих assets и одна обратносовместимая UI-опция общей темы контрагента.
PHP-файлы продукта, контроллеры, Form types, Actions, Query/Repository/Facade,
Money, БД, миграции, API, роли, UiModeResolver и cookies не меняются.
PHP-файлы допускаются только в тестах. Документация и тестовые fixtures — в scope.

Контракты:

- Сводка/карточка принимают `from`, `to`, `counterparty`, `limit`, `page` по текущим
  формам; на карточке контрагент фиксирован route-параметром `id`, поле counterparty
  в её filterForm удалено. В списке документов сохраняется существующий контекст,
  без новых фильтров, для которых контроллер не передаёт данных.
- `_period_presets` в link-mode жёстко пишет `dateFrom/dateTo`; не включать его
  напрямую с route Settlement. В этом UI-рефакторинге достаточно поповера периода
  с существующими `from/to`, без новых пресетов и автоматических изменений дат.
- Legacy `_pagination` сам не добавляет route-параметры: передавать
  `params = query|merge(route_params)`, чтобы `id` карточки не терялся и query не
  мог его заменить. При применении нового фильтра page сбрасывается.
- Контрагент — прежний `CounterpartyPickerType(browse=true)` и готовые legacy field/
  pill widgets. Для field допускается scoped Twig-переменная URL поиска с прежним
  значением по умолчанию у остальных потребителей. Серверный select/choices/keep_id
  остаются границей значения; свободный текст или чужой ID не становятся выбором.
- Все денежные вычисления остаются в существующем Money; UI выводит точные строки
  через `vf_money`/`vf_amount`. Полные суммы, две копейки, U+00A0, U+2212, ₽ в шапке
  RUB-колонки; красный для ошибок, не сумм. Положительный долг не окрашивать как
  денежный приход: знаки/смысл ДДС на шесть корзин не переносятся.
- Сохраняются CSRF/requestId/version, имена/ID полей, HTTP-коды/редиректы, права,
  повторы, preview≤50, пагинация и независимость ОПиУ/обязательства/ДДС.
- Из ДДС берётся внешний вид, а не новые функции: импорт, экспорт, поиск `q`,
  фильтр счёта/направления, массовое удаление не добавляются. Для проведённых
  документов остаётся датированная отмена с причиной, а не «Удалить».

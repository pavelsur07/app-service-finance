## Что уже есть и что расходится

| Участок | Проверенный факт | Решение |
|---|---|---|
| Основа | `_layout/app.html.twig` подключает Inter и CSS-кит; `t-table`, кнопки, вкладки, пагинация, денежные фильтры уже используются | Сохранить эту основу, менять компоновку и недостающие состояния |
| Панель фильтров | `_filter.html.twig` рендерит весь `form_widget(filterForm)` одним flex-ребёнком; кнопка — другой растягиваемый ребёнок | Вывести поля отдельно прямыми `.form-field` детьми `.wz-row.wz-filters`, кнопку поместить в `.wz-row-actions` |
| Шесть KPI | Один `.wz-row` с flex-basis 200px даёт на снимке раскладку 5+1 | Общая сетка кита `.kpi-grid`: 3/2/1 колонки, точные суммы, все шесть показателей отдельно |
| Действия | `.wz-row-actions` используется под `.wz-head`/`.card`, хотя CSS задаёт его поведение только для прямого ребёнка `.wz-row` | `.wz-head-actions` для шапки, `.wz-actions` для формы/карточки, `.wz-row-actions` только для фильтра |
| Формы | Общий `form_widget(form)` ставит дату/причину перед контрагентом; все поля растянуты, типы используют общий класс `input` | Явный порядок `form_row`, смысловые группы, `select`/`textarea`/checkbox по DS, скрытые поля сохранить через `form_rest` |
| Таблицы | Метки строк в `<th scope=row>`, но kit/table.css оформляет тело только через `tbody td` | Для обычных ячеек данных использовать канонические `td`; сохранить заголовки колонок и доступные подписи таблиц |
| Статусы и пустота | Статус — обычный текст; пустые строки без `t-empty`; просрочка и отсутствие срока слиты в абзац | Бейджи DS, `t-empty`, отдельные подписи/метаданные без выдуманных итогов и сроков |
| Flash | Все сообщения, кроме success, окрашиваются как warning | success/info/warning/danger сопоставить своим вариантам DS; ошибке `role=alert`, уведомлению `role=status` |
| Контрагент | `CounterpartyPickerType(browse=true)` есть, но локальная тема заменяет widget обычным select; app.js не подключает legacy picker | Отдельный app-адаптер на существующем ядре поиска/списка; серверный select и company scope сохраняются |
| Деньги | Money и `vf_money`/`vf_amount` уже применяются корректно | Сохранить вычисления; визуально сверить копейки, знак, цвет, валюту в заголовке |

## Подход

1. Только заменить классы — небольшой объём, но не исправляет структуру фильтра,
   порядок полей, сетку и поведение контрагента.
2. **Рекомендация: Twig + существующий app kit, небольшой React-остров только для
   выбора контрагента.** Серверные формы остаются основой; поиск/клавиатура
   переиспользуют существующее ядро, оформление — классы кита.
3. Переписать весь раздел на React — добавляет состояние и контракты для уже
   работающих серверных сценариев. Для данной цели избыточно.

Вариант 2 — решение автора плана, предлагаемое владельцу, не ранее полученное
одобрение. Общую палитру, app shell, шаблоны Баланса/ОПиУ и legacy-стили не менять.

## Целевая композиция

Сводка: заголовок и главное действие → вкладки → компактные фильтры → шесть KPI
→ просрочка/без срока → таблица → пагинация внутри общей карточки.

```text
Взаиморасчёты                              [Новый документ]
Сводка | Документы | Начало учёта
С [дата]  По [дата]  Контрагент [поиск]  На странице [50] [Показать]
[Нам должны]        [К оплате]        [Выданные авансы]
[Полученные авансы] [Нераспр. выплаты] [Нераспр. поступления]
Просрочено ... · Без срока ... · Итоги по всей выборке
Контрагенты и шесть отдельных остатков
Показано ...                                  [1] [2] [→]
```

При обычных значениях на1440/1280px —3колонки KPI, на768px —2, на390px —1. Для очень длинных сумм предусмотрены более широкие карточки (2/2/1/1): полная точность важнее плотности. Таблица прокручивается
внутри области; вся страница не имеет горизонтального скролла. Суммы не обрезать.

Новый документ: контрагент → вид/направление → сумма/дата изменения/срок оплаты
→ основание/причина → действия. На узком экране группы переходят в одну колонку.
Детали документа: номер/вид/статус, сумма и свободный остаток, реквизиты и источники,
связанные документы, движения, действия по текущим правам.

## Инварианты и границы

- Все 13 GET-экранов раздела входят в план, включая setup, два источника,
  распределение, корректировку, классификацию и две формы отмены.
- Денежные значения остаются Money/точными строками; в JS денег и арифметики нет.
  Для сверки сохраняются две копейки и полные суммы даже в KPI этого раздела.
  Отрицательные движения имеют U+2212, текущий явный плюс у движений сохраняется;
  это журнал изменений, не банковские приходы. Красный не используется для сумм.
- Шесть корзин, исторические даты/знаки/итоги, независимость ОПиУ и оснований,
  полный размер Cash, ручные распределения, правила отмен/закрытия не меняются.
- Сохраняются маршруты, имена полей, ID select, CSRF/requestId/version, HTTP-коды
  и редиректы, company scope, серверная проверка choices и защита от повторов.
- READ сохраняет фильтры и просмотр; write-кнопки не показываются, формы записи
  недоступны для ввода. POST по-прежнему защищён контроллером и Actions.
- Новых эндпоинтов, миграций, библиотек и глобального подключения Tabler нет.
  Поиск использует существующий GET `/api/counterparties/search?q=...`.
- Loading/no-results/error/retry относятся к поиску. Серверные страницы не получают
  фиктивных спиннеров. Планируются реальные empty/error/readonly состояния.

Исполнение — только после следующего поручения владельца. Текущая задача поставляет
этот дизайн и [план](plan.md), без изменений продукта или production.

# Marketplace Stage 0: предварительный roadmap

Этот roadmap **дополняет, не заменяет** `docs/financial-core/10-migration-roadmap.md`. Нумерация ниже — Marketplace Stage 1–8 (M1–M8); она не означает, что Financial Core Stage 1–10 завершены. Каждый M Stage — отдельный deploy с обратимым переключателем, обратной совместимостью схемы и сообщений; legacy остаётся источником финансовой записи, пока не завершены shadow-сверки. Никаких изменений по этому плану в рамках аудита не выполнено.

### Инварианты каждого Stage

1. Старая и новая версии контейнеров читают одинаковый versioned envelope, а старые FQCN Messenger Message остаются до опустошения очереди (`ARCHITECTURE.md:373-375`). Для изменения routing сначала разворачиваются consumers, затем producers, затем drain старого транспорта; `failure` и отложенные сообщения входят в drain. Разделение Ingestion требует **нового DSN/stream/group и собственного worker**, не просто другого имени transport (`site/config/packages/messenger.yaml:20-32`; `site/vendor/symfony/redis-messenger/Transport/Connection.php:33-46`).
2. Shadow путь **не** вызывает `ProcessMarketplaceRawDocumentAction`, `CloseMonthStageAction`, `FinanceFacade` или Financial Core producer. Только сравнивает counts/hash/точные суммы. Выбор единственного writer по `(company, provider, connection, resource, period)` атомарен и наблюдаем.
3. Коррекции Ozon/WB не превращаются в duplicate: source revision, natural key, unique inbox и processing state. Закрытый период и ручные исправления соблюдают ADR-007; никаких автоматических молчаливых изменений формул/категорий (`docs/financial-core/07-idempotency.md`, `docs/financial-core/adr/007-period-states.md`).
4. Новые таблицы/колонки вводятся расширением и используются только после применения миграции; удаление откладывается до M8. Перед каждым deploy проверяются старая и новая версии схемы/сообщений.
5. Production sanity после каждого Stage — read-only: worker/lag/failed, полнота raw, контрольные суммы и инварианты, сравнение с baseline. Ручные production команды, миграции и изменение workers/очередей требуют отдельных согласований по `AGENTS.md` §3.3 и `docs/workflow/release.md`; этот документ ничего не санкционирует.

**Ближайший Stage:** M1. Решение о Go/Python (загрузка, парсинг, source normalization — раздельно, [08](08-normalization-boundary.md)) откладывается до измерений M1/M2, а изменения Financial Core следуют его собственному roadmap.

DS-Decisions

Все решения дизайн-системы (действующие и архив) и changelog.

ДС «Ваш Финдир» v3.4 · 15.11.2026 · все листы: README

01 — Decisions

Решения по всем расхождениям из аудита. Каждое решение — одна строка с обоснованием. PROPOSED — требует подтверждения.

1
Card padding
16px 20px
Компромисс между плотными KPI и просторными drawer-секциями; не теряет содержимое мелких карточек и не выглядит «дёшево» в крупных.
2
KPI value size
22px (compact) · 28px (hero)
Две шкалы: 22 — для рядов виджетов, 28 — для одиночного hero-метрика (общий баланс, главный остаток). 26 удалён.
4
Drawer width
680px
Достаточно для двухколоночных форм (split-операции, parent + child fields); 640 ужимает.
5
Backdrop
opacity 0.45 · blur 6px
Среднее затемнение, мягкий blur — модалки читаемы, контекст за ними различим.
6
Avatar / initial sizes
sm 24 · md 32 · lg 40
Шаг кратный 8. Прежние 28/30/34 убраны — нет смысла, разница неразличима.
7
Direction indicator
colored dot + знак суммы
Минимум визуального шума, не конкурирует со status-пилюлями. Знак направления передаётся самой суммой (+/−).
8
Status
pill с точкой (везде)
Пилюля заметнее dot+text, лучше для accessibility (форма + цвет). Sync-статусы на счетах тоже теперь pill.
9
Money — знак минуса
U+2212 (−) · везде
Типографически правильный, ширина совпадает с +. Hyphen-minus запрещён в формате сумм.
10
Money — миллионы
М (короткая запись)
В таблицах и на осях графиков: компактнее «млн», вписывается в узкие колонки. В описаниях допустимо «млн ₽».
11
Money — цвет
цвет только для дельт
Балансы — всегда тёмные (нейтральные). Зелёный/красный — только для %-дельт, сумм поступлений/расходов и signed transactions. Остаток на конец периода — НЕ цветной.
12
Tint chip
именованные токены
Никакой математики с opacity — каждый тип чипа имеет свой набор переменных (--src-api-bg, --status-success-bg, …). Предсказуемо, не зависит от подложки.
13
Drawer padding
24px со всех сторон (--s-6) · footer 16px 24px
v3.1: 28px нет в шкале. 24px совпадает с модалкой, разница в 4px глазом не читается, а исключение пришлось бы помнить. Шапка и тело drawer — единый отступ.
14
Tabular numerals
для всех числовых контекстов · задано на контейнерах
v3.1: подтверждено. Правило висит на .t-table, .report, .coverage, .kpi, .acc-card, .money и наследуется — не нужно помнить о нём в каждом компоненте. Manrope содержит OpenType-фичу tnum (проверено по файлу шрифта), свойство реально работает.
15
Icon color rule
currentColor inheritance · semantic роль на пункте
Иконки внутри компонентов наследуют currentColor. Цветом окрашивается ВЕСЬ пункт по семантической роли (default · primary · danger), не иконка отдельно. Эмодзи-иконки запрещены.
16
Toast vs Alert
Toast — результат действия, auto-dismiss 4s · Alert — контекст, не исчезает сам
Toast подтверждает то, что только что сделал пользователь. Alert — статус системы или окружения, не привязан к моментному действию. Не путать роли — Alert не должен «всплывать», а Toast не должен жить на странице постоянно.
17
Confirmation Dialog
обязателен для destructive/irreversible действий
Удаление, архивирование, отмена операции, закрытие без сохранения — всегда через .mdl--compact + confirm-*. Primary-кнопка окрашивается по риску: danger-solid (удалить), warning-solid (отменить операцию), primary (закрыть без сохранения).
18
Feedback icon rule
SVG 16px · currentColor · нейтральные пиктограммы
Иконки в Toast, Alert, Confirmation — стандартные пиктограммы (info, warning, check, x). Цвет задаётся семантикой родительского компонента через currentColor. Никаких эмодзи и фирменных иллюстраций.
20
Запрет на семантическую контрабанду токенов
semantic токены — только по своей семантике
success / danger / warning принадлежат feedback-семантике: статус, направление денег, валидация. Аналитические классификаторы (ABC × ABC, скоринг, рейтинги) используют ОТДЕЛЬНЫЙ набор токенов (--abc-*, --score-* и т.д.), который под капотом может алиаситься на feedback, но компоненты об этом не знают. При ребрендинге классификатор и фидбек редактируются независимо.
21
Totals row обязателен для аналитических таблиц
.t-row--totals — последняя строка таблицы с числовыми колонками
Суммы, проценты-взвешенные (margin = profit/revenue, ROI = profit/costs), счётчик строк — обязательны. Без totals пользователь скроллит до конца и сам считает. Per-unit метрики («Себест. ед.», unit-цены) — прочерк, их складывать бессмысленно. Sticky-bottom — желателен, но не обязателен.
22
Именование новых компонентов — BEM
Новые компоненты: .component, .component--modifier, .component__element. Старые Tabler-style (.btn-primary, .kpi-label) — не переименовываем.
Файл содержит две конвенции: Tabler-style (до v1.5) и BEM (v1.5+). Переименование старого — breaking-change для legacy-шаблонов. Новые компоненты пишем в BEM для консистентности с v1.5+. Со временем legacy естественно уйдёт при миграции модулей.
23
INPUT-WRAP — базовый паттерн input с prefix/suffix
.input-wrap + .prefix / .suffix — канонический примитив для любых фиксированных префиксов/суффиксов (₽, %, .ru, ИНН). .password-field и .search-field — специализации того же паттерна с фиксированной иконкой вместо API prefix/suffix.
Фактически классы были в CSS с v1.x, но не были задокументированы: без demo, без nav-ссылки — формально «не в UI Kit». Команда переизобретала то же самое локально. v2.3 выводит примитив в публичный канон. v3.4: поиск и пароль — тот же .input-wrap с .input-icon / .input-action; .search-field и .password-field удалены.
25
CARD-HEAD — заголовок секции в карточке
.card-head — 11px uppercase 700, tracking 0.05em, --text-tertiary, отбивка --s-3. Вариант B — .card--flush для таблиц edge-to-edge (шапка получает --card-padding + разделитель 1px).
Заголовки секций внутри карточек были инлайн-стилями в демо. Вынесены в компонент — единый вид и один способ верстки.
26
PAGE SCAFFOLD — ритм контента workzone (.wz-*)
Семейство .wz-head / .wz-title / .wz-row — вертикальный ритм в .app-workzone. Заголовок 28px/700, отбивка --s-5; gap в ряду --s-4, между рядами --s-5; перенос ряда при <200px на карточку.
Ритм страницы верстался инлайн-отступами вразнобой. Канонизирован из admin-shell.css (миграция /admin/*).
27
Modal vs drawer для форм — потолок 520 / drawer 680
Форма — в модалке до 8 полей (S 440 / M 520). Шире формы или > 8 полей — drawer 680, не широкая модалка. L/XL модалки — только для контента (таблица, визард, сравнение).
Широкая модалка под длинную форму рвёт зрительный поток и хуже читается, чем полноразмерный drawer. Границу зафиксировали, чтобы не плодить 640-модалки под формы.
28
MODAL SIZES — шкала S/M/L/XL
S 440 · M 520 · L 640 (v3.4: XL и side-модалка удалены — широкий и длинный контент уходит в drawer 680)
Размеры модалок были разовыми инлайн-max-width. Свёрнуты в четыре именованных ступени — предсказуемый выбор под сценарий.
31
Трёхслойная система токенов
primitives → semantic → component
Развитие Decision 19. Палитра вынесена в примитивы (--gray-*, --blue-*…), прежние имена стали semantic-слоем и ссылаются на примитивы. Компоненты не используют примитивы и hex. Тема меняет только semantic.
32
Контраст вторичного текста — WCAG AA
--text-tertiary #5E6E84 · --text-muted = tertiary
v2.6: muted #8B95A7 давал 2.8:1 на фоне страницы, tertiary — 4.4:1; оба ниже 4.5:1. Muted использовался для helper-текста и плейсхолдеров — читаемость критична. Два уровня вторичного текста сведены в один; иерархию дают размер и вес.
33
Граница полей ввода ≥ 3:1
input · select · textarea · toggle off → --border-strong · hover --text-tertiary · disabled --border + --bg-subtle
WCAG 1.4.11: граница интерактивного элемента — минимум 3:1. В v2.6 поле было 1.18:1 и на белом почти не читалось. Карточки и разделители остаются мягкими (#E8ECF3) — они декоративны. v3.1: подтверждено; в v3.0 select и textarea по ошибке остались на мягкой границе — выровнены. Disabled освобождён от требования и уходит в мягкую границу, чтобы отличаться от активного поля.
34
Шкала шрифтов — 9 целых ступеней
11 · 12 · 13 · 14 · 16 · 18 · 22 · 28 (+10 для инициалов)
v2.6: 25 разных font-size, из них 6 дробных (9.5, 10.5, 11.5, 12.5, 13.5). Дробные пиксели рендерятся по-разному в браузерах и неразличимы глазом. Плюс ролевые шорткаты --type-*.
35
Spacing и radius — только токены
полушаги --s-0_5 … --s-3_5 · --r-xs … --r-xl
В v2.6 252 из 341 отступа были сырыми px. Полушаги 2/6/10/14 добавлены как токены (реально используются). 3/5/7/9px сведены к шагу. Radius 5px убран.
36
Focus-visible для всех интерактивных элементов
outline 2px --focus-ring-color · offset 2px
В v2.6 кольцо фокуса было только у полей. Кнопки, табы, chip, ссылки — без индикации при работе с клавиатуры (WCAG 2.4.7).
37
Motion и z-index — именованные токены
--dur-fast/base/slow · --z-raised … --z-toast
Убирает магические числа и даёт единое управление анимацией и слоями.
38
Тёмная тема — beta, только в ките BETA
Системная / Светлая / Тёмная · по умолчанию prefers-color-scheme · явный выбор важнее
В продукт — только когда в его CSS не останется hex (иначе тема будет «рваной»). Правила: уровень поверхности передаётся светлотой фона, а не тенью; палитра графиков — отдельный набор под тёмный фон; фирменные цвета банков и маркетплейсов — константы. Перед релизом — визуальный аудит экранов продукта.
39
Компоненты сгруппированы по назначению
Действия · Поля · Выбор · Данные · Таблицы · Навигация · Оверлеи · Обратная связь · Каркас
В v2.6 порядок был хронологическим (блок «v1.5 — Global chrome» внутри Components, App Shell числился в Patterns, но лежал в Components).
41
Геометрия компонентов — именованные токены
--control-h 38 · --input-icon-slot 36 · --sb-indent 28 · --app-header-gutter 28
Размеры, завязанные на иконки и контролы, не обязаны попадать в шкалу отступов, но должны иметь имя: видно, откуда число и что изменится. Слоты под иконку в поиске, суффиксе, пароле, select и пикере сведены к одному значению (было 34 / 36 / 38).
42
Подсветка совпадений в поиске
<mark> / .hl · --highlight-bg · --highlight-text
Браузерный жёлтый не тематизируется и в тёмной теме даёт кричащее пятно. Токен — amber-200 в светлой, полупрозрачный amber в тёмной.
43
Цветовая схема «Фирменный красный» (вариант A)
текст и интерактив — navy #0B1020 / #1E2A44 · кнопки — navy #1E2A44 · crimson #B00020 — только бренд · рост #0E7A4F · снижение и ошибки #C2410C · нейтрали #F5F5F7 / #E3E4E8
Цвета логотипа становятся цветами продукта. Красный в рабочем интерфейсе не используется (см. Decision 44): в финансовом продукте он читается как «минус» и «опасность». Поэтому снижение, ошибки и деструктивные действия — оранжевые, предупреждения — жёлтые, info — отдельная синяя роль. Фокус — navy, чтобы не путаться с ошибкой. Фон страницы #F5F5F7, карточки белые: в приложении поверхность и фон меняются местами относительно сайта, иначе карточки на белом фоне не читаются.
44
Primary-кнопка — navy, красный — только бренд
.btn-primary #1E2A44 → hover #141B2E → active #0B1020 · тёмная тема: светлая кнопка #DDE3F0 с тёмным текстом
v3.2 сделал все главные кнопки красными, и интерфейс стал выглядеть тревожно: красный — общепринятый сигнал ошибки и опасного действия, а в финансах ещё и «минуса». Практика продуктовых систем (Stripe, Linear, Carbon, Atlassian): яркий бренд-цвет в рабочем UI дозируется, главное действие — спокойный тёмный или фирменный нейтральный цвет. Красный остаётся токеном --color-accent для логотипа, промо и лендинга. На сайте маркетинговая CTA может быть красной — там одна кнопка на экран, а не десятки.
45
Ревизия кита: только то, что нужно продукту
удалены 10 элементов · 6 объединены · документация сокращена
Кит сверен с экранами продукта (app-service-finance). Удалены дубли (интерактивные модалки, паттерны Row dropdown и .field), вторая правая панель (side modal), Modal XL без сценария, внутренний админ-компонент Coverage matrix, лишние варианты KPI, Marketplace badge и Heavy table. Объединены: поиск и пароль → «Поле с дополнением», Header button → Button (.btn-icon), Breadcrumbs → AppHeader, Direction → Money, табы пикеров → Tabs. Правило: новый компонент попадает в кит, только если у него есть экран в продукте и он не собирается из существующих.
46
Пагинация — компонент кита
.t-pagination (вместо стандартной пагинации Tabler)
Разработка ведётся на Tailwind, Tabler-пагинация теряет смысл. Компонент кита уже построен на токенах и поддерживает тёмную тему.
Архив решений — исполнены или заменены · 6
3
Border color
#E8ECF3
Используется чаще, мягче по тону; #E2E8F0 удалён. Inputs и cards теперь единая линия.
19
Двухуровневая система токенов
raw tokens + semantic tokens
Raw (--color-primary, --bg-card) — палитра. Semantic (--button-primary-bg, --card-bg) — связь с компонентом. Тёмная тема и ребрендинг затрагивают только raw, semantic остаются неизменными. Сейчас компоненты используют raw напрямую — миграция на semantic поэтапная.
24
DEPRECATION: .field / .field-label → .form-field / .form-label
.field и .field-label помечены @deprecated в v2.3 и будут удалены в v3.0. Новые компоненты используют .form-field / .form-label.
Два одинаковых по назначению layout-примитива (v1.x .field и v2.2 .form-field) — путаница «что выбрать». Оставляем старые рабочими, чтобы legacy-шаблоны не сломались — но все demo переведены на новый примитив как единственный образец.
29
SIDE MODAL — full-height сайд-шит (.mdl--side)
.mdl--side — модалка, док справа во всю высоту: position:fixed, height:100vh, .mdl-body — единственная скролл-зона (flex:1), head/foot sticky, slide-in mdl-slide-in, тень --shadow-drawer.
Для длинных форм и мастеров в именно модальном (blocking) сценарии, когда M/L тесны. Пересекается с drawer 680 — не плодить оба на одном экране.
30
Form-field интервал — только в блочном потоке (bugfix)
Правило .form-field + .form-field { margin-top: --s-3 } сброшено в gap-контейнерах: .row-2col / .row-3col / .form-grid / .demo. Там интервал даёт gap.
Стек-хелпер протекал в grid-строки: первый элемент без margin, второй — с margin 12px → правая колонка съезжала вниз. Интервал в grid обеспечивает только gap.
40
Decision 24 исполнен: .field / .field-label удалены
.form-field / .form-label
Классы не использовались в разметке кита. .field-helper остаётся.

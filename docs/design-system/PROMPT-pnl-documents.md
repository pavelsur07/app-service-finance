Работай по `AGENTS.md`, `CLAUDE.md`, `CLAUDE.frontend.md`. Начни со Stage 0 (аудит) и отчёта; код — после. Правила DS: `docs/design-system/sheets/` (Tokens, Table, Tabs, Controls, Money, Feedback), планы `docs/plan/ds-legacy-tabler-audit.md`, `docs/plan/ds-operations-dds.md` (как делали «Операции ДДС» — тот же подход, тот же паттерн фильтров).
Эталон — макеты и скриншоты из пакета: `docs/design-system/screens/OperationsPnl.dc.html`, `PnlDocument.dc.html`, `docs/design-system/screens/pnl-refs/*.png`. Спецификация и разрыв с моделью — `docs/design-system/PNL-DOCUMENTS-SPEC.md` (прочитай целиком, особенно таблицу §3).

## Цель
Страница, которая сейчас называется «Операции ОПиУ» (`/documents/`, роут `document_index`), становится «Документы ОПиУ» в новом дизайне. Одноимённая страница редактирования (`document_edit`, `document_new`) оформляется по макету. Один документ содержит несколько операций, и доходных и расходных одновременно.

## Рамки
- Только legacy-слой: `templates/_layout/legacy.html.twig`, Tabler, токены `--vf-*`, `legacy-app.css/js`. Не трогать `_layout/app.html.twig`, `assets/react/**`, `site/ui-kit/`, и не брать их за образец.
- Роуты, имена роутов, имена полей формы, CSRF, `data-*`-хуки (`data-collection-holder`, `add_item_link`, `remove-item`, `data-document-*`, `data-operation-*`) не менять — на них завязаны JS и тесты.
- Не вводить значения в `DocumentType`/`DocumentStatus`/`PLDocumentSource`, не менять схему БД и миграции без необходимости. Если макет требует то, чего нет в модели — не изобретай: выбери решение из SPEC §3 или вынеси вопрос в отчёт.
- Название «Документы ОПиУ» — в заголовке, breadcrumbs, пункте меню, `title`, `_tabs`; «Удалённые» остаются. Адреса не менять.

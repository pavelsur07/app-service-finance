## 2. Страница «Редактирование операции ДДС»
Сейчас: «Редактирование транзакции» (Tabler, сетка 3/2/2, нативные select, Проект/Контрагент — picker с кнопками папка/галочка/крестик, внизу карточка «Документы ОПиУ на основании транзакции»). Название в интерфейсе — **«Операция ДДС»** (заголовок «Операция ДДС от ДД.ММ.ГГГГ»; breadcrumbs «Деньги / Операции ДДС / Редактирование»). Адреса и имена роутов не менять.

### 2.1 Раскладка (1440)
- Контент: 2 колонки `minmax(0,1fr) 320px`, gap 24. Левая — три карточки (Операция, Аналитика, Документы ОПиУ), правая — «Сведения» (sticky, top 16).
- Карточка: белая, border 1px `#dde1ec`, radius 4, тень `0 1px 2px rgba(11,16,32,.04)`; заголовок секции 16/600, padding 16×20, нижняя граница.
- Поля внутри карточки: сетка 2 колонки, gap 16×20, padding 20. Статья ДДС, Контрагент, Описание — на всю ширину.
- Sticky-панель действий снизу: «Все изменения сохранены / Есть несохранённые изменения» слева; справа «Отмена» и **«Сохранить»** (primary; неактивна, пока нет изменений).
- ≤1340 px: правая колонка уходит под основную (одна колонка). ≤760 px: поля в одну колонку, в таблице документов скрывается столбец «Описание».

### 2.2 Поля
| Поле | Контрол | Обяз. | Правила |
|---|---|---|---|
| Дата | `input[type=date]` | да | пусто → «Укажите дату операции» |
| Счёт | select | да | «Выберите счёт»; определяет валюту |
| Направление | segmented radio **Приток / Отток** (иконки ↓ ↑, зелёный/синий акцент выбранного) | да | `role=radiogroup`; меняет фильтр статей |
| Сумма | текстовое, `inputmode=decimal`, выравнивание вправо, справа знак валюты в «кармашке» | да | > 0; запятая или точка; на blur форматируется `5300,00`; ошибки: «Укажите сумму», «Введите число, например 1 250,00», «Сумма должна быть больше нуля» |
| Валюта | **отдельного поля нет** — берётся из счёта, подпись «Валюта берётся из счёта: …» | — | см. вопрос §7.1 |

| ЦФО | поле-выбор с поиском и очисткой | нет | подсказка при пустом: «Без ЦФО операция не попадёт в разрез по ЦФО» |
| Контрагент | поле-выбор (название/ИНН) с очисткой | нет | — |
| Описание | textarea, 3 строки | нет | maxlength 500, счётчик «N из 500» справа |

Проект/ЦФО/Контрагент — один вид с виджетом статьи (`.dds-field`): поле-кнопка 36px, шеврон, кнопка «×» только когда значение выбрано, popover с поиском. **Существующую логику их поиска/сохранения сохранить** (`docs/plan/entity-picker.md`, `docs/plan/ds-counterparties.md`), менять только вид.

### 2.3 Поведение
1. **Смена направления.** Если выбранная статья не подходит новому направлению — она сбрасывается, под полем жёлто-коричневая заметка: «Статья «…» не подходит для притока/оттока и сброшена. Выберите другую.» (скрин 09). Статьи с `flow=both` подходят всегда.
2. **Валидация.** По кнопке «Сохранить»: красная рамка у невалидных полей, сообщение под полем, плюс сводка вверху «Не удалось сохранить: N. Исправьте отмеченные поля.» со списком; фокус — на первое невалидное. Ошибки сервера выводить тем же способом (скрин 04).
3. **Несохранённые правки.** Бейдж в заголовке «Есть несохранённые изменения»; «Отмена» при изменениях открывает модалку «Выйти без сохранения?» (кнопки «Выйти без сохранения» / «Остаться», скрин 06). Дополнительно — `beforeunload` при уходе по ссылке.
4. **Удаление.** «Ещё → Удалить операцию» → модалка «Удалить операцию?» (скрин 07): текст сообщает, что документы ОПиУ остаются, но связь снимается; операцию можно восстановить. После удаления — жёлтый баннер «Операция удалена…» + «Восстановить»; поля read-only. Реализовывать **только то, что есть в бэкенде** (soft-delete/restore); если восстановления нет — спросить владельца, не придумывать.
5. **Операция из банковской выписки** (`OperationDdsBank`, скрин 05): серая плашка «Операция загружена из банковской выписки…», поля Дата/Счёт/Направление/Сумма — `disabled` (серый фон `#f4f6fb`, текст `#525b78`), остальное редактируется. Бейдж «Из выписки». Точный список блокируемых полей — по модели (см. §7.2).
6. **Блок «Документы ОПиУ на основании операции».** Таблица: Документ (номер + дата), Описание, Сумма в валюте операции со знаком («−» у оттока, «+» у притока), «Открыть» → страница документа ОПиУ. Внизу «Разнесено в ОПиУ: X ₽» и бейдж: «Разнесено полностью» (зелёный) / «Не разнесено X ₽» (жёлтый) / «Превышение на X ₽» (красный) / «Не разнесено в ОПиУ» (серый, если документов нет). Кнопка «Создать документ ОПиУ» ведёт на создание документа с предзаполнением (если такой роут есть).
7. **Меню «Ещё»**: в прототипе — «Дублировать», «История изменений», «Удалить». Переносить только пункты, для которых есть бэкенд; остальные не показывать (не оставлять нерабочих элементов).
8. **Сведения (правая колонка)**: источник (Вручную / Банковская выписка), создана, изменена, автор + пояснение про «Не распределено». Данные брать из сущности; если поля нет — строку не показывать.

## 3. Виджет «Статья ДДС» (переиспользуемый)
Контракт — в шапке `dds-tree-picker.js` и в `.html.twig`. Коротко:
- **Выбрать можно только лист.** Группа (узел с детьми) лишь раскрывается/сворачивается; при клике по ней значение не меняется.
- Вложенность **до 4 групп + лист**; шаг 22 px; слева направляющие линии (по одной на уровень); группа: жирный на 1-м уровне, 600 на вложенных; справа в «таблетке» число листьев внутри (включая вложенные).
- **Поле:** название выбранной статьи (500) + путь серым («Выбытие › Заработная плата › Директор»); шеврон; «×» для очистки (только если в select есть пустая option); пустое — «Не распределено».
- **Popover:** поиск «Найти статью»; строка «Статьи для оттока. Показать все» (только если известно направление); «Развернуть всё · Свернуть всё»; дерево (max-height 340 в форме); подвал-подсказка «↑ ↓ — выбрать · Enter — подтвердить / Esc — закрыть».
- **Поиск:** по подстроке названия листа без учёта регистра; при поиске все группы раскрыты, пустые группы скрыты; совпадение подсвечено (`#fff1b8`, жирный); если совпала сама группа — показываются все её подходящие листья; первый результат активен автоматически; пустой результат: «Статья не найдена. Проверьте название[ или покажите все статьи].»
- **Клавиатура:** фокус остаётся в поле поиска, ↑/↓ двигают активную строку (`aria-activedescendant`), Enter выбирает, Esc закрывает и возвращает фокус на кнопку; клик вне закрывает.
- **A11y:** кнопка `aria-haspopup=dialog aria-expanded`, popover `role=dialog`, дерево `role=tree`, строки `role=treeitem`, группы `aria-expanded`, листья `aria-selected`; контраст текста ≥ 4.5:1; фокус виден (2px primary).
- **Данные:** дерево отдаёт сервер (JSON в `data-tree`), id листа == value `<option>`; тексты вставлять как текст (не HTML). Для больших деревьев (>500 листьев) — согласовать виртуализацию отдельно.
- Не ломать форму: исходный `<select>` остаётся в DOM (визуально скрыт), его `change` срабатывает при выборе.

## 7. Разрыв с моделью / открытые вопросы (вынести в отчёт, не изобретать)
1. **Валюта.** В текущей форме отдельное поле «Валюта» (серое). В макете оно убрано — валюта счёта показана подписью. На референсе встречается расхождение (₽ в операции, $ в документах ОПиУ) — подтвердить, в какой валюте считать «Разнесено».
2. **Выписочная операция.** Какие поля блокировать (макет: дата, счёт, направление, сумма) и можно ли удалять такую операцию.
3. **ЦФО** — общий справочник компании или зависит от проекта.
4. **Дерево статей**: откуда берётся иерархия (parent_id / materialized path), максимальная глубина, как определяется `flow` листа и что такое «Технические операции».
5. Нужно ли «Дублировать» и «История изменений».

## 8. Реализация виджета в проекте (рекомендация)
CSS — в legacy-слой рядом с остальными стилями DS (перенеси `dds-pickers.css`, сопоставь алиасы с `--vf-*`); JS — модуль в `legacy-app.js`-цепочке (подключить `initDdsTreePickers()` на странице и после динамической вставки форм); Twig-обёртку положить в `templates/partials/`. Дерево строит Facade/сервис модуля справочников (без запросов в Twig-цикле), в шаблон передаётся массивом.

## 9. Особенности прототипа
В прототипе поля связаны (направление ↔ статья, сумма ↔ «Разнесено в ОПиУ», dirty-состояние) — это поведение нужно воспроизвести. Все тексты на макетах — эталонные русские формулировки.

# SPEC — страницы «Вход» и «Регистрация» + логотип + юридический блок

Эталон — макеты и скриншоты из пакета (`screens/Login.dc.html`, `Register.dc.html` рендерятся только в среде дизайна; в репозитории сверяйся с PNG из `screens/auth-refs/`). Макеты — **прототипы**: берёшь размеры, тексты, состояния, поведение; не копируешь разметку. Демо-логика прототипа (пароль `wrong`, email `busy@company.ru`, таймеры 800/900 мс, «Вы вошли», «Проверьте почту» без реальной отправки) — только для показа.
Область: **legacy-слой** (Tabler, токены `--vf-*`). Не трогать `_layout/app.html.twig`, `assets/react/**`, `site/ui-kit/`.
Логика аутентификации и регистрации (Security, FormType, роуты, CSRF, подтверждение email, сброс пароля) **не меняется**: меняется только вид, тексты, юридический блок и логотип.

## 6. Юридический блок (подвал обеих страниц)
1. **Документы** (13/400, `#525b78`, по центру, перенос): Публичная оферта · Пользовательское соглашение · Политика конфиденциальности · Обработка персональных данных · Политика cookie. Открываются в новой вкладке (`rel=noopener`). Страницы документов должны существовать по адресам `/legal/offer|terms|privacy|personal-data|cookies` (если нет — вынести вопрос; не оставлять мёртвых ссылок).
2. **«Сведения о компании»** (заголовок 11/700 капсом): правообладатель и оператор, ИНН/КПП, ОГРН, юридический адрес, поддержка (email, телефон), контакт по ПДн, запись в реестре российского ПО, рег. номер в реестре операторов ПДн Роскомнадзора. Сетка 2 колонки (gap 8×32), ≤560 — 1 колонка; подпись 11/600 капсом `#525b78`, значение 13/400.
3. Оговорка: ПДн граждан РФ обрабатываются и хранятся на серверах на территории РФ; сервис не является консультацией.
4. Копирайт: «© {год} {организация}. Все права защищены.»
**В макете реквизиты — демо.** В коде они берутся из конфигурации (`legal.example.yaml`), не из шаблонов. Строки реестров скрываются, если значение пустое. Юрист проверяет тексты и состав блока до запуска.

## 7. Баннер cookie
- Закреплён снизу (`position:sticky; bottom:0`), белый, граница сверху, тень вверх; текст 13/20 + ссылка на Политику cookie; кнопки «Только необходимые» (вторая) и «Принять все» (primary), высота 32. ≤560 px — кнопки на всю ширину.
- Выбор сохраняется в cookie `vf_cookie_consent` (`all|necessary`, 180 дней). Пока не выбрано — баннер виден на обеих страницах.
- **Аналитика и маркетинговые скрипты не загружаются до «Принять все»** (событие `vf:cookie-consent`, `detail.level`). Необходимые cookie (сессия, CSRF) работают всегда.
- Баннер не блокирует форму; доступен с клавиатуры; `role=region`, `aria-label="Файлы cookie"`.

## 8. Токены и состояния
- Цвета: navy `#0b1020`, muted `#525b78`, border `#dde1ec`, border поля `#c3c8d6`, фон `#f7f8fc`, primary `#1d4ed8` (hover `#1a40b0`), danger `#9a001b` на `#fdecee`, рамка ошибки `#efb6bd`, ok `#1d7a30`/`#e4f5e7`. Бренд-красный `#b00020` — **только логотип** и слабый индикатор пароля.
- Поле: высота 40, 15/20, radius 4, border `#c3c8d6`; ошибка — красная рамка + `inset 0 0 0 1px`; фокус — `outline:2px solid #1d4ed8; offset 2px`; placeholder `#8a92ab` (декоративный: подпись всегда в `<label>`).
- Ссылки: `#1d4ed8`, подчёркнуты (offset 2px); в подвале и юр. строках — серые, подчёркиваются при наведении/в тексте.
- Движение: спиннер 0,8 с; при `prefers-reduced-motion` анимация отключается.
- Доступность: у каждого поля `<label for>`; ошибки `role=alert` + `aria-describedby`; радио-группа в `<fieldset><legend>`; контраст текста ≥ 4.5:1; все действия с клавиатуры.

## 10. Открытые решения (не изобретать — отчёт + вопрос владельцу)
1. Реальные реквизиты и номера реестров; обязательность записи в реестре российского ПО.
2. Тексты документов `/legal/*` и существующие URL; нужна ли отдельная «Политика cookie».
3. Где хранить отдельное согласие на рассылку (поле, дата, источник) и как оно связано с почтовым сервисом.
4. Текущий поток подтверждения email и экран «Проверьте почту»; есть ли «Отправить ещё раз».
5. Нужна ли в баннере cookie настройка по категориям (сейчас две кнопки).
6. Возрастное ограничение/тип клиента (юрлицо, ИП, самозанятый) — менять ли формулировку подтверждения 18+.

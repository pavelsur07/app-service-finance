# Промпт приёмки: страницы «Вход» и «Регистрация», логотип, юридический блок

Ты — независимый ревьюер. Ничего не чини, пока не закончишь проверку: сначала отчёт, правки — отдельным шагом по запросу.
Прочитай `docs/design-system/AUTH-SPEC.md`, `CHECKLIST-auth-pages.md`, `brand/README-logo.md`, `screens/auth-refs/*.png`. Сверяй реализацию **с эталонными скриншотами и SPEC**, а не с прототипами `*.dc.html`.

## Что сделать
1. Подними приложение. Сними скриншоты 1440 и 390 для состояний 01–13 (вход: пусто, ошибки полей, неверный пароль, баннер; регистрация: пусто, ошибки, email занят, надёжный пароль, экран подтверждения, баннер) и положи рядом с эталонами.
2. Пройди чек-лист пункт за пунктом: «выполнено / частично / нет» + доказательство (скриншот, селектор, строка кода, вывод теста). Без доказательства — «нет».
3. Сценарии вручную:
   - **Логотип:** файл SVG (не текст в div) в шапках обеих страниц, в меню приложения, favicon во вкладке, письмо; размеры и охранное поле по README; `alt`/`aria-label` без дублирования.
   - **Вход:** пустая отправка → ошибки и фокус; неверный пароль → плашка без уточнений; «глаз» работает с клавиатуры; «запомнить меня» и CSRF как раньше; кнопка блокируется при отправке; успешный вход ведёт туда же, куда раньше.
   - **Регистрация:** индикатор и правила пароля совпадают с серверной валидацией; два обязательных согласия — раздельные, ошибки у каждого; рассылка выключена по умолчанию и не блокирует регистрацию; email занят → плашка; данные согласий сохраняются как раньше.
   - **Юридический блок:** 5 ссылок открываются в новой вкладке и не ведут на 404; реквизиты берутся из конфигурации; пустая строка реестра скрывается; ссылки `mailto:`/`tel:` рабочие.
   - **Cookie:** при первом заходе баннер виден; «Только необходимые» — аналитика не грузится (проверь Network); «Принять все» — грузится после выбора; выбор сохраняется на 180 дней; повторный заход — баннера нет; баннер не перекрывает кнопку формы на 390.
4. Регресс: вход/выход, сброс пароля, подтверждение email, rate limit входа, существующие тесты; нет утечки данных в логах и URL; формы работают без JS.
5. Гейты: `make site-stan`, `make site-cs-check`, `make site-cs-strict-types`, `make site-test`, `npm run lint`, `npm run build`, `npm run check:ui-kit`. Не прогнан — так и пиши.
6. Границы: не изменены `_layout/app.html.twig`, `assets/react/**`, `site/ui-kit/`, имена роутов и полей, нет миграций без согласования. Реквизиты не захардкожены в шаблонах; демо-значения помечены в отчёте.

## Формат отчёта
Таблица «пункт чек-листа → статус → доказательство», затем список расхождений с эталоном (с номером скриншота), затем риски и открытые решения SPEC §10. Итог одной строкой: «готово к merge» / «нужны правки: N».

Эталон — макеты и скриншоты из этого пакета. Файлы `*.dc.html` — **прототипы** (рендерятся только в среде дизайна; для сверки в репозитории опирайся на PNG из `screens/pnl-refs/`). Не копируй их разметку: бери размеры, тексты, состояния, поведение. Демо-данные в прототипе (список статей, проекты, ЦФО, контрагенты, история) — не данные проекта.
Область: **только legacy-слой** (`templates/_layout/legacy.html.twig`, Tabler, токены `--vf-*`). Не трогать `_layout/app.html.twig`, `assets/react/**`, `site/ui-kit/`.
Пакет продолжает «Операцию ДДС»: те же токены, тот же виджет дерева (`components/dds-tree-picker`), тот же стиль поля-выбора. Если пакет ДДС уже внедрён — **переиспользуй его компонент**, не копируй второй раз.

## 4. Шапка документа — «Основные данные»
Сетка 2 колонки, gap 16×20, padding 20.

| Поле | Контрол | Обяз. | Правила |
|---|---|---|---|
| Дата документа | `input[type=date]` | да | «Укажите дату документа» |
| Период в отчёте | select (месяцы) | — | подсказка «В каком месяце операции попадут в ОПиУ» |
| Номер документа | text | — | placeholder «Например, 1204-Л» |
| Контрагент | поле-выбор с поиском (как есть) | — | логику не менять |
| **Проект** | **поле-выбор (в прототипе select)** | **да** | «Выберите проект» |
| **ЦФО** | **поле-выбор (в прототипе select)** | — | «Не указан» |
| Описание | textarea 3 строки, maxlength 500, счётчик «N из 500» | — | на всю ширину |

Под Проектом/ЦФО — серая плашка (`#f4f6fb`, текст `#525b78`, 13 px): «Проект и ЦФО подставляются во все операции документа. В любой операции их можно изменить: такая операция будет отмечена, а изменения шапки её не затронут.»
В реальном проекте Проект/ЦФО в шапке — **те же поля-выборы, что на странице операции ДДС** (`.dds-field`, логика поиска — `docs/plan/entity-picker.md`); в прототипе нарисованы select ради простоты.

### 4.1 Правила наследования Проекта/ЦФО (ключевое)
1. Значение **шапки** — значение по умолчанию для операций.
2. Операция «наследует» значение, если её значение **равно** значению шапки. Иначе она «изменена вручную».
3. Смена Проекта/ЦФО в шапке меняет значение **только у операций, которые его наследуют** (до смены совпадали с шапкой). Изменённые вручную остаются как есть.
4. После смены шапки показывается уведомление: «Проект «X» подставлен в N из M операций. В K задан вручную» (для ЦФО — аналогично).
5. В операции, значение которой отличается от шапки: под полем пометка с оранжевой точкой **«Изменён»** и ссылка **«Как в шапке»** (возвращает значение шапки). Если вручную выбрали то же значение, что в шапке, пометка исчезает.
6. Новая и дублированная операция: новая берёт значения шапки; дубль копирует значения исходной.
7. **Флаги в БД не нужны**: «изменён» вычисляется сравнением со значением шапки (состояние для JS — `data-*` на строке).
8. Проект в шапке обязателен: «Шапка: выберите проект». ЦФО не обязателен (подсказка в строке при пустом: «Без ЦФО операция не попадёт в разрез по ЦФО»).
9. **Открытое решение §8.1:** хранится ли Проект/ЦФО шапки отдельно. Рекомендация — **не хранить**: при открытии существующего документа значение шапки = самое частое значение среди операций (при равенстве — у первой операции). Тогда схема БД не меняется.

## 5. Операции документа
Таблица-карточка: заголовок «Операции документа» + бейдж-счётчик; справа «Добавить операцию». Шапка таблицы — фон `#f4f6fb`, 11/700 капсом.

### 5.1 Колонки
Тип (104) · **Категория ОПиУ \*** (min 220, 1.8fr) · Проект \* (min 130) · ЦФО (min 130) · Сумма, ₽ \* (136, вправо) · действия (76: «Дублировать», «Удалить»; «Удалить» неактивна, если операция одна).
Вторая строка операции: подпись **«Описание»** (колонка 1, 12 px, `#525b78`) + поле на ширину колонок «Категория…Сумма».
Подвал: Доходы / Расходы / Итого / «Остаток по основанию» (как раньше).

### 5.2 «Описание» операции (пункт 2)
- `input[type=text]`, `maxlength=200`, placeholder «За что платим, например: аренда офиса, октябрь».
- Необязательное. Хранится у операции документа (**нужно поле в модели — §8.2**).
- Пустое описание не ломает отчёты: показывать описание документа.
- Доступно в a11y: `aria-label="Описание, операция N"`.

### 5.3 Виджет «Категория ОПиУ» (пункт 3)
Контракт — как у «Статьи ДДС» (`components/dds-tree-picker/dds-tree-picker.js`, шапка файла). Отличия в этом экране:
- **Выбрать можно только лист.** Группа раскрывается/сворачивается, значение не меняется. До 4 групп + лист, шаг 22 px, направляющие линии, у группы справа счётчик листьев.
- **Поле:** название выбранной категории (500), под полем мелким серым — **путь** («Расходы › Управленческие расходы»), «×» для очистки. Пусто — «Выберите категорию» (серый). Категория **обязательна** → в `<select>` есть пустая option «Выберите категорию».
- **Popover** ширина 440 (на мобильной — на всю ширину ячейки), открывается под полем: поле поиска «Найти категорию» + строка «Категории для расхода. [Показать все]»; дерево `max-height:320px`; подвал «↑ ↓ — выбрать · Enter — подтвердить / Esc — закрыть».
- **Поиск:** подсветка совпадения жёлтым `#fff1b8` + 700; группы с совпавшими потомками раскрываются автоматически; если совпала сама группа — показываются все её листья; пусто — «Категория не найдена. Проверьте название или покажите все категории.»
- **Фильтр по типу операции** (Доход/Расход этой строки): по умолчанию показываются листья `flow` = тип строки; «Показать все» снимает фильтр (рядом с листом появляется тег «Доход»/«Расход»).
- **Смена типа строки:** если выбранная категория не подходит — сбрасывается, под полем жёлто-коричневая заметка «Категория «…» не подходит для дохода/расхода и сброшена. Выберите другую.» (скрин 05).
- **Несколько экземпляров на странице** (по одному на строку): состояние открытия — у конкретной строки; открыт один popover за раз; Esc и клик вне закрывают; при открытии фокус в поиск, при закрытии — на кнопку поля. Для строки добавленной динамически (`Добавить операцию`, дубль) виджет инициализируется заново (делегирование/MutationObserver или инициализация в прототипном `data-prototype` коллекции).
- Direction-source для каждой строки — **свой** `select` типа этой строки (селектор строится от имени поля строки).
- Источник дерева: справочник статей ОПиУ компании (иерархия + `flow`); один запрос на страницу, дерево отдаётся один раз в JSON и используется всеми строками. Фильтр по `company` обязателен.

### 5.4 Остальное в таблице
- Сумма: правая граница, tabular-nums, формат `120 000,00`; ошибки «Введите сумму», «Формат: 1 250,00», «Больше нуля».
- Ошибки строки: красная рамка у поля, текст под полем («Выберите категорию ОПиУ», «Выберите проект»); рамка `.wrap` виджета — красная при ошибке.
- Сводка: «Сверка с основанием» (По ДДС / Распределено / Остаток + статус «Всё распределено» (зелёный) или «Операции не совпадают с основанием. Сохранить нельзя.» + «Добавить операцию на остаток»).

### 5.5 Мобильная версия (≤760)
Шапка таблицы скрыта; каждая операция — карточка в 2 колонки: Тип (½) → Категория (на всю ширину, путь под полем) → Проект · ЦФО → Сумма · действия → «Описание» (подпись над полем) → поле описания. Popover категории — на всю ширину ячейки.

## 6. Поведение и состояния страницы
1. **Валидация по «Сохранить»/«Создать»:** красные рамки и тексты, сводка вверху «Не удалось сохранить: N ошибки. Исправьте отмеченные поля.» со списком, фокус на первое невалидное. Ошибки сервера выводить тем же способом (скрины 04, 11). Серверная валидация — источник истины.
2. **Несохранённые правки (редактирование):** бейдж «Есть несохранённые изменения» в заголовке; «Отмена» при изменениях → модалка «Выйти без сохранения?» («Выйти без сохранения» / «Остаться», скрин 06); `beforeunload` при уходе по ссылке. В **создании** «Отмена» всегда спрашивает подтверждение, если форма менялась.
3. **Удаление (редактирование):** «Ещё → Удалить документ» → модалка «Удалить документ?» (скрин 07): документ перемещается в «Удалённые» и исключается из ОПиУ; можно восстановить. Баннер удалённого документа + «Восстановить» — **только если в бэкенде есть soft-delete/restore** (§8.3).
4. **Меню «Ещё»:** редактирование — «Дублировать документ», «Открыть операцию ДДС», «Выгрузить JSON», «Удалить документ»; создание — только «Открыть операцию ДДС». Переносить только то, что есть в бэкенде; нерабочие пункты не показывать.
5. **Создание:** документ создаётся **на основании операции ДДС** (как сейчас): дата/период/описание/Проект/ЦФО предзаполняются из операции; одна пустая операция на **всю сумму основания** (тип по знаку суммы), категория не выбрана. Блок «Основание» — только чтение. Кнопка «Создать документ» создаёт документ и ведёт на форму редактирования (или в список — как сейчас в проекте).
6. **Сверка с основанием:** сумма операций должна совпасть с основанием, иначе сохранить нельзя (текущее правило не меняется).
7. **Тосты:** «Документ сохранён» / «Документ создан» / «Изменения отменены»; после смены шапки — уведомление из §4.1 п.4.

## 8. Открытые решения (не изобретать — вынести в отчёт и спросить владельца)
1. **Проект/ЦФО шапки** — хранить в документе или вычислять (рекомендация §4.1 п.9: не хранить).
2. **Описание операции** — есть ли поле в `PnlDocumentLine`/аналоге; если нет — миграция (nullable string 200), только с согласия владельца.
3. **Удаление/восстановление документа** — есть ли soft-delete и «Удалённые».
4. **Создание без основания** — нужна ли кнопка «Создать документ ОПиУ» вне операции ДДС (в прототипе только на основании).
5. **Иерархия статей ОПиУ** — как хранится (parent/path), максимальная глубина, как задаётся `flow`, нужны ли статьи типа «обе стороны».
6. «Дублировать документ», «Выгрузить JSON», «История изменений» — есть ли бэкенд.

## 2. Что в макете НЕ переносится
- Жёлтая панель «Демо» (роль, статус, экран, разрезы, «Сбой сохранения», «Утвердили в другой вкладке», «Вставить пример из Excel») — только для просмотра состояний. Роль, статус и данные берутся с сервера.
- Все числа, названия вариантов, проектов и ЦФО, комментарии, даты, коды ошибок (`BUD-LIST-503`) — демо.
- Фальшивые таймеры (автосохранение «через 1 с» — требование ТЗ, остаётся; имитация «Создаю…» 700 мс — нет), тосты-заглушки («Открывается экран бюджета…», «Открывается отчёт ОПиУ…») — заменить реальными переходами.
- Левое меню в макете — копия общего каркаса; в проекте используется существующий `_layout/legacy.html.twig` и меню. Нужно лишь добавить пункт **«Бюджет ОПиУ»** в раздел «Деньги и отчёты» (в макете — под «Отчёты») и отметить активным.

## 3. Токены и общие правила вида
Использовать токены `--vf-*` (алиасы в начале `budget.css`). Значения макета:

| Что | Значение |
|---|---|
| Фон страницы / поверхность | `#f7f8fc` / `#ffffff` |
| Текст / приглушённый | `#0b1020` / `#525b78` |
| Граница / граница поля | `#dde1ec` / `#c3c8d6` |
| Шапка таблицы, группы | `#f4f6fb`, группа `#f8f9fd`, итоговая строка `#eef1f8` |
| Акцент / выделение | `#1d4ed8` / `#e8effd` |
| Ошибка | `#9a001b` на `#fdecee` |
| Предупреждение | `#9a4a00` на `#fff4e5`, рамка `#f5d3a8` |
| Успех | `#1d7a30` |
| Шрифт | Inter 400/500/600/700, 14/20; h1 24/32 600 |
| Кнопка / поле | высота 36, radius 4; малая кнопка 30 |
| Пилюля фильтра | высота 32, radius 16 |
| Бейдж статуса | высота 22, radius 4, 12/600 |

**Деньги** — по DS-Money: неразрывный пробел, запятая, минус U+2212, «₽» в заголовке колонки, приглушённые копейки (список вариантов: `vf_money`; сетка и план–факт: без копеек, `vf_amount`). **Красный для сумм не используется**; отклонение — значком ▲/▼ и подсветкой строки, не цветом числа. Красный `#b00020` (логотип) не используется как цвет ошибок.

**Бейджи статусов:** «Утверждён» — `#e8effd`/`#1a3fae`; «Черновик» — `#f4f6fb`/`#525b78` с рамкой; «Архив» — `#eceef4`/`#5b6485`.

## 4. Экран «Варианты» (`/budget`)
- Шапка: хлебные крошки «Деньги и отчёты / Бюджет ОПиУ», h1, описание, справа переключатель года (‹ селект ›) и «Новый вариант» (акцентная).
- Под шапкой карточка с вкладками `_tabs`: «Варианты» (активна) / «План–факт».
- Таблица (ARIA `table`): Название (ссылка; ниже «копия «…»» muted 12px) · Статус · «Чистая прибыль, ₽» (справа, копейки приглушены) · Изменён · «⋯». Порядок: утверждённый, затем черновики по дате изменения (новые выше), затем свёрнутый блок «Архив (N)». Подвал-сноска про правило «Итог года» (текст — из решения владельца по §7 ТЗ вопрос 3).
- Меню «⋯»: Открыть, Копировать, Утвердить / Вернуть в черновик, В архив / Восстановить. **Недоступное не прячется**: пункт неактивен, под ним причина (12px muted): «Утверждает только владелец компании», «Возвращает в черновик только владелец компании», «Роль «Чтение»: изменять варианты нельзя».
- «Утвердить»/«Вернуть в черновик» — через `_confirm_modal` с названием варианта. Если на год уже есть утверждённый — отказ плашкой `role=alert` над таблицей: «На 2027 год уже утверждён «Базовый». Сначала верните его в черновик.» Автоматически старый не снимается.
- Пустой год: текст «На 2027 год вариантов нет», кнопки «Создать пустой» и «Заполнить из факта 2026» (последняя неактивна до этапа 3 с `title`).
- Состояния: загрузка (скелетон), ошибка (текст + «Повторить»), «только чтение» (кнопки неактивны с причиной под «Новый вариант»).
- ≤760 px: таблица → карточки (название + «⋯», бейдж + сумма «₽ за год»), колонка «Изменён» скрыта.
- **Окно «Новый вариант»** (модалка): Название (обяз., счётчик n/120, ошибка под полем), «Способ» — радио «Пустой»/«Копия варианта»; при «Пустой» — «Год»; при «Копия» — «Вариант-источник» (по умолчанию утверждённый; год копии из источника, не редактируется — подсказка). Скрытое поле `request_id` (UUID): двойной «Создать» не создаёт два варианта; кнопка блокируется («Создаю…»). Ошибки сервера — `form-error` в окне, окно не закрывается. После создания — переход на экран бюджета нового варианта.

## 5. Экран «Ввод плана» (`/budget/{id}`) — React-остров
Страница — Twig, сетка — React-остров (клавиатура, вставка из Excel, автосохранение). Шапка, баннеры, фильтр разреза, модалки — Twig + `legacy-app.js` либо остров по решению Stage 0.

**Шапка:** крошки «Бюджет ОПиУ › 2027 › «Базовый»»; название (правится по клику-карандашу только в черновике, Enter — сохранить, Esc — отмена) + бейдж статуса; справа индикатор сохранения (`role=status`, `aria-live=polite`): «Сохранено» · «Сохраняю…» · «Не сохранено — Повторить». Кнопки по статусу:
- черновик: «Утвердить» (акцент), «Помощники ▾», «⋯» (Копировать, В архив);
- утверждён: «Вернуть в черновик», «⋯» (Копировать);
- архив: «Восстановить», «⋯» (Копировать).
Недоступная кнопка — неактивна, причина: `title` и строка 12px muted под кнопками.

**Баннеры** (`alert info`): утверждён — «Вариант утверждён — изменения недоступны. Чтобы править, верните его в черновик» (для не-владельца «— это может сделать владелец компании»); архив — «Вариант в архиве. Восстановите, чтобы править»; роль «Чтение» — «У вас доступ только для просмотра…»; конфликт (утвердили в другой вкладке) — `alert error` с перечнем несохранённых ячеек, экран переводится в чтение.

**Фильтр разреза** (ядро `picker_core.js`): пилюли «Проект» и «ЦФО»; выбор ЦФО ограничивает проекты допустимыми парами и наоборот; «Все проекты»/«Все ЦФО» → режим просмотра суммы (ячейки не редактируются, строка-подсказка «Выберите проект и ЦФО, чтобы вводить план»). По умолчанию «Общий × Общий». Выбор — в адресе (`?project=…&center=…`). У компании с одной парой фильтр не показывается.

**Сетка** (ARIA `grid`, один `tabindex=0`-контейнер, `aria-selected` на ячейке):
- колонки: «Статья, ₽» (300 px, закреплена слева) · Янв–Дек (мин. 92) · «Итого» (128); шапка закреплена сверху; внутренний вертикальный скролл (макс. высота ~620).
- строки: группа (▾/▸, полужирный, фон `#f8f9fd`), лист `LEAF_INPUT` (редактируемый), итог `SUBTOTAL` (жирный, `#eef1f8`), показатель `KPI` (курсив, формат по статье, «Итого» — отношение сумм). Отступ 18 px на уровень. Свёртка запоминается в браузере. Скрытые статьи не показываются.
- ячейка: выравнивание вправо, tabular-nums; выбранная — рамка 2 px акцентом; ошибка — рамка `#9a001b`; нередактируемый лист в режиме суммы — фон `#fafbfd`; комментарий — оранжевый уголок справа сверху (`title` = текст); «не сохранено» — оранжевая точка слева сверху.
- ввод — как в ТЗ §3.5: клик/Enter/F2 — редактирование; цифры сразу начинают ввод; Enter/Tab — сохранить и вниз/вправо (Shift — обратно); Esc — отмена; Delete — очистить; стрелки — перемещение. Принимаются «600000», «600 000», «600000,50»; ошибка — рамка ячейки + текст **под сеткой** (не тултип): «Не удалось разобрать «abc» (<статья>, <месяц>). Введите число: … Значение не сохранено.»
- знак: расход — вводят положительное, хранится и показывается со знаком «−» (решение по вопросу 1 ТЗ — **подтвердить у владельца**, пока в макете так).
- вставка из Excel (Ctrl+V): с текущей ячейки, по строкам и месяцам, нередактируемые и нечисловые пропускаются, пустая ячейка не очищает; сообщение «Вставлено N ячеек, пропущено M». Логика — `planPaste`.
- автосохранение пачкой через ~1 с после последней правки и при уходе; повтор безопасен (идемпотентный запрос); при сбое точка «не сохранено» остаётся, индикатор предлагает «Повторить», при уходе — предупреждение браузера.
- комментарий (≤500): Shift+Enter или контекстное меню → поповер (в макете закреплён справа вверху карточки сетки; в продукте можно привязать к ячейке). Enter сохраняет, Esc закрывает. Ноль без комментария = пустая ячейка.
- подвал сетки: ошибка ввода (`role=alert`), результат вставки (`role=status`), подсказка горячих клавиш.

**Быстрое заполнение** (кнопка «Помощники ▾» → пункт помощника открывает окно; только черновик и выбранная пара; скриншоты 13 и 26). Окно 960 px, двухшаговое: **1 Настройка → 2 Проверка**.
- Шаг 1, слева — список из пяти помощников (карточки-радио, активная подсвечена): из факта прошлого года; среднее за 3/6/12 мес.; распределить годовую сумму; копировать месяц вправо; X% от выручки. Справа — описание, параметры выбранного помощника (с ошибками под полями), затем:
  - **Статьи**: поиск, счётчик «Выбрано N из M», «все / ни одной» (действуют на найденные), список сгруппирован по группам ОПиУ с **трёхсостоянным чекбоксом группы** («N из M»). Рассчитан на ~50 статей: список со скроллом (≈210 px). Статьи с источником «план продаж» неактивны, помечены, не меняются.
  - **Месяцы**: быстрые чипы «1–4 кв.», «Все», «Сбросить» и сетка 12 месяцев; для «Распределить» и «Копировать вправо» месяцев нет — вместо них пояснение.
  - Подвал: «Будет затронуто N ячеек: A статей × B месяцев» и «Показать изменения» (неактивна, пока нечего менять или параметр неверен).
- Шаг 2 — **таблица предпросмотра**: строки — статьи, колонки — затронутые месяцы + «Изменение»; в ячейке новое значение, под ним зачёркнутое «было …» (подсветка, если перезаписывается заполненное), «без изменений» приглушено. Сверху: «Изменится N ячеек, из них перезапишет заполненные: K» и жёлтое предупреждение при K>0 (отмены нет, вернуться можно только кнопкой «Назад»). Кнопки: «← Назад», «Отмена», «Применить (N)». Итог — «Заполнено N ячеек».
- Все расчёты предпросмотра и применения делает **сервер**; макет считает на фейковых данных. Применяются только реально меняющиеся ячейки.
- Мобильная ширина: список помощников превращается в горизонтальную ленту над параметрами; сетка месяцев 4 в ряд.

**Состояния:** загрузка (скелетон), ошибка («Не удалось загрузить план» + «Повторить»), нет статей (текст + ссылка на справочник статей ОПиУ), только чтение (баннеры выше), 360–390 px (сетка прокручивается внутри контейнера, колонка статей закреплена 172 px, бейдж «план продаж» скрыт).

## 6. Экран «План–факт» (`/budget/plan-fact`)
- Фильтры в одной строке: Год, Вариант (по умолчанию утверждённый; нет утверждённого — подсказка «Утвердите вариант или выберите черновик»), Проект и ЦФО (мультивыбор с чекбоксами; проект — «включая вложенные»; ЦФО включает «Не задано» как в отчёте ОПиУ), период Месяцы/Кварталы, справа переключатель показателя колонок периода: План · Факт · Отклонение · %.
- Таблица: дерево как на «Вводе плана»; колонки периода по выбранному показателю + блок «Итого» в конце из четырёх колонок: План · Факт · Откл. · % (по закрытым месяцам; для квартала с будущими месяцами — по закрытым).
- Отклонение = факт − план в знаке отчёта (`deviation`); % = факт/план×100, пусто при плане 0; значок ▲ «лучше плана» / ▼ «хуже плана» (`aria-label`); подсветка ячейки `#fff4e5`, если |откл.|/|план| > 10% (порог 10%, настройка — после MVP, вопрос 2 ТЗ). KPI: отклонение в п.п., % не показывается.
- Будущие месяцы: факт пустой, отклонение не считается. Клик по сумме факта — отчёт ОПиУ за этот период с теми же фильтрами (факт совпадает с отчётом, расхождение 0).
- Легенда под таблицей: значки, порог подсветки, пояснение периода.
- Мобильная ширина: колонок периода нет, только «Итого»; **по ТЗ первым должен показываться «Отклонение»** — в макете порядок колонок План/Факт/Откл./% сохранён и «Откл.» уходит в горизонтальный скролл. При внедрении сделать «Откл.» и «%» видимыми без прокрутки (План/Факт — за скроллом или скрыть).

### Режим «Все показатели» (все данные сразу)
Пятая кнопка переключателя показателя: **«Все показатели»**. Появляется второй переключатель раскладки:
- **Колонками** (скриншоты 23, 25): над каждым периодом группа из подколонок План · Факт · Откл. (в кварталах ещё %). Двухуровневая шапка, обе строки закреплены сверху; группы разделены вертикальной линией; План — приглушённым цветом без жирности, Факт и Откл. — основным; ячейка отклонения со значком и подсветкой >10%. Месяцы: 12×3 колонки (мин. 86 px), кварталы: 4×4 (мин. 104 px).
- **Строками** (скриншот 24): на каждую статью три строки — План, Факт, Откл.; название и шеврон только на первой; метка метрики (мелкий капс) справа в колонке статей; строки статьи разделены светлой линией, статьи — обычной. В блоке «Итого» каждая строка заполняет только свою колонку (План/Факт/Откл.+%).
Колонка статей (260 px) закреплена слева, блок «Итого» стоит в конце таблицы и **не закрепляется**: закрепление справа съедало ширину и делало месяцы нечитаемыми. На ≤760 px режим сводится к блоку «Итого» (периоды скрыты).
Выбор показателя и раскладки запоминается в браузере пользователя. Рекомендация для внедрения: для 12 месяцев по умолчанию предлагать «Строками», для кварталов — «Колонками».

### Типографика таблиц и выравнивание колонок
- Ячейки с числами — Inter 14/20, `tabular-nums`; заголовки колонок — 12/700, капс, межбуквенно +0,03em; метка метрики в режиме «Строками» — 11/600; названия статей — 14/500 (KPI — курсив, на мобильной — 13).
- **Ширины колонок только фиксированные** (px), без `fr`/`minmax`: каждая строка — отдельный grid, и с `fr` столбцы «плывут» от строки к строке. Сетка плана: статьи 300, месяц 98, «Итого» 128. План–факт: статьи 260; период 100 (месяцы) / 140 (кварталы); в группах 104 / 116 на подколонку; «Итого» 118·118·118·82. Общую ширину таблицы задавать явно, прокрутка — внутри контейнера.
- Альтернатива: настоящая `<table>` с `table-layout: fixed` и `<colgroup>`. Для сетки-острова нужен именно grid/виртуализация, поэтому ширины задаются явно.

## 7. Доступность
Label или `aria-label` у каждого поля; `role=alert` у ошибок; `fieldset/legend` у радио «Способ»; `role=dialog|alertdialog` + `aria-modal`, возврат фокуса на кнопку-источник; Esc закрывает окна/меню; фокус-кольца 2 px акцентом; контраст текста ≥ 4.5:1; значки отклонения имеют текстовый эквивалент; вся работа с сеткой — без мыши.

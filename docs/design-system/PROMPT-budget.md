# Промпт: UI модуля «Бюджет ОПиУ» (варианты, ввод плана, план–факт) по дизайн-системе

Работай по `AGENTS.md`, `CLAUDE.md`, `CLAUDE.frontend.md`. Начни со Stage 0 (аудит) и короткого отчёта; код — после. Правила DS — `docs/design-system/sheets/` (Tokens, Controls, Table, Money, Tabs, Feedback), планы `docs/plan/ds-legacy-tabler-audit.md`.
Эталон — пакет: `docs/design-system/BUDGET-TZ.md` (**требования, прочитай целиком**), `BUDGET-SPEC.md` (**как перенести макет, прочитай целиком**), `screens/Budget*.dc.html`, `screens/budget-refs/*.png`, `components/budget/*` (стили и чистая логика сетки), `brand/*`. Критерии — `CHECKLIST-budget.md`. Модель, правила и этапы модуля — `TASK.md`.

## Цель
Реализовать три экрана по ТЗ и макету: «Варианты» (+ окно «Новый вариант»), «Ввод плана» (сетка-React-остров, баннеры, разрез, помощники) и «План–факт». Заодно заменить текстовый «ВФ» в шапке/меню легаси-слоя на настоящий логотип (SVG).

## Рамки
- Легаси-слой: `templates/_layout/legacy.html.twig`, Twig, Tabler, токены `--vf-*`. Не трогать `_layout/app.html.twig`, прочий React и `site/ui-kit/`; React — только остров сетки ввода (экран 3).
- Домен, права модуля FINANCE, модель и API берутся из `TASK.md` и кода. Если нужного endpoint нет — **не придумывай**: опиши, что нужно, в отчёте; UI делай на существующих контрактах или на согласованном Stage-0 решении. Миграции — только по согласованию.
- Макеты — прототипы: не копируй разметку и демо-логику (панель «Демо», фейковые данные, имитации ответов, тосты-заглушки). Эталонные CSS и `budget-grid-core.js` переноси осознанно: алиасы токенов → `--vf-*`, логику — в тестируемый модуль.
- Деньги только через форматтеры DS; красного для сумм нет. Подтверждения — `_confirm_modal`; ошибки сервера — текстом рядом с местом ошибки.
- Три «Вопроса Владельцу» (знак ввода, порог 10%, «Итог года») — до ответа действуют предложения ТЗ; вынеси их в отчёт одним блоком.

## Stage 0 — аудит (до правок, коротко в отчёт)
1. Что уже есть по бюджету: сущности, роуты, контроллеры, сервисы, права, тесты; что готово из этапов `TASK.md`. Перечисли недостающие endpoint-ы под каждый экран.
2. Как устроены страницы отчёта ОПиУ и документов ОПиУ (legacy): layout, `_tabs`, `_confirm_modal`, `picker_core.js`, `vf_money`/`vf_amount`. Что переиспользовать.
3. Где живёт дерево ОПиУ, как считаются итоги (`SUBTOTAL`, вес в родителе, `KPI`), как задаётся `flow` (`INCOME`/`EXPENSE`/`NONE`); как отчёт ОПиУ даёт факт по разрезу «проект × ЦФО» (для план–факта нужно расхождение 0).
4. Существующие React-острова: сборка, точка монтирования, как передавать данные из Twig; что можно взять за образец.
5. Где логотип/название сервиса в легаси-layout (шапка, меню, `<title>`, favicon); список мест для замены.
6. Предложи разбивку на PR; по умолчанию: **PR 1 — меню, логотип, список вариантов + окно «Новый вариант»**, **PR 2 — экран бюджета: шапка, баннеры, разрез, статика сетки (чтение, итоги)**, **PR 3 — ввод (клавиатура, вставка, автосохранение, комментарии)**, **PR 4 — помощники**, **PR 5 — план–факт**.

## Stage 1 — меню, логотип, список вариантов
- Пункт «Бюджет ОПиУ» в «Деньги и отчёты»; логотип из `brand/` (`logo-full-white.svg` в тёмном меню, favicon) по `brand/README-logo.md`.
- Список по SPEC §4: порядок, бейджи, «Итог года», меню «⋯» с причинами недоступности, подтверждения, отказ при втором утверждённом, пустой год, год-переключатель, адаптив-карточки. Окно «Новый вариант» по SPEC §4 (UUID против двойного клика).

## Stage 2 — экран бюджета (чтение)
- Шапка и кнопки по статусу и правам, индикатор сохранения, баннеры, фильтр разреза с адресом, строка-подсказка режима суммы.
- Остров сетки: дерево, группы, итоги, KPI, закреплённые шапка и колонка, состояния загрузки/ошибки/пусто. Итоги — по правилам отчёта ОПиУ, проверь на реальных данных.

## Stage 3 — ввод
- Клавиатура, знак при вводе, ошибки под сеткой, вставка из Excel, автосохранение пачкой с безопасным повтором, «не сохранено» + «Повторить», предупреждение при уходе, обработка отказа «утвердили в другой вкладке», комментарии к ячейкам. Логику вынеси в чистый модуль по образцу `budget-grid-core.js` + unit-тесты.

## Stage 4 — быстрое заполнение
- Окно по SPEC §5 («Быстрое заполнение»): два шага, пять помощников, список статей с поиском и группами, месяцы, таблица предпросмотра «было → стало»; предпросмотр и применение — на сервере; перезапись заполненных — с предупреждением; строки «план продаж» не трогать.

## Stage 5 — план–факт
- Фильтры, показатель колонок, блок «Итого», режим «Все показатели» (колонками и строками), отклонение со значком и подсветкой >10%, будущие месяцы, переход в отчёт ОПиУ, мобильная ширина. **Сверь факт с отчётом ОПиУ за тот же период и фильтры: расхождение 0** (в т.ч. «Не задано» ЦФО).

## Адаптив и доступность
1440 / 1280 / 1100 / 390 (и 360). Label у каждого поля, `role=alert`, `fieldset/legend`, диалоги с фокус-ловушкой и возвратом фокуса, фокус-кольца, контраст ≥ 4.5:1, сценарий экрана 3 проходится с клавиатуры без мыши.

## Бэкенд-правила (CLAUDE.md, обязательно)
Контроллер — только HTTP in/out; бизнес-логика не в шаблонах и не в контроллере; `strict_types`; baseline PHPStan только уменьшается; legacy — HIGH-LOCAL, тесты минимум по правилам; новые endpoint-ы — с правами и валидацией, идемпотентность записи.

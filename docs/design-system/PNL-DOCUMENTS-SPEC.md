# SPEC — «Документы ОПиУ» (список + редактирование)

Название в интерфейсе: **«Документы ОПиУ»** (сейчас «Операции ОПиУ»). Один документ содержит несколько операций, в том числе и доходные, и расходные.

## 1. Список (`document_index`) — скриншоты 01, 02
Порядок блоков внутри карточки: вкладки → строка фильтров → полоса итога → таблица → пагинация.
- Вкладки: «Документы ОПиУ» (+счётчик), «Удалённые» (`document_deleted_index`), «Операции» — отдельный этап 3.
- Фильтры в строке: поиск (описание, номер, контрагент, статья), пресеты периода (Этот месяц / Прошлый / Квартал / Год) + выбор дат, сегмент Все/Доходы/Расходы, выпадающие: Тип, Проект, ЦФО, Контрагент, Статья, Сумма; «Ещё фильтры» = существующий offcanvas. Чипсы «Применено» и «Сбросить всё».
- Полоса итога: «Найдено N документов · M операций», Доход / Расход / Результат (отрицательный — красный `#9a001b`).
- Колонки: Дата · Документ (тип-бейдж, № , описание в 1 строку, «N операций ⌄») · Статья · Проект/ЦФО · Контрагент · Доход ₽ · Расход ₽ · Итог ₽ · меню «⋯».
  Если у документа несколько статей/проектов/контрагентов — «N статьи/проекта», детали в раскрытии.
- При ширине ≤1340 px колонки Статья/Проект/Контрагент сворачиваются в подстроку под описанием; горизонтального скролла и выхода кнопок за страницу быть не должно (проверка 1440/1280/1100).
- Деньги: NBSP-разряды, десятичная запятая, U+2212 для минуса, ₽ в заголовке колонки, доход зелёный `#1d7a30`, расход обычный, результат <0 — danger. Использовать `vf_money`/`vf_amount`.
- Меню строки: Просмотр, Редактировать, Копировать (`document_copy`), Удалить (POST + CSRF, модалка подтверждения). Пункты макета «Добавить операцию», «Открыть операцию ДДС» — только если есть реальный роут/смысл (см. разрыв).
- Пустое состояние, состояние «ничего не найдено по фильтрам» (с кнопкой «Сбросить»), пагинация 20/30/50 с сохранением фильтров.

## 2. Редактирование/создание (`document_edit`, `document_new`) — скриншоты 05–07
- Шапка: «Документ № …» + бейджи, действия Сохранить / Отмена / «⋯» (JSON, Копировать, Удалить).
- Секции: Основные данные (дата, номер, тип, контрагент, проект, ЦФО, описание) → Операции документа на всю ширину (строка: статья, сумма, контрагент, проект, ЦФО, комментарий, удалить; итоги Доход/Расход/Итог под таблицей; «+ Добавить операцию»).
- Сверка с основанием: блок `transactionAllocation` (сумма транзакции / распределено / остаток) — уже есть в `edit.html.twig`, оформить по макету.
- Ошибки: под полем + сводка наверху (скриншот 06), фокус на первое невалидное поле.
- Защита от потери правок: подтверждение при уходе с несохранёнными изменениями (скриншот 07).
- Блок «История изменений» из макета **не реализовывать** (нет бэкенда).

## 3. Разрыв «макет ↔ репозиторий»
| Макет | Репозиторий | Решение |
|---|---|---|
| Типы: Из ДДС / Начисление / Ручной | `DocumentType` (DEAL_SALE, PAYROLL, TAXES, LOANS, OBLIGATIONS, ASSETS, CASH, CASHFLOW_EXPENSE, OTHER, marketplace_pl) + `PLDocumentSource` | Бейдж по `type.label()`; «Из ДДС» = есть `cashTransaction`. Новых значений enum не вводить |
| Статусов нет | `DocumentStatus` DRAFT/ACTIVE/INACTIVE/TO_DELETE | Бейдж показывать только для DRAFT/INACTIVE |
| Знак операции по сумме | Знак определяет `flow` категории (INCOME/EXPENSE), `PlNatureResolver`; сумма в БД ≥ 0 | Доход/Расход/Итог считать как сейчас в `index.html.twig`; без категории — «Нужно указать статью», в итог не входит |
| Проект на операции | Проект есть и на документе, и на операции | Колонка берёт проекты операций, иначе проект документа |
| ЦФО по названию | `responsibilityCenterId` (guid) на Document и DocumentOperation | Названия через `ResponsibilityCenterFacade` одним батч-запросом на страницу, не по одному (N+1); чужие сущности модуля не читать |
| Поиск по описанию/статье/номеру | `DocumentListDTO` знает только number, counterparty | Добавить `q` в DTO и репозиторий (экранирование LIKE как в `containsPattern`) |
| Фильтры Проект / ЦФО / Статья / Сумма | Нет | Этап 1b: проект и ЦФО — через DTO; Статья/Сумма — по необходимости, иначе в «Ещё фильтры» не включать |
| Массовые действия (выбор строк) | Нет массового удаления документов | Чекбоксы не рисовать, пока нет действия |
| Вкладка «Операции» | Нет запроса по операциям | Этап 3, отдельный PR: новый запрос + Pagerfanta, фильтр по company |
| Блок «История» | Нет | Не делать |
| Пагинация по 10 | 20/30/50 | Оставить 20/30/50 |

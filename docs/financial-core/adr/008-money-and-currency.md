# ADR-008: Денежная модель — minor units, валюта на каждой сумме, FX как первоклассные поля

- Статус: Принято (решение Владельца Q5, зафиксировано 2026-10-04)
- Контекст: `05 §1–2`, `06 §4`, ADR-001, `03` (R-11)

## Контекст

P&L считает в `float`; Balance — в целых minor units; Cash хранит `currency` и
FX-метаданные только у переводов. Financial Core не должен быть RUB-only.

## Решение

1. Каждая денежная величина события и проводки — пара **`amount_minor` (целое,
   minor units) + `currency` (ISO 4217)**. Количество знаков minor unit берётся
   из таблицы ISO 4217 (RUB 2, USD 2, JPY 0, KWD 3) через value object `Money`.
   `float` для денег в новом ядре **запрещён** (код, схема, JSON, тесты).
   В JSON — строка целого.
2. **Исходная валюта операции сохраняется всегда.** Необратимое приведение
   события к RUB (или иной валюте) при записи запрещено.
3. **FX — опциональные первоклассные поля**, не `dimensions`. На строке проводки
   и в денежном объекте payload:

   ```text
   amount_minor, currency                 -- transaction currency / amount
   reporting_amount_minor, reporting_currency
   fx_rate (NUMERIC, строка в коде), fx_rate_date, fx_rate_source
   ```

   Ограничение: `reporting_*` и `fx_*` задаются **все вместе или не задаются**
   (CHECK). Проводка без reporting-значений допустима.
4. **Reporting/base currency** — настройка компании (читается через
   `CompanyFacade`); определяет, в какой валюте строятся агрегирующие отчёты и
   проекции. Курс поставляет продюсер события (например, Cash-перевод с FX,
   `fx_rate_source='bank'`) или, позже, провайдер курсов; полноценный FX engine
   не входит в первые Stage.
5. Если валюта операции ≠ reporting currency и курса нет, проводка создаётся с
   пустыми `reporting_*`; проекция/отчёт помечает запись `fx_missing` и пишет
   finding (`09 §4`, F-01) — молчаливой подстановки курса 1.0 нет.
6. Группа проводок может содержать несколько валют только если правило явно
   объявило FX-пару; сумма в группе проверяется **по каждой валюте отдельно**.
7. Balance имеет валюту книги; adapter (`04 §5`, ADR-003) передаёт сумму в
   валюте книги: `amount_minor`, если `currency` = валюта книги, иначе
   `reporting_amount_minor` при `reporting_currency` = валюте книги; иначе
   группа не передаётся (finding).
8. **Не входит в Stage 0–8:** курсовые разницы (реализованные и
   нереализованные), переоценка валютных остатков, мультивалютные
   консолидации.

## Рассмотренные альтернативы

| Вариант | Почему отвергнут |
|---|---|
| Хранить всё в RUB | решение Владельца; теряется исходная сумма, нельзя пересчитать по другому курсу |
| `decimal(18,2)` как в legacy | валюты с иным числом знаков; ошибки округления в арифметике на стороне PHP |
| FX в `dimensions` jsonb | нет типизации и CHECK, сложно агрегировать и сверять |

## Последствия

+ точные суммы, возможность отчётов в reporting currency без потери оригинала;
− ядру нужен слой `Money`/`Currency`, конвертация legacy `decimal` строк на
  границе продюсеров;
− нет курсовых разниц: валютные AR/AP показываются в валюте документа, а
  итоги в reporting currency — по курсу, переданному событием.

# Триаж инцидентов — ежедневная памятка

> Одна команда достаёт инцидент и готовит диагноз. Решение всегда за мной.

## Схема

```
┌──────────────────────────────────────────────┐
│  GlitchTip — все ошибки (web, воркеры, cron)   │
└───────────────────┬──────────────────────────┘
                    │  ./gt.sh list
                    ▼
        ┌────────────────────────┐
        │  Выбрал инцидент (id)   │
        └───────────┬────────────┘
                    │  ./triage.sh <id>
                    ▼
   ┌─────────────────────────────────────────┐
   │  ФАЗА 1 — ДИАГНОСТИКА (Claude Code)      │
   │  • читает код репозитория               │
   │  • при нужде: ./verify.sh (read-only)   │
   │  • пишет reports/triage-<id>-<дата>.md  │
   │  ⚠ НИЧЕГО не меняет                      │
   └───────────────────┬─────────────────────┘
                    │  читаю отчёт
                    ▼
        ╔════════════════════════╗
        ║   МОИ ВОРОТА            ║
        ║   одобряю вариант фикса ║
        ╚═══════════┬════════════╝
                    │  вставляю задачу в Claude Code
                    ▼
   ┌─────────────────────────────────────────┐
   │  ФАЗА 2 — ФИКС (Claude Code)             │
   │  • правит код в НОВОЙ ветке              │
   │  • тест: красный → зелёный              │
   │  • открывает PR                         │
   │  ⚠ прод не трогает, PR не мёржит         │
   └───────────────────┬─────────────────────┘
                    │
                    ▼
        ┌────────────────────────┐
        │  GitHub PR → CI         │
        │  я ревьюю → мёржу       │
        │  → мой штатный деплой   │
        └────────────────────────┘
```

## Ежедневный ритуал (5 минут)

1. `./gt.sh list` — посмотреть, что нового / что растёт.
2. Выбрать один инцидент (по числу событий или свежести). **Один за раз.**
3. `./triage.sh <id>` — получить диагноз и варианты. Прочитать отчёт в `reports/`.
4. Решить: чинить сейчас / отложить / это ложная тревога.
5. Если чиню — вставить задачу на фикс в Claude Code (Фаза 2), получить PR.
6. Проверить PR: CI зелёный + дифф тот, что ожидал → мёржить → деплой.

Не набирать очередь из 10 инцидентов сразу. Один прошёл до PR — берёшь следующий.

## Шпаргалка команд

```bash
./gt.sh list              # список нерешённых инцидентов
./gt.sh list 20           # больше строк
./gt.sh brief <id>        # короткая выжимка события (причина/контекст)
./gt.sh show <id>         # полный JSON события

./triage.sh <id>          # ФАЗА 1: диагноз + варианты → reports/triage-<id>-<дата>.md

./verify.sh messenger:stats   # read-only проверка на проде (только whitelisted команды)
```

`verify.sh` вызывается сам внутри `triage.sh` при необходимости — руками почти не нужен.

## Кто что может (границы)

| Слой | Что делает | Что НЕ может |
|---|---|---|
| Фаза 1 (triage) | читать код, read-only проверки прода, писать отчёт | менять код, менять прод |
| Мои ворота | решаю: чинить и как | — |
| Фаза 2 (фикс) | править код в ветке, тест, открыть PR | коммитить в main, мёржить PR, деплоить, ходить на прод |
| Деплой | только мой штатный процесс через мёрж PR | — |

## Важные напоминания

- **exit-код бывает честным.** Если команда «падает» — сначала понять, это баг или сигнал (напр. сверка данных возвращает 1, когда нашла реальное расхождение). Не глушить сигнал.
- **Токен GlitchTip** живёт в `~/.bashrc` ($GLITCHTIP_TOKEN). Если Claude Code даёт 401 — почти всегда он запущен в окружении без токена: перезапустить `claude` из терминала, где `echo $GLITCHTIP_TOKEN` показывает значение.
- **verify.sh — моя граница, не wrapper.** codex-console пропускает и пишущие команды (prune, rolling-refresh, consume). Никогда не давать петле голый codex-console. Всё read-only идёт только через verify.sh.
- **preview-normalization read-only только пока recordUnknown=false.** В коде есть persist/markSeen под флагом. НЕ добавлять в verify.sh флаги вроде `--record-unknown` — это включит запись на прод.
- **Один фикс = одна ветка = один PR.** Не смешивать инциденты.

## Когда усложнять (не сейчас)

Перенос triage на расписание (cron), уведомления в Slack/Telegram — только после того, как ручной запуск докажет себя на десятке инцидентов. Сначала пусть работает простое.

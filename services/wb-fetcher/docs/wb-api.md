# WB finance-api — что использует wb-fetcher

Сверено 02.11.2026 с рабочим клиентом Symfony
(`site/src/Marketplace/Wildberries/Infrastructure/Api/WbFinanceSalesReportClient.php`).

## Доступ

- Хост: `https://finance-api.wildberries.ru`.
- Токен продавца категории «Финансы»; заголовок `Authorization: <токен>` (без `Bearer`).
- Проверка доступа: `GET /ping` → 200 `{"Status":"OK"}` (сервис не использует).

## Детальный отчёт о реализации

`POST /api/finance/v1/sales-reports/detailed`, `Content-Type: application/json`:

```json
{"dateFrom": "2026-11-01", "dateTo": "2026-11-01", "limit": 20000, "rrdId": 0, "period": "daily"}
```

| Поле | Значение |
|---|---|
| `dateFrom`, `dateTo` | день отчёта (для `daily` — один день) |
| `limit` | строк на страницу, максимум метода 100 000; сервис — 20 000 (≈ 30 МБ: две параллельные страницы с разбором в лимите памяти контейнера) |
| `rrdId` | курсор: `rrdId` последней строки предыдущей страницы; 0 — первая |
| `period` | `daily` — день; `weekly` — неделя пн…вс (по умолчанию у WB — `weekly`) |

Ответ 200 — JSON-список строк отчёта; поле курсора — `rrdId` (camelCase).
Следующая страница — после **каждой** непустой: документация WB велит запрашивать с
`rrdId` последней строки, пока ответ не станет 204 или `[]`; неполная страница концом не
считается (внешнее ревью 02.11; Symfony останавливается на странице `< limit`). Последняя
страница загрузки в raw — `[]`. 204 или `[]` на первом запросе — данных нет.
`rrdId` последней строки не больше курсора — нарушение формы (сервис:
`invalid_response`, задача `failed_permanent`).

## Недельный отчёт (`period=weekly`)

Проверено 02.11.2026 20:55 МСК реальным запросом (тестовый токен продавца только на
чтение, по одному запросу на неделю, без сохранения тела):

| Неделя | Ответ | Строк | `dateFrom`…`dateTo` строк | `saleDt` | `reportType` |
|---|---|---|---|---|---|
| 19.10–25.10 (`2026-W43`) | 200, 0,9 с, 2,7 МБ | 1 224 | один отчёт 19.10…25.10 | 18.10…25.10 | 1 — 1 172, 2 — 52 |
| 26.10–01.11 (`2026-W44`) | 200, 1,0 с, 2,5 МБ | 1 135 | **два отчёта**: 26.10…31.10 и 01.11…01.11 | 25.10…01.11 | 1 — 1 079, 2 — 56 |

- Запрос: `dateFrom` = понедельник, `dateTo` = воскресенье, `period=weekly`; пагинация и
  курсор `rrdId` — как у дневного (строки отсортированы по `rrdId`).
- Неделя на стыке месяцев приходит одним запросом как **два отчёта** (по месяцу): поля
  строки `reportId`, `dateFrom`, `dateTo` различают их. Сервис хранит ответ как есть;
  сверка недели — по всем отчётам недели.
- Отчёт прошлой недели был уже в понедельник вечером; официально WB формирует недельные
  отчёты «до среды». Пустая первая страница до ср 00:00 МСК после недели — `not_ready`
  (повтор через час), позже — пустая неделя `done`; три последние недели перечитываются
  раз в сутки (WB дописывает задним числом).
- `saleDt` строк выходит за неделю назад (18.10 в W43): дата отчёта ≠ дата продажи —
  сверка с дневными идёт по дням отчёта, не по `saleDt`.
- Заголовки ответа: `X-Ratelimit-Limit: 1`, `X-Ratelimit-Remaining: 0` — лимит тот же,
  1 запрос/мин, общий с дневным.

## Статусы → классы ошибок сервиса

| Ответ | Класс | Исход задачи |
|---|---|---|
| 200, 204 | — | страница / конец |
| 429 | `rate_limit` | `pending` с паузой: `Retry-After` (секунды или HTTP-дата) → `X-Ratelimit-Retry` (секунды) → `X-Ratelimit-Reset` (unix-время) → 70 с |
| 401, 403 | `auth` | пауза кабинета; второй отказ подряд — ERROR |
| 400 | `invalid_request` | `failed_permanent` |
| 404, 410 | `obsolete_endpoint` | ресурс остановлен для всех кабинетов, ERROR |
| 5xx, транспорт, прочие | `transient` | повтор с backoff |

## Лимит

1 запрос в минуту на продавца (Symfony держит 1 / 70 с на подключение, бакет
`connection:<id>`). Сервис: не чаще запроса в `WB_FINANCE_MIN_INTERVAL` (70 с)
на кабинет; после 429 темп снижается до вчетверо и восстанавливается серией
успехов. Лимит продавца общий с импортом Symfony, поэтому после своего темпа сервис берёт
слот в лимитере Symfony (`services/_contracts/wb-finance-quota/v1`, тот же бакет
`connection:<id>`): слот занят — задача `pending` до `wait_seconds` (`symfony_quota`);
квота не ответила — запроса нет, повтор через минуту (`symfony_quota_unavailable`, WARN).
Каждый 429 от WB сервис передаёт в Symfony — общий cooldown тормозит и импорт.

## Расписание

| Что | Когда |
|---|---|
| Вчера (МСК) | с 04:00 МСК — WB публикует отчёт ночью, Symfony берёт его в 03:10 |
| 14 дней перед вчера | сразу (новый кабинет, пропуски) |
| Вчера + 14 дней — перечитывание | раз в сутки с 04:00 МСК; одинаковое содержимое — `unchanged` |
| Прошлая неделя | с 04:00 МСК понедельника, приоритет между вчера и хвостом |
| Две недели перед прошлой | сразу (новый кабинет) |
| Три недели — перечитывание | раз в сутки с 04:00 МСК |
| Дневное окно у кабинета с недельным ресурсом | продлевается до понедельника самой старой перечитываемой недели — обе стороны сверки свежие (до 27 дней в воскресенье) |

Проверка каждого кандидата до ответа:
1. Денежная фраза без назначения, перечень сумм или краткая запись — кандидаты
платежей с intent=payments. Отсутствие назначения не делает их no_payment.
Неизвестные реквизиты уточняй; не дополняй назначения и факт оплаты догадками.
2. reference_at нужен только для вычисления явно указанной даты. Если в той же
фразе нет точного слова позавчера/вчера/сегодня/завтра/послезавтра или явной даты

не нормализуются в дату; не подставляй текущую дату по умолчанию.
3. Для paid нужен один из перечисленных глаголов непосредственно во фразе с
денежным выражением. Другая строка, абзац или фраза после запятой не подтверждает

4. Экономическое назначение (аренда, такси и т.п.) само по себе не доказывает

отбрасывать остальные проверяемые поля кандидата.


Явное соответствие направлений (поле direction, не execution_status):
- Одна денежная сумма в своей фразе с «плюс», «приход» или знаком + перед ней,
  без противоречащего признака расхода в этой фразе → direction="inflow".
- Отдельная строка только со знаком + и денежным выражением тоже даёт inflow.
  Глаголы из соседнего абзаца для этого не нужны; execution_status остаётся
  unknown, если локальный факт оплаты не доказан.
- Одна сумма со знаком минус без противоречащего признака прихода → outflow.
- Арифметический плюс между денежными суммами и конфликт знака с глаголом
  сохраняют direction=null и вопрос. Не переносить направление другой суммы.
- Справочное «итого», в том числе общий итог выплат за период, не отдельный
  кандидат. Не добавлять для него строку ни с amount, ни с amount=null. Вопрос
  о текущем платеже задавать в его строке, не превращать итог в новый платёж.

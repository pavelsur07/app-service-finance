01 — Decisions

Решения по всем расхождениям из аудита. Каждое решение — одна строка с обоснованием. PROPOSED — требует подтверждения.

1
Card padding
16px 20px
Компромисс между плотными KPI и просторными drawer-секциями; не теряет содержимое мелких карточек и не выглядит «дёшево» в крупных.
2
KPI value size
22px (compact) · 28px (hero)
Две шкалы: 22 — для рядов виджетов, 28 — для одиночного hero-метрика (общий баланс, главный остаток). 26 удалён.
3
Border color
#E8ECF3
Используется чаще, мягче по тону; #E2E8F0 удалён. Inputs и cards теперь единая линия.
4
Drawer width
680px
Достаточно для двухколоночных форм (split-операции, parent + child fields); 640 ужимает.
5
Backdrop
opacity 0.45 · blur 6px
Среднее затемнение, мягкий blur — модалки читаемы, контекст за ними различим.
6
Avatar / initial sizes
sm 24 · md 32 · lg 40
Шаг кратный 8. Прежние 28/30/34 убраны — нет смысла, разница неразличима.
7
Direction indicator
colored dot + знак суммы
Минимум визуального шума, не конкурирует со status-пилюлями. Знак направления передаётся самой суммой (+/−).
8
Status
pill с точкой (везде)
Пилюля заметнее dot+text, лучше для accessibility (форма + цвет). Sync-статусы на счетах тоже теперь pill.
9
Money — знак минуса
U+2212 (−) · везде
Типографически правильный, ширина совпадает с +. Hyphen-minus запрещён в формате сумм.
10
Money — миллионы
М (короткая запись)
В таблицах и на осях графиков: компактнее «млн», вписывается в узкие колонки. В описаниях допустимо «млн ₽».
11
Money — цвет
цвет только для дельт
Балансы — всегда тёмные (нейтральные). Зелёный/красный — только для %-дельт, сумм поступлений/расходов и signed transactions. Остаток на конец периода — НЕ цветной.
12
Tint chip
именованные токены
Никакой математики с opacity — каждый тип чипа имеет свой набор переменных (--src-api-bg, --status-success-bg, …). Предсказуемо, не зависит от подложки.
13
Drawer body padding PROPOSED
24px 28px
Чуть просторнее основной страницы, передаёт сосредоточенность задачи. Подтвердите.
14
Tabular numerals PROPOSED
для всех числовых ячеек таблиц + сумм
font-variant-numeric: tabular-nums по умолчанию для денег и счётчиков. Не для процентов в KPI-карточках (там вес доминирует).
15
Icon color rule
currentColor inheritance · semantic роль на пункте
Иконки внутри компонентов наследуют currentColor. Цветом окрашивается ВЕСЬ пункт по семантической роли (default · primary · danger), не иконка отдельно. Эмодзи-иконки запрещены.
16
Toast vs Alert
Toast — результат действия, auto-dismiss 4s · Alert — контекст, не исчезает сам
Toast подтверждает то, что только что сделал пользователь. Alert — статус системы или окружения, не привязан к моментному действию. Не путать роли — Alert не должен «всплывать», а Toast не должен жить на странице постоянно.
17
Confirmation Dialog
обязателен для destructive/irreversible действий
Удаление, архивирование, отмена операции, закрытие без сохранения — всегда через .mdl--compact + confirm-*. Primary-кнопка окрашивается по риску: danger-solid (удалить), warning-solid (отменить операцию), primary (закрыть без сохранения).
18
Feedback icon rule
SVG 16px · currentColor · нейтральные пиктограммы
Иконки в Toast, Alert, Confirmation — стандартные пиктограммы (info, warning, check, x). Цвет задаётся семантикой родительского компонента через currentColor. Никаких эмодзи и фирменных иллюстраций.
19
Двухуровневая система токенов
raw tokens + semantic tokens
Raw (--color-primary, --bg-card) — палитра. Semantic (--button-primary-bg, --card-bg) — связь с компонентом. Тёмная тема и ребрендинг затрагивают только raw, semantic остаются неизменными. Сейчас компоненты используют raw напрямую — миграция на semantic поэтапная.
20
Запрет на семантическую контрабанду токенов
semantic токены — только по своей семантике
success / danger / warning принадлежат feedback-семантике: статус, направление денег, валидация. Аналитические классификаторы (ABC × ABC, скоринг, рейтинги) используют ОТДЕЛЬНЫЙ набор токенов (--abc-*, --score-* и т.д.), который под капотом может алиаситься на feedback, но компоненты об этом не знают. При ребрендинге классификатор и фидбек редактируются независимо.
21
Totals row обязателен для аналитических таблиц
.t-row--totals — последняя строка таблицы с числовыми колонками
Суммы, проценты-взвешенные (margin = profit/revenue, ROI = profit/costs), счётчик строк — обязательны. Без totals пользователь скроллит до конца и сам считает. Per-unit метрики («Себест. ед.», unit-цены) — прочерк, их складывать бессмысленно. Sticky-bottom — желателен, но не обязателен.
22
Именование новых компонентов — BEM
Новые компоненты: .component, .component--modifier, .component__element. Старые Tabler-style (.btn-primary, .kpi-label) — не переименовываем.
Файл содержит две конвенции: Tabler-style (до v1.5) и BEM (v1.5+). Переименование старого — breaking-change для legacy-шаблонов. Новые компоненты пишем в BEM для консистентности с v1.5+. Со временем legacy естественно уйдёт при миграции модулей.
23
INPUT-WRAP — базовый паттерн input с prefix/suffix
.input-wrap + .prefix / .suffix — канонический примитив для любых фиксированных префиксов/суффиксов (₽, %, .ru, ИНН). .password-field и .search-field — специализации того же паттерна с фиксированной иконкой вместо API prefix/suffix.
Фактически классы были в CSS с v1.x, но не были задокументированы: без demo, без nav-ссылки — формально «не в UI Kit». Команда переизобретала то же самое локально. v2.3 выводит примитив в публичный канон.
24
DEPRECATION: .field / .field-label → .form-field / .form-label
.field и .field-label помечены @deprecated в v2.3 и будут удалены в v3.0. Новые компоненты используют .form-field / .form-label.
Два одинаковых по назначению layout-примитива (v1.x .field и v2.2 .form-field) — путаница «что выбрать». Оставляем старые рабочими, чтобы legacy-шаблоны не сломались — но все demo переведены на новый примитив как единственный образец.

Когда <select>, а когда .select-popup: нативный <select> рендерит выпадающий список средствами ОС/браузера — это нельзя стилизовать (цвет выбранной строки, шрифт, отступы зависят от системной темы). Не комбинируй .kpi--accent-* с .kpi--dark — hero-карточка ведёт визуально сама.
Не дублируй акцентом то, что уже передаёт .delta--up/--down — это разные слои информации.
Цвет — только из токенов --success-dot, --danger-dot, --warning-dot, --color-primary. Никаких новых hex.

Правила (must)

  • Знак минуса — U+2212 (−). Не U+002D (-).
  • Разделитель разрядов — U+2009 (&thinsp;), не обычный пробел.
  • Десятичные — запятая ,. Только в коротких форматах и процентах.
  • «млн» и «тыс.» — нет. Используем М и К для коротких форм.
  • ₽ — суффикс, всегда после числа с пробелом. $/€ — префикс без пробела.
  • Цвет: signed transactions, deltas — да; балансы, итоги по дню, остаток на конец — нет.
  • Шрифтовое начертание — font-variant-numeric: tabular-nums в любой ячейке таблицы или блоке суммы.
  • Если значение ноль и контекст денежный — приглушённый --text-faint, цифра 0 или em-dash — ₽.
